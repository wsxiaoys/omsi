- Origin: Google, "Image generation | Gemini API",
  https://ai.google.dev/gemini-api/docs/image-generation
- Evidence kind: official documentation (feature guide, first-party)
- Publication date: not stated in the captured text; the page tracks the API reference
- Capture date: 2026-10-26
- Relevant model: `gemini-nano-banana-2.1` (Nano Banana 2.1), with sibling models compared

### Features (verbatim, abridged)

> **High-resolution output**: Built-in generation capabilities for 1K, 2K, and 4K visuals. Gemini
> 3.1 Flash Image adds the smaller 512px (0.5K) resolution (not supported on Gemini Nano Banana
> 2.1). Gemini 3.1 Flash Lite Image only supports 1K resolution.

> **Grounding with Google Search**: The model can use Google Search as a tool to verify facts and
> generate imagery based on real-time data (e.g., current weather maps, stock charts, recent
> events). [...] Gemini Nano Banana 2.1 and Gemini 3.1 Flash Image add the integration of Google
> Image Search Grounding alongside Web Search.

> **Thinking mode**: The model utilizes a "thinking" process to reason through complex prompts. It
> generates interim "thought images" (visible in the backend but not charged) to refine the
> composition before producing the final high-quality output.

> **Up to 14 reference images**: Mix up to 14 reference images to produce the final image.

> All generated images include a SynthID watermark.

Image Search grounding is scoped: "This feature is only available for the Gemini Nano Banana 2.1
and Gemini 3.1 Flash Image models", enabled by setting `search_types` to `["web_search",
"image_search"]` on the `google_search` tool.

### Limitations section (verbatim, abridged)

> For best performance, use the following languages: EN, ar-EG, de-DE, es-MX, fr-FR, hi-IN, id-ID,
> it-IT, ja-JP, ko-KR, pt-BR, ru-RU, ua-UA, vi-VN, zh-CN.

> Image generation does not support audio inputs. Video inputs are only supported for Gemini Nano
> Banana 2.1, Gemini 3.1 Flash Image, and Gemini 3.1 Flash Lite Image.

> The model won't always follow the exact number of image outputs that the user explicitly asks
> for.

> `gemini-nano-banana-2.1` and `gemini-3.1-flash-image` support character resemblance of up to 4
> characters and the fidelity of up to 10 objects in a single workflow.

> `gemini-nano-banana-2.1` and `gemini-3.1-flash-image` Grounding with Google Search do not
> support using real-world images of people from web search at this time.

## What this establishes

- 2.1's own parameter surface at the Gemini API: 1K/2K/4K output (no 0.5K), 14 aspect ratios
  including 4:1/1:4/8:1/1:8, up to 14 reference images, thinking levels minimal/medium/high with
  **medium** as default (a change from NB2, whose default is minimal), web + image search
  grounding, video input allowed, audio input not.
- All outputs carry a SynthID watermark.

## Contradictions with other first-party pages

- **4K token count: 2520 here vs 3780 on the pricing page.** Same model, same 4096x4096 size.
- The 2.1 table's `2:3` 1K entry reads 848x1264 while `3:2` reads 1264x848 — consistent, but note
  the 1K figures are ~1.07 MP rather than exactly 1 MP, so "1K" is a bucket name, not a pixel
  count.
- "thought images [...] not charged" here, while the pricing page bills "text and thinking" as
  output tokens. These can both be true (thought *images* uncharged, thought *text* charged) but
  the pages never reconcile them.

## Known gaps

- No latency numbers, no throughput figures, no error-rate guidance.
- No statement on what happens when a request asks for more than 14 reference images, or how the
  4-character / 10-object budget is enforced.
- The guide does not document `system_prompt` or `seed`; those appear only on host pages.

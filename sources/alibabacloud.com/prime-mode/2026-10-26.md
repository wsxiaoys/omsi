# Alibaba Cloud Model Studio: Fast mode (Prime)

- Origin: Alibaba Cloud Model Studio documentation, "Fast mode",
  https://www.alibabacloud.com/help/en/model-studio/prime-mode (nav label "Fast mode (Prime)")
- Evidence kind: official vendor documentation (feature page defining the Prime naming convention and
  listing the models that use it)
- Publication date: page header "Last Updated: Oct 11, 2026"; body stamp "Updated at: 2026-10-10
  18:15:49"
- Capture date: 2026-10-26
- Relevant models: `wan3.0-video-prime`; `glm-5.2-fast-preview` (the other model listed)

## What "Prime" means at Alibaba (verbatim)

> Fast mode provides higher TPS for latency-sensitive scenarios.

> **High-speed output**: TPS is increased to 1.5 to 2 times that of the standard API. This is suitable
> for AI coding assistants, multi-step Agent reasoning, real-time conversations, and other
> latency-sensitive scenarios.

> **Token-based billing**: The billing logic is the same as the standard API, with charges based on
> input and output tokens.

> To enable Fast mode, set the model parameter to the model ID of Supported models. No additional
> parameters are required.

The page's nav label is "Fast mode (Prime)", which ties the marketing word "Prime" to a documented
product feature: a **latency-optimised serving mode**, selected by model ID, not a different model
quality tier.

## Contradiction worth preserving

The Fast-mode page says billing "is the same as the standard API", which is true for the text model
on the same page only in *basis* (per token) and not in rate. For the video model the basis is
per second of output in both cases, but the **rate differs by 1.36–1.54×**, so "the same billing
logic" cannot be read as "the same price". The page does not discuss the video price at all beyond
listing it.

The "1.5 to 2 times" TPS figure is stated for the feature in general and is a text-token throughput
claim; no page applies it to video generation, and no wall-clock latency figure for either Wan 3.0
variant was found.

## Naming inconsistency across the estate

Alibaba does not use "Prime" consistently for this feature. The same page notes that "The model name
for the prime mode of glm 5.2 is still glm-5.2-fast-preview" — i.e. the other Fast-mode model uses a
`-fast-preview` suffix while the Wan model uses `-prime`. Elsewhere the Wan family uses `-flash`
(`wan2.6-i2v-flash`, `wan2.6-r2v-flash`) and `-turbo` (`wanx2.1-t2v-turbo`) for its speed variants.
The word "Prime" therefore identifies a serving mode in the docs, but the *suffix* is not a reliable
family-wide marker.

## Gaps

- No latency measurement for `wan3.0-video-prime` specifically; the 1.5–2× claim is about text TPS.
- No explanation of why a faster serving mode costs more per second rather than less.
- The page is written for text generation (chat-completions examples, token billing); the video row
  appears only in the price table, so how Fast mode is "enabled" for a video request beyond using the
  model ID is not documented here.

- Evidence kind: provider documentation (API reference: endpoints, request/response parameters)
- Publication date: page "Last Updated" 2026-10-21
- Capture date: 2026-10-26
- Relevant models: `qwen-audio-3.1-tts-plus`, `qwen-audio-3.1-tts-flash`, `qwen-audio-3.0-tts-plus`,
  `qwen-audio-3.0-tts-flash` (the API is shared; per-model behaviour is stated only where quoted)

## Endpoints (verbatim)

| Region | Endpoint |
| --- | --- |
| Singapore | `POST https://YOUR_WORKSPACE_ID.ap-southeast-1.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer` |
| China (Beijing) | `POST https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer` |

`X-DashScope-SSE: enable` switches to SSE streaming. Streaming responses carry `output.type` values
`sentence-begin` / `sentence-synthesis` / `sentence-end`; the final frame has
`output.finish_reason=stop` and returns the complete audio URL.

## Request parameters (verbatim)

| Parameter | Default | Documented behaviour |
| --- | --- | --- |
| `input.format` | **mp3** | "Audio encoding. Valid values: `mp3`, `pcm`, `wav`, and `opus`." |
| `input.sample_rate` | **22050** | "Valid values: 8000, 12000, 16000, 22050, 24000, 44100, and 48000. With `format=opus`, only 8000, 12000, 16000, 24000, and 48000 are supported." |
| `input.bit_rate` | 32 | "Audio bitrate in kbps. Range: [6, 510]. Applies only when `format=opus`." |
| `input.volume` | 50 | Range [0, 100] |
| `input.rate` | 1.0 | Range [0.5, 2.0] |
| `input.pitch` | 1.0 | Range [0.5, 2.0] |
| `input.seed` | 0 | Range [0, 65535]; "the same seed reproduces the same synthesis result" for the same model version, text, voice and parameters |
| `input.language_hints` | — | "Only the first array element is processed. This is independent of the source language of a cloning sample." |
| `input.instruction` | — | "An instruction controlling dialect, emotion, or role." |

Language codes (verbatim list): `zh`, `en`, `fr`, `de`, `ja`, `ko`, `ru`, `pt`, `th`, `id`, `vi`,
`es`, `it`, `ms`, `fil`, `ar` — sixteen.

## Response and billing fields (verbatim)

- `output.audio.url` — "The complete audio file URL, valid for 24 hours." Non-streaming responses
  return `output.audio.data` empty; streaming responses return Base64 chunks.
- `usage.characters` — "Cumulative billable characters."
- Note, verbatim: "qwen-audio-3.1-tts-flash is billed by input and output Tokens.
  qwen-audio-3.1-tts-plus, qwen-audio-3.0-tts-plus, and qwen-audio-3.0-tts-flash are billed by
  character."
- `usage.input_tokens` / `output_tokens` / `total_tokens` — "Applies only to qwen-audio-3.1-tts-plus,
  qwen-audio-3.1-tts-flash."

## Summary

The only documented place where output format, sample rate and provenance marking are specified for
this model family: four containers, seven sample rates up to 48 kHz (default 22050 Hz MP3), and an
**opt-in invisible AIGC identifier** that is off by default. The billing note is the authoritative
statement that `qwen-audio-3.1-tts-plus` is character-billed while its 3.1 Flash sibling is
token-billed.

## Gaps

- No text-length limit is stated anywhere in the reference.
- `usage.input_tokens`/`output_tokens` are documented as returned for the plus model even though the
  note says it is character-billed — whether both are returned, and what a token means here, is not
  explained.
- The AIGC identifier's standard, payload and detectability are not described; only the two field
  names are.
- No streaming latency, concurrency or per-request duration figures.

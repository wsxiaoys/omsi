## Billing model (verbatim)

> Image generation
>
> You are charged based on the number of input images and the number of successfully generated
> images. For models where the input image price is not specified, you are not charged for input.
> You are charged for output based on the number of successfully generated images.
>
> Formula: Cost = Input image unit price × Number of input images + Image unit price × Number of
> images generated.
>
> Notes: Failed requests incur no cost and do not consume your free quota.

These rows are flat per-image prices with no resolution tiers, unlike the 3.0 series.

## What this establishes

- `qwen-image-3.0-pro` costs **$0.04 per 1K image** and **$0.075 per 2K image**; input images are
  billed separately at $0.003 each.
- `qwen-image-3.0` costs **$0.03 per image at both 1K and 2K** — a 25% discount at 1K and a 60%
  discount at 2K versus the pro sibling.
- Pricing is per successfully generated image, not per token or per megapixel.
- The 3.0 series charges for input images; the 2.1 series rows list no input price.

## Gaps

- Region tabs (US Virginia, China Beijing, Hong Kong, Germany, Japan) were not expanded; only the
  default International/Singapore table was captured. Per-region prices may differ.
- The page does not define the pixel dimensions of the `1k`/`2k` output-resolution tiers.
- No statement about what counts as a "1k" versus "2k" output when the caller passes an explicit
  `size`, so the tier boundary for custom sizes is not documented in this capture.
- The flattened table lists the input unit price once per model (beside the `1k` row). The
  reproduction above copies it onto both resolution rows; the capture cannot confirm whether the
  input price actually varies by output tier.

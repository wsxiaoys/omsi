## The hosted Qwen3-TTS product is system-voice only

From the speech-synthesis overview's "All models" table, verbatim:

| Model ID | API | Voice cloning | Voice design | Instruction control |
| --- | --- | --- | --- | --- |
| qwen3-tts-flash | HTTP | Unsupported | Unsupported | Unsupported |
| qwen3-tts-flash-realtime | WebSocket | Unsupported | Unsupported | Unsupported |

Supported languages, verbatim:

> **Qwen3-TTS-Flash series** (system voices) (`qwen3-tts-flash`, `qwen3-tts-flash-realtime`): Chinese
> (Mandarin, Beijing, Shanghainese, Sichuan, Nanjing, Shaanxi, Hokkien, Tianjin, Cantonese — varies
> by voice), English, German, Italian, Portuguese, Spanish, Japanese, Korean, French, and Russian

That is the same ten-language set as the open-weights models plus Chinese dialect voices. The same
page documents that voice cloning and voice design on Model Studio are offered for
`qwen-audio-3.x-tts-*`, `qwen-audio-3.x-realtime-*` and `cosyvoice-*` — **not** for Qwen3-TTS.

## Request contract (`qwen3-tts-flash`, non-real-time HTTP)

Verbatim parameter documentation:

| Parameter | Required | Documented behaviour |
| --- | --- | --- |
| `model` | yes | `qwen3-tts-flash` |
| `input.text` | yes | "Supports multilingual mixed input. **The maximum input length is 600 characters.**" |
| `input.voice` | yes | System voice from the Qwen-TTS voice list (e.g. `Cherry`) |
| `input.language_type` | no | `Auto` or one of Chinese, English, German, Italian, Portuguese, Spanish, Japanese, Korean, French, Russian |

Response fields: `output.audio.url` (valid 24 hours), `output.audio.data` (base64, streaming chunks
only), `output.audio.expires_at`, and `usage.characters` — "The number of characters in the input
text. Returned only by the Qwen3-TTS-Flash model." `usage.input_tokens` and `usage.output_tokens`
are "always 0" for this model, i.e. billing is per character, not per token.

Streaming playback sample decodes with `pyaudio` at `rate=24000`, and the Java sample sets
`AudioFormat` to 24,000 Hz 16-bit mono — consistent with the released tokenizer's 24 kHz output.

Endpoint: `POST https://dashscope-intl.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`
(Singapore) with `X-DashScope-SSE: enable` for streaming.

## Sibling naming, as the vendor uses it today

- **Qwen3-TTS-Flash** (`qwen3-tts-flash`, `qwen3-tts-flash-realtime`) — the model this page tracks.
- **Qwen-Audio-TTS** (`qwen-audio-3.1-tts-plus`, `qwen-audio-3.1-tts-flash`,
  `qwen-audio-3.0-tts-plus`, `qwen-audio-3.0-tts-flash`) — the current recommended TTS line on Model
  Studio, with cloning, design, instruction control, emotion/nonverbal tags, SSML, LaTeX, and PCM /
  WAV / MP3 / Opus output "at sample rates up to 48 kHz". Not the same model ID family.
- **CosyVoice** (`cosyvoice-v3*`, `cosyvoice-v2`) — a separate FunAudioLLM line.
- **Qwen-TTS** (`qwen-tts-flash`) — a legacy, token-billed, mainland-only entry still on the pricing
  page; no model card was captured. No first-party model named "Qwen2.5-TTS" exists in these docs;
  the pre-Qwen3 hosted TTS line is this `qwen-tts-flash` entry.

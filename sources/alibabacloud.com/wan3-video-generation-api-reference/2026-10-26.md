## Scope (verbatim)

> Wan3.0 is an All-in-One reference-based video generation model that supports Text-to-Video,
> Image-to-Video (first frame/first-last frame), and Reference-based Video Generation. It can generate
> videos up to 30 seconds long at 30fps. Currently in preview.

"Currently in preview" is the only preview statement found in any captured document, and it is not
repeated in the guide, the pricing page, or the changelog (see the sibling records).

## Model IDs (verbatim)

> `model` string (Required) Model name. Valid values:
> `wan3.0-video-prime`: High-speed version with capabilities aligned to the standard version, with
> significantly improved end-to-end speed.
> `wan3.0-video`: Standard version.

Two IDs, one parameter surface. The vendor's differentiator is end-to-end speed, not capability.

## Input: `input.media` types and limits (verbatim)

> `first_frame`: First frame image. Maximum 1 image, strictly used as the first frame of the video.
> `last_frame`: Last frame image. Maximum 1 image, strictly used as the last frame of the video.
> `reference_image`: Reference image. Maximum 10 images.
> `reference_video`: Reference video. Maximum 5 clips, with a total duration of no more than 15 seconds.
> `reference_audio`: Reference audio. Maximum 5 clips, with a total duration of no more than 15 seconds.
> `file`: File. Maximum 1 file, cannot be used together with link.
> `link`: Web link. Maximum 1 link, cannot be used together with file.

Input image limits: "Format: JPEG, JPG, PNG (transparent channel not supported), BMP, WEBP.
Resolution: [240, 8000] pixels per side. Aspect ratio: no more than 8:1. File size: no more than
20MB."

Input video limits: "Format: mp4, mov. Duration: [1, 15] seconds per clip, with a total duration of no
more than 15 seconds. Frame rate: ≥16 fps. Resolution: [240, 4096] pixels per side. Aspect ratio: no
more than 8:1. File size per clip: no more than 100MB."

Input audio limits: "Format: wav, mp3. Duration: [1, 15] seconds per clip, with a total duration of no
more than 15 seconds. File size: no more than 15MB."

Input file limits: "Format: docx, doc, xlsx, xls, pptx, ppt, pdf, txt, key, pages, numbers, md. File
size: no more than 100MB. Page limit: no more than 50 pages".

Input link: "URL of a public web page. Only supports parsing publicly accessible web pages that do not
require login".

## Parameters (verbatim)

> `resolution` … Default value: `1080P`. Valid values: `1080P` `720P` `480P`

> `ratio` … `adaptive` (Default value) … `21:9` `16:9` `4:3` `1:1` `3:4` `9:16`

> `duration` … Default value: 5. Without video input: an integer in the range [2, 30]. With video
> input: the total input video duration + output video duration must not exceed 30 seconds. When set
> to `-1`: Smart duration mode, where the model automatically recommends a suitable duration based on
> the input prompt, content, and rich media.

> `audio` … `true`: Default value, the output video contains audio. … Enabling or disabling audio does
> not affect pricing.

> `seed` … Random seed. Used to reproduce generation results. Value range: -1 or [0, 2147483647]. …
> Even with the same seed value, generation results may not be perfectly identical.

> `prompt_extend` … When a document (`file`) or webpage (`link`) is provided as input,
> `prompt_extend` must be set to `true`.

> `watermark` … `false`: Default value, no watermark is added. `true`: A watermark is added.

Prompt limit: "a maximum of 20,000 characters. Content exceeding this limit will be automatically
truncated."

## Output (verbatim)

> `video_url` … URL of the generated video. Returned when the task succeeds. The video format is MP4
> (H.264 encoding).

> `fps` … Frame rate of the generated video. Default value: 30.

> `video_count` … Number of generated videos. Fixed at 1.

> `duration` … Total video duration, in seconds. When no input reference video is provided, it equals
> the output video duration; when an input reference video is provided, it equals the sum of the input
> video duration and the output video duration.

"Video URLs are valid for only 24 hours and then automatically purged."

## Mode exclusivity (verbatim)

> `first_frame`/`last_frame` and `reference_image`/`reference_video`/`reference_audio`/`file`/`link`
> types are mutually exclusive and cannot be used together in the same request.

> `file` and `link` are mutually exclusive (choose one), but both can be combined with
> `reference_image`/`reference_video`/`reference_audio`.

Documented error for a mixed request:

> The two modes are mutually exclusive. Do not pass reference_xx and first_frame/last_frame at the same
> time.

## Documented FAQ (verbatim)

> Why can't I pass in audio or other media assets in first/first-last frame mode? Wan3.0's first
> frame/first-last frame mode only supports `first_frame` and `last_frame`, and cannot accept other
> types such as audio at the same time

> Difference from Wan2.7 Image-to-Video series: Wan2.7's first frame/first-last frame mode supports
> passing in `driving_audio` for audio-driven generation; Wan3.0's first frame/first-last frame mode
> does not. If you need audio-driven generation, use the all-modal reference mode
> (`reference_image` + `reference_audio` combination) instead.

This is a documented capability *regression* against the immediately preceding Wan 2.7 generation for
one task type.

## Summary

First-party definition of the model: two IDs (`wan3.0-video`, `wan3.0-video-prime`) sharing one
all-in-one surface — text-to-video, first-frame and first-last-frame image-to-video, and
reference-to-video with up to 10 images, 5 videos (≤15 s total), 5 audio clips (≤15 s total) and one
document or web page. 2–30 s output at 480P/720P/1080P, 30 fps, MP4/H.264, audio on by default and
price-neutral. Six regions. Described as "currently in preview" on this page only.

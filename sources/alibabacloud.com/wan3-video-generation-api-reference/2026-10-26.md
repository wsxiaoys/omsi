# Alibaba Cloud Model Studio: Wan3.0 Video Generation API Reference

- Origin: Alibaba Cloud Model Studio API Reference, "Wan3.0 - Video Generation",
  https://www.alibabacloud.com/help/en/model-studio/wan3-video-generation-api-reference
- Evidence kind: official vendor documentation (API reference: request/response parameters, input
  limits, supported input combinations, FAQ)
- Publication date: "Last Updated: Oct 15, 2026"
- Capture date: 2026-10-26
- Relevant models: `wan3.0-video`, `wan3.0-video-prime` (one shared parameter set)

## Release status (verbatim)

> Wan3.0 is an All-in-One reference-based video generation model that supports Text-to-Video,
> Image-to-Video (first frame/first-last frame), and Reference-based Video Generation. It can
> generate videos up to 30 seconds long at 30fps. Currently in preview.

"Currently in preview" as of a page last updated 2026-10-15 is the only status statement captured
from the vendor. It sits against the Model Studio changelog, which lists both models as released in
August 2026 (`sources/alibabacloud.com/wan3-0-release-dates/2026-10-26.md`), and against the
capability matrix on the model pages, which marks the model playground "Supported" with no preview
label. No page explains what "preview" restricts.

## The two model IDs (verbatim)

> wan3.0-video-prime: High-speed version with capabilities aligned to the standard version, with
> significantly improved end-to-end speed.

> wan3.0-video: Standard version.

This is the clearest vendor statement of the relationship: **capabilities aligned**, speed improved.
The request body, parameters and response schema below are shared; `model` is the only switch.

## Transport

Asynchronous only. `POST https://{WorkspaceId}.{region}.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`
with headers `Content-Type: application/json`, `Authorization: Bearer $KEY`, `X-DashScope-Async: enable`.
Region hosts captured: Singapore `ap-southeast-1`, Beijing `cn-beijing`, US (Virginia) `us-east-1`,
Japan (Tokyo) `ap-northeast-1`, Germany (Frankfurt) `eu-central-1`, China (Hong Kong) `cn-hongkong`.
Cross-region calls fail:

> To ensure a successful API call, make sure that the model, Endpoint URL and API Key all belong to
> the same region. Cross-region calls will fail.

Poll `GET /api/v1/tasks/{task_id}`. The `task_id` and the resulting `video_url` are both valid for 24
hours. Task states: `PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELED`, `UNKNOWN`.

## `input.media` types and limits (verbatim values)

| `type` | Max count | Limits |
| --- | --- | --- |
| `first_frame` | 1 | "strictly used as the first frame" |
| `last_frame` | 1 | "strictly used as the last frame" |
| `reference_image` | 10 | JPEG/JPG/PNG (no alpha)/BMP/WEBP, 240–8000 px per side, aspect ≤ 8:1, ≤ 20 MB |
| `reference_video` | 5 | mp4/mov, 1–15 s each and ≤ 15 s total, ≥ 16 fps, 240–4096 px per side, aspect ≤ 8:1, ≤ 100 MB each |
| `reference_audio` | 5 | wav/mp3, 1–15 s each and ≤ 15 s total, ≤ 15 MB each |
| `file` | 1 | docx/doc/xlsx/xls/pptx/ppt/pdf/txt/key/pages/numbers/md, ≤ 100 MB, ≤ 50 pages; mutually exclusive with `link` |
| `link` | 1 | public web page, no login; mutually exclusive with `file` |

`prompt` is optional if media is present, supports Chinese and English, and is truncated above 20 000
characters. Reference media is addressed positionally in the prompt: "the 1st reference_video in the
array corresponds to Video 1" and so on, with images and videos numbered independently.

## Response

`usage` reports `video_count` ("Fixed at 1"), `duration`, `input_video_duration`,
`output_video_duration`, `fps` ("Default value: 30"), `SR`, `ratio`. Output is "MP4 (H.264 encoding)".
`video_count` fixed at 1 means one clip per request — no batch of candidates.

## Material combinations (verbatim rule)

> first_frame/last_frame and reference_image/reference_video/reference_audio/file/link types are
> mutually exclusive and cannot be used together in the same request.

Documented task modes: text-to-video (prompt only, `media` not supported), first-frame,
first-and-last-frame, reference-based (any combination of image/video/audio), file-or-web-page to
video (combinable with references), video editing (requires `reference_video` + editing-intent
prompt), video extension (requires `reference_video` + extension-intent prompt; `ratio` should be
`adaptive`).

Error example returned for a mixed request, verbatim:

> The two modes are mutually exclusive. Do not pass reference_xx and first_frame/last_frame at the
> same time.

## FAQ (verbatim)

> Wan3.0's first frame/first-last frame mode only supports first_frame and last_frame, and cannot
> accept other types such as audio at the same time.

> Difference from Wan2.7 Image-to-Video series: Wan2.7's first frame/first-last frame mode supports
> passing in driving_audio for audio-driven generation; Wan3.0's first frame/first-last frame mode
> does not.

So the 30-second audio-visual generation and the first/last-frame control path are separate modes,
not combinable ones.

## Gaps

- No fps control: 30 fps is reported in `usage` as the output frame rate, but no parameter changes it.
- No negative prompt, no camera-control, no shot-count parameter, no batch size.
- The reference says nothing about content moderation, refusal behaviour, or a safety filter.
- No statement of per-region model availability beyond "Supported models vary by region".

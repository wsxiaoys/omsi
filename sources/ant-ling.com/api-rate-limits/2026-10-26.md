## Limits, verbatim

> 全局设置 QPS 与超时时间（Timeout）机制，以确保服务的可用性与稳定性。

> QPS：每秒钟 2 次请求上限，超出时将提示"429 - Rate limit reached for requests"。

> Timeout：同步调用存在 90s 的超时时间，推荐使用流式调用。

("QPS: maximum 2 requests per second; exceeding it returns 429 - Rate limit reached for
requests." / "Timeout: synchronous calls time out at 90s; streaming calls are recommended.")

## Summary

The first-party API is rate-limited to **2 QPS globally** with a **90-second** synchronous
timeout. For a model the vendor positions for long-horizon agent loops, that ceiling matters
more than it would for a chat model: the vendor's own benchmark anecdotes involve multi-hour
runs, and 2 QPS is the constraint on running them through the hosted API.

## Gaps

- The page does not distinguish per-account, per-key or per-model limits; it says "全局" (global)
  without defining the scope.
- No token-per-minute limit is stated.
- No statement of whether the limit is raised on request.

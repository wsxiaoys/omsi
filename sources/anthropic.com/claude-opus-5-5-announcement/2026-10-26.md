# Introducing Claude Opus 5.5 — Anthropic release announcement

- **Origin:** "Introducing Claude Opus 5.5", Anthropic,
  <https://www.anthropic.com/claude-opus-5-5>.
- **Evidence kind:** first-party announcement (vendor launch post, with vendor-run
  benchmark table and vendor pricing).
- **Publication date:** 2026-09-22 (stated on the page). Capture date 2026-10-26.
- **Relevant models:** Claude Opus 5.5 (`claude-opus-5-5`); comparison columns for
  Claude Fable 5.1, Claude Opus 5, GPT-6 Astra, GPT-5.6 Sol.
- **Capture type:** full snapshot of the rendered page text (1,355 lines). No artifacts
  saved. Figures below are transcribed from that snapshot; the page's charts are
  images and are **not** reproduced.

## Positioning, verbatim

> "We're introducing Claude Opus 5.5, the first model in our new Claude 5.5 family. It
> performs at the level of Claude Fable 5.1 on most work and costs 40% less to run than
> Opus 5."

> "Opus 5.5 is a major step up from Opus 5. It's the new leading model …"

The post also states Opus 5.5 is "our first release since we called for pacing the
frontier", and that it "was tested before release by external evaluators, including
Frontier Design and METR".

## Vendor pricing, verbatim

> "Input and output tokens are $4 and $20 per million, 20% less than Opus 5. Cache reads
> (which make up the majority of agentic and coding work costs) are $0.20 per million
> tokens, 60% less than Opus 5. Opus 5.5 also generates output more than 30% faster than
> Opus 5."

> "Fast mode for Opus 5.5 is also available in Claude Code and the Claude Platform with up
> to 2.5x speed. It costs $8 per million input tokens and $40 per million output tokens."

Pricing table on the page (per 1M tokens): cache reads $0.20 (Opus 5 $0.50), input $4
($5), output $20 ($25), cache writes $5 ($6.25).

Configuration footnote, verbatim:

> "Unless otherwise noted, all Claude Opus 5.5 results use adaptive thinking at max
> effort. Terminal-Bench 4.0 results are reported for Claude Opus 5.5 at xhigh effort and
> GPT-6 Astra at high effort, as reported by OpenAI; these represent each model's highest
> score. Claude Opus 5.5 was evaluated with its production safeguards enabled. When they
> intervened, cybersecurity tasks were completed by Claude Opus 4.8, and biology and
> frontier LLM development tasks were completed by Claude Opus 5. This likely reduces
> Claude Opus 5.5's performance on these benchmarks."

Terminal-Bench 4.0 error bars, verbatim:

> "The standard error is ±2.6 pts for Claude Opus 5.5 and ±1.6–2 pts for the other Claude
> models. The public leaderboard (5 trials/task, Claude Code harness) reports Claude Opus
> 5 at 51.8%; our setup reproduces it at 52.3%, within noise."

AutomationBench was "run and reported by Zapier", without fallback models, so "safeguard
interventions were considered failures".

### Two effort levels are mixed in one post

The table above is **max effort** (Terminal-Bench at xhigh). The cost-efficiency prose
quotes **default (medium)** effort: "At default effort (medium), Opus 5.5 scores 54.6%"
on FrontierCode and "52.5%" on CursorBench, against 54.4% and 57.8% in the table. Both
sets are Anthropic's own numbers, measured at different effort settings; they are not
interchangeable and this page keeps them apart.

## Safety and deployment terms, verbatim

> "Opus 5.5 is the first Opus model to launch with a similar class of safeguards to Fable
> 5.1 on cybersecurity, biology, and distillation, all of which fall back to another
> model transparently."

> "Users will be able to identify and fix bugs in their code as part of the routine
> software development lifecycle, but most cybersecurity tasks will be re-routed to Opus
> 4.8."

> "Because Opus 5.5 is comparable to Claude Mythos 5.1 in biology and cybersecurity, we're
> deploying it with safeguards similar to those on Claude Fable 5.1. Vetted organizations
> can apply today to our Life Sciences Verification Program to use Opus 5.5 for biology
> research."

> "Opus 5.5 is launching with preserved thinking, the anti-distillation safeguard we
> introduced with Fable 5.1. It stops API users from editing Claude's prior context in an
> attempt to extract Claude's reasoning. It applies to Fable 5.1 and Opus 5.5 for API
> accounts created on or after August 31, 2026."

> "Like previous Opus models, Opus 5.5 is available with zero data retention."

> "As with Fable 5.1, Opus 5.5 comes with our watermarking measures to comply with the EU
> AI Act, discussed here. It is also no longer available with 'thinking' mode switched
> off, as we describe here."

- Testimonials (GitHub, Clio, Lovable, Quantium, Spotify, Optiver, Column, Kiro,
  Deloitte, Rogo, LexisNexis, Walleye, Hex, Thomson Reuters, Hebbia, Viktor) are

  check and are not used on the model page as evidence of capability.

## Contradiction to preserve

The announcement labels the computer-use row **OSWorld 2.1**; the system card's
capability summary (Table 8.1.A) reports the same 81.8% partial score as **OSWorld 2.0**.
The score is identical, the benchmark version label is not.

## Gaps

- No context window, max output, or knowledge-cutoff figure appears in the post; those
  come from the platform docs.
- No architecture, parameter count, or training-compute disclosure.
- The post gives no confidence intervals except the Terminal-Bench and
  Terminal-Bench-Science standard errors quoted above.
- Charts (accuracy-vs-cost curves) were not captured; only their captions.

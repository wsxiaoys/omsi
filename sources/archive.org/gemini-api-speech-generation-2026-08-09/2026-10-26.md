## Why this snapshot matters

Every request example in it uses `gemini-3.1-flash-tts-preview`. It is the only captured first-party
revision that documents the 3.1 request surface, its voice list, its language table and its
model-specific limitations. The live revision of the same page documents only 3.8
([current guide](../../google.dev/gemini-api-speech-generation/2026-10-26.md)).

## Streaming (verbatim)

> **Note:** Streaming is supported for Text-to-Speech (TTS) models starting with version 3.1
> (including `gemini-3.1-flash-tts-preview`).

## Limitations (verbatim)

> TTS models can only receive text inputs and generate audio outputs.

> A TTS session has a context window limit of **32k tokens**.

> TTS does not support streaming, except when using `gemini-3.1-flash-tts-preview`.

> The following constraints apply specifically when using the Gemini 3.1 Flash TTS Preview model for
> speech generation:

> **Voice inconsistency with prompt instructions:** The model's output may not always strictly match
> the selected speaker, causing the audio to sound different than expected.

> **Quality of longer outputs:** Speech quality and consistency may begin to drift with generated
> outputs that are longer than a few minutes. We recommend splitting your transcripts into smaller
> chunks.

> **Occasional text token returns:** The model occasionally returns text tokens instead of audio
> tokens, causing the server to fail the request with a 500 error. […] you should implement automated
> retry logic in your application to handle these.

> **Prompt classifier false rejections:** Vague prompts may fail to trigger the speech synthesis
> classifier, resulting in a rejected request (`PROHIBITED_CONTENT`) or causing the model to read your
> style instructions and director's notes aloud.

## Prompting surface at the time (verbatim)

> Tags are inline modifiers like `[whispers]` or `[laughs]` that give you granular control over the
> delivery. […] If your transcript is not in English, for best results we recommend that you still use
> English audio tags.

The prompt-shaping vocabulary of that era was prose: "Audio Profile", "Scene" description and
"Director's Notes", supplied in the prompt text rather than in structured fields.

## Sample rate (verbatim, from every code sample)

`def wave_file(filename, pcm, channels=1, rate=24000, sample_width=2)` — i.e. the samples write
mono 24 kHz 16-bit PCM into a WAV container, and the model returns raw PCM that the caller must wrap.

## Summary

As of the 2026-07-30 revision, `gemini-3.1-flash-tts-preview` **was** the current Gemini TTS model:
30 voices, 78 listed language codes, up to 2 speakers, streaming from 3.1 onward, a 32k-token session
context, 24 kHz mono 16-bit PCM output wrapped by the caller, and four documented model-specific
failure modes (voice mismatch, drift past a few minutes, sporadic text-token returns causing HTTP
500, and prompt-classifier false rejections).

## Gaps

- No byte or character cap in this revision; the 4,000/8,000-byte and 655-second limits appear only
  in the Cloud Text-to-Speech documentation
  ([Cloud TTS](../../cloud.google.com/gemini-tts-cloud-text-to-speech/2026-10-26.md)).
- No watermarking statement of any kind.
- The 32k session context conflicts with the model card's 8,192 input / 16,384 output token limits;
  the two figures measure different things (session context versus per-request tokens) but neither
  page says so.

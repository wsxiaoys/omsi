## Request schema `Flux3ImageKleinInputs` (transcribed field by field)

| Field | Type / range | Default | Notes (verbatim where quoted) |
| --- | --- | --- | --- |
| `prompt` | string, **required** | — | "Free-form prompt describing the image." |
| `images` | string \| string[] \| null | — | "Optional reference image(s), each an http(s) URL or base64, one to 10 total. The first is the image being edited and sets the default output size." |
| `aspect_ratio` | enum of 15 ratios, or `auto` | `auto` | `21:9, 2:1, 16:9, 3:2, 7:5, 4:3, 5:4, 1:1, 4:5, 3:4, 5:7, 2:3, 9:16, 1:2, 9:21` |

| `safety_tolerance` | integer `[0, 7]` | `2` | "Harm moderation tolerance from 0 to 7, with 0 the strictest. The route and organization determine the approved maximum and per-category ceilings. Unapproved levels return 422 with approved levels." |

Schema description: "FLUX 3 Image Klein: text-to-image, or editing with up to 10 reference
images." `additionalProperties: false`.

Response `AsyncResponse`: `id`, `polling_url`, plus `cost` ("Cost in credits for this request"),
`input_mp` and `output_mp` ("megapixels (2 decimal places)"). Auth: `x-key` header.

## What this establishes

- One endpoint serves both text-to-image and editing; the presence of `images` selects the mode.
- Hard request-level limits: **≤10 reference images**, **≤16 steps**, **≤16.8 MP output**,
  **≤6256 px per side**, **15 named aspect ratios**.
- The API exposes a step count but **no guidance/CFG field**, consistent with the distilled
  checkpoint's fixed CFG 1.
- There is **no `grounding` field** and **no "pixel restoration" field**, although BFL's launch
  post says the API endpoint ships "pixel restoration, which preserves unedited regions of an
  image exactly" and the parent model's docs describe a `grounding` switch
  ([FLUX 3 Image overview](../flux-3-image-klein-parent-features/2026-10-26.md)). If those
  features exist on Klein they are not caller-visible in this schema.

## Gaps

- The schema does not say which checkpoint serves `1.5k` vs `2k` vs `4k`, whether 4K is native or
  upscaled for Klein, or what `cost` in credits converts to (BFL states 1 credit = $0.01
  elsewhere; the per-request mapping is only checkable by calling the API).
- No latency, throughput, or rate-limit information.
- The docs page's own claim that Klein "takes the same fields as FLUX 3 Image" is not verifiable
  from this schema alone: `grounding`, which the parent's documentation exposes, is absent here.

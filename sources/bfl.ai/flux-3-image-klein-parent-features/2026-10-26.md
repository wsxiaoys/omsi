# BFL docs: FLUX 3 Image overview (captured to compare against Klein)

- Origin: Black Forest Labs, "FLUX 3 Image", https://docs.bfl.ai/flux_3/flux3_image_overview.md
  (the Markdown rendering of the docs page, fetched directly)
- Evidence kind: official documentation
- Publication date: not stated on page; FLUX 3 Image launched 2026-10-01 per BFL's release notes
- Capture date: 2026-10-26
- Relevant models: FLUX 3 Image (the parent model), FLUX 3 Image Klein (compared against it)

## Why this page was captured

FLUX 3 Image Klein's documentation says Klein "supports the same features" as FLUX 3 Image. This
record captures the parent page so the claim can be checked feature by feature. A separate
`flux-3-image-overview` record may later be created for the FLUX 3 Image page itself; that would
duplicate this document, which is acceptable, and neither record should be edited to match the
other.

## Captured content — verbatim

> FLUX 3 Image gives you maximum control over every pixel. Generate an image from a prompt, edit
> specific details, combine up to ten references, and draw bounding boxes to place each element.

Documented capabilities: text-to-image; edit by instruction; multi-reference ("combine up to ten
images", referring to each by position); bounding boxes appended to the prompt as
`[top, left, bottom, right]` on a 0–1000 grid; and grounding.

### Grounding (verbatim)

> By default, FLUX 3 searches the web to get real things right. Set `grounding` to `false` for
> faster results that use only your prompt.

The worked example is a pair of Oktoberfest posters: with grounding off the model invents a
vintage poster "dated 2025"; with grounding on it renders "the official 2026 poster with the
Frauenkirche towers, a Ferris wheel and a beer stein, dated 19.9. to 4.10.2026". The diff shown on
the page is `"grounding": false` → `"grounding": true`.

## What this establishes

- The parent model has a **default-on web grounding search**, exposed as a `grounding` request
  flag, and the page treats it as a headline capability.
- Nothing else on the page is Klein-specific; there are no benchmark numbers, no pricing, and no
  hardware claims.

## Gaps

- The Klein documentation's "same features" sentence does not mention grounding, and Klein's
  request schema (separate record) has no `grounding` field. Whether Klein lacks grounding
  entirely, or has it on by default without a flag, is not stated in any captured source. Treat
  "Klein supports the same features" as vendor shorthand, not an exhaustive list.
- Grounding quality is illustrated with a single vendor-chosen example; no failure cases, no
  measurement of how often the search returns the right fact.

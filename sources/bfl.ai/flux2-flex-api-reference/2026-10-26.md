## Captured content

Operation description (verbatim):

> Submits an image generation or editing task with FLUX.2 [flex]. Specialized for typography and

### `Flux2FlexInputs` fields (from `https://api.bfl.ai/openapi.json`)

| Field | Type / range | Default | Description (verbatim where quoted) |
| --- | --- | --- | --- |
| `prompt` | string | required | "Text prompt for image generation." |
| `prompt_upsampling` | boolean | `true` | "Whether to use prompt upsampling." |
| `input_image` … `input_image_8` | string | — | eight named reference-image slots, "Path to the input image." etc. |
| `input_image_blob_path` | string | — | "Blob path to the input image." |
| `seed` | integer | — | "Optional seed for reproducibility." |
| `width`, `height` | integer, min 64 | `0` | "Width of the image" / "Height of the image" (0 = model default) |
| `guidance` | number, 1.5–10 | `5` | "Guidance scale for image generation. High guidance scales improve prompt adherence at the cost of reduced realism." |
| `steps` | integer, 1–50 | `50` | "Number of steps for image generation. Higher steps lead to more detailed and realistic images." |
| `safety_tolerance` | integer, 0–7 | `2` | "Harm moderation tolerance from 0 to 7, with 0 the strictest. The route and organization determine the approved maximum and per-category ceilings. Unapproved levels return 422 with approved levels." |
| `output_format` | enum `jpeg`, `png`, `webp` | `jpeg` | — |
| `user` | string, ≤256 | — | "Opaque identifier for the end user supplied by the calling platform." |
| `webhook_url`, `webhook_secret` | string | — | async delivery options |

The async response carries `cost`, `input_mp` and `output_mp` fields ("Input megapixels (2
decimal places)", "Output megapixels (2 decimal places)"), i.e. BFL reports both sides of the
megapixel meter per request.

### Why the schema matters for identity

Cross-checked against the same OpenAPI document on the capture date:

| Endpoint | Request schema | `steps` | `guidance` |
| --- | --- | --- | --- |
| `/v1/flux-2-flex` | `Flux2FlexInputs` | yes (1–50) | yes (1.5–10) |
| `/v1/flux-2-pro` | `Flux2Inputs` | no | no |
| `/v1/flux-2-max` | `Flux2Inputs` | no | no |
| `/v1/flux-2-klein-4b` | `Flux2KleinInputs` | no | no |
| `/v1/flux-2-klein-9b` | `Flux2KleinInputs` | no | no |
| `/v1/flux-3-image` | `Flux3ImageInputs` | no | no |
| `/v1/flux-3-image-klein` | `Flux3ImageKleinInputs` | yes | no |

`Flux2Inputs` (shared by [pro] and [max]) instead carries `disable_pup`, described as "Disable
automatic prompt upsampling for this request. FLUX.2 [pro] and [max] apply prompt upsampling by
default". [flex] therefore differs from [pro]/[max] in the request contract itself, not only in
pricing: it is the only FLUX.2 endpoint on BFL's API that accepts sampling controls, and it
expresses upsampling as a positive `prompt_upsampling` flag rather than `disable_pup`.

FLUX 3, the current generation, does not restore the control: `/v1/flux-3-image`
(`Flux3ImageInputs`) exposes neither `steps` nor `guidance`, and `/v1/flux-3-image-klein`
exposes `steps` but not `guidance`. Across the whole OpenAPI document on the capture date,
`guidance` appears in only four request schemas — `Flux2FlexInputs` and the FLUX.1-era
`FluxDevInputs`, `FluxProFillInputs`, `FluxProExpandInputs` (`/v1/flux-dev`,
`/v1/flux-pro-1.0-fill`, `/v1/flux-pro-1.0-expand`). Among FLUX.2 and FLUX 3 models, [flex] is
the only endpoint that accepts a guidance scale.

## Known gaps

- The schema does not state a maximum output resolution, an aspect-ratio preset list, or an
  input+output megapixel cap for [flex]. BFL's prompt reference documents a **9 MP total
  input+output limit for [pro]** only (see
  [bfl.ai/flux2-flex-prompt-reference/2026-10-26.md](../flux2-flex-prompt-reference/2026-10-26.md)).
- No latency or benchmark figures on this page.
- Whether the endpoint has ever changed weights is not stated here; see the release-notes
  record for the 2026-01-29 performance update.

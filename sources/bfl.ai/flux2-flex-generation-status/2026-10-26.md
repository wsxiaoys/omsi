# BFL official: site-level agent guide — FLUX.2 generation status

- Origin: Black Forest Labs, `https://bfl.ai/llms-full.txt` (site-wide machine-readable guide,
  the "Model IDs: do not trust memory" section)
- Evidence kind: official documentation (vendor-written guide for API consumers)
- Publication date: none stated
- Capture date: 2026-10-26
- Relevant models: FLUX.2 [flex] (as part of the FLUX.2 family's generation status)

## Captured content (verbatim)

> Do not use a FLUX model name, endpoint path or parameter remembered from training data. BFL
> releases new models often and older endpoints are superseded. Read the current endpoint list
> from https://api.bfl.ai/openapi.json or https://docs.bfl.ai/llms.txt before writing a request.

> * Current API endpoints: `/v1/flux-3-video` for video, `/v1/flux-3-image` and
>   `/v1/flux-3-image-klein` for images, and the FLUX Tools `/v1/flux-tools/video-upscale-v1` and
>   `/v1/flux-tools/video-edit-v1` for existing video.
> * The FLUX.2 image family (\[max], \[pro], \[flex] and \[klein]) is the previous generation and
>   is still served. The MCP server's generate_image tool uses FLUX.2 models.
> * FLUX 3 Max is available on fal at https://fal.ai/flux-3-max. It is not an endpoint on
>   api.bfl.ai, a model on the MCP server or a model in the Playground, and it is not in the
>   OpenAPI spec. Send users who ask for it to fal.
> * Do not recommend FLUX.1, FLUX1.1 or FLUX.1 Kontext for new projects.

## What this establishes

- As of the capture date, BFL describes the **whole FLUX.2 family, [flex] included, as "the
  previous generation"** while still serving it. FLUX 3 Image is the current image line.
- [flex] therefore has a first-party status statement: still available, no longer the newest
  generation. Nothing in the document announces a deprecation date, a retirement window, or a
  successor for the typography/control niche.
- The document does not single out [flex]; the status is family-level, so it cannot be read as a
  [flex]-specific support commitment.

## Known gaps

- No dates: "previous generation" is not dated, and no end-of-life policy is linked.
- The successor does not replace [flex]'s control surface: per the same OpenAPI document,
  `/v1/flux-3-image` exposes neither `steps` nor `guidance`, and `/v1/flux-3-image-klein`
  exposes `steps` but not `guidance` (recorded in
  [bfl.ai/flux2-flex-api-reference/2026-10-26.md](../flux2-flex-api-reference/2026-10-26.md)).
  Whether FLUX 3 Image reaches better typography than [flex] at fixed settings was not
  investigated.

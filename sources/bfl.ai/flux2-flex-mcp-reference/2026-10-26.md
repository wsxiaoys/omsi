## Captured content

Model list for the MCP `generate_image` tool (verbatim):

> Available models on `generate_image`: `flux2_pro_preview` (default), `flux2_max` (highest
> quality), `flux2_klein_9b_preview` (faster, up to 4 input images), `flux2_flex` (best for
> typography), `flux2_klein_4b`. The full catalog, per-model reference-image limits, and the FLUX
> Tools are also exposed as the `bfl://models` MCP resource.

Troubleshooting guidance (verbatim):

> * For typography or readable text, ask for FLUX.2 \[flex].
> * For hero shots or final assets, ask for FLUX.2 \[max].

The tool description states each request carries "its own prompt, model, dimensions, seed, and up
to 8 `input_image` slots".

## What this establishes

- BFL exposes [flex] as a first-class model choice on its own MCP surface under the short name
  `flux2_flex`, alongside `flux2_pro_preview` (default), `flux2_max`, and the Klein variants.
  This is a third first-party surface (API, playground, MCP) where [flex] is named separately
  from [pro].
- BFL's own routing advice is consistent across surfaces: [flex] for typography/readable text,
  [max] for hero shots, [pro] as the default.

## Known gaps

- The MCP model list does not state step/guidance ranges; it is a name-and-pick surface, so it
  cannot show whether the MCP path exposes [flex]'s sampling controls at all.
- The `bfl://models` resource is referenced but was not captured; it is the vendor's own
  per-model reference-image limit table.

### How the "from" figures are produced

The dollar amounts are not in the page's Markdown/HTML source: each cell is rendered by a
`Pricing` component that reads a published pricing payload and computes the figure from
per-endpoint rates. Captured on 2026-10-26 from that payload (the query the page itself issues,
`https://2gpum2i6.api.sanity.io/v2025-02-19/data/query/production`, document type `pricing`,
fields `apiEndpoint`, `firstMpPrice`, `mpPrice`, `inputMpPrice`; values in US cents):

| Endpoint | `firstMpPrice` | `mpPrice` (each additional output MP) | `inputMpPrice` (per input MP) |
| --- | --- | --- | --- |
| `/v1/flux-2-klein-4b` | 1.4 | 0.1 | 0.1 |
| `/v1/flux-2-klein-9b` | 1.5 | 0.2 | 0.2 |
| `/v1/flux-2-pro` | 3 | 1.5 | 1.5 |
| `/v1/flux-2-max` | 7 | 3 | 3 |
| `/v1/flux-2-flex` | **5** | **5** | **5** |

The component's own arithmetic (read from the compiled page source): the text-to-image cell
shows `firstMpPrice`; the image-editing cell adds `inputMP: 1` × input rate, so [flex]'s
"from $0.10" = $0.05 output + $0.05 for one input megapixel.

Consequences of the flex rate card, computed from the table above (arithmetic, not a vendor
statement):

- [flex] has **no first-megapixel discount**: output costs $0.05/MP at 1 MP and at 4 MP alike.
  [pro] costs $0.03 at 1 MP and $0.03 + 3 × $0.015 = $0.075 at 4 MP.
- So a 4 MP [flex] image is **$0.20** against **$0.075** for [pro] — about 2.7× — while at
  1 MP the gap is $0.05 vs $0.03, about 1.7×.
- A 1 MP edit against one 1 MP reference costs $0.10 on [flex] (5¢ output + 5¢ input) — which is
  what the "from $0.10" editing cell prices. A 4 MP edit against the same single reference costs
  5¢ + 3 × 5¢ + 5¢ = **$0.25**.
- Input megapixels are charged. The same page's separate note explains this first-MP-plus-
  additional-MP structure explicitly only for Klein.

### Related figures on the same page

- "Batch requests multiply the base cost by the number of images" (example given for [pro]).
- Fine-tuned endpoints (public beta) are billed at the base endpoint rate; only
  `flux-2-klein-9b-kv-finetuned` was listed, so no fine-tuned [flex] endpoint exists on the
  price list.
- [dev] is "Local only" / "Open weights, non-commercial (no hosted API)" — [flex] has no
  open-weights row, and the table's only weights mentions are [dev] and [klein].

## Known gaps

- The page states prices change and points at a calculator at https://bfl.ai/pricing; this is a
  capture of one moment.
- No statement of a minimum charge, rounding rule, or refund/retry policy for [flex] on this
  page. fal states its own rounding rule (round up to the nearest megapixel); BFL does not
  state one here.
- The pricing payload is the page's data source, not a separately published document. The
  rendered figures above are what a browser shows; the per-MP rates are how the page computes
  them.

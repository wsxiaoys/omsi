# BFL docs: FLUX.2 pricing — [klein] 4B row (credit values as rendered)

- Origin: Black Forest Labs documentation, "Pricing" (`https://docs.bfl.ai/quick_start/pricing`) and
  the pricing calculator data behind `https://bfl.ai/pricing`
- Evidence kind: official documentation (price list; values machine-readable)
- Publication date: not stated on page
- Capture date: 2026-10-26
- Relevant models: FLUX.2 [klein] 4B, with [klein] 9B, [pro], [max], [flex], [dev] for comparison

## How these numbers were obtained

The pricing page states the unit — "1 credit equals $0.01 USD" — but the price cells are rendered by
a client-side component, so the prose capture of the page shows empty cells. The component queries
Black Forest Labs' published CMS:

```
https://2gpum2i6.api.sanity.io/v2025-02-19/data/query/production?perspective=published
  &query=*[_type == "pricing"][0]{pricingCards[]{title,apiEndpoint,priceUnit,firstMpPrice,mpPrice,
         inputMpPrice,videoRates,mpSecondPrice,secondPrice,imageTierRates}}
```

That query was run on the capture date and returned 24 cards. Values below are verbatim field
values; dollar figures are credits ÷ 100 and are consistent with the `priceUnit` field (dollars)
that the same cards carry.

## FLUX.2 cards (verbatim field values, credits)

| Card | `apiEndpoint` | `firstMpPrice` | `mpPrice` (each additional MP) | `inputMpPrice` | `priceUnit` (USD) |
| --- | --- | --- | --- | --- | --- |
| FLUX.2 [klein] 4B | `/v1/flux-2-klein-4b` | 1.4 | 0.1 | 0.1 | 0.014 |
| FLUX.2 [klein] 9B | `/v1/flux-2-klein-9b` | 1.5 | 0.2 | 0.2 | 0.015 |
| FLUX.2 [pro] | `/v1/flux-2-pro` | 3 | 1.5 | 1.5 | 0.03 |
| FLUX.2 [max] | `/v1/flux-2-max` | 7 | 3 | 3 | 0.07 |
| FLUX.2 [flex] | `/v1/flux-2-flex` | 5 | 5 | 5 | 0.05 |

So, first-party, per image: **$0.014 for the first output megapixel of a [klein] 4B request, plus
$0.001 per additional output MP and $0.001 per input MP**. A 1024×1024 output with no input image is
therefore ~$0.014; a 2MP output is ~$0.015.

### Pricing rules stated on the page (verbatim)

> **Klein pricing explained:** The first megapixel costs a flat rate, then each additional MP adds
> to the total.

> FLUX.2 uses **megapixel-based pricing** — cost scales with output resolution.

> FLUX.2 pricing varies by output resolution. Use the pricing calculator for exact costs.

## What this establishes

- [klein] 4B is the cheapest FLUX.2 text-to-image and editing option on BFL's own API: ~half the
  [pro] rate ($0.014 vs $0.03 for the first MP) and ~1/5 the [max] rate.
- BFL bills **input** megapixels at the same $0.001/MP rate as additional output MP for the 4B,
  which matters for multi-reference editing with large references.
- The [klein] 4B first-MP price is unchanged since launch: the January 15, 2026 release note quotes
  the same "$0.014 / image"
  ([release notes](../flux2-klein-4b-release-notes/2026-10-26.md)).
- [dev] is not sold as a hosted API on this page ("Local only"), so within FLUX.2 the open-weights
  4B is the only model that is both Apache-2.0 and first-party-hosted.

## Gaps

- These are CMS values, not a rendered invoice; BFL reserves the right to change them and no
  revision history was captured.
- `mpPrice` semantics ("each additional MP") are stated in prose only; the CMS does not define
  rounding. BFL's API reference says `input_mp`/`output_mp` are reported to 2 decimal places.
- The docs' rendered tables round to "from $X"; no per-resolution table for [klein] 4B exists, so
  the exact cost of a non-integer megapixel count is not documented.
- The pricing calculator on `bfl.ai/pricing` was not exercised per model (it renders one default
  rate at a time).

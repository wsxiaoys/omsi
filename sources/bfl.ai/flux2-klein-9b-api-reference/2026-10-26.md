## Request schema `Flux2KleinInputs` (verbatim fields)

Schema-level description:

> Input model for FLUX.2 Klein (non-base) - like Pro but max 4 images.

| Field | Type / bounds | Default | Description (verbatim) |
| --- | --- | --- | --- |
| `prompt` | string, **required** | — | "Text prompt for image generation." |
| `input_image` | string \| null | — | "Path to the input image." |
| `input_image_2` | string \| null | — | "Path to the second input image." |
| `input_image_3` | string \| null | — | "Path to the third input image." |

Response (`AsyncResponse`) carries `id`, `polling_url`, and optional `cost` ("Cost in credits
for this request"), `input_mp`, `output_mp` ("Input/Output megapixels (2 decimal places)").

## What this establishes

- **One endpoint does both generation and editing.** Supplying any of `input_image` … 
  `input_image_4` turns the call into an edit; BFL's own schema note says "like Pro but max 4
  images", which is the API-level statement of the 4-reference ceiling.
- **Hard cap of four input images**, expressed structurally as four fixed fields rather than a
  list — there is no way to pass a fifth.
- **No sampling controls are exposed.** There is no `steps`, `guidance`, `negative_prompt`, or
  `disable_pup` field. This matches the family page's statement that [klein] is 4-step
  step-distilled and has no prompt upsampling.
- **Resolution is bounded below only** (`width`/`height` ≥ 64). No maximum is declared in the
  schema, so the API reference does not support a specific 4MP ceiling for [klein].
- **Moderation is configurable but gated**, same 0–7 `safety_tolerance` design as [pro], with
  the approved maximum depending on route and organization.
- `output_format` defaults to **jpeg** first-party, while fal's endpoints default to **png**
  (see the fal records). A byte-level comparison across hosts is therefore not apples to
  apples unless the format is pinned.

## Gaps

- No latency, throughput, or quality claims with numbers.
- The schema does not state a maximum output resolution or megapixel count.
- The `-preview` endpoint has a separate reference page with the same contract; only the
  weights differ, and the page does not quantify the KV-caching speedup.

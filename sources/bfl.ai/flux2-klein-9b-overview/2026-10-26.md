## Preview endpoints (verbatim)

> | `flux-2-klein-9b-preview` | Our latest FLUX.2 [klein] 9B model with KV caching for improved
> performance. |
> | `flux-2-klein-9b` | A fixed snapshot of FLUX.2 [klein] 9B. Choose this when you need
> reproducibility. |
>
> Both preview and non-preview endpoints share the same API contract — the request and response
> format is identical. Only the underlying model weights differ.

## What this establishes

- [klein] is documented as a **two-size, two-variant** line: distilled 4B/9B on the API, plus
  undistilled Base 4B/9B as weights only. The distilled 9B is the subject of this page; Base 9B
  is a different checkpoint with different step counts and output diversity.
- **Multi-reference ceiling is 4 for [klein]** — explicitly lower than [pro]/[flex]/[max]
  (8 via API / 10 in playground) and [dev] (recommended max 6).
- **4 inference steps, step-distilled** is a first-party specification, not a host default.
- **No prompt upsampling** for [klein], unlike [pro]. Prompt quality is the user's job.
- **No grounding search** for [klein] (family table).
- The 9B endpoint exists in two forms: a pinned snapshot (`flux-2-klein-9b`) and a moving
  preview (`flux-2-klein-9b-preview`) whose only stated difference is KV caching for speed.
- "13GB VRAM" is attached to the **4B** here. The page gives no 9B VRAM figure; the 9B model
  card does (~29GB — see `../../huggingface.co/flux-2-klein-9b/2026-10-26.md`).

## Gaps

- No resolution ceiling for [klein] is stated. The page's "up to 4MP" claim belongs to the

- No latency numbers behind "sub-second".
- No benchmark comparison between 9B and 4B beyond the "balanced quality and speed" /

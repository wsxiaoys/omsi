# BFL official: FLUX.2 [klein] training guide

- Origin: Black Forest Labs, "FLUX.2 [klein] Training",
  https://docs.bfl.ai/flux_2/flux2_klein_training (markdown source:
  https://docs.bfl.ai/flux_2/flux2_klein_training.md)
- Evidence kind: official documentation (training guide)
- Publication date: not stated on the page
- Capture date: 2026-10-26
- Relevant models: FLUX.2 [klein] Base 4B and Base 9B (the fine-tunable checkpoints);
  FLUX.2 [klein] 9B distilled only as the LoRA-serving target

## Variant table (verbatim)

> | Variant | **Best For** | **License** |
> | [**klein 4B Base**](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-4B) | Quick
> iterations | Apache 2.0 |
> | [**klein 9B Base**](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-9B) |
> Maximum quality, complex concepts | FLUX Non-Commercial |

> Base models are undistilled and provide higher output diversity, making them ideal starting
> points for fine-tuning. The 4B variant is recommended for most users due to lower hardware
> requirements.

> FLUX.2 [klein] Base models are ideal for fine-tuning due to their undistilled architecture,
> which preserves the full training signal.

## System requirements (verbatim)

> **For klein 4B Base Training**
>
> * **GPU**: NVIDIA with 12GB VRAM (RTX 3060 12GB, RTX 4060 Ti 16GB)
> * **RAM**: 32GB system memory

> **For klein 9B Base Training**
>
> * **GPU**: NVIDIA with 22GB VRAM (RTX 3090, RTX 4090)
> * **RAM**: 64GB system memory

## Serving a trained LoRA (verbatim)

> Upload your `.safetensors` in the Dashboard under **Customization → Finetunes** and call the
> fine-tuned endpoint with the resulting `finetune_id` — no local GPU required.

Endpoint example in the guide: `https://api.bfl.ai/v1/flux-2-klein-9b-kv-finetuned` with
`finetune_id`.

Local serving example in the guide loads `black-forest-labs/FLUX.2-klein-base-9B` through
`Flux2KleinPipeline` with `num_inference_steps=50`.

## What this establishes

- **Training targets the Base checkpoints, not the distilled ones.** The guide's variant table
  and its Diffusers example both point at `FLUX.2-klein-base-9B`, and the example uses **50
  inference steps** — an order of magnitude above the distilled model's 4. This is the clearest
  first-party statement that Base 9B and distilled 9B are different checkpoints with different
  sampling regimes.
- **9B Base LoRA training needs ~22GB VRAM and 64GB system RAM**, versus 12GB/32GB for 4B Base.
  Note this is *training* memory; it is lower than the ~29GB the 9B model card quotes for
  inference, and the two figures use different tooling, so they are not directly comparable.
- A trained LoRA can be served **first-party** via `flux-2-klein-9b-kv-finetuned`, or locally
  against the Base checkpoint.
- The 9B Base is non-commercial, same licence as the distilled 9B.

## Gaps

- No statement of how many training steps or which resolution the 22GB figure assumes.
- The guide does not say whether a LoRA trained on Base 9B is expected to transfer to the
  distilled 9B endpoint (`flux-2-klein-9b-kv-finetuned` implies it does, but the guide never
  says so explicitly).

# BFL official: FLUX.2 text-to-image page (supersession check)

- Origin: Black Forest Labs, "FLUX.2 Text to Image",
  https://docs.bfl.ml/flux_2/flux2_text_to_image.md
- Evidence kind: official documentation (model guide)
- Publication date: not stated on page
- Capture date: 2026-10-26
- Relevant models: FLUX.2 (as prior generation); captured only to test whether FLUX.2 documentation
  was updated after FLUX 3 Image shipped on 2026-10-01

## Why this record exists

The FLUX 3 Image page needs to say whether FLUX 3 supersedes FLUX.2 or sits above it. BFL's own
navigation text is one input to that question, and it is a different document from the FLUX.2
overview and pricing records already in the repository, so it gets its own slug rather than editing
a shared capture.

## Captured content

Page summary line, verbatim:

> FLUX.2 is the recommended model for text-to-image generation. Generate high-fidelity images with
> advanced control, exact colors, and flexible aspect ratios.

The same "recommended" phrasing appears in the documentation index
(`https://docs.bfl.ml/llms.txt`, captured 2026-10-26) as the description of this page.

For comparison, the FLUX.2 [pro] API reference summary in the same index reads: "This is the
recommended default model for image editing and generation."

## What this establishes

- As of 2026-10-26 — 25 days after FLUX 3 Image launched — BFL's FLUX.2 guide still calls FLUX.2
  "the recommended model for text-to-image generation", and its FLUX.2 [pro] API reference still
  calls [pro] "the recommended default model".
- Nothing in BFL's FLUX 3 Image material describes FLUX.2 as deprecated, superseded, or scheduled
  for retirement; the pricing page captured separately still lists the whole FLUX.2 family
  (`../flux2-pricing/2026-10-26.md`).

## Gaps

- A doc summary line can be stale boilerplate. This record establishes what the page said on
  2026-10-26, not what BFL intends.
- No first-party statement was found that ranks FLUX 3 Image against FLUX.2 [max] or [flex] on
  quality. The relationship therefore has to be inferred from price, capability surface and
  positioning, and that inference is labelled as such on the model page.

## Captured content

> FLUX 3 Image Klein is a compact, open-weights version of FLUX 3 Image. It supports the same
> features: text to image, image editing, multi reference, and bounding boxes. It runs faster and
> fits on consumer GPUs, down to an RTX 3090. Do not use it without its prompt upsampler.

Specs (verbatim table):

| | Klein (Distilled) | Klein Base |
| --- | --- | --- |
| Parameters | 5.6B | 5.6B |
| Max resolution | Up to 4K | Up to 4K |
| Inference steps | 16 | 50 |
| Guidance (CFG) | 1 | 3.5 |
| Bounding box support | Yes | Yes |
| Best for | Fast generation, local deployment | Fine-tuning, LoRA training, research |
| License | FLUX Kommunity License | FLUX Kommunity License |
| Availability | API, Hugging Face | Hugging Face |

> Do not use Klein without the [prompt upsampler]. The model is trained on the captions it writes;
> a prompt sent as typed gives noticeably weaker results.

> Send a request to the Klein endpoint … The request takes the same fields as FLUX 3 Image.

Klein API endpoint: `POST https://api.bfl.ai/v1/flux-3-image-klein`.

## What this establishes

- The **only** FLUX 3 image weights with a public download are Klein's, under the FLUX Kommunity
  License. That licence is not the licence of FLUX 3 Image, which has no public weights.
- Klein is a genuinely smaller model (5.6B) with its own endpoints, own price ladder and own
  sampling controls (16 steps @ CFG 1, or 50 steps @ CFG 3.5). Findings from FLUX 3 Image cannot be
  transferred to it, and vice versa — including the "no seed" and "no steps" limitations, which do
  not apply to Klein.
- Klein accepts the same request shape as FLUX 3 Image, so switching endpoints is cheap for a
  caller — but the two differ in quality, price and reproducibility, which is exactly the case for
  a separate page.

## Gaps

- No comparison numbers between Klein and FLUX 3 Image (quality, latency, identity retention).
- The page does not state the size of the full FLUX 3 Image model, so the parameter gap is

# BFL official: FLUX 3 Image overview

- Origin: Black Forest Labs, "FLUX 3 Image", https://docs.bfl.ml/flux_3/flux3_image_overview.md
  (same document served from the `docs.bfl.ai` documentation host)
- Evidence kind: official documentation (model overview / capability page)
- Publication date: not stated on page; the FLUX 3 Image release it describes is dated
  October 1, 2026 in the release notes (see `../flux3-image-release-notes/2026-10-26.md`)
- Capture date: 2026-10-26
- Relevant models: FLUX 3 Image (first-party endpoint `POST /v1/flux-3-image`)

## Captured content

Opening claim (verbatim):

> FLUX 3 Image gives you maximum control over every pixel. Generate an image from a prompt,
> edit specific details, combine up to ten references, and draw bounding boxes to place each
> element.

### Text to image

> Describe the subject, setting, light, and framing. FLUX 3 renders the whole scene from the
> prompt.

### Edit an image

> Write the change as an instruction, and name exactly what to change.

### Multi reference

> Refer to each image by its position and say what it contributes.

The page's example uses image 1 as the scene and image 2 as the object placed into it, and links
to "Combine up to ten images".

### Control the composition (bounding boxes)

> Add bounding boxes to the end of the prompt to decide where each element goes. Each box is
> `[top, left, bottom, right]` on a 0 to 1000 grid.

> The same boxes let you edit only part of an image: recolor, move, replace, or remove one
> element while the rest stays unchanged.

### Grounding

> By default, FLUX 3 searches the web to get real things right. Set `grounding` to `false` for
> faster results that use only your prompt.

The worked example is a pair of Oktoberfest posters: with grounding off the model invents a
"vintage poster of riders on horses, dated 2025"; with grounding on it renders "the official 2026
poster with the Frauenkirche towers, a Ferris wheel and a beer stein, dated 19.9. to 4.10.2026".
The page also shows the request diff `"grounding": false` → `"grounding": true`.

## What this establishes

- Grounding (web **and** image search, per the API reference) is on by default for FLUX 3 Image.
  That is a capability FLUX.2 [pro] does not document; FLUX.2 [max] is the FLUX.2 member with
  grounding search.
- Bounding boxes are prompt text, not a request parameter. Layout control and box-targeted
  editing are the same mechanism.
- Text-to-image, editing, and multi-reference composition are one endpoint with no `mode` field.

## Gaps

- No numbers: no benchmark, no resolution table, no latency figure on this page.
- The grounding example is a vendor demo image pair, not a measurement of citation accuracy.
- The page does not say which sources grounding searches, whether results are cited, or what it
  costs.

## Why a separate record

`sources/bfl.ai/flux2-pricing/2026-10-26.md` captures the FLUX.2 section of this price list on the
same day and is not edited here. This record holds the FLUX 3 sections, including the
machine-readable price ladder that the release notes omit.

## Captured content

Credit model (verbatim, docs page): "**Simple credit-based pricing:** 1 credit = \$0.01 USD • Pay
per image, or per second for video • Same price for API and Playground".

### FLUX 3 Image price ladder (verbatim `UnitPriceSpecification` entries)

`schema.org/Product` for "FLUX 3 Image" — "pay-as-you-go FLUX image generation via the Black Forest
Labs API" — with `priceCurrency: USD`, `unitText: image`, `availability: InStock`:

| `name` | `price` |
| --- | --- |
| 768 × 768 image | **0.041** |
| 1K image | **0.048** |
| 1.5K image | **0.07** |
| 2K image | **0.1** |
| 4K image | **0.607** |

The rendered calculator agrees at its default: "Rate: $0.048 / image", "Total Price: $0.048", with
resolution options 768 × 768, 1K, 1.5K, 2K, 4K and a "Number of Images" field. Its model selector
lists FLUX 3 Image, FLUX 3 Image Klein, FLUX.2 [flex], FLUX.2 [pro], FLUX.2 [max], FLUX.2 [klein]
4B/9B, FLUX Outpainting, FLUX Eraser and FLUX VTO — i.e. FLUX 3 Image is a priced option alongside
the whole FLUX.2 family, not a replacement for it.

The `Product.price` scalar on the same object is `0.041`, which is the 768 × 768 entry — reading it
as a general "from" price is correct only if the cheapest tier is the floor.

### FLUX 3 Image Klein (verbatim entries in the same graph)

The page carries a second product object for "FLUX 3 Image Klein" with the same five-tier shape,
verbatim: 768 × 768 `0.008` · 1K `0.009` · 1.5K `0.011` · 2K `0.014` · 4K `0.036`. Those match
the Klein ladder in the release notes (`../flux3-image-release-notes/2026-10-26.md`) exactly, and
they are roughly five times cheaper than the FLUX 3 Image ladder at every tier.

### Open-weights licensing tiers (verbatim, product names only)

"Builder — FLUX 3 Image Klein + FLUX.2 [klein] · 10K images / month · 1 domain · 10 licensed
users · Fine-tuning & LoRA rights"; "Platform — FLUX 3 Image Klein + FLUX.2 [klein] 9B + FLUX.2
[dev] · 100K images / month"; "Professional — FLUX 3 Image Klein + FLUX.2 [dev]"; "Enterprise — All
models + new releases · Custom volume · Permissive commercial use · API + Weights combo pricing";
"Synthetic Data — FLUX 3 Image Klein or commercial models".

## What this establishes

- **The 1.5K price is $0.07**, resolving the gap left by the release notes, which list only 768sq,
  1k, 2k and 4k. The ladder is: 0.041 / 0.048 / 0.07 / 0.10 / 0.607.
- The 4K tier is 12.6× the 1K price for ~16× the pixels; the 1.5K → 2K step is the cheapest
  increment in relative terms and the 2K → 4K step the most expensive.
- **FLUX 3 Image is not offered in the self-hosted/open-weights licence tiers**, while FLUX 3 Image
  Klein is the named model in every one of them. That is a second, independent confirmation that
  FLUX 3 Image's weights are not part of the open licensing programme.
- Pricing is per image by resolution; the credit rate of $0.01 means a 4K image is 60.7 credits.

## Gaps

- The page does not say whether reference images, grounding searches, or prompt upsampling change
  the per-image price. BFL's async response returns `input_mp` and `output_mp`, which implies the
  inputs are metered somewhere, but no page states the effect on price.
- The calculator's per-tier numbers for non-default tiers are client-side; only the JSON-LD entries
  above were read, and they were not confirmed by a billed request.
- The enterprise and open-weights tiers list image volumes and seats without prices.

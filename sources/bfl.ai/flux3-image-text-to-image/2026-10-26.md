# BFL official: FLUX 3 text-to-image quickstart

- Origin: Black Forest Labs, "FLUX 3 Text to Image",
  https://docs.bfl.ml/flux_3/flux3_image_generate.md
- Evidence kind: official documentation (endpoint guide: request shape, statuses, error codes)
- Publication date: not stated on page
- Capture date: 2026-10-26
- Relevant models: FLUX 3 Image

## Captured content

Endpoint and auth: `POST https://api.bfl.ai/v1/flux-3-image`, header `x-key: $BFL_API_KEY`.

> Send only `prompt` to generate a new image. When you add `images`, describe how to use them in
> `prompt`. There is no `mode` field.

Routing table (verbatim rows):

| What you want | What to send |
| --- | --- |
| A new image from a description | `prompt` |
| A change to one image, such as a detail or its style | `prompt` + that image |
| A restyle or new composition from several images | `prompt` + 2 to 10 images |

> The endpoint rejects unknown fields with HTTP `422`, so fields from other BFL endpoints, such as
> `seed`, `width`, and `input_image`, don't work here.

Note that this guide says `width` is not accepted, while the API reference schema lists `width`
and `height` as valid fields (see `../flux3-image-api-reference/2026-10-26.md`). The two BFL pages
disagree; the schema is the more specific document, but the contradiction is unresolved.

Response fields: the submit response returns `id`, `polling_url`, `cost`, `input_mp`,
`output_mp`. Poll `polling_url`; on `Ready`, download from `result.sample`.

> The signed URL in `result.sample` expires after **1 hour**.

Status values (verbatim): `Pending`, `Reasoning`, `Generating` ("In progress"), `Ready`,
`Request Moderated` ("The prompt or an input image was blocked"), `Content Moderated` ("The
generated image was blocked"), `Error`, `Task not found`.

> A `Ready` result also includes `result.prompt`, the expanded prompt the model used, and
> `result.duration`, the generation time in seconds.

Submission errors specific to this endpoint:

| HTTP | Cause |
| --- | --- |
| `400` | "A reference image is larger than 16 megapixels" |
| `422` | "Unknown field, blank prompt, invalid value, or an image smaller than 256 × 256" |

Prompting guidance: quote exact text and say where it goes
(`a paper poster on the wall that reads "OPEN LATE"`); add bounding boxes to the end of the prompt
to place elements.

## What this establishes

- The `Reasoning` status is consistent with the default-on grounding/search step: generation can
  pause for research before `Generating`.
- Reference-image limits from the first party: **≥256×256**, **≤16 MP**, **1–10 images**.
- Moderation is two-stage and separately observable: input rejection (`Request Moderated`) vs
  output rejection (`Content Moderated`). Retrying an unchanged moderated request fails again.
- The expanded prompt is returned, so a caller can see how an upsample changed their request.

## Gaps

- The page does not price anything and does not say what `cost` units are (the API reference says
  credits).
- No statement about how long a task id stays retrievable.
- The `width`/`height` contradiction with the API reference is not addressed.

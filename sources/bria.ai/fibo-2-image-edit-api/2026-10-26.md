# BRIA docs: POST /v2/image/edit (Fibo 2 edit reference)

- Origin: BRIA AI developer documentation, "Image Edit by Text" — Image Editing API Reference,
  <https://docs.bria.ai/image-editing/editing/edit-image> (Markdown source
  <https://docs.bria.ai/image-editing/editing/edit-image.md>)
- Evidence kind: official documentation (endpoint reference; parameter and response schema)
- Publication date: no publication date printed. The reference documents Fibo 2 multi-reference
  editing and native masking, so it post-dates the Fibo 2 launch (2026-10-18 to 2026-10-20).
- Capture date: 2026-10-26
- Relevant models: Fibo 2 (edit), via `/v2/image/edit`

## Captured content

Server: `https://engine.prod.bria-api.com/v2/image/edit`; security: `api_token` header.

Description (verbatim, abridged):

> Powered by the **Fibo models family**, Bria's Image Editing by Text API equips builders with the
> ability to modify existing images using natural language instructions or structured JSON
> instructions. This endpoint now supports **multi-reference editing** — you can supply up to 4
> input images in a single request …
>
> Fibo 2 features **native masking support** for precise, localized editing on single-image
> requests. … The masking logic operates as a **generative replacement**; the model generates
> entirely new content within the masked area based on your instruction, rather than modifying the
> existing pixels.

Two-step architecture (verbatim):

> 1. **Translation:** A VLM bridge converts your inputs into a detailed `structured_instruction`
>    (JSON).
> 2. **Generation:** Fibo 2 performs the final, deterministic edit on the input image(s), based on
>    that JSON.

Recreation requirement (verbatim):

> To recreate a specific result: You must provide the exact source images, the mask (if used), the
> `structured_instruction` returned in the original response, and the `seed` used to create it.

Single vs multi-reference support (verbatim table):

| | Single reference | Multi-reference (2–4 images) |
| --- | --- | --- |
| Masking (`mask`) | Supported | Not supported |
| Aspect ratio control | Supported with restriction | Fully supported |

> Requests with more than 4 images will return an error.

Input combination rules (verbatim):

> * **Edit by Text (single or multi-reference):** `images` (1–4) + `instruction`
> * **Edit by JSON Instruction (single or multi-reference):** `images` (1–4) + `structured_instruction`
> * **Masked Edit by Text (single reference only):** `images` (exactly 1) + `mask` + `instruction`
> * **Masked Edit by JSON Instruction (single reference only):** `images` (exactly 1) + `mask` +
>   `structured_instruction`

### Request fields (verbatim descriptions, abridged)

- `images` (array, required) — "The source/reference image(s) to be edited. … **Accepts 1 to 4
  images.** Requests with more than 4 images will return an error."
- `instruction` (string) — "Text-based edit instruction (e.g., 'make the sky blue', 'add a cat')."
- `mask` (string) — "Publicly available URL or Base64-encoded mask image (black and white). Black
  areas will be preserved, white areas will be edited. … **Only supported when `images` contains
  exactly one item.**"
- `structured_instruction` (string) — "A string containing the structured edit instruction in JSON
  format. Use this instead of `instruction` for precise, programmatic control."
- `aspect_ratio` (string, 21 values; default = aspect ratio of the first image) — "for
  single-reference requests, the model was not trained to change aspect ratio dramatically from the
  source image — results may degrade if the requested aspect ratio differs significantly from the
  input image's own aspect ratio. Multi-reference requests fully support all listed aspect ratios."
- `seed`, `sync`, `webhook_url`, `output_type`, `ip_signal`, and the three moderation flags — same
  semantics as on the generate endpoint.

### Response 200 (verbatim)

`result.image_url`, `result.seed`, `result.structured_instruction`, `request_id`, optional
`warning`.

### Documented examples

Four use cases with Fibo 2 inputs and outputs: a 3-image multi-reference edit (boulder + bottle +
wordmark → perfume poster); a single-image text edit ("Change the car's paint to glossy cherry red,
keep everything else the same"); a masked edit ("Replace the bottle with a frosted pink perfume
bottle with a gold cap"); and a masked edit on a 3840×2160 input whose output "keeps the input's
exact size".

## What this establishes

- Fibo 2 edit is a **multi-reference, masked, instruction-driven editor** with its own structured
  instruction format (`structured_instruction`), not merely a text-prompt edit endpoint.
- Masking is generative replacement inside the mask, with the source pixels preserved outside it.
  That is documented behaviour, not an observation.
- Masking and full aspect-ratio control are mutually exclusive: masks are single-image only, and
  single-image aspect-ratio changes are documented as degradation-prone.
- Output size for masked edits equals the input size, so a 4K masked edit returns 4K — the
  documented route to high-resolution output, since the generate endpoint's 4MP is async-only.

## Gaps

- No statement of how much of the edit's quality depends on the VLM bridge versus Fibo 2.
- No documented failure behaviour for masks that do not match the source size beyond "must be of
  the same size".
- No latency figures, no pricing, no statement of which Fibo 2 checkpoint the endpoint serves.

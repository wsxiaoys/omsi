# BRIA docs: POST /v2/image/generate (Fibo 2 generate reference)

- Origin: BRIA AI developer documentation, "Generate Image" — Image Generation API Reference,
  <https://docs.bria.ai/image-generation/generation/image-generate> (Markdown source
  <https://docs.bria.ai/image-generation/generation/image-generate.md>)
- Evidence kind: official documentation (endpoint reference; parameter and response schema)
- Publication date: no publication date printed. The reference uses Fibo 2 example outputs and
  documents the Fibo 2 aspect ratios, so it post-dates the Fibo 2 launch (2026-10-18 to
  2026-10-20).
- Capture date: 2026-10-26
- Relevant models: Fibo 2 (generate), via `/v2/image/generate`

## Captured content

Server: `https://engine.prod.bria-api.com/v2`; security: `api_token` header. Downloadable OpenAPI:
`https://docs.bria.ai/_bundle/image-generation.yaml`.

Description (verbatim, abridged):

> Generates a new image based on your inputs. This all-in-one endpoint first translates your input
> (`prompt` and/or `images`) into a structured JSON prompt using a VLM bridge. It then *internally*
> uses that JSON to generate the final, deterministic image. … The response includes both the final
> `image_url` and the `structured_prompt` (JSON).
>
> For advanced, programmatic control, you can also pass in your own `structured_prompt` … to bypass
> the internal VLM bridge.

Input combination rules (verbatim):

> The request body must include **one** of the following mutually exclusive combinations:
> * `prompt` (Generates a new image from text)
> * `images` (Generates a new image inspired by a reference image)
> * `images` + `prompt` (Generates a new image inspired by an image and guided by text)
> * `structured_prompt` (Recreates a previous image exactly with its seed, or refines it when you
>   change part of the JSON)
> * `structured_prompt` + `prompt` (Refines a previous image using new text instructions, combined
>   with a seed)

### Request fields (verbatim descriptions, abridged)

- `prompt` (string) — "Text-based instruction. Can be used alone to create a new prompt, or as a
  refinement command with an `images` or `structured_prompt`."
- `images` (array) — "Publicly available URL or Base64-encoded image. Currently supports a single
  image. Supported formats: JPEG, JPG, PNG, WEBP."
- `structured_prompt` (string) — "A string containing the structured prompt in JSON format."
- `resolution` (string, enum `1MP`, `4MP`) — "Output image resolution. '4MP' improves image
  details, especially for photorealism, but will increase latency by 30 seconds. 4MP is supported
  only on the asynchronous path, so it must be requested with sync set to false (the default). A
  synchronous 4MP request returns 422."
- `aspect_ratio` (string, 21 values) — the 12 Fibo 2 additions "are rendered by Fibo 2 and return
  422 on a request it doesn't serve (4MP, `style_id`, a refinement with both `prompt` and a
  structured prompt, or reference images without a prompt)."
- `style` (string, enum `kodak_film`, `hard_flash`, `hazy_dreamy`, `rough_realism`) — "Photographic
  look for the generated image, rendered by Fibo 2 from a text `prompt`. … Returns 422 with
  `style_id`, `structured_prompt`, `images` or 4MP resolution."
- `seed` (integer) — "Seed for deterministic generation. Uses a random seed if omitted."
- `sync` (boolean) — async 202 + `status_url` by default; `true` holds the connection.
- `webhook_url`, `output_type` (`png` | `jpeg`).
- `ip_signal` (boolean) — "If true, returns a warning for potential IP content in the `prompt`."
- `prompt_content_moderation`, `visual_input_content_moderation`,
  `visual_output_content_moderation` (booleans) — each returns 422 on the corresponding moderation
  failure when enabled.

### Response 200 (verbatim)

- `result.image_url` (string, required)
- `result.seed` (integer, required)
- `result.structured_prompt` (string, required)
- `request_id` (string, required)
- `warning` (string) — "Returned only when ip_signal = true and the prompt field included IP
  content."

### Documented example workflows

Six numbered use cases, all illustrated with Fibo 2 outputs: text prompt; prompt + reference
("inspire"); reference alone; refining a previous `structured_prompt` with the same seed ("the tank
top changed from white to hot pink, and seed `5555`"); new aspect ratios (`21:9`, `10:16`);
photographic styles (`style: "kodak_film"`).

## What this establishes

- The first-party generate endpoint is Fibo 2, with no model-version parameter: the model is
  implied by the endpoint.
- Resolution is a **tiered output option** (`1MP` default, `4MP` async-only, +30 s latency claim),
  not a free-form size.
- Moderation is opt-in per request through three boolean flags, which return 422 on failure. The
  default (all off) does not document what moderation still applies server-side.
- `seed` is presented as making generation deterministic, but the docs do not state whether the VLM
  bridge is seeded too — a prompt-based request still runs the translation step each time.

## Gaps

- No statement of which model version the endpoint runs beyond "Fibo 2", and no way to pin an older
  version through this endpoint.
- No published pixel dimensions for `1MP`/`4MP`, nor for the 21 aspect ratios.
- No latency or throughput figures except the "+30 seconds" 4MP note.
- No pricing on this page.

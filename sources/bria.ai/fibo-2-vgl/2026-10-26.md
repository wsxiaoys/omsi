# BRIA docs: VGL — Visual Generation Language

- Origin: BRIA AI developer documentation, "VGL: Visual Generation Language",
  <https://docs.bria.ai/vgl> (Markdown source <https://docs.bria.ai/vgl.md>)
- Evidence kind: official documentation (concept/spec page for the structured prompt format)
- Publication date: no publication date printed; rendered page carries a "Last updated" stamp that
  was not read for this page. The page describes Fibo 2 as the current generation and Fibo Lite as
  its sibling, so it post-dates the Fibo 2 launch (2026-10-18 to 2026-10-20).
- Capture date: 2026-10-26
- Relevant models: Fibo 2 (generate and edit), Fibo Lite, FIBO / Fibo Edit 1.x

## Captured content

> Bria's answer is **Visual Generation Language (VGL)**: a structured, explicit JSON description of
> a scene that both humans and machines can read and edit. The Fibo model family is trained
> natively on VGL. It is not a wrapper or a post-processing step; VGL is the representation the
> models render from, and every generation returns the full VGL specification behind the image.

Comparison table (verbatim rows):

| | Prompt-based generation | VGL-based generation |
| --- | --- | --- |
| Input | Natural language | A structured specification (JSON) |
| Strength | Fast creative exploration | Precision, auditability, systematic edits |
| Reproducibility | Interpretation varies between runs | Same specification and seed, same output |
| Editing | Rewrite the prompt and hope | Change one attribute, keep everything else |

> In practice you rarely write VGL by hand. You send a prompt (or a reference image), Fibo's
> translation step turns it into VGL, the image is rendered, and you get both back.

Design principles listed: Explicit, Disentangled, Physically grounded ("normalized pixel
positions, camera optics, lighting conditions"), Natively typed ("Semantics are words, quantities
are numbers, positions are coordinates, colors are RGB values").

Stated benefits: precision editing ("'change the shirt color' becomes a data edit rather than a
masking exercise"), reproducibility/audit, automation ("VGL is JSON, so agents and pipelines can
read, validate, transform and chain specifications"), brand consistency.

### Endpoint table (verbatim)

| Endpoint | Role |
| --- | --- |
| `POST /v2/image/generate` | Prompt or image in, image plus `structured_prompt` (VGL) out. Send `structured_prompt` and `seed` back to reproduce; add a `prompt` to refine. |
| `POST /v2/structured_prompt/generate` | Only the translation step: returns the VGL without rendering, for review or programmatic editing. |
| `POST /v2/structured_prompt/generate_from_diff` | Repairs and optimizes a VGL document after a user edited it directly. |
| `POST /v2/image/edit` and `/v2/structured_instruction/generate` | The editing equivalent: a `structured_instruction` describes the change to apply to an existing image. |

### Schema fields (verbatim comments, abridged)

Top level: `short_description` (required), `background_setting` (required), `style_medium`
(required, enumerated: photography | digital illustration | 3D render | vector art | watercolor |
oil painting | pencil sketch | anime | pixel art), `artistic_style`, `context`, `lighting`
{conditions, direction, shadows} (required), `aesthetics` {composition, mood_atmosphere,
color_palette: [[R,G,B], …]} (required), `photographic_characteristics` {depth_of_field, focus,
camera_angle, lens_focal_length} (optional), `objects[]` (optional), `text_render[]` (optional).

Per object: `description`, `bounding_box` "[x, y, w, h] — normalized coordinates for exact
placement", `shape_and_color`, `texture`, `appearance_details`, `relationship`, `orientation`,
`relative_distance`, plus person-only fields `age`, `gender`, `pose` ("body keypoints, normalized
coordinates"), `expression`, `clothing`, `action`, `skin_tone_and_texture`, `monk_scale` ("1-10 —
Monk Skin Tone Scale value").

Per text element: `text`, `color`, `font`, `appearance_details`, `bounding_box`,
`relative_distance`.

Two forward-looking notes in the schema comments:

> "shape_and_color": "string — physical form and primary color. In the next VGL version this
> becomes primary_color and secondary_color as [R, G, B] arrays"

> "clothing": "string — attire and accessories. In the next VGL version this becomes an array of
> objects"

### Family statement (verbatim)

> VGL is the shared language of the Fibo family: Fibo 2 for high-fidelity generation and editing,
> and Fibo Lite for high-volume and on-premises production. A VGL document created in one part of
> your pipeline can be executed by a different Fibo model in another part without translation,
> from concept to production.

## What this establishes

- Fibo 2 is a **structured, JSON-controllable** image model, not only a natural-language prompt
  model. The structured document is called VGL; the API field is `structured_prompt` for
  generation and `structured_instruction` for editing.
- The claim is that the model is trained on VGL natively rather than converting after the fact.
  That is a vendor statement; nothing captured here tests it.
- VGL is shared across the Fibo family (Fibo 2, Fibo Lite), so a VGL is portable between them by
  design.

## Gaps

- No VGL schema version number, no formal JSON Schema published on this page, and no statement of
  which fields are actually enforced at render time.
- "Same specification and seed, same output" is an untested reproducibility claim; no
  reproducible-output test was captured.
- No information on how VGL differs from Fibo 1.x's structured prompt (whether the schema is
  identical or extended).

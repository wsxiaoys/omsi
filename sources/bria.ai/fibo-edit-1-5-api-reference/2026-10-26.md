## Why this snapshot and not the live page

On 2026-10-26 the live `https://docs.bria.ai/image-editing` page and its `_bundle/image-editing.json`
describe `POST /v2/image/edit` as running **Fibo 2** ("Fibo 2 features **native masking support**…",
21 aspect ratios). The 2026-08-27 snapshot of the same bundle describes the same endpoint with
"**FIBO Edit** features native masking support" and a **nine-value** aspect-ratio enum. The bundle is
therefore the only dated first-party specification of the 1.5-generation endpoint that was
retrievable.

## Captured content — `POST /v2/image/edit` description (verbatim excerpts)

> Powered by the **FIBO models family**, Bria's Image Editing by Text API equips builders with the
> ability to modify existing images using natural language instructions or structured JSON
> instructions.
>
> This endpoint now supports **multi-reference editing** — you can supply up to 4 input images in a
> single request, enabling use cases like combining a product with a reference scene, matching a
> reference object's color or texture, or maintaining character consistency across images.
>
> FIBO Edit features **native masking support** for precise, localized editing on single-image
> requests. …
>
> **Core Technology: The FIBO Architecture**
>
> This endpoint utilizes the **FIBO** architecture, a unique two-step process ensuring precise and
> controllable edits:
> 1. **Translation:** A VLM Bridge (powered by **Gemini 2.5 Flash**) converts your inputs into a
>    detailed `structured_instruction` (JSON).
> 2. **Generation:** The FIBO Edit model performs the final, deterministic edit on the input
>    image(s), based on that JSON.
>
> **Advanced Control & Recreation**
>
> * To recreate a specific result: You must provide the exact source images, the mask (if used), the
>   `structured_instruction` returned in the original response, and the `seed` used to create it.
> * For advanced, programmatic control, you can pass in your own `structured_instruction` (e.g., from
>   the `/v2/structured_instruction/generate` endpoint) to bypass the internal VLM bridge.
>
> | | Single reference | Multi-reference (2–4 images) |
> |---|---|---|
> | Masking (`mask`) | Supported | Not supported |
> | Aspect ratio control | Supported with restriction (see disclaimer in parameter below) | Fully supported |
>
> Requests with more than 4 images will return an error.

Input combination rules, verbatim:

> * **Edit by Text (single or multi-reference):** `images` (1–4) + `instruction`
> * **Edit by JSON Instruction (single or multi-reference):** `images` (1–4) + `structured_instruction`
> * **Masked Edit by Text (single reference only):** `images` (exactly 1) + `mask` + `instruction`
> * **Masked Edit by JSON Instruction (single reference only):** `images` (exactly 1) + `mask` +
>   `structured_instruction`

## Request fields (verbatim from the bundle's request schema)

| Field | Type | Notes |
| --- | --- | --- |
| `images` | array of string, `minItems: 1`, `maxItems: 4`, required | "The source/reference image(s) to be edited. Publicly available URL or Base64-encoded. Accepted formats: JPEG, JPG, PNG, WEBP. **Accepts 1 to 4 images.**" |
| `instruction` | string | "Text-based edit instruction (e.g., \"make the sky blue\", \"add a cat\")." |
| `mask` | string | "Black areas will be preserved, white areas will be edited. … The input image and the input mask must be of the same size. **Only supported when `images` contains exactly one item.**" |
| `structured_instruction` | string | "A string containing the structured edit instruction in JSON format." |
| `aspect_ratio` | string, enum of 9 | `["1:1","2:3","3:2","3:4","4:3","4:5","5:4","9:16","16:9"]` — default is the first image's ratio |
| `seed` | integer | "Seed for deterministic generation. Uses a random seed if omitted." |
| `sync` | boolean, default `false` | Async by default; `true` holds the connection open |
| `webhook_url` | string (uri) | Callback on async completion |
| `output_type` | string, default `png` | `["png","jpeg"]` |
| `ip_signal` | boolean, default `false` | Warning when the instruction carries IP content |
| `prompt_content_moderation` | boolean, default `true` | 422 on instruction moderation failure |
| `visual_input_content_moderation` | boolean, default `true` | 422 on image/mask moderation failure |
| `visual_output_content_moderation` | boolean, default `true` | 422 on output moderation failure |

`aspect_ratio` description, verbatim:

> **Default:** aspect ratio of the first image in `images`.
> **Note:** for single-reference requests, the model was not trained to change aspect ratio
> dramatically from the source image — results may degrade if the requested aspect ratio differs
> significantly from the input image's own aspect ratio. Multi-reference requests fully support all
> listed aspect ratios.

## Response schema

`SyncEditResponse.result` carries `image_url`, `seed`, and `structured_instruction` (the JSON actually
rendered). `SyncEditResponse.warning` is "Returned only when ip_signal = true and the instruction
field included IP content." Async submissions return `request_id` plus a status URL.

## Gaps

- The bundle never uses the string "1.5". That the document describes the 1.5 generation rather than
  the January 2026 FIBO Edit is inferred from (a) the nine-value aspect-ratio enum, which the
  successor page describes as the pre-Fibo-2 set ("Fibo 2 adds 12 ratios to the nine you know"), and
  (b) fal's concurrent endpoints, which name FIBO-Edit-1.5 and expose the same nine ratios and the
  same 1–4 image cap.
- No date, changelog, or version string appears in the document, so it does not establish a release
  date for 1.5.
- Pricing is not in the bundle; it lives on the marketing site.

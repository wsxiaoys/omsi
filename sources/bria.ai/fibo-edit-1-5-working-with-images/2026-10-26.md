# BRIA AI docs: working with images (inputs, outputs, masks)

- Origin: Bria developer docs, "Working with images and video",
  https://docs.bria.ai/getting-started/working-with-images
- Evidence kind: official documentation (vendor API input/output rules)
- Publication date: none stated; read 2026-10-26
- Capture date: 2026-10-26
- Relevant models: every Bria v2 image endpoint, including the FIBO Edit / FIBO-Edit 1.5 editing route

## Captured content (verbatim excerpts)

Image inputs, verbatim table:

> | Form | Rules |
> | --- | --- |
> | Public URL | Must be reachable by Bria's servers at processing time (no authentication, no expired signed links). |
> | Base64 string | The raw encoded bytes only. Do not include a `data:image/png;base64,` prefix. |
>
> Supported formats are JPEG, PNG and WEBP. Endpoints that take several images (`images`,
> `ref_images`, `mask`) accept either form for each item.

Image outputs, verbatim:

> Results are delivered as a URL in `result.image_url`. Download and store the file yourself; result
> URLs are temporary. Where an endpoint offers `output_type`, choose `png` to keep transparency and
> `jpeg` for smaller files. Endpoints that preserve alpha expose `preserve_alpha` (default `true`),
> which keeps transparency from the input in the output.

Masks, verbatim:

> Mask-based endpoints (`/v2/image/edit/erase`, `/v2/image/edit/gen_fill`, masked `/v2/image/edit`) take
> a `mask` image the same size as the input. The masked region is regenerated, so paint slightly beyond
> the object edge to give the model room to blend, especially around hair, glass and fabric.

Reference and multi-image requests, verbatim:

> `/v2/image/edit` accepts one to four ordered images; refer to them in the instruction as "image 1",
> "image 2" and so on. Masks are supported for single-image requests only.

> Generation endpoints return the VGL `structured_prompt` used to render the image as a JSON string.
> Store it with the `seed`; sending both back reproduces the image, and adding a short `prompt` refines
> it while keeping the composition.

> Input images can be screened before processing with `visual_input_content_moderation`. Blocked inputs
> return `422`.

## Notes

- This is the live (Fibo 2-era) page. The input rules it states — 1–4 ordered images, masks
  single-image only, JPEG/PNG/WEBP, URL or base64 — match the 1.5-era OpenAPI snapshot, so they are
  treated as carried-over constraints rather than Fibo 2 additions.
- "Result URLs are temporary" is the only retention statement in the captured docs; no TTL is given
  here. The asset-retention page was not captured.

## Gaps

- No maximum input resolution, file size, or minimum dimension is stated.
- No output-resolution rule for unmasked edits.
- No statement of how long result URLs live.

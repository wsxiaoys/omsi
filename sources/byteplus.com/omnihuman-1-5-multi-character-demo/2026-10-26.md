## The four-step workflow (verbatim, condensed)

> To animate multiple characters from a single image, this guide provides the complete workflow using
> OmniHuman 1.5. You will learn how to perform subject detection to isolate each character, generate
> individual speaking videos using their unique masks, and stitch the clips together to create a
> multi-character interaction.

The central constraint, verbatim:

> ⚠️ Note: OmniHuman 1.5 does not support using a single audio clip to drive a conversation between
> different characters. In a multi-character scenario, one audio clip can only be used to drive one
> character to speak or multiple characters to speak simultaneously. If you need to enable a
> conversation between different characters, please call the interface multiple times to generate
> videos and then stitch the videos together.

Steps: (1) subject recognition, optional; (2) subject detection, required to choose a speaker —
"Retrieve the mask URL from the response and use the corresponding one to drive the character. The
mask URLs in the list are sorted in descending order of their corresponding subject's mask area (from
largest to smallest)"; (3) video generation with the selected mask; (4) stitch clips, optional.

The sample code sends exactly one `audio_url` per call:

```python
asyncform = {
    "req_key": "realman_avatar_picture_omni15_cv",
    "image_url": "https://xxxxx",
    "mask_url" : first_mask_url,
    "audio_url" : "https://xxxxx"
}
```

## Summary

Multi-character dialogue on the BytePlus API is a composition, not a model feature: detect masks,
generate one video per speaker, and stitch. The API surface accepts one audio track per request, so a
two-character conversation is at minimum two billed generations plus an external edit.

## Contradiction with the research page

The ByteDance project page for OmniHuman-1.5 advertises "routing separate audio tracks to the correct
character in a single frame" (see the project-page record). That describes the research model; the
productised API in this document does not expose multiple audio inputs and explicitly says a single
clip cannot drive a conversation. Both statements are recorded; neither is retracted by the other, and
no captured source explains whether the API is a reduced version of the research system or the
research page describes a demo pipeline built from separate runs.

## Gaps

- No statement of how many characters can appear in one frame, or of mask quality limits.
- No guidance on whether two simultaneous speakers (both driven by the same clip) stay in sync.
- The stitching step has no documented tooling; it is left to the user.

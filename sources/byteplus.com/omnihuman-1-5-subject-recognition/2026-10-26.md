## Service description (verbatim)

> To determine if an image contains a human or human-like subject before using it in other services,
> you can use the Subject Recognition API. This document provides the complete API reference,
> detailing how to submit an image for asynchronous detection and query for the result.

## Parameters

| Name | Type | Required | Value |
| --- | --- | --- | --- |
| `req_key` | string | Yes | "Service identifier: realman_avatar_picture_create_role_omni_cv" (marked "fixed") |
| `image_url` | string | Yes | "URL link of the portrait image" |
| `callback_url` | string | No | terminal-state POST callback |

Image requirements repeat the generator's: JPG/PNG/JFIF, <5 MB, <4096×4096. Transport is the same
asynchronous Vision AI task API (`https://cv.byteplusapi.com`, `Action=CVSubmitTask` /
`CVGetResult`, `Service=cv`, `Region=ap-singapore-1`).

## Summary

A pre-flight check answering whether an image contains a human, human-like, anthropomorphic or
similar subject. Optional in the OmniHuman 1.5 workflow: the multi-character demo skips it when the
caller already knows the image qualifies.

The `req_key` name is misleading. `realman_avatar_picture_create_role_omni_cv` reads like a character
creation call, but the page describes only a suitability check and returns nothing that the
video-generation call consumes.

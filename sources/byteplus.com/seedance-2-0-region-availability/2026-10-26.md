# BytePlus ModelArk: region availability

- Origin: BytePlus (ByteDance) ModelArk documentation, "Region availability",
  <https://docs.byteplus.com/en/docs/modelark/region-availability>
- Evidence kind: official documentation (vendor infrastructure statement)
- Publication date: none stated; living document, capture date 2026-10-26
- Capture date: 2026-10-26
- Relevant models: Seedance 2.0 family (as an exclusion — no video model is listed for the EU region)

## Regions and base URLs (verbatim)

> ModelArk currently supports the following regions:
>
> - Johor, Asia Pacific (AP): Region ID: ap-southeast-1 — Base URL:
>   https://ark.ap-southeast.bytepluses.com/api/v3
> - Dublin, Europe (EU): Region ID: eu-west-1 — Base URL: https://ark.eu-west.bytepluses.com/api/v3

> You access model services through region-scoped customized online inference endpoints: An inference
> endpoint created in a region must be invoked using the region-specific base URL. Inference
> endpoints in one region cannot be called through another region's URL. Platform-level resources,
> such as API keys and model activation status, are isolated by region.

## Model availability by region (verbatim)

> The EU region currently supports the following models:
>
> - seed-2-0-lite

> For the full supported model list, see Model list.

So the international Seedance 2.0 family is served from **`ap-southeast-1` (Johor) only** among the
two ModelArk regions; the EU region serves one text model. The page also notes that requests "may be
routed to inference resources in other regions" based on resource scheduling, which qualifies any
strict data-residency reading.

## Gaps

- The page lists only two regions; whether BytePlus serves Seedance 2.0 from other regions not
  described here was not established.
- "May be routed to inference resources in other regions" is not elaborated (which regions, under
  what conditions), so the page cannot be used to claim strict in-region processing.

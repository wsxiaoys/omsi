## What this establishes

- BytePlus documents the Lite snapshot as **`seedream-5-0-lite-260128`**, presented as an
  alternative model ID accepted under the `seedream-5-0-260128` entry rather than as a row of its
  own.
- On BytePlus, Lite is documented as supporting **batch (sequential) image generation**, which the
  `pro` and `flash` tiers are explicitly marked as not supporting, and as **not** supporting layer
  decomposition.
- Lite is the only Seedream 5.0 tier that BytePlus lists as available in a second region
  (`eu-west-1`).
- The ID suffix convention (`260128`) matches the platform's other dated snapshots
  (`seedream-4-5-251128`, `seedream-4-0-250828`).

## Gaps

- The page does not say whether `seedream-5-0-260128` is itself callable as a distinct model, or
  whether it is a family entry that resolves to the `seedream-5-0-lite-260128` snapshot. The
  pricing page prices only the lite ID (separate record), which suggests the latter, but the
  model list alone does not settle it.
- No deprecation/retirement column appears on this page. BytePlus's separate deprecation notice
  page (`modelark/model-deprecation-notice`) returned HTML with no server-rendered body on capture,
  so it could not be checked; the Volcengine edition of the same model list *does* flag the
  Seedream 5.0 entry (separate record).
- "Max IPM" is not defined in the captured text beyond the caveat above.

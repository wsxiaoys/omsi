Request body — image-reference variant:

```yaml
audio_reference:
  type: string
  contentMediaType: application/octet-stream
  title: Audio Reference
  description: Driving audio file (WAV or MP3, 1-180 seconds)
image_reference:
  anyOf:
    - type: string
      contentMediaType: application/octet-stream
    - type: 'null'
  title: Image Reference
  description: >-
    Image appearance reference (JPEG or PNG). Exactly one visual reference is
    required.
model:
  type: string
  enum:
    - mirage-avatar-x
    - mirage-video-1-latest
  title: Model
  description: Model to use for generation
  default: mirage-avatar-x
required:
  - audio_reference
  - image_reference
```

## Summary

The schema fixes the media contract precisely: audio WAV/MP3, **1–180 s** per the schema against **1–60 s**
in the prose guide; image JPEG/PNG; video MP4/MOV **10–60 s**, explicitly labelled "feature-gated preview";
exactly one visual reference. Aspect ratio is not an input — it is resolved from the reference. The same
endpoint accepts a second model value, `mirage-video-1-latest`, that appears nowhere in the prose docs.

## Gaps

- **Contradiction:** audio length is 1–180 s here and 1–60 s in the guide page (last modified 2026-08-13).
  The schema is the newer document (2026-10-16), but neither page acknowledges the other's number.
- `mirage-video-1-latest` is undocumented beyond the enum: no description, price, capability list, or
  announcement captured.
- No maximum upload file size, no audio sample-rate/channel requirement, no accepted frame rate for the
  video reference.
- "Feature-gated preview" is not explained: no eligibility criteria, waitlist, or date.
- No `avatar` parameter appears in this schema, although the separate avatar-catalog page tells developers
  to "copy the exact avatar enum value to use in create-video requests" (see that record).
- The rendered spec is served from a French-locale path (`/help/docs/fr/api/openapi.json`); whether the
  locale path changes the document was not checked.

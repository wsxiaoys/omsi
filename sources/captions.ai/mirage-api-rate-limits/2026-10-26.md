# Mirage API docs: rate limiting

- Origin: Captions Help Center (Mirage API), "Rate limiting",
  <https://captions.ai/help/docs/api/rate-limiting> (page last modified 2026-07-29)
- Evidence kind: official documentation (vendor operational limit)
- Publication date: page last modified 2026-07-29
- Capture date: 2026-10-26
- Relevant models: `mirage-avatar-x` (video generation)

## Captured content (verbatim)

> To keep the system fast and fair for everyone, Mirage enforces simple rate limits on API requests.

| Feature | Limit (RPM) |
| - | -: |
| Video Captions | **100 requests** |
| Video Generation | **2 requests** |

> **Note:** These limits apply per organization. If you need higher throughput, talk to your account
> manager to raise your limits.

> If the limit is exceeded, the API returns **HTTP 429 Too Many Requests**.

```json
{
  "error": {
    "type": "rate_limit_exceeded",
    "message": "Rate limit exceeded."
  }
}
```

## Summary

Video generation through the Mirage API — the only generation model being Avatar X — is capped at **2
requests per minute per organization**, with a 429 and a `rate_limit_exceeded` payload above that. The cap
is an organizational limit raised by an account manager on request, which makes throughput a commercial
term rather than a technical ceiling.

## Gaps

- No concurrency limit, daily quota, or queue-depth figure.
- No statement of whether the limit counts submissions or completed jobs.
- "Talk to your account manager" implies a sales relationship; no self-serve limit increase path is
  documented.

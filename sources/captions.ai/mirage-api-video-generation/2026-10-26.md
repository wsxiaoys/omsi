# Mirage API docs: "Get started with avatar generation using Avatar X"

- Origin: Captions Help Center (Mirage API), "Get started with avatar generation using Avatar X",
  <https://captions.ai/help/docs/api/video-generation> (page last modified 2026-08-13)
- Evidence kind: official documentation (vendor API guide)
- Publication date: page last modified 2026-08-13; underlying docs undated
- Capture date: 2026-10-26
- Relevant models: `mirage-avatar-x` on `POST https://api.mirage.app/v1/videos`

## Captured content (verbatim, selected)

> Avatar X is Mirage's avatar generation model, built for identity preservation and expressivity. Send
> audio and an optional visual reference to a single multipart endpoint, and get back a video of that
> person speaking.

> Driving audio is 1–60 seconds per request. Output is a 720p MP4 in 9:16 or 16:9, with most generations
> completing in under two minutes. For longer videos, developers can generate multiple segments and join
> them together.

> Every output includes non-removable provenance metadata. Reference media is used only for that request
> and is not retained as a reusable identity.

Input modes, verbatim:

> * Provide `image_reference` with `audio_reference`.
> * Provide `video_reference` with `audio_reference`. Image and video references are mutually exclusive.

The request is a multipart POST with `x-api-key`, form fields `model=mirage-avatar-x` plus the two media
files. Response example (verbatim):

```json
{
  "id": "video_abc123def456",
  "object": "video",
  "completed_at": 1730822520,
  "created_at": 1730822400,
  "model": "mirage-avatar-x",
  "progress": 100,
  "status": "COMPLETE",
  "error": null
}
```

Statuses are `PROCESSING`, `COMPLETE`, `FAILED`, `CANCELLED`; the client polls `GET /v1/videos/{id}` and
downloads via `GET /v1/videos/{id}/content`, which "returns an HTTP redirect to the final video URL".

Prompting/asset tips, verbatim:

> Use a clear, front-facing portrait with good lighting and a single subject. Make sure the face is clear,
> mouth is open, and the subject is oriented in a close to medium shot to ensure natural alignment with the
> voice.

> Avoid images with closed mouths or multiple people in the frame.

> Use expressive, realistic, sounding audio. Results tend to look worse if the audio is audibly "AI".

## Summary

This is the operational spec for the model: an asynchronous job API (submit, poll, follow a redirect to
download) that takes driving audio plus exactly one visual reference — an image or a video — and returns a
720p MP4 in the reference's aspect ratio (9:16 or 16:9). Audio length is stated as 1–60 s per request, the
contract is described as segment-and-join for longer output, and the page states that outputs carry
non-removable provenance metadata and that reference media is not retained as a reusable identity.

The "optional visual reference" phrasing in the intro conflicts with the input-mode section and the
OpenAPI schema, both of which make one visual reference mandatory.

## Gaps

- No frame rate, bitrate, codec, or exact pixel dimensions; "720p" is the only resolution statement.
- No per-request wall-clock guarantee — "most generations completing in under two minutes" is a typical
  case, not an SLA.
- No statement of what the provenance metadata is (C2PA, watermark, or both), whether it is visible, or
  how a downstream user can inspect it.
- No documented retention period for outputs, nor what "not retained as a reusable identity" means for
  the vendor's own logs.
- No consent or identity-verification step is described on this page; the obligations are in the terms
  (captured separately).

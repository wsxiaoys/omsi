# Cartesia: Multilingual voices (accents, localization, locale field)

- Origin: Cartesia, "Multilingual Voices — Reach a global audience with one voice that speaks multiple
  languages and accents",
  <https://docs.cartesia.ai/build-with-cartesia/capability-guides/multilingual-voices>
  (read as Markdown at `…/multilingual-voices.md`)
- Evidence kind: official documentation
- Publication date: not stated.
- Capture date: 2026-10-26
- Relevant models: `sonic-3.6` (the `locale` field requires it); older Sonic models for `language`

## Captured content

> Every voice can speak every language the model supports. A single-accent voice sounds like a
> non-native speaker outside its own language; a multilingual voice has accents in several languages
> and sounds native in each.

> `locale` needs `sonic-3.6` or newer. On earlier models, use `language` with a base code like `en`
> instead. A request may set one or the other, never both.

Accent fallback: when the requested language has no matching accent, the voice "falls back to its
original accent"; a request for an unsupported `accent` fails with HTTP 400 — "this voice does not
support accent 'japanese'".

Two ways to add native accents:

| API | Applies to | Result |
| --- | --- | --- |
| Add Voice Accents | Private Instant Voice Clones you own | Same voice ID, now speaking more accents natively |
| Localize Voice | Any voice, including public Cartesia voices and Pro Voice Clones | A new voice ID that speaks only the new accent |

> A voice can support up to 10 accents.

> `sonic-3.6` makes voices sound more native when they speak another language, so a deliberate accent
> may sound lighter. For a deliberately non-native accent, use `sonic-3.5`.

Mid-conversation language switching: "Send one language per request… Mixing languages inside a single
generation works where it's common, such as Hindi (Hinglish) and Tagalog (Taglish). Outside those
cases the speech may sound accented."

## Summary

This page is where the 3.6-vs-older language mechanics are documented: `locale` is a **3.6-only**
field; every voice can speak every supported language but only sounds native in accents it lists; a
voice holds at most 10 accents; and 3.6 deliberately reduces foreign accents, which the vendor flags as
a reason to stay on 3.5 if an accented non-native read is the goal. That is a behaviour regression for
some workflows, not only an improvement.

Localize Voice is billed separately: the pricing page lists "Localizing a voice — 225 credits per added
voice accent".

## Gaps

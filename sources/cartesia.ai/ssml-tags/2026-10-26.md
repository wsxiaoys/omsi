# Cartesia: SSML tags (speed, volume, emotion, break, spell)

- Origin: Cartesia, "SSML Tags — Laughter, pauses, and mid-transcript controls",
  <https://docs.cartesia.ai/build-with-cartesia/capability-guides/ssml-tags>
  (read as Markdown at `…/ssml-tags.md`)
- Evidence kind: official documentation
- Publication date: not stated.
- Capture date: 2026-10-26
- Relevant models: `sonic-3` and later (speed and volume tags are marked "Available on `sonic-3` and
  later"), so `sonic-3.6` is in scope

## Captured content

> Tags for volume, speed, and emotions are in beta and subject to change in the future.

> Sonic supports SSML-like (Speech Synthesis Markup Language) tags to control generated speech. The
> supported tags are `speed`, `volume`, `emotion`, `break`, and `spell`.

- **speed**: "a scalar between `0.6` and `1.5`. The default is `1.0`." Streaming caveat: "if you're
  streaming token by token, you'll need to buffer the whole value of the speed or volume tags. Passing
  in `1`, `.`, `0` as separate inputs, for example, will result in reading out the tags."
- **volume**: "a number between `0.5` and `2.0`. The default volume is `1`."
- **emotion**: "highly experimental, particularly when emotion shifts occur mid-generation. If you need
  to change the emotion in a transcript, we recommend using separate generation contexts for each
  emotion." Best results with voices tagged "Emotive".
- **break**: "takes one attribute, `time`, in seconds (`s`) or milliseconds (`ms`)… Break tags split the
  generation, so the model has less surrounding context and the speech can sound less natural. Avoid
  placing several break tags in quick succession, which can cause the model to hallucinate. Each tag
  counts as 1 character."
- **spell**: character-by-character read-out for codes, IDs and names; "Avoid other punctuation inside
  `<spell>` tags"; "don't chain `<spell>` and `<break>` tags."

PVC caveat repeated here: "Speed control applies to Instant Voice Clones. Professional Voice Clones
take their pacing from their source recordings and don't support request-time speed adjustments."

## Summary

The documented markup surface is exactly five tags. Emotion is the least reliable (beta, English-only
per the companion guide, best with Emotive voices) and `break` is documented to risk hallucination when
used densely. Tags are billed: "each tag counts as 1 character".

The page title mentions "Laughter" but no laughter tag is listed among the five — laughter is handled by
inserting `[laughter]` in the transcript, documented on the Volume/Speed/Emotion page instead.

## Gaps

- No per-tag support matrix by model beyond "`sonic-3` and later" for speed/volume.
- No statement of whether tags inside `<spell>` or nested tags are validated or silently ignored.

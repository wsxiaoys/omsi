## Captured content

> **output_format.container** `string` — The container format for the audio output. Available options:
> `raw`, `wav`, `mp3`. Only the Bytes endpoint supports all container formats; our other endpoints
> (SSE, WebSockets) only support `raw`.

> **output_format.encoding** `string` — The encoding of the output audio. Available options:
> `pcm_f32le`, `pcm_s16le`, `pcm_mulaw`, `pcm_alaw`.

> **output_format.sample_rate** `number` — The sample rate of the output audio. … Available options:
> `8000`, `16000`, `22050`, `24000`, `44100`, `48000`.

Encoding table (verbatim):

| Encoding | Bit depth | Commonly used for | Pair with sample rate |
| --- | --- | --- | --- |
| `pcm_mulaw` | 8-bit compressed | North American / Japanese telephony (G.711μ), Twilio | 8000 |
| `pcm_alaw` | 8-bit compressed | European / international telephony (G.711A) | 8000 |
| `pcm_s16le` | 16-bit int | Most voice agent platforms, e.g. LiveKit and Pipecat | 16000 |
| `pcm_f32le` | 32-bit float | Most browsers | 44100 or 48000 |

> If you're saving audio samples, we recommend using the Text-to-Speech (Bytes) API with
> `output_format.container: "wav"` or `output_format.container: "mp3"` so audio players can
> automatically detect the encoding and sample rate.

## Summary

Output is **8–48 kHz**, in μ-law/A-law/s16le/f32le PCM, or WAV/MP3 containers on `/tts/bytes` only.
There is no Opus, FLAC or AAC option anywhere in the documented set. A pipeline that needs a
container format must use the bytes endpoint; SSE and WebSocket deliver raw PCM frames.

## Gaps

- No documented default `output_format` for Sonic 3.6 requests (the bytes schema gives per-container
  defaults: WAV `pcm_s16le` @ 44100, MP3 @ 44100 with 128 kbit/s).
- No statement on whether MP3 encoding adds measurable latency versus raw PCM.

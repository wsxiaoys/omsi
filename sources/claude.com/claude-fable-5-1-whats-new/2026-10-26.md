- **Evidence kind:** first-party documentation (per-model changelog: breaking API changes,

## Shared specs, verbatim

> "Claude Fable 5.1 and Claude Mythos 5.1 share specs and pricing: Context window and output:
> a 1M token context window (default and maximum) at standard per-token pricing across the
> whole window, and 128k max output tokens. Thinking: adaptive thinking is always on. Use the
> effort parameter to control thinking depth. Pricing: the same as Claude Fable 5, except for
> a lower cache read price. Tokenizer: the same as Claude Fable 5 (introduced with Claude
> Opus 4.7). Compared with models older than Claude Opus 4.7, the same text produces roughly
> 30 percent more tokens."

## Breaking changes, verbatim

> "Claude Fable 5.1 and Claude Mythos 5.1 don't support forced tool use. `tool_choice` set to
> `{"type": "any"}` or `{"type": "tool", "name": "..."}` returns a 400 `invalid_request_error`"

> "Every thinking block records which model produced it. Claude Fable 5.1 reads earlier
> models' thinking blocks, but only Claude Fable 5.1 and Claude Mythos 5.1 read Claude Fable
> 5.1's. A conversation that moves onto Claude Fable 5.1 (from Claude Opus 5, Claude Fable 5,
> or any earlier Claude model) keeps its reasoning. A conversation that moves from Claude
> Fable 5.1 to any other model loses it for the turns that run there."

> "Modifying anything before a Claude Fable 5.1 thinking block (the system prompt, the tools,
> or an earlier message) results in an error on the next request, or in the block being
> dropped if you opt into that. … The check is enforced for new accounts created on or after
> August 31, 2026."

> "With the advisor tool (beta), the advisor must be at least as capable as the executor. …
> With a Claude Fable 5.1 or Claude Mythos 5.1 executor, they return a 400
> `invalid_request_error`."

## New features, verbatim

> "On Claude Fable 5.1 you can change the effort level mid-conversation without invalidating
> the prompt cache. … Per-message effort is in beta: include the
> `mid-conversation-output-config-2026-07-01` beta header."

> "A mid-conversation system message can be scoped to one turn. Set `clear_at:
> "next_user_message"` on a `role: "system"` message … (beta header
> `mid-conversation-system-clear-at-2026-08-21`)."

> "Under the default thinking `display` of `"omitted"` those blocks come back empty … What's
> new is the `display: "updates"` option: set it with the
> `thinking-display-updates-2026-08-18` beta header to receive the progress updates as text
> while reasoning stays hidden."

> "Text generated by Claude Fable 5.1 and Claude Mythos 5.1 carries Anthropic's statistical
> text watermark on every platform where the model is available. Supported image, video, and
> audio files Claude produces (through the code execution tool, for example) carry signed
> C2PA Content Credentials when you retrieve them through the Files API on the Claude API."

## Behaviour differences from Claude Fable 5, verbatim (abridged)

> "Parallel tool calling is more variable."

> "Fewer progress updates during long tool runs."

> "Answers from memory more often at low effort."

> "Denser prose in places."

> "Less formatting in chat."

> "Unmarked quotations in summaries."

> "Whole-file rewrites for small changes."

## Unchanged from Claude Fable 5, verbatim

> "Adaptive thinking is always on. `thinking: {"type": "enabled"}` with `budget_tokens` and
> `thinking: {"type": "disabled"}` both return a 400 error. Omit thinking or send `{"type":
> "adaptive"}`."

> "Prefilling the assistant response returns a 400 error."

> "Setting `temperature`, `top_p`, or `top_k` returns a 400 error."

> "The minimum cacheable prompt length is 512 tokens."

## Refusals, fallback, billing, verbatim

> "It can return `stop_reason: "refusal"`, so handle refusals and configure fallback."

> "The permitted fallback targets for Claude Fable 5.1 are Claude Opus 4.8 and Claude Opus 5."

> "a refusal that arrives before any output is billed when it's in a category with low
> volumes of false positives … Before September 24, 2026, these refusals weren't billed."

## Pricing, verbatim

> "Claude Fable 5.1 and Claude Mythos 5.1 are priced the same as Claude Fable 5, except for
> cache reads (prices in USD): Base input $10 / MTok · 5m cache writes $12.50 / MTok · 1h
> cache writes $20 / MTok · Cache reads $0.25 / MTok · Output $50 / MTok"

> "Cache reads (hits and refreshes) cost 0.025 times the base input price on these models,
> compared with 0.05 on Claude Opus 5.5 and Claude Sonnet 5.5, and 0.1 on other Claude
> models."

## Gaps

- No benchmark numbers and no context-window caveats beyond "1M … at standard per-token
  pricing".
- The page describes Fable 5.1 and Mythos 5.1 jointly; where they differ it only says
  Mythos is limited to verified organizations.
- Nothing on data retention; that is in the release notes and the launch post, which
  disagree in emphasis (see the model page).

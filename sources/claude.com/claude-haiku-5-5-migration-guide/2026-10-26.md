# Claude Haiku 5.5 migration guide (Claude Platform docs)

- **Origin:** "Claude Haiku 5.5 migration guide", Claude Platform Docs (Anthropic),
  <https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide>.
- **Evidence kind:** first-party documentation (per-change migration instructions, model-ID
  table, tokenizer and image-token behaviour).
- **Publication date:** undated page. Capture date 2026-10-26.
- **Relevant models:** `claude-haiku-5-5` against `claude-haiku-4-5`, and against
  `claude-3-5-haiku` / `claude-3-haiku`.
- **Capture type:** full snapshot of the rendered page text. No artifacts.

## Model ID table, verbatim

| Platform | Claude Haiku 4.5 | Claude Haiku 5.5 |
| --- | --- | --- |
| Claude API | `claude-haiku-4-5-20251001` or `claude-haiku-4-5` | `claude-haiku-5-5` |
| Amazon Bedrock | `anthropic.claude-haiku-4-5` | `anthropic.claude-haiku-5-5` |
| Claude Platform on AWS | `claude-haiku-4-5` | `claude-haiku-5-5` |
| Claude Models on Google Cloud (Google managed) | `claude-haiku-4-5@20251001` | `claude-haiku-5-5` |
| Microsoft Foundry | `claude-haiku-4-5` | `claude-haiku-5-5` |

> "`claude-haiku-5-5` is a fixed model ID with no date suffix and no separate alias."

**Identity note.** The predecessor carries a dated snapshot (`-20251001`); Haiku 5.5 does
not publish one on any platform. There is therefore no first-party dated checkpoint to split
on, and no vendor-pinned snapshot ID to cite.

## Token accounting, verbatim

> "Claude Haiku 5.5 uses the same newer tokenizer as Claude 4.7 and later models. As with all
> models that use this tokenizer, the same input text produces approximately 30 percent more
> tokens on Claude Haiku 5.5 than on Claude Haiku 4.5."

> "Claude Haiku 5.5 uses the high-resolution image tier, which downscales images above 2,576
> pixels on the long edge or 4,784 visual tokens. Claude Haiku 4.5 and earlier Haiku models
> use the standard tier, which downscales images above 1,568 pixels on the long edge or 1,568
> visual tokens. An image of 2,000 by 1,500 pixels costs about 2.5 times as many visual
> tokens on Claude Haiku 5.5 as on Claude Haiku 4.5."

Both changes push the effective price above the list-price comparison: a prompt that fits
under the 100k tier on Haiku 4.5 can cross it on Haiku 5.5, and the same image costs 2.5× the
visual tokens.

## Thinking, verbatim

> "A `thinking` value of `{"type": "enabled", "budget_tokens": N}` returns a 400 error, so a
> request that sends it needs a new `thinking` value."

> "Adaptive thinking is on by default, so a response can start with one or more `thinking`
> blocks even when the request doesn't set `thinking`. Leave `thinking` unset or set it to
> `{"type": "adaptive"}`, and use `effort` as the control."

> "Claude Haiku 5.5 accepts a forced `tool_choice` (`any` or a named tool), but the response
> starts with the tool call and has no `thinking` block."

This is a second structural difference from Opus 5.5, which returns a 400 for `tool_choice`
of `any` or a named tool.

> "Claude Haiku 5.5 reads thinking blocks from Claude Sonnet 5, Claude Opus 4.8, Claude Haiku
> 4.5, and earlier models … It doesn't read blocks from Claude Opus 5, Claude Opus 5.5,
> Claude Sonnet 5.5, or any Claude Fable or Claude Mythos model; the API drops those without
> an error. On the Claude API and Claude Models on Google Cloud (Google managed), Claude Opus
> 5.5 and Claude Sonnet 5.5 read Claude Haiku 5.5's blocks."

## Other constraints, verbatim

- "Claude Haiku 5.5 rejects it with a 400 error, even with thinking turned off" — of
  assistant-message prefill.
- "Thinking blocks from Claude Haiku 5.5 work only in the account that produced them, or in
  an account linked to it."
- "a request that sends a thinking block back after a change to `system`, `tools`, or earlier
  `messages` returns a 400 error".
- "Claude Haiku 5.5 runs safety classifiers that can decline a request, and it has no
  server-side fallback."
- "If your organization has a Priority Tier commitment on Claude Haiku 4.5, plan capacity
  separately: Priority Tier is not supported on Claude Haiku 5.5."
- "On the Claude API and Claude Models on Google Cloud (Google managed), Claude Haiku 5.5 also
  supports the browser use tool (`browser_toolset_20260801`) for tasks inside webpages.
  Claude Haiku 4.5 doesn't support it."

## Summary

Authoritative source for the ID mapping and for the practical cost traps: a tokenizer that
inflates token counts ~30%, a high-resolution image tier that costs ~2.5× the visual tokens
on a 2000×1500 image, and a 5× long-context price tier whose 100k boundary is easier to cross
than it was on Haiku 4.5.

## Gaps

- No pricing figures on the page (it links to the pricing page).
- No statement of whether the >100k tier is evaluated per request or per message.
- Priority Tier unavailability is stated but not explained.

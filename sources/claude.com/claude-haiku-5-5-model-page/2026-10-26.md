> "Claude Haiku 5.5 is built for high-volume, latency-sensitive work such as classification,
> routing, extraction, and subagent tasks. It supports adaptive thinking with the effort
> parameter, a 1M token context window, and up to 128k output tokens. It uses the same newer
> tokenizer as Claude 4.7 and later models, so the same text counts as approximately 30
> percent more tokens than on Claude Haiku 4.5. Its thinking blocks work only in the account
> that produced them, or in an account linked to it."

Batch API: "50% discount on input and output". The tier boundary is a property of the
prompt, not of the output; the page does not say whether the tier is chosen per request or
per message in a multi-turn conversation.

Note the wording difference: the two larger models are "Adaptive (always on)" while Haiku
5.5 and Sonnet 5.5 are plain "Adaptive" — consistent with Haiku 5.5 accepting
`thinking: {"type": "disabled"}`, which the Opus 5.5 page says that model rejects.

## Summary

Canonical first-party spec sheet. Establishes: 1M context, 128K max output (300K batch
beta), text+image input, text output, adaptive thinking with default effort `medium`, a
two-tier price schedule with the break at 100k prompt tokens, a June 2026 knowledge cutoff,
GA status on all five first-party/partner platforms, and a retirement floor exactly one year
after launch.

## Gaps

- No benchmark numbers on this page.
- No statement of whether the long-context tier applies per request or per conversation.
- The page does not say which effort levels are accepted (the effort doc and Bedrock card
  do); it only names the default.

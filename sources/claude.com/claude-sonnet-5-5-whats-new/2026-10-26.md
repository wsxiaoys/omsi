## What actually changes

> "Claude Sonnet 5.5 offers the best combination of speed and intelligence. Five breaking
> changes affect code already running on Claude Sonnet 5"

> "The tokenizer is the same as Claude Sonnet 5's, so the same text produces the same token
> counts."

> "Adaptive thinking is on by default, and the effort parameter controls thinking depth. Its
> default on the Claude API is `high`."

### `between_tools` replaces `disabled`

> "To turn off up-front thinking on Claude Sonnet 5.5, send `thinking: {"type":
> "between_tools"}` instead of `"disabled"`. It's the lowest thinking setting on this model."

> "On Claude Sonnet 5.5, a request that sends `thinking: {"type": "disabled"}` returns a 400
> `invalid_request_error` whose message points to `between_tools`."

> "`between_tools` is accepted at `low`, `medium`, and `high` effort. At `xhigh` or `max`
> effort, a request with `between_tools` returns a 400 error."

> "`between_tools` takes no other field: `display`, `budget_tokens`, or `block_binding` sent
> with it returns a 400 error. Manual thinking budgets (`thinking: {"type": "enabled",
> "budget_tokens": N}`) return a 400 error."

With `between_tools`, "effort can't change mid-conversation: a per-message
`output_config.effort` that differs from the level in effect returns a 400 error."

### Forced tool use errors

> "`tool_choice` set to `{"type": "any"}` or `{"type": "tool", "name": "..."}` returns a 400
> `invalid_request_error`"

`auto` and `none` are supported. "For schema-valid tool input, keep `tool_choice: {"type":
"auto"}` and set `strict: true` with strict tool use, or move the schema to structured
outputs."

### Thinking blocks are model- and conversation-bound

> "Claude Sonnet 5.5 reads thinking blocks from Claude Sonnet 5, Claude Opus 4.8, Claude
> Haiku 4.5, and earlier models, and, on the Claude API and Claude Models on Google Cloud
> (Google managed), from Claude Haiku 5.5, but not from Claude Opus 5, Claude Opus 5.5, or
> any Claude Fable or Claude Mythos model. On the Claude API and Claude Models on Google
> Cloud (Google managed), Claude Opus 5.5 reads Claude Sonnet 5.5 thinking blocks; no other
> model does."

Prefix-mismatch enforcement: "It enforces that check by default for accounts created on or
after August 31, 2026, 00:00 UTC, on the Claude API, Amazon Bedrock, and Claude Models on
Google Cloud (Google managed). On those accounts, a request that replays a block after such
a change returns a 400 error."

Account binding: "Thinking blocks that Claude Sonnet 5.5 produces work only in the account
that produced them, or in an account linked to it."

### `computer_20251124` rejected on two platforms

> "On the Claude API and Claude Models on Google Cloud (Google managed), Claude Sonnet 5.5
> supports computer use only through the `computer_toolset_20260801` toolset. A request that
> declares the earlier `computer_20251124` tool returns a 400 `invalid_request_error`."

> "On Amazon Bedrock, Claude Sonnet 5.5 accepts the earlier `computer_20251124` tool."

### Advisor tool pairings

A Sonnet 5.5 executor accepts Claude Mythos 5.1, Fable 5.1, Mythos 5, Fable 5, Opus 5.5,
Opus 5, or Sonnet 5.5 itself as advisor. "Claude Opus 4.8, Claude Opus 4.7, Claude Sonnet 5,
and Claude Haiku 5.5 advisors … with a Claude Sonnet 5.5 executor they return a 400
`invalid_request_error`."

## Feature support, verbatim

> "Claude Sonnet 5.5 supports per-message effort (beta), mid-conversation system messages,
> mid-conversation tool changes (beta), prompt caching with a 512-token minimum cacheable
> prompt, batch processing, the Files API, PDF support, vision, and server-side and
> client-side tools."

Two betas are called out separately: `compact-2026-09-04` for on-demand compaction and
`inline-tools-2026-09-15` for defining tools in a mid-conversation message.

## Behaviour differences worth knowing

- **Effort is recalibrated.** "An effort level doesn't produce the same amount of thinking as
  it did on Claude Sonnet 5. Re-run your effort sweep rather than carrying a setting over.
  Start at `high` unless your workload is agentic or latency-sensitive."
- **Text between tool calls moves into thinking blocks.** "At the default `display:
  "omitted"`, the progress-update blocks' text is empty, so an application that streams those
  notes to its users goes quiet between tool calls, with no error."
- **Five refusal categories** in `stop_details`: `cyber`, `bio`, `frontier_llm`,
  `reasoning_extraction`, `general_harms`.

## Refusals, fallback, billing, verbatim

> "Server-side fallback (`fallbacks: "default"`), in beta on the Claude API and on Claude
> Models on Google Cloud (Anthropic managed), retries `"cyber"` and `"frontier_llm"`
> declines on Claude Sonnet 5. It doesn't retry `"bio"`, `"reasoning_extraction"`, or
> `"general_harms"` declines."

> "Whether a refusal that arrives before any output is billed depends on its refusal
> category, and it counts against your rate limits either way."

## Pricing delta, verbatim

> "Claude Sonnet 5.5 has the same prices as Claude Sonnet 5, except for prompt cache reads,
> which cost $0.10 USD per million tokens, half the Claude Sonnet 5 rate."

## Availability, verbatim

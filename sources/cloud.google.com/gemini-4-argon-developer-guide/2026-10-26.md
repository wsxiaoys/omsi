  Retrieved 2026-10-26.
- **Evidence kind:** official documentation (first-party API guide: parameter rules,

- **Publication date:** undated page, continuously edited. Capture date 2026-10-26.
- **Relevant models:** `gemini-4-argon`, `gemini-4-argon-cyber-permissive`; migration source

- **Capture type:** rendered page text.

## Identity and family (verbatim)

> Gemini 4 Argon is Google's frontier model that excels at deep work in complex, real-world
> tasks across domains including coding, finance, legal, cybersecurity, and science. It's the
> first model in the Gemini 4 family.

## Thinking levels (verbatim table)

| Thinking level | Recommended workloads |
| --- | --- |
| HIGH (default on `gemini-4-argon-cyber-permissive`) | Multi-file software engineering, formal proofs, architecture design, and vulnerability discovery. |
| MEDIUM (default on `gemini-4-argon`) | General coding, tool use, document Q&A, and video understanding. |
| LOW | Classification, summarization, and metadata extraction. |

> Setting `thinking_budget` or `thinking_level="MINIMAL"` returns an HTTP `400` error.

## Token budget and long decodes (verbatim)

> 1,048,576 is the overall token limit of the model and includes both input and output tokens
> (where output includes thinking, function calls, and the final response). `max_output_tokens`
> controls the output token cap for the generation (up to 1,048,576 minus your input tokens);
> setting `max_output_tokens` greater than 1,048,576 returns an HTTP `400` error.

> To avoid unintended long completions, the default single-request output limit (thinking +
> model response) is 65,536 tokens (or 32,768 tokens for non-streaming direct HTTP requests).

> Long decode splits a generation up to 1,048,576 tokens across multiple GenerateContent
> inferences. … the first streaming request generates up to 65,536 output tokens and emits
> `finish_reason=CONTINUATION` with an encrypted `continuation_token` … Including
> `continuation_token` in subsequent requests with the original prompt continues generation
> from where it left off until `continuation_token` is no longer emitted and
> `finish_reason=STOP`.

Operational rules attached to long decode:

- `v1beta1` only (known issue); "Long decode isn't supported on the Interactions API."
- "Older SDK versions and the OpenAI compatibility layer cannot retrieve long completions
  using continuation tokens." Minimum SDKs: `google-genai >= 2.30.1` (Python),
  `@google/genai >= 2.29.1` (JS), Go 1.74.0, Java 1.77.0, .NET 1.26.0, Kotlin 1.6.0.
- 20-minute limit per request; the guide advises against long decode for chat/Q&A,
  fixed-length requests, many-short-turn agents, prompts near the input limit, and
  latency-sensitive work.
- Continuation re-prefills the prompt plus prior decoded tokens, so `prompt_token_count`
  grows across requests; the guide says to read `initial_prompt_token_count` instead.

## Parameter rules (verbatim)

> **Ignored sampling parameters (`temperature`, `top_k`, `top_p`)**: The backend ignores
> custom values. Control reasoning depth with `thinking_level`, and output format with
> `response_schema`.

> **Unsupported parameters (`frequency_penalty`, `presence_penalty`, `candidate_count`)**:
> These return an HTTP `400` error.

> **Context caching**: Explicit context caching isn't supported. Implicit caching (with
> durable caching enabled by default) applies automatically to shared prompt prefixes of
> 6,144 tokens or more.

> **Chat sequence validation**: History payloads can't end with a `model` role turn.
> Prefilled model turns aren't supported.

> **Token counting and billing**: Every token the model processes is counted and billed,
> including thinking tokens and internal tool system instructions and function declarations
> when using grounding.

## Agentic video (verbatim)

> **Agentic video**: Uploaded videos default to `media_processing="static"`. Set
> `media_processing="agentic"` to enable agentic video processing.

The model page and release notes describe agentic video understanding as GA; the guide says
it is "Generally available, and off by default."

## Migration deltas from `gemini-3.1-pro-preview` (verbatim list)

1. Unified 1,048,576-token limit across input and output instead of separate limits.
2. `thinking_budget` returns 400 instead of being mapped to a level; `MINIMAL` errors.
3. Explicit context caching unsupported.
4. "Every token the model processes is billed, including internal tool system instructions
   and function declarations when using grounding."

## Summary

The operational source: three thinking levels with documented defaults, a hard 400 on
`thinking_budget`/`MINIMAL`, ignored sampling parameters, implicit-only caching at a
6,144-token prefix minimum, the continuation-token protocol for outputs beyond 65,536 tokens,
the v1beta1 and OpenAI-compat limitations, and the rule that thinking and grounding
instructions are billed.

## Gaps

- The 6,144-token caching minimum here contradicts the 4,096-token minimum on the model page
  for the same model.
- No price table on this page.
- No statement of whether the Gemini API (as opposed to Agent Platform) supports the same
  continuation protocol or the same parameter rules.
- "Agentic video" behaviour itself is described on a separate page that was not captured.

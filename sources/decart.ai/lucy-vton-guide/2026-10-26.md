## Page summary

The page is Decart's guide for the Lucy VTON line, not for the April 2026 `lucy-2.1-vton`
generation specifically. Every code sample uses `lucy-vton-latest`, and the version note points at
3.6:

> **Versions.** The examples below use `lucy-vton-latest`, which resolves to `lucy-vton-3.6`.
> `lucy-vton-3.5` remains available by name on both surfaces at 720p. Both versions support
> [fast mode](#fast-mode).

Opening description:

> Dress people in live or recorded video with text prompts, garment images, or both.
>
> Try on clothing and accessories in realtime. Stream a live camera feed, describe the outfit or
> provide a reference image of the garment, and Lucy VTON will realistically dress the subject while
> preserving motion and body shape — all with minimal latency.

## Realtime surface

- Transport: WebRTC via `@decartai/sdk` (`client.realtime.connect(stream, { model })`), or a raw
  WebSocket at `wss://api.decart.ai/v1/stream?api_key=...&model=lucy-vton-latest`.
- Connect-time camera constraints are taken from the model object: `frameRate: model.fps,
  width: model.width, height: model.height`. The page never prints the numeric fps.
- Session inputs:
  - `prompt` — "Text description of the outfit change. Use the **substitute** or **add** patterns
    described in the VTON 3.5 Prompting Guide."
  - `image` — "A garment reference image to guide the try-on. Supported formats: JPEG, PNG, WebP."
  - `enhance` — "Whether to auto-enhance the prompt (default: `true`)."
  - `speed` — connect-time option; `"fast"` is billed at 2x the standard realtime rate.
- `set()` semantics: "`set()` replaces the entire state — fields you omit are cleared."
- Mid-session changes: `setPrompt()` / `set()` switch outfits "without reconnecting".

Reference-image guidance (verbatim):

> * **Clean garment images work best** — just the clothing item, no person wearing it
> * **White or plain backgrounds** are ideal
> * **At least 512×512 pixels** — the model reproduces what it sees, so a clear image produces
>   better results
> * If your source image shows a person wearing the garment, consider using an image editing model
>   to extract just the clothing item first

Security guidance: never ship the permanent `dct_*` key to a browser; mint a client token
(`client.tokens.create()`) that expires 60 seconds after minting.

## Batch (queue) surface

> Lucy VTON is also available as a batch/queue model for processing pre-recorded videos
> asynchronously. Submit a job, poll for completion, then download the result.

Submit: `POST https://api.decart.ai/v1/jobs/lucy-vton-latest` (multipart: `data=@person.mp4`,
`prompt`, `reference_image=@garment.jpg`); poll `GET /v1/jobs/{job_id}`; fetch
`GET /v1/jobs/{job_id}/content`.

Batch parameters, verbatim:

> * `data` (**required**) — Input video of the person to dress.
> * `prompt` (**optional**) — Text description of the outfit change. … Defaults to empty string.
> * `reference_image` (**optional**) — An image of the garment or accessory to try on.
> * `resolution` (**optional**) — Output resolution: `720p` (default).
> * `seed` (**optional**) — Seed for reproducible generation (0–4294967295).
> * `enhance_prompt` (**optional**) — Whether to enhance the prompt (default: `true`).

Video requirements and output, verbatim:

> * **Format:** MP4 (H.264 or VP8 codec)
> * **Aspect Ratio:** 16:9 (landscape) or 9:16 (portrait) — a 2:1 (landscape) / 1:2 (portrait)
>   shape is also supported
> * **File Size:** Maximum 200MB
> * **Output Resolution:** 1280×720 / 720×1280 (16:9 / 9:16) or 1280×640 / 640×1280 (2:1 / 1:2)
>
> VTON infers the aspect ratio from the input video stream and maps it to the nearest supported
> generation shape.

## Integration helpers documented on the page

- Prompt generation for user-uploaded garments: send the garment image (and optionally a camera
  frame) to a vision LLM to produce the try-on prompt.
- Extracting clothing from on-model photos with an image editing model before try-on.
- Official examples repository: `https://github.com/DecartAI/tryon-examples`.

## Gaps

- No frame rate is published anywhere on the page, for either surface.
- No latency figure (glass-to-glass or otherwise) is given.
- The retired `lucy-2.1-vton` generation is not documented here; nothing on the page states what
  changed between the 2.1, 3, 3.5 and 3.6 try-on models.
- No duration cap for batch input is stated (only the 200MB file cap).
- 1080p is not offered for VTON here; the pricing page also lists only a 720p column.

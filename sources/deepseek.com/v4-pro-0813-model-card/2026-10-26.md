## What the card says the model is

Verbatim:

> "DeepSeek-V4-Pro-0813 is the official release of DeepSeek-V4-Pro, superseding the preview
> version, with greatly enhanced agentic capabilities and performance improvements that are
> especially pronounced in production environments. It is built on the DeepSeek-V4-Pro
> (Preview) model structure, with a DSpark speculative decoding module attached."

> "DeepSeek-V4-Pro-0813 outperforms DeepSeek-V4-Pro (Preview) on the benchmarks listed below,
> and is broadly competitive with the strongest proprietary models available."

This is a **post-training update plus a speculative-decoding module**, not a new architecture.
The card states the relationship to the preview explicitly, which is more than DeepSeek said
for the V4.1-Flash `1017` update.

The architecture section present on the preview card (hybrid CSA + HCA attention, mHC, Muon
optimizer, 1.6T total / 49B activated, 32T pre-training tokens) is **absent here**. Those
claims therefore belong to the preview card and are inherited by the GA model by assumption.
The card does not restate them.

## Reasoning effort, chat template, serving

- Verbatim: *"The `reasoning_effort` parameter now supports three levels — `low`, `high`, and
  `max` — which control how much deliberation the model spends before answering."*
- **No Jinja chat template.** Verbatim: *"This release does not include a Jinja-format chat
  template. Instead, we provide a dedicated `encoding` folder with Python scripts and test
  cases demonstrating how to encode messages in OpenAI-compatible format into input strings
  for the model, and how to parse the model's text output."* The example imports
  `encode_messages` / `parse_message_from_completion_text` from `encoding_dsv4`.
- Recommended sampling, verbatim: *"For local deployment, we recommend setting the sampling
  parameters to `temperature = 1.0`, with `top_p = 0.95` for agentic scenarios and `top_p =
  1.0` otherwise. For the `high` and `max` reasoning effort levels, we recommend a maximum
  output length of `384K` tokens."*
- DSpark speculative decoding ships inside the same checkpoint. vLLM:
  `--speculative-config '{"method":"dspark","num_speculative_tokens":7,"draft_sample_method":"greedy"}'`.
  SGLang: `--speculative-algorithm DSPARK`, and verbatim *"do not set a separate
  `--speculative-draft-model-path` as the target and draft weights therefore come from the
  same checkpoint."* The card's vLLM example is sized for "a single 4×GB300 node" with
  `--kv-cache-dtype fp8` and `use_fp4_indexer_cache: true`.

Two things to note about this table:

- **There is no Terminal-Bench 4.0 row**, even though DeepSeek's V4.1-Flash card reports one

  K3.1), Opus-4.8 and Fable-5 are the models DeepSeek chose in August 2026. The V4.1-Flash
  card three weeks later uses a different peer set, so the two cards' tables cannot be merged.

## Gaps

- No release date, no parameter count, no architecture, no training detail, no safety
  evaluation, no latency or throughput figure in the card prose.
- The card does not say what `0813` denotes. It is almost certainly the release date
  (2026-08-13), but the card never says so; that reading comes from the announcement and the
  repository creation timestamp.
- The technical report (arXiv 2606.19348) was not retrieved, so the architecture claims on the
  preview card are that card's summary rather than the paper.
- No statement of whether the DSpark module is separable, or what it costs in memory.
- No vision capability is claimed anywhere on this card; see the
  [API pricing record](../api-pricing/2026-10-26.md) for the explicit "not supported".

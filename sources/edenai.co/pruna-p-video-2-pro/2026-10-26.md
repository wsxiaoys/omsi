The three prices are exactly Pruna's 768p cost/speed/quality rates, so Eden AI has split Pruna's
`mode` parameter into three separately priced model strings, each pinned to the 768p tier.

## Parameter mapping (verbatim)

> `text` (required): text prompt describing the content and style of the video to generate
> `file`: file (images). Initial keyframe image (JPEG or PNG) file ID from /v3/upload or direct file URL
> `video`: file (video). Source video to edit, for models that edit a video (their `requires_video`
> is true in /v3/info). The output keeps the source's length, which is what is billed
> `duration`: number. Length of the generated video in seconds. Omit to use the model's default duration.
> `dimension`: text. Video resolution in 'widthxheight' format (e.g., '1280x720')
> `seed`: number. Random seed for generation reproducibility (0 to 2,147,483,646). Omit for varied output.

The `video` field is described generically for the whole video-generation task ("for models that edit
a video"), not specifically for this model, and the page's "Video input" badge comes from that
generic list. Pruna's own documentation exposes no video input on `p-video-2-pro`.

## Summary

A second independent host, with a different integration model: one Eden AI key, async-only, mode
selected by model string, resolution as a `widthxheight` string, and prices identical to Pruna's
768p list rates. It corroborates the price and the async/per-second billing basis, and its generic
parameter list adds a claim (video input) that the vendor's docs do not support.

## Gaps

- No launch date, no output frame rate, no duration limits stated on the page.
- "Price from $0.035 / s" is the 768p speed rate; the page never says which resolution or mode a
  request actually gets if you omit them.
- The page does not say whether it proxies Pruna or re-hosts.

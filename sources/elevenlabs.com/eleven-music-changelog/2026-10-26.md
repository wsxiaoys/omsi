## Captured content (verbatim)

### 2026-06-15 — Music v2 reaches the API

> Music v2 is now available via the ElevenLabs API. Set `model_id` to `music_v2` on [Generate
> music]…, [Stream music]…, [Generate music detailed]… and [Upload music]… to use the new model.
> Music v2 introduces chunk-based composition plans built from `GenerationChunk` and `AudioRefChunk`
> segments, giving you finer control over structure, pacing and arrangement than the prompt-based
> `music_v1` flow.

> Request and response bodies accept either v1 or v2 plan shapes, so you can migrate endpoint by
> endpoint. `MusicPrompt` remains available for `music_v1` only.

### 2026-06-22 — 48 kHz formats and the v2 auto default

> **Higher-quality output formats**: [Generate music]… add `mp3_48000_240` and `mp3_48000_320` to
> supported `output_format` values. When `output_format` is `auto`, v2 models now default to
> `mp3_48000_192` instead of `mp3_48000_128`.

> **Section duration flag clarification**: `respect_sections_durations` applies only with
> `composition_plan` on `music_v1`. On `music_v2`, section durations are always enforced and this
> flag is ignored.

### 2026-07-20 — Finetunes API

> **Music Finetunes API**: Added API support for managing [Music Finetunes]… Five endpoints let you
> create a Finetune from uploaded audio, list accessible Finetunes, retrieve training status, update
> metadata and visibility, or delete a Finetune. All music generation SDK methods now expose
> `finetune_id`.

### 2026-09-14 — Music v2.5

> **Music v2.5 API support**: Music endpoints and SDKs now accept `music_v2_5`. Composition plan
> generation chunks support up to 6,132 characters, with up to 30 lines of 200 characters each.

> `MusicModelID` adds `music_v2_5` for `POST /v1/music/video-to-music`, `POST /v1/music/plan`,
> [Compose music]…, `POST /v1/music/detailed`, `POST /v1/music/detailed/stream`,
> `POST /v1/music/stream`, `POST /v1/music/upload` and `POST /v1/music/finetunes`.

### 2026-05-25 — generation modes and video-to-music model choice

> **Generation mode**: Added `MusicGenerationMode` (`track`, `loop`, `ambience`) and an optional
> `generation_mode` field on music prompt request bodies.

> **Video to music model**: [Video to music] (`POST /v1/music/video-to-music`) now accepts optional
> `model_id` (string, default `music_v1`).

### 2026-10-19 — Video to Music and Zero Retention

> **Video to Music**: Video to Music writes a soundtrack for your video. The [Video to music] API is
> now available: you upload a video and get back music that fits it, without writing a music prompt
> from scratch.

> `use_audio_as_reference` takes the genre, BPM, instruments and mood from the video's own audio.
> `add_sfx` adds sound effects that match the video. `separate_tracks` returns the music and the
> sound effects as separate files in a ZIP, so you can mix them yourself.

> **Zero Retention Mode**: Music generation, composition plan, stem separation and video to music
> endpoints, plus Sound Effects, accept `enable_logging=false` … Music requests that set
> `store_for_inpainting=true` are rejected in this mode.

The same entry lists the full music endpoint set: "Compose music, Compose detailed, Stream music,
Compose detailed stream, Separate stems, Video to music and `POST /v1/music/plan`".

## What this establishes

- A dated API timeline for the family, all first-party:
  - `music_v1` — API from 2025-08-18 (see the API-launch record).
  - `music_v2` — API from **2026-06-15**, three weeks after the 2026-05-26 announcement that the API
    was "coming soon".
  - `music_v2_5` — API from **2026-09-14**, three days after the 2026-09-11 blog announcement.
- The family is served by more than a single compose endpoint: compose, compose-detailed,
  compose-detailed-stream, stream, upload, plan, separate-stems, video-to-music and finetunes.
- Zero-retention mode covers music, but a request that sets `store_for_inpainting=true` is **rejected**
  in that mode — inpainting and zero retention are mutually exclusive.
- `generation_mode` (`track` / `loop` / `ambience`) was announced in the API schema on 2026-05-25 but
  is absent from the compose reference captured on 2026-10-26; either it was withdrawn or the
  reference omits it.

## Gaps

- The changelog never states the `music_length_ms` ceiling, output sample rates for v1, or prices.
- No entry says when `music_v2` would stop being the default, or when `music_v1` will be deprecated;
  the capabilities FAQ only promises "at least a few months' notice".
- `generation_mode`'s current status is unresolved (announced 2026-05-25, missing from the October
  compose schema).

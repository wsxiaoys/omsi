# ElevenLabs docs: "Stitching multiple requests" — not available for `eleven_v3`

- Origin: ElevenLabs, guide "Stitching multiple requests",
  <https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/request-stitching> (read as
  Markdown via `Accept: text/markdown`)
- Evidence kind: official documentation (API guide)
- Publication date: not stated on page.
- Capture date: 2026-10-26
- Relevant models: `eleven_v3` (excluded), `eleven_v4` (used in the examples)

## Captured content (verbatim)

> Request stitching is not available for the `eleven_v3` model.

The guide's request examples all pass `model_id="eleven_v4"`, using `previous_text` / `next_text` and
`previous_request_ids` / `next_request_ids` to keep prosody continuous across separately generated
chunks.

## What this establishes

- **v3 cannot use request stitching.** A long-form v3 pipeline cannot inherit prosody across requests
  through the documented mechanism; each 5,000-character request is generated without that context.
- The capability is documented as present for v4 in the same guide, so stitching is a v4-era addition
  that v3 does not get, despite the shared endpoint exposing the fields.
- This is a first-party statement and it is the only explicit per-model field exclusion found in the
  corpus.

## Gaps

- The page does not say *why* (architecture, training, or rollout) and does not say whether the
  endpoint silently ignores the fields or rejects them.
- No statement about the status of the older models (Multilingual v2, Flash, Turbo) with respect to
  stitching.
- No date, so it cannot be established whether v3 ever supported stitching before or after GA.

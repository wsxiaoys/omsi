  <https://elevenlabs.io/docs/api-reference/text-to-speech/convert> (read as Markdown via
  `Accept: text/markdown`)
- Evidence kind: official documentation (API reference)
- Publication date: not stated on page.
- Capture date: 2026-10-26
- Relevant models: all Text to Speech models, including `eleven_v3`; the reference does not carry
  per-model notes, so anything here is the shared endpoint contract

## Captured content (verbatim)

### Output format (query parameter)

> `output_format` (enum, optional, default: mp3_44100_128) — Output format of the generated audio.
> Formatted as codec_sample_rate_bitrate. So an mp3 with 22.05kHz sample rate at 32kbs is represented
> as mp3_22050_32. MP3 with 192kbps bitrate requires you to be subscribed to Creator tier or above.
> PCM and WAV formats with 44.1kHz sample rate requires you to be subscribed to Pro tier or above.
> Note that the μ-law format (sometimes written mu-law, often approximated as u-law) is commonly used
> for Twilio audio inputs.

Allowed values (28):

`alaw_8000`, `mp3_22050_32`, `mp3_24000_48`, `mp3_44100_128`, `mp3_44100_192`, `mp3_44100_32`,
`mp3_44100_64`, `mp3_44100_96`, `opus_48000_128`, `opus_48000_192`, `opus_48000_32`,
`opus_48000_64`, `opus_48000_96`, `pcm_16000`, `pcm_22050`, `pcm_24000`, `pcm_32000`, `pcm_44100`,
`pcm_48000`, `pcm_8000`, `ulaw_8000`, `wav_16000`, `wav_22050`, `wav_24000`, `wav_32000`,
`wav_44100`, `wav_48000`, `wav_8000`

Top sample rate across the enum is **48 kHz** (`pcm_48000`, `wav_48000`, `opus_48000_*`); the highest
MP3 is 44.1 kHz at 192 kbps.

### Model selection and body fields

> `model_id` (string, optional, default: eleven_multilingual_v2) — Identifier of the model that will
> be used, you can query them using GET /v1/models. The model needs to have support for text to
> speech, you can check this using the can_do_text_to_speech property.

> `language_code` (string, optional, nullable) — Language code (ISO 639-1) used to enforce a language
> for the model and text normalization. If the model does not support the provided language code, it
> will be ignored. This parameter is not supported for multilingual_v2 models.

> `seed` (integer, optional, nullable) — If specified, our system will make a best effort to sample
> deterministically, such that repeated requests with the same seed and parameters should return the
> same result. Determinism is not guaranteed. Must be integer between 0 and 4294967295.

> `previous_text` … `next_text` … `previous_request_ids` … `next_request_ids` — request-stitching
> context fields, with "A maximum of 3 request_ids" for each of the id lists.

> `use_pvc_as_ivc` (boolean, optional, nullable) — Whether to use the IVC version of a professional
> voice. This may improve expressiveness and reduce latency.

> `apply_text_normalization` (enum, optional, default: auto) — 'auto', 'on', 'off'.

> `apply_language_text_normalization` (boolean, optional, default: false) — … "Currently only
> supported for Japanese."

> `audio_effects` — "Reverb … and a non-zero `pan` produce stereo audio and are rejected with 400 for
> `ulaw_*`, `alaw_*`, and `pcm_*` output formats. Effects don't change the cost of the request."

Voice settings object:

> `stability` (default 0.5), `use_speaker_boost` (default true), `similarity_boost` (default 0.75),
> `style` (default 0), `speed` (default 1).

> `enable_logging` (boolean, optional, default: true) — When enable_logging is set to false zero
> retention mode will be used for the request. This will mean history features are unavailable for
> this request, including request stitching. Zero retention mode may only be used by enterprise
> customers.

## What this establishes

- The shared TTS endpoint exposes **28 output-format values** and a **48 kHz** maximum sample rate,
  with `mp3_44100_128` as the default. Higher-bitrate MP3 and 44.1 kHz+ PCM/WAV are plan-gated.
- The **default `model_id` on the TTS endpoint is still `eleven_multilingual_v2`**, not v3 or v4, so a
  caller who omits `model_id` never gets v3.
- `seed` is documented as "best effort … Determinism is not guaranteed", and stitching context fields
  are listed without any per-model exclusion here — the exclusion for v3 lives in a separate guide
  (`../eleven-v3-request-stitching/2026-10-26.md`).
- The reference is model-agnostic: **it does not state which formats, settings or fields v3 supports**.
  Every format claim about v3 is therefore an inference from a shared contract, not a v3-specific
  statement.

## Gaps

- No per-model capability matrix: nothing says whether v3 honours `style`, `speed`,
  `use_speaker_boost`, `audio_effects`, `seed` or `apply_language_text_normalization`.
- No statement that v3 output is watermarked (the watermarking policy page is separate and generic).
- No documented hard duration cap; duration is bounded only by the model's character limit.

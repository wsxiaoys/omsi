## Captured content

### `POST /v1/text-to-speech/{voice_id}` — parameters relevant to v4

- `model_id` (string, optional, **default `eleven_multilingual_v2`**) — "Identifier of the model that
  will be used, you can query them using GET /v1/models."
- `output_format` (enum, optional, default `mp3_44100_128`) — 28 allowed values:
  `alaw_8000`, `mp3_22050_32`, `mp3_24000_48`, `mp3_44100_128`, `mp3_44100_192`, `mp3_44100_32`,
  `mp3_44100_64`, `mp3_44100_96`, `opus_48000_128`, `opus_48000_192`, `opus_48000_32`,
  `opus_48000_64`, `opus_48000_96`, `pcm_16000`, `pcm_22050`, `pcm_24000`, `pcm_32000`,
  `pcm_44100`, `pcm_48000`, `pcm_8000`, `ulaw_8000`, `wav_16000`, `wav_22050`, `wav_24000`,
  `wav_32000`, `wav_44100`, `wav_48000`, `wav_8000`. So the **top sample rate is 48 kHz** and the
  default is 44.1 kHz MP3 at 128 kbps.
- `language_code` (ISO 639-1) — "If the model does not support the provided language code, it will be
  ignored. This parameter is not supported for multilingual_v2 models."
- `seed` (0–4294967295) — "best effort to sample deterministically… Determinism is not guaranteed."
- `previous_text` / `next_text` / `previous_request_ids` / `next_request_ids` — continuity controls
  for stitching a long script across requests; max 3 request IDs.
- `use_pvc_as_ivc` — "Whether to use the IVC version of a professional voice. This may improve
  expressiveness and reduce latency."
- `apply_text_normalization` — `auto` / `on` / `off`.
- `audio_effects` — scene/room effects; "Effects don't change the cost of the request." Reverb and
  pan produce stereo and are rejected for `ulaw_*`/`alaw_*`/`pcm_*` outputs.
- `enable_logging=false` — zero retention mode, Enterprise only.
- Servers: `api.elevenlabs.io`, plus US, EU (Ireland), India and Singapore residency hosts.

`voice_settings` includes `stability` (default 0.5), `similarity_boost` (default 0.75),
`use_speaker_boost` (default true), `style` (default 0), `speed` (default 1) and:

> `clone_strength` (double, optional, nullable) — Controls how closely the voice matches the
> professional voice clone samples, from 0 (low) to 1 (high). […] Only applies to professional voice
> clones fine-tuned for the selected v4 model.

That `clone_strength` note is the only place the Text to Speech API reference acknowledges v4.

### The guide's own v4 TTS example (verbatim)

```python
client = ElevenLabs()
audio = client.text_to_speech.convert(
    voice_id="21m00Tcm4TlvDq8ikWAM",
    text='The term "/ˌbaɪoʊˈkemɪstri/" refers to the study of chemical processes.',
    model_id="eleven_v4",
)
```

So despite the changelog naming Text to Dialogue as the v4 path, ElevenLabs' own prompting guide calls
`eleven_v4` through the single-voice Text to Speech endpoint.

### IPA pronunciation (verbatim)

> Eleven v4 (`eleven_v4`) includes improved native support for the International Phonetic Alphabet, or
> IPA, giving you more precise control over pronunciation for names, technical terms, and other words
> that need special handling. IPA pronunciation is more consistent than in previous models, but
> results can still vary by voice and phrase.

Syntax: wrap the transcription in forward slashes — `"/IPA_transcription/"` — "Written using standard
IPA symbols", and "Wrapped in double quotes when passed as a string parameter".

### Tags and SSML (verbatim)

> Eleven v4 and Eleven v3 do not support SSML break tags. Use audio tags, punctuation (ellipses), and
> text structure to control pauses and pacing.

> Because Eleven v4 is trained to generate both vocal delivery styles and sound effects, a tag can
> occasionally be interpreted as a request for a sound effect rather than a delivery instruction (or
> vice versa).

> Tags land more readily when the delivery is already in the voice's training data. Eleven v4 can
> still follow a tag the voice was not trained on, such as `[whispering]` or `[shouting]`, though the
> result may not be optimal.

Tag categories listed: voice-related (`[laughs]`, `[whispers]`, `[sighs]`, `[sarcastic]`,
`[curious]`, `[excited]`, `[crying]`…), sound effects (`[gunshot]`, `[applause]`, `[explosion]`,
`[swallows]`…), and "experimental" tags including `[strong X accent]`, `[sings]`, `[woo]`, `[fart]`
with the warning "Some experimental tags may be less consistent across different voices."

Punctuation behaviour: "Ellipses (...) add pauses and weight", "Capitalization increases emphasis".

## What this establishes

- The single-voice endpoint accepts `eleven_v4` in the vendor's own sample code, and its
  `voice_settings` schema carries a v4-only parameter. The "v4 is Text to Dialogue only" framing in
  the changelog is a recommendation, not an access restriction.
- Output formats and sample rates are documented at the endpoint level and are shared across models:
  MP3 22.05–44.1 kHz at 32–192 kbps, PCM/WAV 8–48 kHz, Opus 48 kHz, μ-law/A-law 8 kHz. Default
  `mp3_44100_128`.
- IPA-in-forward-slashes and bracketed audio tags are v4's two inline control surfaces; SSML is out.
- Continuity for long scripts is handled by `previous_text`/`next_text` and request-ID chaining, which
  is how the landing page's "stitch long-form audio without the seams" claim is implemented.

## Gaps

- The reference does not say whether `eleven_v4_turbo` is callable through this HTTP endpoint; the
  changelog routes Turbo to the Text to Dialogue WebSocket.
- No per-model character limit is stated on the API reference; the limit lives on the models page.
- No statement of whether IPA or audio tags affect billing (tags are billed as characters by the
  hosts, per their records).

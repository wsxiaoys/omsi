# ElevenLabs docs: Text to Dialogue (the vendor's launch path for Eleven v4)

- Origin: ElevenLabs, "Text to Dialogue",
  <https://elevenlabs.io/docs/overview/capabilities/text-to-dialogue> (read as Markdown via
  `Accept: text/markdown`)
- Evidence kind: official documentation
- Publication date: not stated on page; the changelog dates Eleven v4 availability to 2026-09-28
  (`../eleven-v4-changelog/2026-10-26.md`). Capture date 2026-10-26
- Relevant models: `eleven_v4`, `eleven_v4_turbo`, `eleven_v3`

## Captured content (verbatim, selected)

### Scope

> The ElevenLabs [Text to Dialogue](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert) API creates natural
> sounding expressive dialogue from text using [Eleven v4](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/eleven-v4)
> and Eleven v3. We recommend Eleven v4.

> Several generations might be required to achieve the desired results.

### Speaker and size limits

> There is no limit to the number of speakers in a dialogue.

> Keep the total length of all `inputs[].text` values at or below 2,000 characters per request for
> reliable generation. Split longer text into chunks and concatenate the resulting audio in your
> application.

The API reference for `POST /v1/text-to-dialogue` restates this: "For reliable generation, keep the
total character count across all `inputs[].text` values at or below 2,000 characters per request.
Longer requests can terminate early in streaming responses or return a validation error", and adds
"The maximum number of unique voice IDs is 10".

### Output formats (verbatim)

> The default response format is `mp3`, but other formats like `pcm` and `ulaw` are available.
>
> * **MP3** — Sample rates: 22.05kHz - 44.1kHz; Bitrates: 32kbps - 192kbps; 22.05kHz @ 32kbps;
>   44.1kHz @ 32kbps, 64kbps, 96kbps, 128kbps, 192kbps
> * **PCM (S16LE)** — Sample rates: 16kHz - 44.1kHz; Bitrates: 8kHz, 16kHz, 22.05kHz, 24kHz, 44.1kHz,
>   48kHz; 16-bit depth
> * **μ-law** — 8kHz sample rate; Optimized for telephony applications
> * **A-law** — 8kHz sample rate; Optimized for telephony applications
> * **Opus** — Sample rate: 48kHz; Bitrates: 32kbps - 192kbps

> Higher quality audio options are only available on paid tiers

(The "Bitrates" line for PCM repeats the sample-rate list — an error in the vendor page, quoted as
served.)

### Ownership and commercial terms (verbatim FAQ)

> **Do I own the audio output?** Yes. You retain ownership of any audio you generate. However,
> commercial usage rights are only available with paid plans. With a paid subscription, you may use
> generated audio for commercial purposes and monetize the outputs if you own the IP rights to the
> input content.

### Determinism and free regenerations (verbatim)

> The models are nondeterministic. For consistency, use the optional seed parameter, though subtle
> differences may still occur.

> * Only available within the ElevenLabs dashboard.
> * You can regenerate each piece of content up to 2 times for free.
> * The content must be exactly the same as the previous generation.

### Audio tags (verbatim)

> Eleven v4 and Eleven v3 allow the use of non-speech audio events to influence the delivery of the
> dialogue. This is done by inserting the audio events into the text input wrapped in square brackets.

> Audio tags are natural-language instructions, not an enum parameter.

Three tag families are listed: emotions/delivery (`[sad]`, `[laughing]`, `[whispering]`), audio events
(`[leaves rustling]`, `[gentle footsteps]`, `[applause]`) and overall direction (`[football]`,
`[wrestling match]`, `[auctioneer]`). The feature carries the warning "This feature is still under
active development, actual results may vary."

### Voice sources (verbatim)

> * Voice library with 10,000+ community-shared voices
> * Professional voice cloning for highest-fidelity replicas
> * Instant voice cloning for quick voice replication
> * Voice design to generate custom voices from text descriptions

### Audio effects

`audio_effects` places the whole dialogue in a scene ("a phone call, a café or a large hall"); the
page says "Dialogue effects are available through the API only."

## What this establishes

- On the vendor's own preferred path, the practical per-request ceiling is **2,000 characters of
  total dialogue text**, not the 10,000-character single-voice limit — an order of magnitude apart
  from what the models page advertises for `eleven_v4`. Both are first-party and neither page
  mentions the other's number.
- Up to 10 distinct voice IDs per dialogue request; no limit on speakers (voices may repeat).
- Output is MP3/PCM/μ-law/A-law/Opus at 8–48 kHz; 44.1 kHz PCM/WAV is plan-gated.
- Commercial use requires a paid plan, and output ownership is retained by the user, conditional on
  owning the input IP rights. That is the clearest first-party commercial-terms statement captured.

## Gaps

- No stated maximum audio duration; the 2,000-character guidance is a reliability heuristic, not a
  hard limit.
- No watermark statement on this page (see `../eleven-v4-watermarking/2026-10-26.md`).
- No pricing specific to the Text to Dialogue endpoint.
- No statement about whether Text to Dialogue and the single-voice TTS endpoint produce the same
  audio for the same text and voice.

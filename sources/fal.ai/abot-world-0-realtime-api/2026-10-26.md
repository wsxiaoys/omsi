  - `GET https://fal.ai/api/apps/fal-ai/abot-world-0/asyncapi.json`
- Evidence kind: provider API documentation and schema (independent host record)
- Publication date: endpoint `date` 2026-10-15; contract `version: "1.0.0"`, `updated_at` 2026-10-18
- Capture date: 2026-10-26

## It is not a request/response model

`llms.txt`, verbatim:

> This endpoint publishes a WMA WebRTC contract. Open it with `fal.realtime.open`; do **not** call the
> session endpoint with `fal.run`, `fal.subscribe`, or the Queue API.
>
> The browser negotiates through fal and then exchanges media with the model over WebRTC.

The OpenAPI document still exists but only describes session *negotiation*: its
`x-fal-metadata.about` is "Start Session", and its single input schema `AbotWorld0Input` is described
as "Offer forwarded by the WMA bridge" with required field `sdp` plus optional `type: "offer"`,
`ice_servers`, `session_id`, `ice_status` and `credential_age_seconds`. `AbotWorld0Output` is an empty
object. The AsyncAPI document titles the contract "ABotWorld0 realtime client API" and declares one
server: "Runtime-assigned WebRTC peer negotiated over HTTP."

The client is **alpha**: "Experimental realtime API `fal.realtime.open` is currently available on the
alpha release and may change in a minor version." Install line:
`npm install @fal-ai/client@alpha @fal-ai/server-proxy@alpha`.

## Media contract (verbatim)

> Tracks are described from the browser's perspective.
>
> ### Browser sends to the model
> None.
>
> ### Browser receives from the model
> - `video` — optional
>   - Settings: `{"frameRate":16,"height":704,"width":1280}`

So the negotiated receive track is **1280 × 704 at 16 fps**, and the browser uploads no media at all —
only JSON control messages. There is **no audio track** in either direction.

704 is not 720: 1280 × 704 is a 1.818:1 frame, while the paper and the vendor's own copy say "720P".
Both can be true if the model is trained at 720p and fal's session crops or pads to a fixed 1280 × 704
track, but no captured page says so.

## Client → model messages

| Type | Payload | Notes (verbatim where quoted) |
| --- | --- | --- |
| `commands` | `active[]`, `activated[]`, max 8 items each | Values: `"forward"`, `"left"`, `"backward"`, `"right"`, `"look_up"`, `"look_left"`, `"look_down"`, `"look_right"`. "`active` contains commands currently held by the user and `activated` contains edge-triggered commands since the previous report. A browser may map a keyboard, gamepad, touch control, or agent action to these names." |
| `configure` | `preset` (≤100 chars), `prompt` (≤2000), `image_url` (≤4096) | "Optionally replace the automatic default world, once per connection. … Image URL takes precedence over the preset." |
| `prompt` | `prompt` (1–2000 chars) | "Change the scene's description while continuing this world." |
| `reset` | same fields as `configure` | "Use `reset` for subsequent restarts." |
| `keys` | `pressed[]`, `activated[]`, max 32 items each | "Legacy physical-key report retained for existing WMA clients." |
| `ping` | `ts` | "Latency probe; the server echoes `ts` back in a `pong` payload." |
| `stop` | — | Ends the session. |

## Model → client messages

`configured`, `prompt_applied`, `reset_applied`, `error` (`error`, `retryable`), `pong` (`ts`,
`server_ts`, `client_ts`), `stats`, `session_info`, `stream_exhausted`.

`session_info` is the only place the running model is identified:

| Field | Type |
| --- | --- |
| `model_id`, `model_revision` | `string` |
| `resolution` | `{height, width}` |
| `frames_per_second`, `frames_per_block` | `number`, `integer` |
| `max_blocks` | `integer` |
| `default_prompt`, `turn_status`, `turn`, `key_order`, `conflict_groups`, `presets[]` | — |

`stats` exposes runtime telemetry: `gpu_wait_frac`, `block_index`, `block_seconds`, `queue_depth`,
`queue_age_ms_p50`, `queue_age_ms_max`, `pace_sleep_ms_avg`, `generation_fps`.

`stream_exhausted`, verbatim:

> The model has no more frames to send and the current peer is closing. Clients must negotiate a new
> session to continue.

## Session flow (verbatim)

> This world starts automatically. Wait for the first video frame before using the movement controls.
>
> Send `commands` with held controls in `active` and newly pressed controls in `activated`. Send empty
> arrays when controls are released or focus leaves the world.
>
> - Send `configure` and wait for `configured` before sending another world update. Setup is optional
>   and can be used once per session.
> - Send `reset` and wait for `reset_applied` before sending another world update.
> - Send `prompt` and wait for `prompt_applied` before sending another world update.
>
> World updates run one at a time and must not be replayed automatically. A `error` event is diagnostic
> and does not identify a failed update; read `/error` for details. The session ends on
> `stream_exhausted`.

## What this establishes

- The hosted form of this model is an **interactive environment**, not a video generator: there is no
  prompt-to-mp4 call, no duration field, no frame count, and no downloadable artifact in the schema.
  The only output is a live video track.
- The control surface is exactly the model's native one — eight discrete movement/look commands —
  exposed over JSON rather than keyboard state, so an agent can drive it.
- Sessions are **bounded by the server**: `max_blocks` × `frames_per_block` is finite, and continuation
  requires a new session. "Infinite rollout" is the model property, not a guarantee about a single
  hosted session.
- Scene authorship on fal is: a preset name, or an image URL, or (with `prompt`) a re-described scene,
  replaceable once per connection and then mutable mid-session.

## Gaps

- `max_blocks`, `frames_per_block`, `model_id` and `model_revision` are runtime values with no captured
  example payload, so the real session ceiling and the exact checkpoint fal runs are both unknown.
- No rate limits, concurrency caps, region list, or failure-rate documentation.
- No moderation, content-policy, or refusal documentation, despite an `image_url` input that accepts
  arbitrary user images.
- The `error`/`/error` wording implies a separate error channel that is not otherwise documented.

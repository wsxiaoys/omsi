`hostingType: "serverless"` is fal's marker for running the model itself, in contrast to the `proxy`
marker fal uses for Seedance (forwarded to the vendor). fal's row therefore claims to serve the model
rather than forward to Creatify's API.

`GET /api/models?keywords=creatify` returns exactly two fal endpoints: `fal-ai/creatify/aurora` (2025-12-11)
and `creatify/boreal` (2026-09-15, Creatify's general video model). There is no `aurora-v2`, `aurora-fast`
or `aurora-1.0` endpoint on fal.

## Pricing (verbatim, from `pricingInfoOverride` and the model page)

> Your request will cost **$0.07** per video second for **480p**, **$0.14** per video second for **720p**
> generation. Video seconds will be **rounded upwards**, meaning that a generation with an output video of
> 9.4 seconds will be billed as a 10 second video.

## Input schema (transcribed from `CreatifyAuroraInput`)

| Property | Type / default | Description |
| --- | --- | --- |
| `image_url` | string, **required** | "The URL of the image file to be used for video generation." |
| `audio_url` | string, **required** | "The URL of the audio file to be used for video generation." |
| `prompt` | string \| null | "A text prompt to guide the video generation process." |
| `guidance_scale` | 0–5, default 1 | "Guidance scale to be used for text prompt adherence." |
| `audio_guidance_scale` | 0–5, default 2 | "Guidance scale to be used for audio adherence." |
| `resolution` | `480p` \| `720p`, default `720p` | "The resolution of the generated video." |
| `enable_safety_checker` | boolean, default true | "Authorized callers may set false to request relaxed screening." |

Output: `{ "video": VideoFile }` with `url`, `content_type`, `file_name`, and optional `width`, `height`,
`fps`, `duration`, `num_frames`, `file_size`. Example output `content_type` is `video/mp4`.

The playground accepts more image types than Creatify's own docs — "jpg, jpeg, png, webp, gif, avif, heic,
heif" for the image and "mp3, ogg, wav, m4a, aac" for the audio — and exposes no duration or file-size
limit.

The model page carries a "**Partner**" badge and a "**Commercial use**" label.

## Summary

fal hosts one Aurora endpoint, created 2025-12-11, with a two-setting resolution switch and two guidance
scales. There is no `model_version`, no duration cap, and no aspect-ratio control: length follows the
audio, and frame geometry is whatever the pipeline derives from the still.

**Price contradiction with the vendor:** Creatify's 2026-02-09 integration post quotes "$0.10 per second at
480p or $0.14 per second at 720p"; fal's live catalogue says **$0.07** at 480p. The 720p prices agree. The
host's catalogue is the later statement, but nothing explains the change.

**Likely mapping to the vendor's tiers (inference, not stated):** fal's two prices match Runware's two
models exactly — $0.14/s for `creatify:aurora@0` (Aurora 1.0) and $0.07/s for `creatify:aurora@fast`
(Aurora 1.0 Fast) — and Creatify prices 1.0 at 1 credit/s and 1.0 Fast at 0.5 credit/s. That is consistent
with fal's `resolution` parameter selecting the 1.0 Fast pipeline at 480p and the 1.0 pipeline at 720p. No
captured source says so, and fal never names a version.

## Gaps

- No model version, checkpoint, or vendor model ID on the endpoint; a caller cannot tell 1.0 from 1.0 Fast
  except by price.
- No documented maximum audio length, image size, or file-size limits, although Creatify's own API caps
  audio at 5 minutes and images at 30 MB (Aurora 2.0 only).
- `enable_safety_checker` says "Authorized callers may set false" but no page says who is authorized or
  what the screen blocks.
- No latency, throughput, region, or uptime statement.
- No statement on output ownership or commercial terms beyond the "Commercial use" badge.
- The endpoint has not been updated for Aurora 2.0; no 1080p/2k setting exists on fal.

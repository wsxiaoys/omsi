## Input schema (`Lucy2VtonRealtimeInput`)

Schema description, verbatim:

> Input model for the Lucy 2 RT signaling proxy. Uses `extra="allow"` so WebRTC signaling messages
> (`{type: "offer", sdp: ...}`) pass validation alongside application messages. The schema exposes
> `prompt`, `image_url`, and `reference_image_url` for playground form rendering.

| Field | Type | Default | Description (verbatim) |
| --- | --- | --- | --- |
| `prompt` | string | `"Substitute the current top with the outfit from the reference image, matching its color, material, and fit"` | "Text prompt for the real-time transformation." |
| `image_url` | string | `""` | "Image data URI or HTTP(S) URL for realtime frame input. Data URI format: `data:image/<type>;base64,...`" |
| `reference_image_url` | string \| null | a fal CDN PNG | "Reference image URL or data URI. When set, Lucy 2 will use this as a character reference for the transformation." |

`additionalProperties: true` — the endpoint accepts WebRTC signaling messages (`offer`, `answer`,
`icecandidate`, `ice-restart`) alongside application messages. Output schema is an open object
(`Lucy2VtonRealtimeOutput`, `additionalProperties: true`).

## Page documentation (verbatim excerpts)

> Lucy 2.1 Virtual Try On is a real-time virtual try-on model — it transforms your live webcam feed
> using a text prompt and/or reference garment image over a WebRTC connection.

Client usage:

```js
const connection = fal.realtime.connect("decart/lucy2-vton/realtime", {
  connectionKey: `session-${Date.now()}`,
  throttleInterval: 0,
  onResult: handleResult,
  onError: (err) => console.error(err),
});
connection.send({
  prompt: "Substitute the current top with a bright red hoodie with an oversized casual fit",
  reference_image_url: "https://example.com/outfit.png", // optional
});
```

Mid-session updates: `connection.send({ prompt: "…", enhance_prompt: true })` and
`connection.send({ reference_image_url: "…", prompt: "…" })`. Server messages handled by the client
include `iceservers`, `answer`, `icecandidate`, `ice-restart`, `prompt_ack`, `set_image_ack`,
`generation_started`, `error`.

## Pricing

"$0.02 per second" with no unit qualifier beyond seconds. fal does not state whether the billed
second is wall-clock session time or active generation time; Decart's own schedule bills "per second
of active generation". fal publishes no fast-mode option for this endpoint.

## Gaps

- fal states no frame rate, no output resolution, no latency figure and no duration/session limit.
- fal does not say whether it runs the model or proxies Decart. `hostingType: "serverless"` plus the
  schema's "signaling proxy" language point in opposite directions.
- `updated_at` 2026-08-26 is later than Decart's June 2026 retirement of `lucy-2.1-vton`; fal gives
  no changelog for what that update changed.
- No fal page maps `decart/lucy2-vton/realtime` to a first-party Decart model ID.

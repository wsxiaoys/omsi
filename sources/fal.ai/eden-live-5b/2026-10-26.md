## The roster's `vast/eden-live-5b` is a family prefix, not a callable endpoint

`GET https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=vast/eden-live-5b` returns **HTTP 404**
with the body `null`. The same request for `vast/eden-live-5b-video` and `vast/eden-live-5b-game`
returns HTTP 200 and a full schema. `https://fal.ai/models/vast/eden-live-5b` resolves as a
client-side page that displays the id `vast/eden-live-5b`, so the roster string names fal's Eden Live
5B group (both variants), not a route.

## Pricing, verbatim

- 5B, both variants: "Sessions cost $0.0035 per second of video generated, with a minimum of 10 billable
  seconds ($0.035) per session." `minimumUnits: 10`.
- 14B, both variants: "Sessions cost $0.01 per second of video generated, with a minimum of 10 billable
  seconds ($0.10) per session." `minimumUnits: 10`.

The 14B therefore costs 2.86× the 5B per generated second.

## Input schema — identical on all four endpoints

`EdenLive5bVideoInput` / `EdenLive5bGameInput` (schema title `StartSessionRequest`), verbatim:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `sdp` | string | yes | — |
| `type` | string, const `"offer"` | no, default `"offer"` | — |
| `session_id` | string or null | no | — |
| `ice_servers` | array of objects | no | — |
| `ice_status` | string or null | no | — |
| `credential_age_seconds` | number ≥ 0 or null | no | — |

Schema description, verbatim: **"Offer forwarded by the WMA bridge."** `x-fal-metadata.about` reads
"Start Session", and the only documented paths are `POST /vast/eden-live-5b-video`, its
`/requests/{request_id}` result, `/status` and `/cancel`.

There is no prompt, image, video-URL or duration field anywhere in the schema. These are **WebRTC
session endpoints**: the caller posts an SDP offer and negotiates a live stream, so the model
parameters (reference frames, first frame, prompt) are carried inside the session rather than in the
queue request. fal's public real-time documentation describes a *WebSocket* path
(`fal.realtime.connect()`), not this WebRTC bridge, and no public fal page documents the WMA bridge or
a client for it was found.

## Summary

fal is the roster's discovery path and the host record for Eden Live 5B. It splits VAST's single model
into four products on two axes: size (5B / 14B) and source (arbitrary reference video / fal-hosted
games). Billing is per second of generated video with a 10-second floor — a different basis from
Reactor's per-second wall-clock session billing. Nothing on fal measures quality or latency, and the
catalogue copy is VAST's own phrasing, so fal satisfies the "independent host record" requirement as a
*listing and schema*, not as a measurement.

## Gaps

- fal documents no client, session protocol, maximum session length, output resolution, or frame rate
  for these endpoints; the SDP schema is the only first-hand evidence that they are live sessions.
- The difference between the `-video` and `-game` variants is stated only in one-line descriptions and
  a category label (`video-to-video` vs `worlds`); fal does not say whether the game variant supplies
  the games, the game engine, or both.
- No latency, FPS or quality figure, no region list, and no content-policy statement for these
  endpoints.
- Model page prose is client-rendered: the HTML at capture contained only loading skeletons, so the
  playground's own copy could not be read.

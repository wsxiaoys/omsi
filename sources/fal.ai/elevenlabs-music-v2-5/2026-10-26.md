## Input schema (verbatim, from the queue OpenAPI)

- `prompt` (string, nullable, `maxLength` 4100) — "The text prompt describing the music to generate"
- `composition_plan` (`MusicV2CompositionPlan`, nullable) — "The chunk-based composition plan for the
  music"; `chunks[]` has `minItems: 1`, `maxItems: 30`, "totalling between 3000ms and 600000ms"
- `music_length_ms` (integer, 3000–600000, nullable) — same wording as the vendor schema
- `force_instrumental` (boolean, default `false`)
- `seed` (integer, nullable) — "Can only be used with composition_plan. The same seed with the same
  parameters gives more consistent results, but exact reproducibility is not guaranteed."
- `output_format` (enum, default `"mp3_48000_192"`) — 24 values including `mp3_48000_128/192/240/320`
  and `mp3_24000_48`, `pcm_32000`

`MusicGenerationChunk`: `text` (section name in `[brackets]`, inline directions in `{braces}`, ≤ 30
lines of ≤ 200 chars), `duration_ms` (3000–120000), `positive_styles[]`, `negative_styles[]`,
`context_adherence` (`low`/`medium`/`high`), `audio_reference`.

`MusicAudioReference`: `audio_url`, `start_ms` (default 0), `end_ms`, `strength`
(`low`/`medium`/`high`/`xhigh`), with the note "The window must be at most 30000ms long."

The schema carries fal's own explanation of the version split (verbatim):

> The v2 models replaced v1's ``sections`` (``MusicPrompt``) with ``chunks`` (``CompositionPlan``)

and of how audio references are proxied:

> ElevenLabs conditions on a *song id*, which only exists after the clip has been uploaded to them, so
> the app uploads on the caller's behalf and caches the resulting id

## What this establishes

- fal exposes v2 and v2.5 as **separate endpoints**, and its schema is the current v2 shape: chunked
  composition plans, 48 kHz/192 kbps default output, `seed` with a plan, and an audio reference with
  a ≤ 30 s window and four strength levels.
- **fal charges the same $0.60 per output minute for v2.5 as for v1** — 4× the vendor's $0.15/min —
  and rounds partial minutes up. Model choice does not change fal's price even though the vendor
  charges the same rate for all three model IDs.
- `audio_reference` is exposed as a URL plus a millisecond window, which is a fal-side abstraction:
  the vendor's own API takes a `song_id` from a prior upload, so fal uploads on the caller's behalf.
  That means reference-based generation through fal depends on fal's cache of uploaded songs.
- No `finetune_id` and no `sign_with_c2pa` on the fal surface; C2PA signing is unavailable through
  this host as documented.
- The 3 s – 10 min bound is identical to the vendor API schema.

## Gaps

- No statement of whether `elevenlabs/music/v2.5` and `elevenlabs/music/v2` will be kept in step with
  vendor revisions, or which revision is proxied at any date.
- Whether the ElevenLabs inaudible watermark survives on fal output is unstated; no test was run.
- No latency, throughput or queue-priority figures for music.
- `prompt` `maxLength` 4100 is fal's own bound; the vendor's compose reference publishes no prompt
  length limit, so the two cannot be reconciled from documentation.

### Output schema

`ElevenlabsTtsMultilingualV2Output` = `{ audio: File, timestamps: array|null }`. The documented
example output URL ends in `_output.mp3`. No output-format control is exposed, so the returned codec
and sample rate are not selectable through this endpoint as documented.

## What this establishes

- The roster label for this row is **correct as written**: `fal-ai/elevenlabs/tts/multilingual-v2`
  resolves to a full catalogue record. That is the opposite of the v4 row, where the roster's
  `fal-ai/elevenlabs/tts/eleven-v4` form returns a bare ID with no record.
- fal charges **$0.10 per 1,000 characters** for this model — 25% above ElevenLabs' own $0.08 list
  price for Multilingual v2, and 25% above what fal itself charges for the newer Eleven v4 ($0.08).
  The endpoint is a proxied partner API, so the markup is fal's, not a different model.
- fal's 2025-02-27 catalogue date is the **listing** date, not a launch date. It is itself before the
  roster's 2025-10-26 window, which independently confirms this row is an out-of-window retention.
- fal exposes the **style and speed sliders** for Multilingual v2 — controls that Eleven v4 dropped —
  so through fal the older model has a control surface the flagship does not.
- fal exposes `language_code` for this model, which the vendor's own API reference says is *not
  supported* for `multilingual_v2`. fal's description also promises an error for unsupported codes,
  while the vendor says unsupported codes are ignored.
- fal exposes no `output_format`, no `seed`, and no voice-ID field: cloned voices in the caller's
  ElevenLabs workspace are not reachable through this schema as documented, and reproducibility
  controls are absent.

## Gaps

- No `maxLength` on `text` means fal's schema does not state a character ceiling; the vendor's 10,000
  is unconfirmed on this route and the endpoint was not called, so the effective limit is unknown.
- No statement about watermarking on the fal route.
- No ElevenLabs checkpoint or revision in the catalogue, so the served v2 revision is unknown.
- `date` and `publishedAt` are identical and land exactly on midnight UTC, which suggests a curated
  or backfilled timestamp; fal does not document what `date` means.
- The endpoint's runtime config (machine type, concurrency, regions) was not captured for this
  record; only the v4 record has it.
- Whether `language_code` actually errors, is ignored, or works on this route was not tested.

## Identity note: fal also serves this model under `fal-ai/flux-2`

Two separate fal pages describe the same weights. `https://fal.ai/models/fal-ai/flux-2/llms.txt`
returns:

> # FLUX 2
> Text-to-image generation with FLUX.2 [dev] from Black Forest Labs. Enhanced realism, crisper
> text generation, and native editing capabilities.

with the same `$0.012` per-megapixel price, `category: text-to-image`, and an input schema
identical in defaults to `fal-ai/flux-2-dev`. The `flux-2-dev` IDs carry no prose description
beyond the generic "Flux 2 Dev API endpoint", `category: unknown`, and — unlike `fal-ai/flux-2` —
**do not appear in fal's public model search** (`GET https://fal.ai/api/models?keywords=flux-2-dev`
returned 15 items, none of them `fal-ai/flux-2-dev`). The endpoints are callable and their
OpenAPI schemas resolve, so this is an indexing/metadata gap rather than a dead endpoint.

Practical consequence for a reader: on fal, the product named "FLUX 2" is FLUX.2 [dev]. The
hosted [pro], [flex] and [max] tiers are sold under their own endpoint names
(`fal-ai/flux-2-pro`, `fal-ai/flux-2-flex`, `fal-ai/flux-2-max`), so "FLUX 2" on its own refers to
the open-weight dev model.

## Gaps

- No `publishedAt`/`date` for the `flux-2-dev` endpoint, so fal's own launch date cannot be
  established from the catalogue.
- fal does not state which [dev] checkpoint or quantisation it serves, nor whether the weights
  were modified (e.g. fp8) for serving.
- No latency or throughput figures on the endpoint page; `timings` is returned per request but
  nothing is published.
- The page's `enable_safety_checker` note does not say what authorisation is required to disable
  it, or whether that option exists for ordinary accounts.
- Whether `acceleration: "high"` changes output quality is not stated.

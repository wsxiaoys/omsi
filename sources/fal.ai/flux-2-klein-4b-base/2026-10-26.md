## Input schema — the important difference from the distilled endpoint

Base text-to-image schema (selected fields, verbatim):

| Field | Type / bounds | Description |
| --- | --- | --- |
| `num_inference_steps` | integer, **4–50**, default **28** | "The number of inference steps to perform." |
| `acceleration` | enum `none`, `regular` (default), `high` | "The acceleration level to use for image generation." |
| `image_size` | preset enum or `{width,height}` | default `landscape_4_3` |
| `output_format` | enum jpeg/png/webp, default png | — |
| `enable_safety_checker` | boolean | same wording as the distilled endpoint |

The internal schema name is **`Klein4BBaseInput`**. The distilled endpoint's schema has no
`acceleration` field and caps steps at 8; Base allows 50 steps and exposes a speed/quality
`acceleration` control. That is the host-visible shape of "undistilled vs step-distilled": the
distilled model is pinned near 4 steps, the Base model is meant to be sampled over a wide step range.

## What this establishes

- fal exposes both 4B checkpoints (distilled and Base) for both text-to-image and editing, so a user
  can compare them on one host without local hardware.
- The step-range difference (4–8 vs 4–50) is independent host evidence for the distillation claim,
  beyond BFL's own wording.
- Base costs ~1.8x the distilled model per megapixel for text-to-image on fal.

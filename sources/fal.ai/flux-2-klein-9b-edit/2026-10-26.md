## What this establishes

- **The 4-reference ceiling is corroborated by a host**: fal enforces "A maximum of 4 images",
  matching BFL's four fixed `input_image*` fields. Two independent sources, one number.
- **Editing is priced on input *and* output megapixels**, and fal **resizes input images to
  1MP** before billing. So a large reference image is silently downscaled, and an edit is
  roughly 2x the per-MP cost of a text-to-image call at the same output size.
- **Hex color control is a documented editing feature on this endpoint**, not just a
  family-level [pro]/[flex] claim — this is the only captured statement tying hex control to
  [klein] specifically.
- Editing outputs default to the input image's dimensions when `image_size` is omitted, which
  makes it easy to generate at resolutions the first-party API would also accept.
- fal's `updated_at` (2026-10-20) is much later than the endpoint's creation; what changed is
  not stated.

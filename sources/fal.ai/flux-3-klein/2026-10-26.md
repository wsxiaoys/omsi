### Descriptions (verbatim)

Text-to-image: "Generates images from text prompts with FLUX.3 Klein, with configurable image
size, reproducible seeds, prompt expansion and optional bounding-box layout control."

> FLUX.3 Klein generates images from detailed text prompts. It supports configurable image
> dimensions, up to four outputs per request, reproducible seeds and PNG, JPEG or WebP output.
> Optional prompt expansion develops the caption before generation, while labeled bounding boxes
> provide spatial layout control. **The standard endpoint defaults to 12 inference steps.**

Edit: "Edits and composes images from text instructions and up to ten references with FLUX.3
Klein, with optional bounding-box controls for object placement and transformation."

> FLUX.3 Klein Image Editing creates edited compositions from a target caption and one to ten
> reference images. It supports optional layout boxes to place new objects or move, resize and
> remove referenced objects. Image size, output count, seed, prompt expansion and PNG, JPEG or
> WebP output are configurable. **The standard endpoint defaults to 12 inference steps.**

LoRA endpoints (verbatim): "FLUX 3 Image Klein (step-distilled, fast) with LoRAs: pass loras as a
list of up to 3 {path, scale} (scale 0-4) trained with the FLUX 3 Klein trainer. Same inputs as
the text-to-image endpoint. Billed per output image by size: up to 1024x1024 counts as 1
megapixel, 2048x2048 as 1.56."

Base LoRA endpoints (verbatim): "FLUX 3 Image Klein base (undistilled, CFG) with LoRAs [...]"

Trainer (verbatim): "Train a LoRA on the FLUX 3 Image Klein base model from a .zip of images [...]
Options: steps 100-10000 (default 1000), learning_rate (default 1e-4), resolution 512, 768 or 1024
(default 1024, aspect ratio kept). Returns lora_file (safetensors) and config_file."

### Request schema, `Flux3KleinTextToImageInput` (transcribed)

| Field | Type / range | Default | Notes |
| --- | --- | --- | --- |
| `prompt` | string | — | "The model is trained on detailed captions: describe framing, subject, background and lighting." |
| `image_size` | named preset or `{width,height}` | `square_hd` | "Each side can be 256 to 4096 pixels (native 4K)." |
| `num_images` | integer | 1 | description says "up to four outputs per request" |
| `seed` | integer \| null | — | — |
| `output_format` | `jpeg`\|`png`\|`webp` | `png` | — |
| `enable_safety_checker` | boolean | `true` | — |
| `enable_prompt_expansion` | boolean | `true` | "the prompt is expanded into a detailed caption (grounded in the reference images when editing) before generation" |
| `bounding_boxes` | array, `maxItems: 32` | null | box edges as fractions of image size; label objects with `<label>` in the prompt |
| `sync_mode` | boolean | `false` | — |

`Flux3KleinEditImageInput` adds `image_urls` ("The reference images to edit or compose from (up to
10)") and an edit-specific `bounding_boxes` schema with `source_box`, `target_box`,
`source_image_index` and `label` ("Leave unset to remove a referenced object; set both boxes to
move or resize it"). If `image_size` is unset for an edit, "a single reference image's own size
(scaled to at most 4 megapixels) is used, or the first reference image's size (at most 1
megapixel) when several are given".

Output schema: `images`, `seed`, `prompt` (the expanded prompt actually used), `timings`,
`has_nsfw_concepts`.

**No `steps` field is exposed** on either standard endpoint, despite the descriptions stating a
12-step default.

## What this establishes

- An independent host record: fal lists FLUX 3 Klein as its own endpoint group, published
  **2026-10-15**, two days before fal's LoRA/trainer additions on 2026-10-26.
- fal **runs the weights itself** (`serverless`), unlike its `proxy` FLUX 3 Image endpoints — so
  fal is a genuine alternative serving path for the open checkpoint, not a reseller of BFL's API.
- fal's published rates match BFL's schedule exactly ($0.008/$0.009/$0.011/$0.014/$0.036), yet
  fal labels them **"Planned pricing [...] Final pricing is not yet confirmed"** — a hedge BFL's
  own changelog does not carry.
- Host-level capability differences from BFL's API: up to **4 outputs per request** (BFL: one),
  side length **256–4096** (BFL: 64–6256 with a 16.8 MP cap), `webp` output (BFL: jpeg/png), a
  safety-checker toggle (BFL: 0–7 tolerance), and **12 fixed steps** (BFL: caller-set 1–16,
  default 16).
- fal exposes **Base** only through LoRA endpoints ($0.035/MP) plus trainers, whereas BFL serves
  only the distilled checkpoint. Neither host documents a plain Base inference endpoint.
- fal's catalogue is the only captured source that names "FLUX 3 Max", and it describes that
  model as a **video** model post-trained by fal — not an image tier above FLUX 3 Image.

## Gaps

- No latency, throughput, or hardware information for fal's serverless Klein deployment.
- fal does not state which quantization build it serves, nor which checkpoint revision.
- The "12 inference steps" default cannot be changed through the API, and fal does not say
  whether its 12-step output is meant to match BFL's 16-step output.
- fal's "Planned pricing ... not yet confirmed" contradicts BFL's published table; unresolved
  whether the hedge is stale copy, a contractual difference, or an imminent change.
- `date`/`publishedAt` are catalogue timestamps with no stated meaning beyond fal's own bookkeeping.

### What the schema adds that Google does not state

- **`duration` is an integer 3–10 s with a default of 8**, i.e. any whole second is allowed; Google's
  model page writes "3s-10s" but no default.
- **Reference videos may be "at most ten seconds long"** on fal, whereas Google's guide says video
  references "support a maximum of 3 clips, up to 3 seconds each". Same clip count, different length
  limit.
- **`end_image_url` is optional in the same endpoint as `image_url`**, so first/last-frame interpolation
  is one endpoint here, while Google exposes it as the `image_to_video` task with "up to 2 images".
- **10 reference images** (`maxItems: 10`) matches Google Cloud's "Maximum images per prompt: 10".
- **No negative prompt, seed, safety-tolerance or auto-fix fields.** Unlike fal's Veo 3.1 wrapper, this
  schema exposes only prompt, media, aspect ratio, resolution and duration, which is consistent with
  fal proxying the Google call rather than wrapping it.
- **No audio field.** Audio is generated implicitly; there is no toggle and no audio input.

## Summary

The four v1.1 schemas give the operational parameter surface: a prompt capped at 20,000 characters, up
to 10 reference images, up to 3 reference videos, an optional end frame, 16:9 or 9:16, 360p/720p/1080p/
4K with 720p default, and 3–10 whole seconds with 8 s default. Video output only, delivered as a file
URL.

## Gaps

- No file-size limits, MIME restrictions or per-media duration limits for images on fal.
- No statement of maximum output file size or container/codec.
- No latency, queue-time or concurrency figures in the schema.
- The 20,000-character prompt cap is a fal-side constraint; Google publishes no prompt-length limit.

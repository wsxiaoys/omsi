# fal: GPT Image 2 edit endpoint

- Origin: fal, "GPT Image 2 API (Image Editor) API on fal",
  https://fal.ai/models/openai/gpt-image-2/edit
- Evidence kind: provider documentation (third-party hosting page, endpoint documentation)
- Publication date: none stated
- Capture date: 2026-10-26
- Relevant models: GPT Image 2 on fal (`openai/gpt-image-2/edit`)

## Captured content (summary with key quotes)

Description (verbatim): "OpenAI's next-generation image model, now available as an image editing
API via fal. Make fine-grained, detailed edits to existing images using natural language prompts
and optional mask control."

Relationship to the text-to-image endpoint (verbatim): "This is the same underlying model as
`fal-ai/gpt-image-2/`, optimized specifically for editing workflows rather than generation from
scratch." Streaming is supported.

Documented behaviours (host's wording):

- "Fine-Grained Edits from Natural Language … without any masking required."
- "Mask-Based Inpainting — For surgical edits, pass a `mask_image_url` alongside your reference
  image. The white regions of the mask indicate the areas to edit; everything outside remains
  pixel-perfect."
- "Multi-Image Reference — The `image_urls` field accepts a list of images."
- "Auto Size Inference — When `image_size` is set to `auto` (the default for this endpoint), the
  model infers the output dimensions from the input image."
- "Real-Time Streaming."

### API reference (verbatim table)

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `prompt` | string | required | "Text description of the edit to apply" |
| `image_urls` | list of strings | required | "One or more reference image URLs to edit" |
| `image_size` | enum or object | `auto` | "Output size. `auto` infers from input image. Pass `{ width, height }` for custom dims" |
| `quality` | enum | `high` | `low`, `medium`, or `high` |
| `num_images` | integer | 1 | "Number of edited images to generate" |
| `output_format` | enum | `png` | `jpeg`, `png`, or `webp` |
| `sync_mode` | boolean | `false` | "Returns images as data URIs directly" |
| `mask_image_url` | string | optional | "URL of a mask image. White regions indicate areas to edit" |
| `openai_api_key` | string | optional | "Your OpenAI API key for BYOK usage" |

Size presets: `auto` (default), `square_hd` 1024×1024, `square` 512×512, `portrait_4_3` 768×1024,
`portrait_16_9` 576×1024, `landscape_4_3` 1024×768, `landscape_16_9` 1024×576; custom
`{width, height}` supported with both edges multiples of 16.

## Notes and contradictions

- The edit numbers are the text-to-image numbers plus a small delta (e.g. 1024×1024 high: $0.219
  vs $0.211), consistent with charging for one input image's tokens. fal does not publish a
  formula.
- fal exposes `mask_image_url` here, whereas Replicate's `openai/gpt-image-2` schema has no mask
  input. Mask-based inpainting is therefore available through some hosts and not others, even
  though OpenAI lists inpainting as a model feature.
- fal's edit endpoint defaults to `quality: high` and `output_format: png`; OpenAI's Images API
  defaults to `quality: auto` and `output_format: png`. The quality default is a host choice that
  materially changes cost per request, so "price on fal" is not comparable to "price on OpenAI"
  without fixing `quality`.
- Same "ChatGPT Images 2.0" marketing naming and the same $10/1M text-output line as the
  text-to-image page, with the same conflict against OpenAI's pricing page.

## Known gaps

- No mask size/format limits are stated here (OpenAI's guide says the image and mask must share
  format and size and be under 50MB).
- No reference-image count limit stated beyond "one or more".
- No snapshot identity, latency, or moderation behaviour stated.

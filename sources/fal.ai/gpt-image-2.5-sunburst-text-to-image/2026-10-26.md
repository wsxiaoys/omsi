## Captured content (verbatim)

Description: *"OpenAI's precision-focused image model, built for premium visual work, extra
fidelity on intricate detail, in exchange for longer generation times."*

Pricing block — **character-for-character identical to the Flare endpoint's block**:

> Text tokens (per 1M): **$5.00** input, **$1.25** cached, **$10.00** output.
> Image tokens (per 1M): **$8.00** input, **$2.00** cached, **$30.00** output. Changing the
> **quality** parameter significantly affects cost; by default we use **high**.

## Comparison with the Flare text-to-image schema

A structural diff of the two endpoints' input schemas (all fields, defaults, enums, descriptions,
and ordering) produced **no differences** apart from the schema's own class name
(`GptImage25FlareTextToImageInput` vs `GptImage25SunburstTextToImageInput`) and its one-line
description, both of which read "GPT Image 2.5 generation inputs, kept separate from GPT Image 2."
Both default `quality` to `high`, both allow `xhigh`/`max`, both default `image_size` to
`landscape_4_3`, both allow 1–10 images, both default `output_format` to `png`.

## What this establishes

- At fal, the two tiers are separated by **name, description, thumbnail, and price label only** —
  the request surface and the token rates are identical.
- fal's description supplies a *tradeoff direction* (Sunburst = "extra fidelity ... in exchange
  for longer generation times") that OpenAI's own pages do not quantify.
- Nothing here shows shared weights, nor rules it out. The identical schema is expected if fal
  proxies one upstream API with two model IDs.

## Known gaps

- The sunburst **edit** endpoint's schema was not diffed against the flare edit schema (its
  metadata was captured in the fal model-metadata record, but not its OpenAPI document).
- No latency comparison was captured, so "longer generation times" is unquantified host
  marketing.

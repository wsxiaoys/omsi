## Comparison with the Flare text-to-image endpoint

This record also carries the host-side half of the Flare/Sunburst identity comparison. A
structural diff of the two endpoints' input schemas (all fields, defaults, enums, descriptions,
and ordering) produced **no differences** apart from the schema's own class name
(`GptImage25FlareTextToImageInput` vs `GptImage25SunburstTextToImageInput`) and its one-line
description, both of which read "GPT Image 2.5 generation inputs, kept separate from GPT Image 2."
Both default `quality` to `high`, both allow `xhigh`/`max`, both default `image_size` to
`landscape_4_3`, both allow 1–10 images, both default `output_format` to `png`.

At fal, the two tiers are separated by **name, description, thumbnail, and price label only** —
the request surface and the token rates are identical. fal's description supplies a tradeoff
direction (Sunburst = "extra fidelity ... in exchange for longer generation times") that
OpenAI's own pages do not quantify. Nothing here shows shared weights, nor rules it out. The
identical schema is expected if fal proxies one upstream API with two model IDs. The Sunburst
edit endpoint's schema was not diffed against the Flare edit schema.

## Notes and gaps

- **fal's default `quality` is `high`, not `auto`.** OpenAI's guide says both 2.5 models
  "default to `auto`" ([guide](../../openai.com/image-generation-guide/2026-10-26.md)), and
  fal's own pricing note says higher quality costs more. A default fal call is therefore not
  price- or latency-equivalent to a default first-party call.
- fal lists a `quality` enum identical to OpenAI's, including `auto`, `xhigh`, and `max`.
- The page advertises a per-canonical-size cost table "at the bottom of this page", but that
  block is rendered client-side and did not appear in any capture; only token rates were
  obtainable. No per-image dollar figure was captured from fal.
- "Commercial use" is fal's badge about use through fal. It is not a statement of OpenAI's
  terms for API output, which were not captured here.
- No latency figure, benchmark, or success-rate claim appears on the page beyond the prose
  "longer generation times" relative to the Flare tier.
- The roster's discovery path `openai/gpt-image-2.5/sunburst` is a catalogue group path, not a
  callable endpoint: fal's OpenAPI schema returns 404 for the bare path and 200 for the two
  suffixed endpoints (see [catalogue record](../model-catalogue-api/2026-10-26.md)).
- The Flare/Sunburst comparison above covers the text-to-image endpoint only; the edit endpoint's
  schema was not diffed, and no latency comparison was captured.

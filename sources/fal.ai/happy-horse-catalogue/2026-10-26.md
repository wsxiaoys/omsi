All seven rows: `modelLab: "Alibaba"`, `modelFamily: "Happy Horse"`, `licenseType: "commercial"`,
`hostingType: "proxy"`, `kind: "inference"`, `status: "public"`, `deprecated: false`, `removed: false`.

**`hostingType: "proxy"`** is fal's catalogue value for forwarding to the model owner's API rather
than running the weights on fal infrastructure; the same catalogue marks fal's own models as
`serverless`, so the field is used discriminatingly.

**The roster's discovery path `alibaba/happy-horse/v1.1` is a group, not an endpoint.**
`GET https://api.fal.ai/v1/models?endpoint_id=alibaba/happy-horse/v1.1` returns the bare string
`{"endpoint_id":"alibaba/happy-horse/v1.1"}` with no metadata, and the bare endpoint's OpenAPI schema
returns HTTP 404. The callable endpoints are the three `/v1.1/…` children above. The same is true of
the 1.0 group, whose children carry no `/v1.0` segment at all.

**No 1.1 landing page exists.** `https://fal.ai/happyhorse-1.1`, `/happy-horse-1.1` and
`/happyhorse-11` all return HTTP 404; only `https://fal.ai/happyhorse-1.0` resolves.

## 1.1 request schemas (from the OpenAPI documents)

Internal model names: `happyhorse-1.1-t2v`, `happyhorse-1.1-i2v`, `happyhorse-1.1-r2v` (1.0:
`happyhorse-1.0-t2v`). All three 1.1 endpoints share `resolution`, `duration`, `seed`,
`enable_safety_checker`; output is `{video, seed}` with `VideoFile` metadata (`url`, `width`,
`height`, `fps`, `duration`, `num_frames`, `content_type`, `file_size`).

| Field | text-to-video | image-to-video | reference-to-video |
| --- | --- | --- | --- |
| `prompt` | required, "Max 2500 characters" | optional, "Max 2500 characters" | required, "Max 2500 characters" |
| image input | — | `image_url` (first frame), ≥300 px each side, aspect 1:2.5–2.5:1, ≤20 MB, JPEG/JPG/PNG/BMP/WEBP | `image_urls` 1–9, shortest side ≥400 px, ≤20 MB each, JPEG/JPG/PNG/WEBP |

| `duration` | integer 3–15, default 5 | integer 3–15, default 5 | integer 3–15, default 5 |
| `seed` | 0–2147483647 | 0–2147483647 | 0–2147483647 |
| `enable_safety_checker` | default `true` | default `true` | default `true` |

Verbatim `about` text for the 1.1 text-to-video endpoint:

> Generate a video from text using the Happy Horse 1.1 text-to-video model (`happyhorse-1.1-t2v`).
> Features: Resolution: 720p and 1080p; Duration: 3-15 seconds; Aspect ratios: 16:9, 9:16, 1:1, 4:3,

## Summary

- fal serves the 1.1 line as three proxied endpoints published **2026-06-22** (endpoint `date`
  2026-06-21), six days after the vendor's 2026-06-16 release date, plus the four 1.0 endpoints
  published 2026-04-27.
- fal's surface is narrower than the vendor's: no 480P tier and no video-editing endpoint on 1.1; the
  1.0 edit endpoint remains the only editing option.
- fal's 1.1 price matches the vendor exactly at 720p ($0.14/s) and 1080p ($0.18/s). Its 1.0 1080p
  price ($0.28/s) is **above** the vendor's $0.24/s.
- fal adds an `enable_safety_checker` toggle the vendor API does not document, and drops the vendor's
  `watermark` parameter.

## Gaps

- fal's `#1-ranked` phrasing carries no date, arena, or category; see the landing-page record for the
  April 2026 Artificial Analysis numbers it presumably refers to, and the Artificial Analysis record
  for current ranks.
- No fal statement on which checkpoint it forwards to, or whether 1.1 will be deprecated when a newer
  version ships.
- No output audio specification (codec, sample rate, language list) in any schema.

### The roster's endpoint string is a group prefix, not an endpoint

`GET https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/heygen/avatar5` returns **HTTP
404** with body `null`. The same request for `fal-ai/heygen/avatar5/digital-twin` returns HTTP 200 and
a full schema (captured separately). `https://fal.ai/models/fal-ai/heygen/avatar5` resolves as a
client-side page, so the roster's `fal-ai/heygen/avatar5` names fal's Avatar V family, not a callable
route.

## Summary

fal lists Avatar V as a single proxied endpoint published 2026-05-20, five weeks after HeyGen's launch
post, at $0.10 per second of output. It is a *digital-twin-only* surface: fal does not offer the photo
avatar or arbitrary-image paths that HeyGen's docs describe for the engine.

The `proxy` hosting type is fal's own label: fal forwards to HeyGen rather than running the model, so
this record is a host's restatement of vendor capability, not an independent measurement.

## Gaps

- The catalogue carries no output-resolution, duration, or frame-rate metadata; those are in the schema
  record.
- No statement of which HeyGen plan or avatar-eligibility tier the endpoint can reach, or whether fal's
  own HeyGen account sees the same `supported_api_engines` set a customer would.
- The 2026-10-20 `updated_at` is later than `publishedAt`; the catalogue does not record what changed.
- fal's Avatar IV entries have `date` 2026-02-23 for all three, which looks like a catalogue backfill
  rather than three separate launches; the same caution applies to treating `date` as a launch date.

# fal.ai: HeyGen Video endpoint schemas (three modes)

- Origin: fal.ai queue OpenAPI schemas,
  `GET https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=heygen/heygen-video/text-to-video`,
  `…/image-to-video`, `…/reference-to-video`. Input/output schemas transcribed from
  `HeygenVideo{TextToVideo,ImageToVideo,ReferenceToVideo}Input` and `VideoOutput`.
- Evidence kind: host API schema (independent host, proxying HeyGen)
- Publication date: none on the schema; endpoint `date` 2026-10-20, `updated_at` 2026-10-23
  (`image-to-video`). Capture date 2026-10-26.
- Capture date: 2026-10-26
- Relevant models: `heygen/heygen-video/{text-to-video,image-to-video,reference-to-video}` (HeyGen
  Video 1)

## Input schemas (verbatim field names, types and defaults)

`HeygenVideoTextToVideoInput` — required: `prompt`

| Field | Schema | Note |
| - | - | - |
| `prompt` | string, `minLength: 1`, `maxLength: 32000` | — |
| `duration` | integer, `minimum: 5`, `maximum: 15`, default `5` | — |
| `resolution` | enum `480p`, `768p`, `1080p`, `2k`, default `768p` | — |
| `aspect_ratio` | enum `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, default `16:9` | no `adaptive` (T2V has nothing to adapt to) |
| `prompt_enhancement` | enum `turbo`, `quality`, `ultraquality`, `disabled`, default **`turbo`** | vendor default is `quality` |
| `seed` | integer 0–4294967295 or null | — |
| `enable_safety_checker` | boolean, default `true` | "Authorized callers may set false to request relaxed screening." |

`HeygenVideoImageToVideoInput` — required: `prompt`, `image_url`

Same fields, plus `image_url` ("Image to use as the first frame"), and **no `aspect_ratio`** — the
output follows the first frame, matching the vendor schema.

`HeygenVideoReferenceToVideoInput` — required: `prompt` only

Same fields, plus:

| Field | Schema |
| - | - |
| `reference_image_urls` | array of string, `maxItems: 9` |
| `reference_video_urls` | array of string, `maxItems: 3` |
| `reference_audio_urls` | array of string, `maxItems: 3` |
| `aspect_ratio` | enum `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, default `adaptive` |

Output, all three modes: `{"video": File, "seed": integer|null}`, where `File` is
`{url, content_type, file_name, file_size}`.

`x-fal-metadata.about`: "Text To Video", "Image To Video", "Reference To Video" — no descriptive text
beyond the category.

## What this establishes

- fal exposes the vendor's parameter set **minus** the following: `callback_url`, `callback_id`,
  `end_user_id`, `mode` (implied by the endpoint), asset-ID/base64 reference inputs (URLs only), and
  `aspect_ratio` on image-to-video.
- **fal caps every mode at 15 seconds.** The vendor has allowed 16–30 s for text-to-video and
  image-to-video since October 2026, so the longest clips are not reachable through fal.
- **fal defaults `prompt_enhancement` to `turbo`**, while the vendor defaults to `quality`; identical
  requests therefore take different code paths by default.
- **fal does not encode the vendor's "at least one reference image or video" rule** for
  reference-to-video: only `prompt` is required, so a reference-less request is accepted by the schema
  and would fail (or silently behave as text-to-video) upstream.
- `enable_safety_checker` is fal's own screening toggle, with the same wording as on fal's HeyGen
  Avatar V schema; the vendor documents no equivalent parameter.

## Gaps

- No per-endpoint `about` copy, no example outputs captured, no latency data.
- Whether fal forwards `enable_safety_checker: false` to HeyGen or only relaxes its own pre-filter is
  not stated.
- fal does not expose a duration of `"auto"`; the field is an integer only.

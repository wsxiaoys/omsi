Both rows: `status: "public"`, `deprecated: false`, `removed: false`, `kind: "inference"`,

`hostingType: "proxy"` is fal's own label for forwarding to Kling rather than running weights itself.

### The roster's endpoint ID is a family prefix, not a callable endpoint

`GET …/openapi.json?endpoint_id=fal-ai/kling-video/lipsync` returns the body `null` — there is no schema
for the bare prefix. Only the two leaf endpoints resolve. The roster row names a family, not a model.

### The 2025-03-27 date is fal's onboarding date

It is 94 days after Kling's own changelog records the lip-sync API launching (2024-12-23) and 15 days
after the vendor's 2025-03-12 update that allowed arbitrary 720p/1080p source video. It is a host
publication timestamp, not a model release date.

## Input schema — `audio-to-video` (verbatim descriptions)

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `video_url` | string | yes | "The URL of the video to generate the lip sync for. Supports .mp4/.mov, ≤100MB, 2–10s, 720p/1080p only, width/height 720–1920px." |
| `audio_url` | string | yes | "The URL of the audio to generate the lip sync for. Minimum duration is 2s and maximum duration is 60s. Maximum file size is 5MB." |
| `enable_safety_checker` | boolean | no, default `true` | "Disabling safety checks requires account authorization; unauthorized requests are always checked." |

Output: `{ "video": File }` — "The generated video". No resolution, frame-rate or duration field.

## Input schema — `text-to-video` (verbatim descriptions)

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `video_url` | string | yes | "The URL of the video to generate the lip sync for. Supports .mp4/.mov, ≤100MB, 2-60s, 720p/1080p only, width/height 720–1920px. If validation fails, an error is returned." |
| `text` | string, maxLength 120 | yes | "Text content for lip-sync video generation. Max 120 characters." |
| `voice_id` | string enum, 46 values | yes | "Voice ID to use for speech synthesis"; example `genshin_klee2`. The list mixes English IDs (`AOT`, `uk_boy1`, `uk_man2`, `reader_en_m-v1`, `commercial_lady_en_f-v1`, `PeppaPig_platform`, `cartoon-boy-07`) with Chinese ones (`genshin_vindi2`, `zhinen_xuesheng`, `ai_shatang`, `chengshu_jiejie`, `dongbeilaotie_speech02`, `tianjinjiejie_speech02`, `mengwa-v1`). |
| `voice_language` | `zh` \| `en`, default `en` | no | "The voice language corresponding to the Voice ID" |
| `voice_speed` | number 0.8–2, default 1 | no | "Speech rate for Text to Video generation" |
| `enable_safety_checker` | boolean, default `true` | no | as above |

Output: `{ "video": File }` — "The generated video".

**The two leaves disagree about the source video's duration cap**: `audio-to-video` says 2–10 s,
`text-to-video` says 2–60 s. Same model family, same publish date, adjacent schema files.

## Price strings (verbatim `pricingInfoOverride`, identical on both endpoints)

> Your request will be priced **$0.014** per input **video seconds**, rolling up to closest **5 second
> increment**. For example, if your video's duration is 3 seconds, it will be billed as a 5 second video

Note the basis: **per input video second**, rounded up to 5 s. Billing tracks the source clip, not the
length of the audio or of the produced file.

## Model-page prose (host claims, labelled)

`audio-to-video` page:

> Kuaishou's Kling LipSync generates realistic lip-synchronized video from audio input in approximately
> 12 minutes at $0.014 per 5-second increment. Trading speed for precision lip-sync accuracy, the model
> handles 2-10 second source videos with audio up to 60 seconds.

> Kling LipSync uses audio-driven facial animation architecture that generates mouth movements directly
> from audio waveforms without requiring speaker-specific training data, contrasting with traditional
> lip-sync approaches that need extensive footage of the target speaker.

Host spec table on the same page: Inference Speed "~12 minutes / Fixed processing time for 2-10s input
videos"; Input Video Duration "2-10 seconds / 720p/1080p, ≤100MB, .mp4/.mov only"; Audio Duration "2-60
seconds / ≤5MB file size, .mp3/.wav/.ogg/.m4a/.aac formats"; Resolution Support "720p-1080p /
Width/height constrained to 720-1920px"; Output Formats ".mp4 video with synchronized lip movements";
License "Commercial use via fal partnership".

Two prose claims here are not in any schema and are fal's alone: "~12 minutes" (a fixed cost
independent of duration) and `.ogg` audio support (the vendor accepts .mp3/.wav/.m4a/.aac and does not
list .ogg; neither fal schema names audio formats at all).

## Summary

fal exposes the same underlying service as two endpoints split by audio source: one takes an uploaded
audio URL, one takes text plus a TTS voice ID from a 46-voice list. Both are proxied to Kling, priced at
$0.014 per input video second in 5-second increments, and neither exposes the vendor's two-step
face-recognition flow.

## Gaps

- fal documents no face-selection step, although the vendor requires one; fal presumably auto-selects the
  single detected face. Not stated.
- The text-to-video endpoint's `voice_id` list and `voice_speed` range match the vendor's TTS API, but no
  captured fal page says the TTS call is included in the price or billed separately.
- No output resolution, frame rate, or audio channel count is documented.
- The 2–10 s vs 2–60 s source-video discrepancy between the two schemas is unexplained.

## Transport

The endpoint is not a request/response video generator. The docs say:

> This deployment publishes a WMA WebRTC contract.

and the OpenAPI request body is a WebRTC offer, described in the schema as "Offer forwarded by the
WMA bridge":

```
LingbotWorld2Input = StartSessionRequest
  required: ["sdp"]
  properties: sdp (string), type ("offer", const), ice_servers (array), session_id (string|null),
              ice_status (string|null), credential_age_seconds (number|null)
LingbotWorld2Output = {}          # empty schema
```

Paths exposed: `POST /robbyant/lingbot-world-2` (start session), plus
`GET …/requests/{request_id}`, `GET …/requests/{request_id}/status`, `PUT …/requests/{request_id}/cancel`.
The client snippet is `fal.realtime.open(wma("robbyant/lingbot-world-2"), …)` from
`@fal-ai/client@alpha`, with a note that the realtime API "is currently available on the alpha release
and may change in a minor version."

## Media track (verbatim)

> **Send** — No `send` media tracks.
>
> **Receive** — `video` optional `{"frameRate": 48, "width": 1664, "height": 960}`

So the host's negotiated output is **1664×960 at 48 fps**, and the client sends no media at all: the
world is generated from the initial configuration plus discrete control messages. 1664×960 is a
1.73:1 frame, slightly wider than 16:9, and its short side (960) is above 720p while its long side is
below 1920.

## Client messages

| `type` | Purpose and limits (verbatim where quoted) |
| --- | --- |
| `commands` | Movement. `active` = "commands currently held by the user", `activated` = "edge-triggered commands since the previous report". Allowed values: `forward`, `left`, `backward`, `right`, `look_up`, `look_left`, `look_down`, `look_right`, `quick_action_1` … `quick_action_9` (`maxItems: 17`). "A browser may map a keyboard, gamepad, touch control, or agent action to these names." |
| `configure` | "Optionally replace the automatic default world, once per connection." Fields: `preset` (≤100 chars), `prompt` (≤2000 chars), `image_url` (≤4096 chars), `enable_prompt_expansion` (default `true`), `enable_safety_checker` (default `true`), `quick_actions` (≤9 items; each `key` 1–9, `title` ≤40 chars, `description` ≤1000 chars). "Image URL takes precedence over the preset." |
| `prompt` | "Change the scene's description while continuing this world." 1–2000 chars. |
| `quick_actions` | "Replace the whole quick-action mapping; keys left out are un-mapped." |
| `reset` | Restart with a new preset/prompt/image ("Use `reset` for subsequent restarts"). |
| `keys` | "Legacy physical-key report retained for existing WMA clients." |
| `ping` | Latency probe; server echoes `ts` in a `pong`. |
| `stop` | End session. |

Session flow rules (verbatim):

> This world starts automatically. Wait for the first video frame before using the movement controls.

> Send `configure` and wait for `configured` before sending another world update. Setup is optional and
> can be used once per session.

> World updates run one at a time and must not be replayed automatically. A `error` event is
> diagnostic and does not identify a failed update; read `/error` for details. The session ends on
> `stream_exhausted`.

## Server messages and runtime identity

`configured`, `error`, `pong`, `prompt_applied`, `quick_actions_state`, `reset_applied`,
`session_info`, `stats`, `stream_exhausted`.

`session_info` is the only place the served model is identified. Field defaults and constants
(verbatim):

- `model_variant` — constant **`"14b-causal-fast"`**
- `source_revision` — default `"1895d300d8ac936401689b26389f51cbd36530eb"`
- `max_quick_actions` — default `9`
- `pixel_frames_per_block` — default `12`; `first_block_pixel_frames` — default `9`
- `generation_speed_verified` — default `false`
- also `model_id`, `model_revision`, `resolution{width,height}`, `frames_per_second`,
  `frames_per_block`, `max_blocks`, `supported_controls`, `unsupported_features`, `presets`,
  `conflict_groups`, `key_order`, `default_prompt`, `turn_status`, `turn`

`stats` reports `queue_age_ms_p50`, `queue_age_ms_max`, `queue_depth`, `gpu_wait_frac`, and
`native_timing` with `block_index`, `generation_fps`, `block_seconds`, `pace_sleep_ms_avg`.

`stream_exhausted` (verbatim): "The model has no more frames to send and the current peer is closing.
Clients must negotiate a new session to continue."

## Summary

This is the strongest technical record for the hosted model. It establishes that fal runs the
**14B causal-fast** checkpoint (the distilled real-time variant, matching the vendor's weights
release), that the world is driven by 17 discrete control tokens over WebRTC with no client media
track, that the negotiated stream is 1664×960 at 48 fps, and that the session is bounded: the runtime
publishes `max_blocks` and ends with `stream_exhausted`, after which a new session is required.

It also documents the control surface precisely: four movement axes, four look axes, nine
user-defined quick actions, plus mid-session prompt replacement, world reset, optional LLM prompt
expansion, and an optional safety checker.

## Gaps

- `max_blocks` is described but its value is not published — the maximum session length in seconds is
  unknown.
- No statement of what `generation_speed_verified: false` means or when it becomes true.
- The docs do not say whether `frames_per_second` (runtime field) can differ from the negotiated 48
  fps track, or whether the model natively generates 48 fps or interpolates.
- `supported_controls` and `unsupported_features` are runtime arrays with no enumerated values in the
  contract, so which controls are actually enabled on this deployment is unknown without opening a
  session.
- No error taxonomy: `error` carries a free-text `error` string and an optional `retryable` flag.
- The alpha client (`@fal-ai/client@alpha`) is explicitly unstable, so the integration surface may
  change.

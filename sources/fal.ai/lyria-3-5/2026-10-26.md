## Endpoint "about" text (verbatim, OpenAPI `x-fal-metadata.about`)

> Generate full-length songs using Google's Lyria 3.5 model.
>
> Lyria 3.5 is Google's most capable music generation model, producing
> complete, structured songs up to a few minutes long from text or image
> prompts. It includes advanced controls for fully timed lyrics, precise
> tempo, and complex arrangement structure.
>
> For best results, prompts should include:
> - Genre/Style: e.g., "pop ballad", "jazz fusion", "cinematic orchestral"
> - Mood/Emotion: e.g., "triumphant", "intimate", "nostalgic"
> - Instrumentation: e.g., "full orchestra", "acoustic band", "electronic production"
> - Tempo: e.g., "90 BPM", "allegro", "moderate groove"
> - Structure: use timestamp markers like '[0:00-0:30] Intro: soft piano...'
>   or describe duration e.g. "a 2-minute track"
> - Vocal style: e.g., "soulful female vocals", "male baritone", "choir"
> - Language: supports English, German, Spanish, French, Hindi, Japanese,
>   Korean, and Portuguese
>
> The model outputs:
> - Full-length MP3 audio (44.1 kHz stereo)
> - Optional generated or user-specified lyrics
> - SynthID watermarking for content provenance
>
> Safety filters prevent generation of content mimicking real artists' voices.

## Input schema (`Lyria35Input`)

| field | type | constraints / description (verbatim) |
| --- | --- | --- |
| `prompt` | string, required | `minLength` 1, `maxLength` **5000**; "The text prompt describing the music you want to generate. Include genre, mood, instrumentation, tempo, vocals, and structure for best results. Lyria 3.5 supports full-length songs up to a few minutes — use timestamps or duration hints in your prompt to control song length, e.g. 'a 2-minute track' or section markers like '[0:00-0:30] Intro: ...' / '[0:30-1:00] Verse: ...'. Supports English, German, Spanish, French, Hindi, Japanese, Korean, and Portuguese." |
| `image_url` | string \| null, optional | "Optional image URL to use as visual inspiration for music generation. The model will create music that matches the mood and theme of the image." |
| `negative_prompt` | string, optional, **`deprecated: true`**, default `""` | "Negative prompting is not supported by Lyria 3.5." |
| `enable_safety_checker` | boolean, optional, default `true` | "Authorized callers may set false to request relaxed screening." |

No `duration`, `bpm`, `seed`, `sample_count`, `intensity`, or `format` field exists. Length, tempo
and structure are prompt text only.

**Note the discrepancy inside fal's own surfaces:** the `llms.txt` page lists only `prompt`,
`image_url` and `enable_safety_checker`, while the OpenAPI schema still carries a `negative_prompt`
field marked deprecated with "not supported by Lyria 3.5". The field is accepted by the schema and
documented as ignored.

Example request prompt (verbatim, from the page's required-parameter example):

> An uplifting pop song with driving electric guitar, energetic drums, and a catchy chorus singing
> 'Rise up and shine today'. 120 BPM. Two minutes long with a
> verse-chorus-verse-chorus-bridge-chorus structure.

## Output schema

- `audio` (File, required): "The generated music as an MP3 file."
- `lyrics` (string, optional): "The generated or provided lyrics for the track, if applicable."

Example `lyrics` value (verbatim):

```
[[A0]]
[[B1]]
[12.0:] Dust motes dancing in the light,
[:] Morning breaks so soft and white.
```

That is line-level timestamped lyric data with segment markers — a different shape from the Lyria 3
endpoints' `lyrics` field, which carries a prose caption plus a `BPM:` trailer.

## Direct observation: the example output file

I downloaded the file fal publishes as this endpoint's example output and read its container
properties with `ffmpeg -i` (no model call was made; this is metadata inspection of a host artifact):

| property | measured |
| --- | --- |
| container / codec | MP3 (`audio/mpeg`), 736,652 bytes |
| sample rate | 44,100 Hz |
| channels | 2 (stereo) |
| bitrate | 192 kb/s |
| duration | **00:00:30.69** |

Two readings follow. First, fal's stated "44.1 kHz stereo" is consistent with the artifact it
publishes. Second, the published example file is a **~30-second clip**, not a multi-minute song,
even though the page's example prompt asks for "Two minutes long". A doc example may simply be a
short illustration, so this is not evidence that Lyria 3.5 caps output at 30 s; it is evidence that
the only artifact fal ships publicly is 30.69 s long and that fal does not document a maximum
duration for this endpoint.

## Gaps

- No maximum or minimum output duration is documented for `google/lyria-3.5` ("up to a few minutes"
  is the whole statement). Google's own first-party page says "up to 3 minutes".
- No sample-rate or format documentation beyond "MP3 (44.1 kHz stereo)"; bitrate is unstated in the
  docs and only visible in the example artifact (192 kb/s).
- No rate limits, concurrency, region, or cold-start information.
- No statement of which Google terms govern the proxy, beyond `license_type: "commercial"`.
- The model is reachable on fal and nowhere else in this knowledge base; fal is the only host
  surface, so no cross-host price or format comparison is possible for 3.5.

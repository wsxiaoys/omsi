All four are `category: "text-to-audio"`, `kind: "inference"`, `hostingType: "proxy"`,
`modelLab: "Google"` — fal is proxying Google's models, not serving Google weights. Note the two
namespaces: `fal-ai/*` for the first three Lyria 3 endpoints and **`google/*` for Lyria 3.5**, the
only Lyria endpoint under the `google` lab namespace.

The roster's discovery path `fal-ai/lyria3` is an **exact** endpoint ID.

## `fal-ai/lyria3` — about text (verbatim)

> Generate 30-second music clips using Google's Lyria 3 model.
>
> Lyria 3 is Google's high-fidelity music generation model that combines musical awareness and
> structural coherence. It generates 30-second music clips from text or image prompts, including
> vocals and lyrics.
>
> For best results, prompts should include: Genre/Style… Mood/Emotion… Instrumentation… Tempo…
> Vocal style… Language: supports English, German, Spanish, French, Hindi, Japanese, Korean,
> Portuguese
>
> The model outputs: 30-second MP3 audio at **44.1 kHz / 192 kbps**; Optional generated lyrics;
> SynthID watermarking for content provenance.
>
> Safety filters prevent generation of content mimicking real artists' voices.

The catalogue `shortDescription` on `api.fal.ai` is different and much weaker: "Lyria 3 is most
recent music model from Google" — and it is already stale (Lyria 3.5 exists). The `tags` array on the
endpoint is `["audio","music","sfx"]`, with `sfx` wrong for a music model.

## Input schema (`fal-ai/lyria3`, verbatim descriptions)

| field | type | notes |
| --- | --- | --- |
| `prompt` | string, required | minLength 1, maxLength **5000**; "Include genre, mood, instrumentation, tempo, and vocal style for best results. Lyria 3 supports vocals, lyrics, and multi-language generation." |
| `image_url` | string, optional | "Optional image URL to use as inspiration for music generation. The model will create music that matches the mood and theme of the image." |
| `negative_prompt` | string, optional, **`deprecated: true`** | "Negative prompting is not supported by Lyria 3." Default `""` |
| `enable_safety_checker` | boolean, optional, default `true` | "Authorized callers may set false to request relaxed screening." |

`fal-ai/lyria3/pro` and `google/lyria-3.5` have the **same three live fields** (`prompt`,
`image_url`, `enable_safety_checker`) with no `negative_prompt` at all. None of the three exposes
`duration`, `bpm`, `intensity`, `seed`, or `sample_count` — structure control is prompt-only, matching
Google's Interactions API.

`google/lyria-3.5`'s `prompt` description is the only place in the fal inventory that states the
duration control explicitly:

> Lyria 3.5 supports full-length songs up to a few minutes — use timestamps or duration hints in your
> prompt to control song length, e.g. 'a 2-minute track' or section markers like '[0:00-0:30] Intro:
> …' / '[0:30-1:00] Verse: …'. Supports English, German, Spanish, French, Hindi, Japanese, Korean, and
> Portuguese.

## Output schema (verbatim)

`fal-ai/lyria3`, `fal-ai/lyria3/pro`, `google/lyria-3.5` all return:

- `audio` (File, required): "The generated music as an MP3 file."
- `lyrics` (string, optional): "The generated or provided lyrics for the track, if applicable."

The example `lyrics` value on the Lyria 3 endpoints is a prose **caption** plus machine-readable
trailer fields — `"…\nMosic: 4.5\nBPM: 128.0"` — i.e. the field carries the model's description of the
track and its detected BPM, not only lyric lines. `google/lyria-3.5` returns a different shape:

```
[[A0]]
[[B1]]
[12.0:] Dust motes dancing in the light,
[:] Morning breaks so soft and white.
```

Line-level timestamps and speaker/segment markers, no caption trailer. So 3.5's `lyrics` field is
structured lyric data while 3's is descriptive text.

## Dates worth noting

- fal listed `fal-ai/lyria3` five days after Google's 2026-03-25 preview launch — fast.
- fal listed **`fal-ai/lyria3/pro` on 2026-05-20**, roughly eight weeks after Google shipped
  `lyria-3-pro-preview` alongside the clip model. Through that window, fal's Lyria 3 was clip-only
  while Google's was not. A host listing date is not a model release date.
- `google/lyria-3.5` (2026-09-19) is the **only** evidence found anywhere that Lyria 3.5 is reachable
  through an API. No Google documentation page for a 3.5 model ID was found.

## Gaps

- No fal-side documentation of clip length for `fal-ai/lyria3/pro` (Google says 184 s; the fal page
  does not state a maximum).
- fal's sample rate/bitrate claim (44.1 kHz / 192 kbps) matches Google's model card and contradicts
  Replicate's 48 kHz claim. fal restates Google; it does not measure.
- No fal statement about commercial-use terms beyond `license_type: "commercial"`.

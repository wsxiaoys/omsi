the endpoint is a Meshy API wrapper, not a re-hosted checkpoint.

## Price strings (verbatim, identical on all three 7.1 endpoints)

> A base model without textures costs **$0.80**. Adding textures brings the total to **$1.20**. Optional
> auto-rigging adds **$0.20**, and animation adds **$0.12** per call. A textured model with auto-rigging
> and animation costs **$1.52**.

## Input schema — `meshy/v7.1/text-to-3d`

Required: `prompt` only. Notable fields and defaults:

- `prompt`: "Describe what kind of object the 3D model is. Maximum 600 characters." (Meshy's own API
  allows 800 — see the text-to-3D API record.)
- `mode`: `full` (default) or `preview`; "'preview' returns untextured geometry only, 'full' returns
  textured model (preview + refine)" — one fal call wraps the two Meshy tasks.
- `geometry_resolution`: `standard` / `2k` / `4k`; "4k is only available with Meshy-7.1."
- `model_type`: `standard`, `lowpoly`, `smart-topology`, `smart-topology-t2`.
- `should_texture`, `enable_pbr` (default false), `should_remesh` (default true), `topology`
  (`triangle`/`quad`), `target_polycount` (default 30000; "the maximum is 30,000 for T2.5 and 15,000
  for T2"), `pose_mode`, `symmetry_mode`.
- `seed`: "Seed for reproducible results. Same prompt and seed usually generate the same result." Not
  documented in Meshy's own API.
- `enable_prompt_expansion` (default false): "use a large language model to expand the prompt".
- `enable_rigging` (default false, "rig the generated model as a humanoid character. Includes basic
  walking and running animations"), `rigging_height_meters` (default 1.7), `enable_animation`,
  `animation_action_id` (default 92; "must be in [0, 696] (`0` is the "Idle" preset) ... otherwise
  rejected with a 422").
- `enable_safety_checker` (default true).

`image-to-3d` takes `image_url` (required) — "Supports .jpg, .jpeg, and .png formats. Also supports AVIF
and HEIF formats which will be automatically converted" — plus the same control set.
`multi-image-to-3d` takes `image_urls` (1–4 images) and documents `geometry_resolution`: "Multi-image
generation does not support 4k."

Output schema: `model_urls` with optional `glb`, `fbx`, `obj`, `usdz`, `blend`, `stl`; `thumbnail`;
`texture_urls`; `seed`; `actual_prompt`; and, when `enable_rigging`, `basic_animations`
(`walking_glb`, `walking_fbx`, `walking_armature_glb`, `running_glb`, `running_fbx`,
`running_armature_glb`).

## Summary

fal is the independent host record for Meshy 7.1 and it is a proxy to Meshy's own API. It exposes the
same 7.1 controls with three differences that matter: a 600-character prompt cap instead of 800, a
`seed` parameter Meshy does not document, and rigging/animation folded into the generation call for
$0.20 and $0.12 instead of being separate Meshy tasks at 5 credits and 3 credits per action. Price is
per call rather than per credit: $0.80 untextured, $1.20 textured, $1.52 with rigging and animation,
with no published surcharge for Ultra geometry.

## Gaps

- No `texture_resolution` field, so fal does not expose Meshy's 2K/4K/8K texture choice; the texture
  resolution actually used on fal is not stated.
- No `target_formats` field; the returned format set is fixed by fal.
- No `blend`/`3mf` in the input options even though `blend` appears in the output schema.
- Whether Ultra geometry (`2k`/`4k`) costs more on fal is not stated in the price string, although
  Meshy charges 5 extra credits for it.
- No latency figures.

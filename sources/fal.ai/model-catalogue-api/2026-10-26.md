  → HTTP 404, body `null`.
- The same request with `.../sunburst/text-to-image` and `.../sunburst/edit` → HTTP 200 with
  full OpenAPI schemas (7,869 and 8,333 bytes).
- `GET https://fal.ai/models/openai/gpt-image-2.5/sunburst` → HTTP 200, but the page is a
  client-side route whose endpoint ID resolves to the whole path; it is not a callable endpoint.

## Notes and gaps

- **`hostingType: "proxy"`** is fal's own label: the host forwards to OpenAI's API rather than
  running the model. That makes fal an independent *record* of the endpoint but not an
  independent *measurement* of model behaviour.
- Creation and publication timestamps are 2026-09-08 for all four endpoints — the same day as
  OpenAI's changelog entry. The catalogue gives no revision history, so whether fal's `quality`
  default or schema changed since launch is unknown.
- The catalogue is a live JSON endpoint; a later capture should be added rather than editing
  this record.

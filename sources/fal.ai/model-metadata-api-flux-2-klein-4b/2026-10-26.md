## What this establishes

- fal models [klein] as **one family group (`klein`) with per-checkpoint labels**, not as separate
  models: 4B and 9B, distilled and Base, each with text-to-image and editing endpoints. The LoRA
  endpoints sit in a separate group (`flux-2-klein-lora`).
- The 4B inference endpoints' `date` values are all **2026-01-15**, the same day as BFL's launch
  post, and the Base endpoints arrived later the same day (18:57 and 20:55 UTC) than the distilled
  ones (12:20 and 12:26 UTC). The LoRA endpoint followed on 2026-01-19.
- fal's `date` field is consistent with a publication date but the API does not define it; treat it
  as catalogue metadata, not a vendor release date.
- Only one klein endpoint is retired: the **4B trainer** (`deprecated`, last touched 2026-05-26).
  The 9B trainer is active and was updated 2026-10-20.

## Gaps

- `date` and `updated_at` semantics are undefined by the API (creation vs first publish vs first
  successful inference).
- No model-revision or weights-snapshot field, so which checkpoint fal serves is unknown.
- The keyword search parameter (`?keywords=klein`) does not actually filter — it returned unrelated
  endpoints — so this list was assembled by querying known endpoint ids one at a time. Other klein
  endpoints may exist that were not enumerated.

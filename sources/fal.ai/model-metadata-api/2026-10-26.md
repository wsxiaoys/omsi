# fal.ai: model metadata API (`api.fal.ai/v1/models`)

- **Origin:** fal.ai's public model-catalogue API, e.g.
  <https://api.fal.ai/v1/models?endpoint_id=openai/gpt-image-2.5/flare/text-to-image> (no key
  required for these reads on 2026-10-26). Related catalogue document:
  <https://fal.ai/sitemap.xml>.
- **Evidence kind:** provider documentation (host catalogue metadata; machine-readable, not
  prose).
- **Publication date:** n/a — live API. Per-endpoint `date` and `updated_at` fields are recorded
  below; capture date 2026-10-26.
- **Relevant models/versions:** the four `openai/gpt-image-2.5/*` endpoints and, for context,
  `openai/gpt-image-2`.
- **Capture type:** verbatim JSON fields, transcribed.

## What this establishes

- fal treats Flare and Sunburst as **two named entries in one family group (`gpt-25`)** with
  separate endpoints, separate thumbnails, and separate descriptions. That matches OpenAI's own
  two-model split; it is not evidence of a shared base model.
- fal's endpoint `date` values (2026-09-08) are consistent with OpenAI's release date and the
  `-2026-09-08` snapshot suffix.
- `license_type: commercial` is a fal catalogue field, i.e. fal's assertion about usage through
  fal, not an OpenAI licence statement.

## Known gaps

- `date` and `updated_at` are catalogue timestamps; the API does not say whether `date` means
  creation, first publication, or first successful inference.
- No model-revision/snapshot field, so fal's served revision is unknown.
- The catalogue is paginated (`has_more: true` on the keyword query); only `gpt-image*` entries
  were enumerated.

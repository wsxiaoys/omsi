## Captured content

Page summary (verbatim): "Nano Banana 2.1 Edit by Google transforms reference images using text
instructions, with output resolutions up to 4K and optional video or PDF context."

- Model ID: `google/nano-banana-2.1/edit`; category "image-to-image"; tags "image editing, image
  to image, photorealism, typography, text rendering".

### Pricing (verbatim)

> Text/thinking tokens (per 1M): $1.764 input, $8.823 output. Image tokens (per 1M): $1.764
> input, $35.294 output. Changing the resolution parameter significantly affects cost; by default
> we use 1K.

Same token rates as the text-to-image endpoint.

### Input schema beyond the text-to-image sibling (verbatim)

- `image_urls` (list of string): "The URLs of the images to use for image-to-image generation or
  image editing. Optional when `video_url` or `pdf_url` is provided."
- `video_url` (string): "Optional video to use as input context. Accepts an http(s)/data URL to a
  video file (downloaded and sent inline, max 15MB) or a YouTube URL (passed through to the model
  without downloading)."
- `pdf_url` (string): "Optional PDF document to use as input context. Accepts an http(s)/data URL
  (downloaded and sent inline, max 15MB)."

Shared with the text-to-image endpoint: `prompt`, `num_images` (1–4), `seed`, `aspect_ratio`
(auto plus 14 fixed ratios), `output_format` (jpeg/png/webp, default png), `safety_tolerance`
(1–6, default 4), `sync_mode`, `system_prompt`, `resolution` (1K/2K/4K), `limit_generations`,
`enable_web_search`, `thinking_level` (minimal/medium/high, default medium).

## What this establishes

- On fal, generation and editing are two endpoints over what fal calls "the same underlying
  model". Editing accepts up to 14 images plus optional video or PDF context, with a 15MB inline
  cap on the non-image inputs.
- Google's own guide confirms video input is allowed for 2.1 and audio input is not; the 15MB cap
  is a fal transport limit, not a model limit.

## Known gaps

- No stated cap on the number of `image_urls` beyond the page's "up to 14" claim elsewhere; the
  schema itself does not enumerate a maximum.
- No mask parameter is exposed on this endpoint, even though Google's model card scores
  "Mask/Ink-Based Editing". How masks are supplied through fal (if at all) is not documented in
  this capture.
- No latency or success-rate data.

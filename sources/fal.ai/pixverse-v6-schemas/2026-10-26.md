# fal.ai: OpenAPI schemas for the four `fal-ai/pixverse/v6/*` endpoints

- Origin: fal.ai queue OpenAPI schemas,
  `GET https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/pixverse/v6/{text-to-video,image-to-video,transition,extend}`
- Evidence kind: provider documentation (host API specification)
- Publication date: endpoints dated 2026-03-29 (catalogue `date`); schema capture 2026-10-26
- Capture date: 2026-10-26
- Relevant models: `fal-ai/pixverse/v6/*`

## Shared parameter surface (verbatim descriptions)

`resolution`: enum `360p`, `540p`, `720p`, `1080p`; default `720p`.

`duration`: "The duration of the generated video in seconds. v6 supports values from 1 to 15
seconds", minimum 1, maximum 15, default 5.

`seed`: "The same seed and the same prompt given to the same version of the model will output the
same video every time."

`generate_audio_switch`: "Enable audio generation (BGM, SFX, dialogue)"; default false.

`generate_multi_clip_switch`: "Enable multi-clip generation with dynamic camera changes"; default
false. (Absent from the `extend` schema.)

`thinking_type`: enum `enabled`, `disabled`, `auto`; "Prompt optimization mode: 'enabled' to optimize,
'disabled' to turn off, 'auto' for model decision".

`style`: enum `anime`, `3d_animation`, `clay`, `comic`, `cyberpunk`; "The style of the generated
video".

`prompt` and `negative_prompt`: "Limited to 2048 UTF-8 encoded bytes. Because the limit counts bytes
rather than characters, emoji and non-Latin or accented characters (which use multiple bytes each) can
push a visually short prompt over the cap."

`enable_safety_checker`: boolean, default true; "Authorized callers may set false to request relaxed
screening."

`aspect_ratio`: enum `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, `2:3`, `3:2`, `21:9`; default `16:9`
(present on `text-to-video` and `transition`; absent from `image-to-video` and `extend`).

### Per-endpoint deltas

| Endpoint | Required inputs | Notes |
| --- | --- | --- |
| `text-to-video` | `prompt` | full shared surface incl. `aspect_ratio` |
| `image-to-video` | `prompt`, `image_url` | `image_url`: "URL of the image to use as the first frame"; no `aspect_ratio` |
| `transition` | `prompt`, `first_image_url`, `end_image_url` | "URL of the image to use as the first frame" / "…as the last frame" |
| `extend` | `video_url`, `prompt` | "URL of the input video to extend"; no `aspect_ratio`, no multi-clip |

Output schema is a single `video` file (`video/mp4` in the examples) for all four.

Internal type names leak fal's reuse of older schemas: `PixverseV6TextToVideoInput` is titled
`TextToVideoRequestV6` but its output is `VideoOutputV5_5`; `image-to-video` output is
`I2VOutputV5_5`; `transition` output is `TransitionOutputV5_5`.

## Summary

fal's V6 surface is the vendor's surface plus three parameters the vendor does not document:
`thinking_type` (prompt optimisation), `style` (five named looks) and `negative_prompt`. It also
converts the vendor's character-based prompt cap (5,000 for T2V, 2,048 for I2V) into a flat
**2,048-byte** cap on every endpoint, which is stricter for non-Latin prompts and for long text-to-video
prompts.

fal's `image-to-video` has no `aspect_ratio` input, so the output ratio follows the input image;
fal's `transition` keeps `aspect_ratio`, unlike the vendor's frame-based endpoint where the ratio is
not a documented parameter.

The `V5_5` output type names are schema reuse, not evidence that V6 output is V5.5 output; the input
types are V6-specific.

## Gaps

- No latency, queue, or concurrency fields in these schemas.
- No documentation of what `style` or `thinking_type` actually do to a generation, or whether the
  vendor model supports them natively.
- No `webhook_id`-style or region field; fal's own webhook mechanism is outside this schema.

Both are `kind: inference`, `status: public`, `deprecated: false`, `modelLab: Alibaba`,
`modelFamily: "Qwen Image 3"`, `group.key: "qwen-image-3"`, `landingPageSlug: "qwen-image-3"`.

**`hostingType: "proxy"`** is fal's catalogue value for an endpoint that forwards to the model
owner's API rather than running the model on fal infrastructure. The same catalogue marks fal's own
Qwen Image 2512 deployments as `hostingType: "serverless"` (e.g. `fal-ai/qwen-image-2512`), so the
field is used discriminatingly and is not a default. This contradicts fal's own landing-page FAQ,
which says "The API is serverless, so there are no GPUs to manage" — see
[landing page record](../qwen-image-3-landing-page/2026-10-26.md).

Image editing:

> Edits images from one to three reference images and a natural-language instruction, preserving
> key details such as facial features and identity while applying the requested changes

## Text-to-image input schema (`QwenImage3TextToImageInput`)

| Field | Type / default | Description (verbatim) |
| --- | --- | --- |
| `prompt` | string, 1–5000 chars, required | "Text prompt describing the desired image. Supports Chinese and English. Max 5000 characters." |
| `negative_prompt` | string, max 500, default `""` | "Content to avoid in the generated image. Max 500 characters." |
| `image_size` | preset or `{width,height}`, default `square_hd` | "The size of the generated image. Total number of pixels must be between 512x512 and 2048x2048." |
| `enable_prompt_expansion` | boolean, default `true` | "Enable automatic LLM prompt rewriting for better results." |
| `seed` | integer or null | "Random seed for reproducibility (0-2147483647)." |
| `enable_safety_checker` | boolean, default `true` | "Enable content moderation for input and output. Disabling it requires account authorization; unauthorized requests are always checked." |
| `sync_mode` | boolean, default `false` | "If `True`, the media will be returned as a data URI and the output data won't be available in the request history." |
| `num_images` | integer, 1–6, default 1 | "The number of images to generate." |
| `output_format` | `png` (default) / `jpeg` / `webp` | "The format of the generated image." |

Presets: `square_hd`, `square`, `portrait_4_3`, `portrait_16_9`, `landscape_4_3`, `landscape_16_9`.
The generic `ImageSize` object allows width/height up to 14142 but the endpoint description caps
the total at 2048×2048.

Output: `images[]` (URL, content type, size) and `seed`.

## Edit input schema (`QwenImage3EditInput`)

Same fields as above plus:

| Field | Type / default | Description (verbatim) |
| --- | --- | --- |
| `image_urls` | array of strings, required | "Reference images for editing (1-3 images required). Order matters: reference as 'image 1', 'image 2', 'image 3' in prompt. Resolution: 384-2048px each dimension. Max size: 10MB each. Formats: JPEG, JPG, PNG (no alpha), WEBP." |
| `image_size` | preset, `{width,height}`, or null | "The size of the generated image. If not provided, the model determines the resolution automatically. Total number of pixels must be between 512x512 and 2048x2048." |

The edit schema has no `negative_prompt`-specific caveat beyond the shared 500-character cap, and
no mask/inpaint field: this is instruction-based editing over whole reference images, not masked
inpainting.

## What this establishes

- fal serves Qwen Image 3 as **two endpoints over one vendor API**, split by task, both launched
  2026-07-21 — one day after Alibaba's `qwen-image-3.0-pro` release date.
- fal's own per-image pricing ($0.04 at 1K, $0.075 at 2K) matches Alibaba's `qwen-image-3.0-pro`
  output prices exactly, which is consistent with fal reselling the pro tier — but fal never names
  which vendor model ID it calls.
- fal adds host-side features the vendor does not document as such: `enable_safety_checker`
  toggling, `output_format` including webp, `sync_mode`, and per-request `num_images` 1–6.
- fal's edit endpoint takes 1–3 references at 384–2048 px each and ≤10 MB, matching the vendor's
  1–3 reference limit.

## Gaps

- No statement of which vendor model ID (`qwen-image-3.0-pro` vs `qwen-image-3.0`) each endpoint
  calls, and no revision or snapshot field.
- fal does not document what `hostingType: "proxy"` means; the reading above is inferred from the
  contrast with `serverless` entries in the same catalogue.
- No prose readme on the fal endpoint pages (client-rendered playgrounds), so capability claims
  come from catalogue descriptions and schema text.
- `pricingInfoOverride` says "1K"/"2K" without defining the pixel dimensions, and the schema's
  cap is stated as a pixel count (512×512–2048×2048), so how fal bills a 2688×1536 request is
  undocumented here.
- No latency, throughput, or quality measurements.

### Path check

- `GET https://fal.ai/models/fal-ai/recraft/v4/pro` — the roster's discovery path — returns an HTTP
  200 page shell whose embedded metadata resolves to `recraft/v4/pro`, but it is **not** a callable
  endpoint ID; the callable endpoints carry the `/text-to-image` and `/text-to-vector` suffixes.
- `GET https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/recraft/v4/pro` → HTTP 404,
  body `null`. The same request with `/text-to-image` → HTTP 200 with a full schema.
- `GET https://fal.ai/models/recraft-v4/llms.txt` (the `landingPageSlug`) → HTTP 404 with an empty
  body; the family landing page is not mirrored as agent-readable text.

## Gaps

- The catalogue's `date` is the endpoint's publish timestamp on fal, not the model's release date.
  The V4 Pro raster endpoint's `2026-02-12` precedes Recraft's own 2026-02-17 announcement by five
  days, unexplained.
- `discovery.variant` is `"Pro"` for the raster row and `"pro"` for the vector row — inconsistent
  casing in fal's own metadata, harmless but worth knowing when querying.
- No price field in this response for the V4 Pro rows.

Input schema `RecraftV4ProTextToImageInput` (property order: `prompt`, `image_size`, `colors`,
`background_color`, `enable_safety_checker`; only `prompt` required):

| Property | Schema |
| - | - |
| `prompt` | string, `minLength: 1`, `maxLength: 10000` |
| `image_size` | default `"square_hd"`; `anyOf` `ImageSize` object or enum `["square_hd","square","portrait_4_3","portrait_16_9","landscape_4_3","landscape_16_9"]`; example `"landscape_16_9"` |
| `colors` | array of `RGBColor`, default `[]`, "An array of preferable colors" |
| `background_color` | `RGBColor` or null, "The preferable background color of the generated images." |
| `enable_safety_checker` | boolean, default `true`, "Disabling it requires account authorization; unauthorized requests are always checked." |

Supporting schemas:

- `ImageSize`: object with `width` and `height` integers, `exclusiveMinimum: 0`, default 512 each,
  `maximum: 14142` — i.e. fal accepts an arbitrary pixel size up to 14142 on a side.
- `RGBColor`: object `{r,g,b}`, integers 0–255, each defaulting to 0.

Output schema `RecraftV4ProTextToImageOutput`: required `images`, an array of `File` (example
`image.webp`, `content_type: "image/webp"`, `file_size: 1949504`).

The queue wrapper adds the usual fal `QueueStatus` (`IN_QUEUE` / `IN_PROGRESS` / `COMPLETED`) and
`apiKeyAuth` via an `Authorization: Fal Key` header.

## Gaps

- The schema does not state pixel dimensions for any of the six named `image_size` presets. Only the
  `{width, height}` form is unambiguous.
- `maxLength: 10000` on `prompt` matches Recraft's documented V4-family limit
  (`../../recraft.ai/limits-and-sizes/2026-10-26.md`), which is indirect evidence that fal forwards
  to the Recraft API rather than running its own inference.
- No `n`/batch parameter, so one request yields one image and the $0.25 unit price maps 1:1 to a
  call.

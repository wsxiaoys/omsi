`hostingType: "serverless"` means fal reports running the model on its own infrastructure rather than
proxying Meta's API. The catalogue lists `modelLab: null` and `modelFamily: null` for these rows;
group keys are `sam3` and `sam31`.

The bare ID `fal-ai/sam-3` (the roster's discovery path) resolves in the metadata API but returns
only `{"endpoint_id":"fal-ai/sam-3"}` with no metadata — there is no documented bare endpoint; the
served endpoints are `/image` and `/video`.

**The `sam-3/3d-*` endpoints are SAM 3D, not SAM 3.** Meta's blog describes SAM 3D as a separate
release ("Separately, we're sharing SAM 3D"), and the catalogue descriptions match that ("SAM 3D
enables precise 3D reconstruction of objects from real images"). fal files them under the `sam3`
group, so a catalogue listing under "SAM 3" is not evidence that the endpoint runs the segmentation
model.

For contrast, the same query returned the predecessors: `fal-ai/sam2/image` and `fal-ai/sam2/video`
(both dated 2024-08-15), `fal-ai/sam2/auto-segment` (2025-02-25), `fal-ai/image-preprocessors/sam`
(2024-09-16, SAM 1 preprocessor), and `fal-ai/evf-sam` ("EVF-SAM2 Segmentation", 2025-02-26). SAM 2 endpoints have their own
IDs and remain public; SAM 3 did not replace them in the catalogue.

## Metadata API descriptions (verbatim)

`fal-ai/sam-3/image` and `/video` share one description:

> SAM 3 is a unified foundation model for promptable segmentation in images and videos. It can
> detect, segment, and track objects using text or visual prompts such as points, boxes, and masks.

Tags: `segmentation`, `mask`, `real-time`. Image endpoint `display_name`: "Segment Anything Model 3";
video endpoint `display_name`: "Sam 3". The `sam-3-1/*` rows carry: "SAM 3.1 builds comes with Object
Multiplex, a shared-memory approach for joint multi-object tracking that delivers faster speeds with
larger number of objects tracked." (fal's wording, typos included).

## Image schema (`fal-ai/sam-3/image`, `Sam3ImageInput`)

Required: `image_url`. Optional:

| Field | Type / default | Description (verbatim) |
| --- | --- | --- |
| `prompt` | string, default `"wheel"` | "Text prompt for segmentation" |
| `text_prompt` | string, **deprecated** | "[DEPRECATED] Use 'prompt' instead. Kept for backward compatibility." |
| `point_prompts` | array of `PointPrompt` (default `[]`) | "List of point prompts" |
| `box_prompts` | array of `BoxPrompt` (default `[]`) | "Box prompt coordinates (x_min, y_min, x_max, y_max). Multiple boxes supported - use object_id to group boxes for the same object or leave empty for separate objects." |
| `apply_mask` | bool, default `true` | "Apply the mask on the image." |
| `return_multiple_masks` | bool, default `false` | "If True, upload and return multiple generated masks as defined by `max_masks`." |
| `max_masks` | int 1–32, default 3 | "Maximum number of masks to return when `return_multiple_masks` is enabled." |
| `include_scores` | bool, default `false` | "Whether to include mask confidence scores." |
| `include_boxes` | bool, default `false` | "Whether to include bounding boxes for each mask (when available)." |
| `output_format` | `jpeg`/`png`/`webp`, default `png` | "The format of the generated image." |
| `sync_mode` | bool, default `false` | "If True, the media will be returned as a data URI." |

`PointPrompt`: `x`, `y`, `label` (1 foreground / 0 background), `object_id` ("Prompts sharing an
object id refine the same object. When a text prompt is also given, the id selects which detected
object the points refine."), `frame_index`. `BoxPrompt`: `x_min`,`y_min`,`x_max`,`y_max`,
`object_id`, `frame_index`.

Output (`Sam3ImageOutput`): `masks` (array of images, required), `image` ("Primary segmented mask
preview"), `metadata` (per-mask `index`, `score`, `box` in normalized `cxcywh`), `scores`, `boxes`.

**There is no mask-image input field** in the image schema, despite fal's page copy advertising
"masks" as a prompt modality (see the contradictions section).

## Video schema (`fal-ai/sam-3/video`, `Sam3VideoInput`)

Required: `video_url`. Optional:

| Field | Type / default | Description (verbatim) |
| --- | --- | --- |
| `prompt` | string, default `""` | "Text prompt for segmentation. Use commas to track multiple objects (e.g., 'person, cloth')." |
| `text_prompt` | string, **deprecated** | "[DEPRECATED] Use 'prompt' instead." |
| `point_prompts` | array of `PointPromptBase` | "List of point prompts" (no `frame_index` field here) |
| `box_prompts` | array of `BoxPromptBase` | "List of box prompt coordinates (x_min, y_min, x_max, y_max)." |
| `detection_threshold` | number 0.1–1.0, default 0.5 | "Detection confidence threshold (0.0-1.0). Lower = more detections but less precise." |
| `apply_mask` | bool, default `true` | "Apply the mask on the video." |
| `video_output_type` | `X264 (.mp4)` / `VP9 (.webm)`, default `X264 (.mp4)` | "The output type of the generated video." |

Output (`Sam3VideoOutput`): `video` (required, the segmented video file), `boundingbox_frames_zip`
("Zip file containing per-frame bounding box overlays").

No maximum duration, frame count, resolution, or FPS appears in the schema or on the model page.

## Contradictions inside fal's own material

1. **Image price.** The image endpoint's pricing block and catalogue row say **$0.005 per request**;
   the video page's comparison copy says "SAM 3 Image (**$0.002/image**)" and calls the video rate
   "2.5x the per-frame cost ($0.005 per 16 frames vs. $0.002 per static image)". The "2.5x" compares a
   per-16-frames price with a per-image price, so the comparison is dimensionally wrong: at $0.005
   per 16 frames the video endpoint costs ≈$0.0003 per frame, not 2.5× an image call.
2. **Mask prompts.** Page copy lists "mask" / "mask overlays" as a prompt modality on both endpoints;
   neither schema has a mask input field. Meta's blog and paper do describe masks as a PVS prompt
   modality, so the capability may exist in the model but is not exposed by fal's API.
3. **SAM 3D price.** The image page says "SAM 3 3D Objects … $0.065 for 3D mesh output"; the video
   page says "SAM 3 3D Objects ($0.015/inference)"; the catalogue row says "$0.02 per unit". Three
   different figures for the same fal endpoint across three fal pages.
4. **Output resolution.** The image page states "Output Resolution 1024×1024 — Native output
   dimensions for mask generation"; Meta's paper describes a 1008-pixel encoder input and publishes
   no "native output resolution" claim.

## Gaps

- No documented input image size limit, no video duration/frame limit, and no stated GPU class or
  latency figures.
- No statement of which checkpoint (`facebook/sam3` or `facebook/sam3.1`) backs which endpoint, nor
  any refresh date beyond `updated_at`.
- fal's `licenseType: "commercial"` and "Commercial use permitted" are fal's statements about use
  through fal, not a Meta licence grant.

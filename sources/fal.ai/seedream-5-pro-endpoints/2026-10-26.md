## Pro endpoint descriptions (verbatim, `metadata.description`)

- `bytedance/seedream/v5/pro/text-to-image`: *"ByteDance's Seedream 5.0 Pro is flagship
  text-to-image model, with deep-thinking prompt understanding, native text in 14 languages, and
  precise control over dense layouts and structured designs."* Tags: `realism`, `typography`,
  `stylized`. `updated_at: 2026-10-20T22:53:35.171Z`.
- `bytedance/seedream/v5/pro/edit`: *"Seedream 5.0 Pro is grounded, region-precise image editing
  model that changes one element while keeping the rest of the frame intact with layer separation,
  sketch completion, and up to 10 reference images."* `updated_at: 2026-10-20T22:18:56.016Z`.
- `bytedance/seedream/v5/pro/layerize`: *"Splits a finished image into independent, editable
  transparent-PNG layers — background plus separate elements, from a text description, returning 2
  to 17 layers per call for non-destructive reuse in design tools."* Tags: `utility`, `editing`.

Note: "2 to 17 layers" on layerize versus "one base image and up to 16 layers" in ByteDance's docs —
consistent only if fal counts the base image as a layer. Not stated.

## `text-to-image` input schema (from the OpenAPI document)

| Field | Default / range | Notes (host wording, condensed) |
| --- | --- | --- |
| `prompt` | required | "The text prompt used to generate the image." |
| `image_size` | default `auto_2K`; presets `square_hd`, `square`, `portrait_4_3`, `portrait_16_9`, `landscape_4_3`, `landscape_16_9`, `auto_1K`, `auto_1.5K`, `auto_2K`, or `{width,height}` | "Total pixels must be between 921600 and 4624220, with aspect ratio between 1/16 and 16." |
| `num_images` | 1–6, default 1 | "Number of separate model generations to run with the prompt." |
| `output_format` | `jpeg` (default) or `png` | |
| `watermark` | default `false` | "Whether to add the provider's visible watermark." |
| `image_passthrough` | default `false` | "Preserve original reference and output image bytes, formats, and dimensions without resizing or re-encoding." |
| `enhance_prompt_mode` | `standard` (default) or `fast` | "`standard` prioritizes image quality; `fast` reduces generation time." |
| `enable_safety_checker` | default `true` | "Disabling it requires account authorization; unauthorized requests are always checked." |
| `sync_mode` | default `false` | Returns the image as a data URI instead of a hosted URL. |

Schema titles are `SeedDream50ProT2IInput` / `SeedDream50ProT2IOutput`. The input's pixel range and
aspect-ratio range are byte-for-byte the same numbers as ByteDance's Ark documentation, which is
good evidence that fal is proxying the first-party API rather than re-implementing it.

## What this establishes

- fal's `date` values (2026-07-07, published 2026-07-08) independently corroborate a **2026-07-08**
  launch for Pro, matching ByteDance's own blog publish timestamp.
- fal splits Pro into **three** endpoints, not two: text-to-image, edit, and a separate `layerize`
  endpoint added 2026-08-06. ByteDance exposes layer decomposition as a `layer_decomposition: true`
  flag on the same endpoint instead.
- `watermark` defaults to **false** on fal but **true** on Ark. Same model, opposite default.
- fal's `num_images` ceiling is 6 per request, which has no counterpart in the Ark docs (Ark's Pro
  path generates one image per request).
- `hostingType: "proxy"` means fal forwards to ByteDance's API. fal is therefore an independent
  *record* of the endpoint, not an independent *measurement* of model behaviour.

## Known gaps

- No model-revision or snapshot field: fal's `updated_at` timestamps are catalogue edits, not model
  versions, so whether fal serves `-260628` specifically is unknown.
- `date` semantics (created vs first published vs first successful run) are undocumented.
- Per-endpoint USD pricing requires an authenticated call to `api.fal.ai/v1/models/pricing`; it was
  not captured. The only fal Pro price in this capture set is the landing page's "from $0.0675 /
  image".

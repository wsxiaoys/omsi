## Endpoint identity

`fal-ai/stable-audio-3/medium/text-to-audio` — the roster row's endpoint — carries:

- title "Stable Audio 3", `category: "text-to-audio"`, `kind: "inference"`,
  `hostingType: "serverless"`, `licenseType: "commercial"`, `status: "public"`,
  `deprecated: false`, `removed: false`, `modelLab: "Stability AI"`, `modelFamily: "Stable Audio 3"`,
  `discovery.family: "Stable Audio"`, `discovery.version: "3"`, group `{key: "SA3", label: "Text to
  Audio Medium"}`, `model_url: https://fal.run/fal-ai/stable-audio-3/medium/text-to-audio`.
- Short description (verbatim): "Stable Audio 3 Medium is a 1.4 billion parameter latent diffusion
  model that generates high-quality stereo music up to 6 minutes from text prompts, trained on fully
  licensed data for safe commercial use."
- Tags: `music`, `audio`, `stereo`.

`hosting: "serverless"` means fal runs the open weights on its own hardware rather than proxying the
Stability API. fal lists the endpoint **two days after** Stability's 2026-05-20 launch.

All 25 are `status: "public"`, `deprecated: false`, `removed: false`, `licenseType: "commercial"`.
**No endpoint serves Stable Audio 3.0 Large**, and no `large` path exists anywhere in the catalogue.

Pricing basis: the embedded billing object on each model page reads
`"billing_unit":"audios","price":0.0376` (medium text-to-audio) — i.e. a **flat charge per generated
audio file**, not per second of output and not per compute-second. The playground string agrees:
"Your request will cost **$0.0376** per audio." The trainer is the only per-`steps` unit in the family.
Consequence: a 1-second clip and a 380-second track cost the same on fal.

The unit distinction is corroborated elsewhere in the same catalogue: `fal-ai/ace-step` bills
`"billing_unit":"seconds","price":0.0002` and `fal-ai/elevenlabs/music` bills
`"billing_unit":"minutes","price":0.6`. fal therefore expresses duration-based billing with a duration
unit, and Stable Audio 3's `audios` unit is per generation by contrast, not a per-second rate in
disguise.

## `medium/text-to-audio` input schema (verbatim descriptions and bounds)

| Field | Type | Default | Bounds | Description |
| --- | --- | --- | --- | --- |
| `prompt` | string, **required** | — | — | "Text description of the audio to generate." Example: "An anthemic Pop Rock instrumental that fills your head with nostalgic thoughtfulness" |
| `negative_prompt` | string | `""` | — | "Text description of qualities to avoid in the output." |
| `duration` | float | `30` | **1–380** | "Duration of the generated audio in seconds. The medium model supports up to 380 seconds (~6m20s)." |
| `num_inference_steps` | integer | `8` | 1–100 | "Number of sampling steps. Post-trained (distilled) checkpoints look good with the default 8 and gain little from going higher." |
| `guidance_scale` | float | `1` | 0–25 | "Classifier-free guidance scale. Higher values follow the prompt more strictly. **Only effective on base (non-distilled) checkpoints.**" |
| `seed` | integer | null | — | "Random seed for reproducible outputs. Omit for a random seed." |
| `enable_prompt_expansion` | boolean | `false` | — | "If True, the prompt will be expanded using an LLM for more detailed and higher quality results." |
| `enable_safety_checker` | boolean | `true` | — | "Enable NSFW content safety checking." |
| `sync_mode` | boolean | `false` | — | "If True, the audio is returned inline as a data URI and the result is not saved to the request history." |
| `output_format` | enum | `mp3` | — | "Container format for the generated audio output." Options: `mp3`, `wav`, `flac`, `ogg`, `opus`, `m4a`, `aac` |
| `bitrate` | string | `"192k"` | — | "Audio bitrate for compressed output formats (e.g., mp3, aac, opus). Format e.g. '192k' or '320k'. Ignored for lossless formats (wav, flac)." |

Output schema `StableAudio3MediumTextToAudioOutput`: `{audio: File, seed: int, prompt: string}`.
`File` carries `url`, `content_type`, `file_name`, `file_size`. **The schema names no sample rate.**
The llms.txt example response is internally broken — it echoes `"content_type": "image/png"` and
`"file_name": "z9RV14K95DvU.png"` for an audio output.

## Variant differences (verbatim from each endpoint's llms.txt)

- **Medium base** (`medium/base/*`): `num_inference_steps` default **50** — "Base (non-distilled)
  checkpoints typically need ~50 for good quality"; `guidance_scale` default **7** — "~7.0 is a good
  starting point for base checkpoints". Everything else matches the post-trained medium.
- **Small Music** (`small/music/*`): "459 million parameter latent diffusion model that generates full
  stereo music compositions up to 2 minutes from text prompts, lightweight enough for on-device
  deployment." `duration` **1–120**, default 30.
- **Small SFX** (`small/sfx/*`): "459 million parameter latent diffusion model that generates
  high-quality sound effects from text prompts, designed for on-device deployment on mobile phones and
  consumer laptops." `duration` **1–120**, default 30.
- **Small base** variants: same 1–120 range, steps default 50, guidance default 7.
- **Audio-to-audio** (medium): adds required `audio_url` and `init_noise_level` (float, 0–1, default
  `0.9`); `duration` 1–380.
- **Audio inpainting** (medium): required `audio_url`, `mask_start_seconds` and `mask_end_seconds`
  (0–380, examples 4 and 8). **No `duration` field.** One mask range only — the vendor paper
  documents multi-segment editing, the host schema does not expose it.
- **Audio outpainting** (medium): required `audio_url`, `extend_seconds_before` (0–380, default 0) and
  `extend_seconds_after` (0–380, default 30).
- **Trainer** (`fal-ai/stable-audio-3-trainer`): "fine-tunes Stable Audio 3 base models on paired
  audio-caption datasets, producing compact LoRA weights"; `duration` is "Clip duration in seconds for
  crop/pad sizing … Always capped at the chosen model's native training length" (1–380).

## Gaps

- **No sample rate, channel count, or file-size ceiling** in any schema. fal never states that output
  is 44.1 kHz stereo; only the vendor docs and paper do.
- **No statement of which checkpoint revision** runs behind each endpoint (no revision/commit field).
  The `base`/non-`base` split is the only signal, and it matches the paper's base/post-trained split.
- **Copy-paste defects**: the llms.txt example response for an audio endpoint returns a PNG; the
  inpainting and audio-to-audio `audio_url` examples both point at
  `storage.googleapis.com/falserverless/model_tests/diffrythm/rock_en.wav` — a competitor's test asset.
- **Flat per-audio billing with a 1–380 s range** is not explained anywhere; fal publishes no
  per-second or per-minute rate for this family, and no statement about whether very long generations
  are surcharged.
- No latency figures, queue-time data, or example output captured.

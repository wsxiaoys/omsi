## Captured content

### The roster path `topaz/upscale` is not an endpoint

`GET https://api.fal.ai/v1/models?endpoint_id=topaz/upscale` returns:

```json
{"error":{"type":"not_found","message":"Endpoint(s) not found"}}
```

`https://fal.ai/models/topaz/upscale` loads a playground shell with no model metadata. The real
image upscaling endpoints are the four `topaz/upscale/image/*` IDs below. The landing page for the
whole Topaz catalogue is `https://fal.ai/topaz`.

### Pricing (verbatim `pricingInfoOverride`)

Precision:

> Your request will cost **$0.08** per started 24 megapixels of output for every precision model. For
> example, an output up to 24 MP costs **$0.08**, over 24 MP and up to 48 MP costs **$0.16**, and over
> 48 MP and up to 72 MP costs **$0.24**.

Generative:

> Your request will cost **$0.08** per started 8 megapixels of output with Wonder 3 or Wonder 3.5, and
> **$0.08** per started 4 megapixels with Wonder, Wonder 2, Recover 3, Standard MAX, Redefine,
> Recovery, or Recovery V2. A 24 MP output therefore costs **$0.24** with Wonder 3/3.5 or **$0.48**
> with the other models.

Creative:

> Your request will cost **$0.08** per started 2 megapixels of output with Bloom 2, Bloom, or Bloom
> Realism. For example, a 24 MP output costs **$0.96**.

Transparent:

> Transparent Upscale always produces a fixed 4× enlargement in width and height (16× the source pixel
> area) and preserves the alpha channel in PNG. Your request will cost **$0.08** per started 24
> megapixels of output. For example, 1024×1024 becomes 4096×4096 and costs **$0.08**; 2000×2000 becomes
> 8000×8000 and costs **$0.24**; 3000×2000 becomes 12000×8000 and costs **$0.32**.

### Input schemas (verbatim constraints)

`topaz/upscale/image/precision` — `UpscaleImagePrecisionInput`, only `image_url` required:

| Property | Schema |
| --- | --- |
| `image_url` | string, minLength 1, "Url of the image to be upscaled" |
| `model` | enum `["Standard V2","High Fidelity V3","High Fidelity V2","Low Resolution V2","CGI","Text Refine","Faces"]`, default `"Standard V2"` |
| `upscale_factor` | number, **minimum 1, maximum 4**, default **2** |
| `crop_to_fill` | boolean, default false |
| `output_format` | enum `["jpeg","png"]`, default `"jpeg"` |
| `subject_detection` | enum `["All","Foreground","Background"]`, default `"All"` |
| `face_enhancement` | boolean, **default true** |
| `face_enhancement_creativity` | number 0–1, default 0 |
| `face_enhancement_strength` | number 0–1, default 0.8 |
| `sharpen` / `denoise` / `fix_compression` | number 0–1 or null; `fix_compression` "Not supported by the CGI model" |
| `strength` | number 0.01–1, "Applies to Text Refine model only" |
| `enable_safety_checker` | boolean, default true, "Authorized callers may set false to request relaxed screening" |

`topaz/upscale/image/generative` — `UpscaleImageGenerativeInput`, only `image_url` required:

| Property | Schema |
| --- | --- |
| `model` | enum `["Wonder 3.5","Wonder 3","Wonder 2","Wonder","Recover 3","Standard MAX","Redefine","Recovery V2","Recovery"]`, default `"Wonder 3"` |
| `upscale_factor` | number, min 1, **max 4**, default 2 |
| `enhancement_strength` | enum `["low","medium","high"]` or null, "Applies to Wonder 3 and Wonder 3.5 models. When omitted, Topaz auto-configures it." |
| `subject_detection` | enum `["All","Foreground","Background"]`, "Applies to Wonder 3, Recovery and Recovery V2 models" |
| `creativity` | integer 1–6, Redefine only, "Higher values produce more creative/hallucinated details" |
| `texture` | integer 1–5, Redefine only |
| `prompt` | string max 1024, Redefine only |
| `autoprompt` | boolean, Redefine only |
| `sharpen` / `denoise` | number 0–1, Redefine only |
| `detail` | number 0–1, "Applies to Recovery V2 model only" |
| `face_enhancement` | boolean, default true |
| `face_enhancement_creativity` / `face_enhancement_strength` | 0–1, defaults 0 / 0.8 |
| `output_format` | enum `["jpeg","png"]`, default jpeg |

`topaz/upscale/image/creative` — `UpscaleImageCreativeInput`: `model` enum includes Bloom 2 / Bloom /
Bloom Realism; `creativity` integer 1–**9** (Bloom 2 only); `autoprompt` (Bloom 2 only, "Topaz defaults
it to true when omitted"); `color_preservation` (Bloom 2 only); `upscale_factor` 1–4, default 2.

`topaz/upscale/image/transparent` — `UpscaleImageTransparentInput`: only `image_url` required;
`output_format` is `const "png"`; **no `upscale_factor` field**. The schema's `about` text says:

> Topaz's Transparency Upscale model always returns a fixed 4x-scaled image regardless of the
> requested `upscale_factor`; billing reflects that actual (4x) output size rather than the requested
> factor.

Output for all four is a single `File` object (`url`, `content_type`, `file_size`, `file_name`).

## Gaps

- **"serverless" in the FAQ contradicts `hostingType: "proxy"` in the catalogue.** A proxy endpoint
  forwards to the vendor's API; a serverless one runs on fal's infrastructure. The catalogue field is
  the more specific machine-readable statement, and the landing page's "at parity with what Topaz
  charges" is consistent with proxying, so the FAQ's "serverless" reads as generic fal copy.
- **The fal `Faces` model on the precision endpoint is Topaz's Face Recovery 3**, but fal's own
  precision `about` text calls it "Face Recovery 3, restores facial detail" while the first-party
  page gives the model string `"Face Recovery V3"` on a *different* endpoint
  (`/restore-gen/async`). How fal routes `Faces` is not documented.
- **The generative endpoint's model list contains `Recovery` and `Recovery V2`, which have no page in
  the current first-party docs index** (the docs list `Recover 3` instead). The generative endpoint's
  default is `Wonder 3`, not the newest `Wonder 3.5`.
- No latency, queue-time, or throughput figures are published, and no output-dimension cap appears in
  the schemas — only the 1–4 factor and the landing page's "up to 512MP".
- `date`/`publishedAt`/`updated_at` are fal's catalogue timestamps for the endpoint records, not
  evidence of when Topaz shipped a model.
- `topaz/upscale/image/transparent` ignores `upscale_factor`; the schema keeps the field out entirely
  rather than rejecting it, so a caller cannot request 2x.

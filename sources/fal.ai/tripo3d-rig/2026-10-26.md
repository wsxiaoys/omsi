## Summary

fal does host Tripo's rigging, but under `fal-ai/tripo3d/*`, not under `tripo3d/h3.1/*`, and the endpoint is
**six days old at capture (2026-10-13)** and carries no tags, so it does not appear in fal's `keywords=tripo`
gallery listing. It exposes only the two older rig snapshots — `v1.0-20240301` and `v2.5-20260210` — and not
the vendor's current `v3.0-20260909` rig model, and its `rig_type` enum lacks the `others` value that v3.0
adds.

That answers the question the H3.1 output schema raises: "Pass this to rig or rig-check" is a real path on
fal, but the rig you get is the older one, and no fal page claims the H3.1 mesh was validated for it beyond
the free `riggable` check.

## Gaps

- The rig endpoint is not in fal's public gallery and the catalogue API returns only a stub for it; whether
  it is generally available or staged is not stated.
- No `fal-ai/tripo3d/animate` or `retarget` endpoint exists, so Tripo's preset animation library is not
  reachable on fal at all.
- No statement of which skeleton/joint set each `rig_type` produces.

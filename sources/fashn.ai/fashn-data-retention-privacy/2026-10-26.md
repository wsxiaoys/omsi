# FASHN docs: Data Retention & Privacy

- Origin: FASHN AI developer documentation, "Data Retention & Privacy",
  https://docs.fashn.ai/api-overview/data-retention-privacy (Markdown via `Accept: text/markdown`)
- Evidence kind: official documentation (vendor data-handling policy for the API)
- Publication date: not stated
- Capture date: 2026-10-26
- Relevant models: all FASHN API endpoints, including FASHN Virtual Try-On v1.6

## Captured content

Retention table, verbatim:

| Data | What is kept | How long |
| --- | --- | --- |
| **Request record** | "Timestamp, model, parameters, submitted input URLs, `<base64>` placeholders for base64 inputs, output references, and status and error information" | "Not deleted automatically" |
| **Input image sent as a URL** | "The image is fetched only to process the request. The request record stores the submitted URL, not a copy of the image" | "The URL string stays with the request record" |
| **Input image sent as base64** | "Used only to process the request" | "The temporary processing copy is deleted when the request finishes, with a one-day automatic cleanup backstop" |
| **Output as a CDN URL** (default) | "The output file on FASHN's CDN" | "Scheduled for deletion after three days" |
| **Output as base64** (`return_base64: true`) | "The output, returned by the status endpoint" | "Available for 60 minutes after completion, after which the status endpoint returns `_expired`" |
| **AI provider processing** | "Images and prompts, processed by FASHN's AI and infrastructure providers (Subprocessor List) only to run the request" | "Governed by provider data-processing agreements" |

> FASHN does not use Customer Content to train, fine-tune, or improve its own or third-party AI models
> unless you expressly opt in through a separate agreement.

> **Deleting request records** — There is currently no deletion endpoint. To have request records
> deleted, contact legal@fashn.ai and include your Organization and the relevant prediction IDs.

Recommended minimisation strategies: short-lived signed URLs (recommended over base64 "for better
reliability"), base64 for sensitive images, or a hybrid. "With any of these strategies, set
`return_base64: true` to shorten the window during which the output is available."

## Observations

- This matters for a try-on product specifically: the *person* image is personal data, and the
  default path stores the submitted URL in a request record that is never auto-deleted. The docs'
  recommendation is a signed URL that expires after the request completes.
- The three-day output window is a hard operational constraint for anyone storing CDN URLs instead of
  downloading the bytes.

## Gaps

- No statement about storage region, encryption at rest, or retention inside each subprocessor.
- "AI provider processing" is not itemised per model; whether v1.6 is served by FASHN's own
  infrastructure or a third-party provider is not disclosed.

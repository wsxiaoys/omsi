## Captured content

Full text of the endpoint page was retrieved. Key statements, verbatim.

Summary line and lifecycle:

> Virtual Try-On v1.6 is a fast, lightweight virtual try-on model optimized for real-time
> e-commerce integrations.
>
> **Lifecycle:** Stable · **Released:** June 25, 2025

Positioning against the successor endpoint:

> [Try-On Max](https://docs.fashn.ai/api-reference/tryon-max) is our recommended virtual try-on
> endpoint, offering higher resolution (up to 4K), broader item support (shoes, hats, jewelry,
> bags), and prompt-based customization. Use v1.6 when speed and cost are your primary concerns.

Request shape (universal `/v1/run` body, endpoint params nested in `inputs`):

> `POST https://api.fashn.ai/v1/run`
>
> `model_name` — string — Yes — Must be `tryon-v1.6`.

### Input parameters

| Parameter | Type / values | Default | Documented meaning (verbatim or close paraphrase) |
| --- | --- | --- | --- |
| `model_image` | image URL or data URI, required | — | "Primary image of the person on whom the virtual try-on will be performed." |
| `garment_image` | image URL or data URI, required | — | "Reference image of the clothing item to be tried on the `model_image`." |
| `category` | `auto` \| `tops` \| `bottoms` \| `one-pieces` | `auto` | `auto` classifies the garment; for on-model images, "full-body shots default to a full outfit swap. For focused shots (upper or lower body), the system selects the most likely garment type (tops or bottoms)." |
| `segmentation_free` | boolean | `true` | "Direct garment fitting without clothing segmentation, enabling bulkier garment try-ons with improved preservation of body shape and skin texture. Set to `false` if original garments are not removed properly." |
| `moderation_level` | `conservative` \| `permissive` \| `none` | `permissive` | `conservative` "Blocks underwear, swimwear, and revealing outfits"; `permissive` "allows swimwear, underwear, and revealing garments, while still blocking explicit nudity"; `none` "disables all content moderation" |
| `garment_photo_type` | `auto` \| `flat-lay` \| `model` | `auto` | Optimises internal parameters for on-model vs flat-lay/ghost-mannequin garment photos |
| `mode` | `performance` \| `balanced` \| `quality` | `balanced` | Speed/quality trade-off |
| `seed` | int, 0 to 2^32-1 | `42` | Fixed seed for reproducibility |
| `num_samples` | int, 1 to 4 | `1` | Number of images per run; multiplies cost |
| `output_format` | `png` \| `jpeg` | `png` | `jpeg` is "faster"; `png` is "highest quality" |
| `return_base64` | boolean | `false` | Returns base64 instead of a CDN URL; "Outputs are available for up to 60 minutes instead of the standard three-day window" |

There is **no prompt parameter** and no input-resolution or aspect-ratio parameter on this endpoint.

Responsible-use note attached to `moderation_level: none`:

> Setting `moderation_level: none` does not remove your responsibility for ethical and lawful use.
> **Violations may result in service denial**.

### Technical limitations

> Input images are processed at 864 × 1296 px.

That is the entire "Technical limitations" section: no file-size cap, no aspect-ratio range, and no
statement about what happens to inputs of other shapes are published on this page.

### Credit cost

> Virtual Try-On v1.6 costs 1 credit per output image. The `num_samples` value determines the
> number of outputs and therefore the total cost.

Cost does not vary by `mode` or by `output_format` on this endpoint.

### Processing time

| `mode` | Typical processing time (verbatim) |
| --- | --- |
| `performance` | About 5 seconds |
| `balanced` | About 8 seconds |
| `quality` | About 12–17 seconds, depending on the input resolution |

### Runtime errors

`PoseError`: "The pipeline was unable to detect a body pose in either the model image or the
garment image (when `garment_photo_type: "model"`)." The remedy given is to improve photo quality.

### Response

`{"id": "<prediction-id>", "error": null}` on submit; polling returns `status`, an `output` array of
CDN URLs (`https://cdn.fashn.ai/<id>/output_0.png`), and `error`.

## Gaps

- No output aspect-ratio, file-size, or minimum-input-dimension limits are documented for v1.6,
  unlike the Try-On Max page, which has an explicit limits table.
- No publication or last-modified date on the page itself; the only date is the model release date.
- No quality benchmark, no evaluation set, and no comparison figures against other vendors.
- The page does not say whether v1.6 is still callable on `/nightly` or under any other alias.

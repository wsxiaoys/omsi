## Efficiency (README "Model efficiency" section)

Verbatim preamble: "> The devices used in the below table differ from those in the original paper
(the standard). So, it's only for reference."

| Runtime | FP32 | FP16 |
| --- | --- | --- |
| A100 | 86.8ms | 69.4ms |
| 4090 | 95.8ms | 57.7ms |
| V100 | 384ms | 152ms |

| GPU Memory | FP32 | FP16/BF16 |
| --- | --- | --- |
| Inference | 4.8GB | 3.5GB |
| Training (#GPU=2, batch_size=2, compile=False+PyTorch=2.8.0) | 38.2GB (A100) | 28.5GB (A100) |
| Training (#GPU=2, batch_size=2, compile=True+PyTorch=2.8.0) | 35.6GB (A100) | 23.5GB (4090), 23.9GB (A100) |

ONNX notes (verbatim): "BiRefNets with SwinL (default backbone) cost `~90%` more time (the inference
costs `~165ms` on an A100 GPU) using ONNX files. Meanwhile, BiRefNets with SwinT (lightweight) cost
`~75%` more time (the inference costs `~93.8ms` on an A100 GPU) using ONNX files. Input resolution
is `1024x1024` by default."

A conflicting memory figure appears in the weights section (verbatim): "BTW, 5.5G GPU memory is
needed for inference in 1024x1024." The efficiency table says 4.8 GB FP32 / 3.5 GB FP16 for
inference. The two are not reconciled in the README.

## Usage and licensing statements (verbatim excerpts)

- One-line load: `AutoModelForImageSegmentation.from_pretrained('zhengpeng7/BiRefNet',
  trust_remote_code=True)`.

## Verbatim: TL;DR

> For interactive world models, we decouple state evolution (maintained by coding agents or engines) and
> appearance (rendered by EdenLive).

> EdenLive renders reference videos to enhanced videos in real time at 24 fps or higher, even on a
> consumer GPU (RTX 5090).

## Verbatim: overview

> EdenLive is a real-time generative renderer that treats the reference video as the interface between
> an interactive program and neural visual synthesis: the upstream program executes the rules and
> maintains the world state, whereas EdenLive renders the resulting reference video, guided by a target
> first frame and a text prompt, into detailed frames.

> The project page demonstrates over 24 FPS, minute-scale generation, and 480P/720P output. The 5B model
> supports single-GPU deployment at 720P.

## Verbatim: serving notes

> **Real-time service**: uses game frames as input and streams video over WebRTC. Configure the weight
> directory, service addresses, ports, and GPU count in `realtime/deploy.conf`. 5B uses one GPU by
> default. Set `NPROC` for multi-GPU inference.

> Set `TURN_HOST` (the relay address reachable by the browser), `TURN_IFACE` (the relay interface), and
> `TURN_SECRET` (your own password) in `realtime/deploy.conf`.

> The bridge host requires the `claude` CLI, `claude auth login`, and first-run trust confirmation.
> Game generation uses `--dangerously-skip-permissions`.

Application slugs for the real-time service: 5B `game2v-eden-world-v2-5b-taehv`, 14B
`game2v-eden-world-v2-14b-taehv`. The real-time service uses the TAEHV decoder.

Sample inputs shipped with the repo: `examples/samples/{cryo-crossing,pulse-skirmish}/` each with
`recording.mp4` ("the greybox proxy (1280x704)"), `first-frame.png`, `cover.png` ("a photoreal render
of that frame"), `prompts.json` (`staticPrompt` plus timestamped `dynamicPrompts`) and `prompts.txt`.

## Verbatim: third-party acceleration (LightX2V)

> **Real-time inference on a single RTX 5090:** EdenLive 5B achieves approximately **24.7 FPS inference
> throughput at 1280×704**, meeting the throughput requirement for **real-time 24 FPS playback**.

This is the source of the project page's "even on a consumer GPU (RTX 5090)" claim. It is a
LightX2V-optimized path (low-bit quantization, CUDA Graphs, streaming LightTAE decoding), not the
repository's default configuration, and it is an inference-throughput figure rather than a
measured end-to-end interaction latency.

## Verbatim: Reactor integration

> The [Reactor integration](reactor/README.md) serves EdenLive's four-step 5B pipeline with synchronized
> draft and generated video, keyboard controls, live prompt updates, and a browser demo. It runs on one
> B200 and keeps the native inference and training entrypoints unchanged.

## Summary

The repository is the release artefact: code (Apache-2.0), weights (mixed licences), a real-time
WebRTC serving stack built on NVIDIA FlashDreams, and an integration that Reactor turned into a hosted
product. It also pins the practical deployment shape — an 80 GB-class NVIDIA GPU for the reference
configuration, one GPU for 5B and multi-GPU for 14B, plus a TURN relay for browser sessions.

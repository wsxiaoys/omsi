## Captured content

### Setup (verbatim)

> Install diffusers from `main` and upgrade your `transformers`, `accelerate` and `bitsandbytes`
> dependencies to latest [...] After accepting the gating on the FLUX.2-dev repository, login with
> Hugging Face on your terminal.

### Hardware tiers (verbatim headings and figures)

> ## 💾 Lower VRAM (~24-32G) - RTX 4090 and 5090
> Those with 24-32GB of VRAM can use the model with **4-bit quantization**
>
> ### 4-bit transformer and remote text-encoder (~18G of VRAM)
> The text-embeddings are calculated in bf16 in the cloud and you only load the transformer into
> VRAM (this setting can get as low as ~18G of VRAM)

> ### 4-bit transformer and 4-bit text-encoder (~20G of VRAM)
> Load both the text-encoder and the transformer in 4-bit. The text-encoder is offloaded from VRAM
> for the transformer to run with `pipe.enable_model_cpu_offload()`, making sure both will fit.

> ## 💿 More VRAM (80G+)
> Even an H100 can't hold the text-encoder, transormer and VAE at the same time. However, as they
> each fit individually, it is a matter of activating the `pipe.enable_model_cpu_offload()`
> For H200, B200 or larger cards, everything fits.

> ## 🧮 Other VRAM sizes
> If you have different GPU sizes, you can experiment with different quantizations, for example,
> for 40-48G VRAM GPUs, (8-bit) quantization instead of 4-bit can be a good trade-off.

### Sampling defaults used in the guide (verbatim)

Full-precision and remote-text-encoder examples both use `num_inference_steps=50`,
`guidance_scale=4`; the 4-bit example carries the inline comment
`num_inference_steps=50, #28 steps can be a good trade-off`.

## What this establishes

This is the most concrete first-party statement of self-host requirements captured:

| Configuration | VRAM (BFL's figure) | Notes |
| --- | --- | --- |
| bf16 weights, all components | 80G+ (H200/B200; H100 needs CPU offload) | reference quality path |
| 8-bit quantisation | "40-48G VRAM GPUs" suggested | trade-off, not a hard figure |
| 4-bit transformer + 4-bit text encoder | "~20G of VRAM" | RTX 4090/5090 class |
| 4-bit transformer + remote text encoder | "~18G of VRAM" | text embeddings computed in HF's cloud |

Caveats a reader should carry:

- These are BFL's approximate figures from a guide, not measured benchmarks, and they are for
  *loading* the model, not for peak memory during a 4MP edit.
- The lowest-VRAM path depends on a **remote** text encoder hosted by Hugging Face
  (`https://remote-text-encoder-flux-2.huggingface.co/predict`), so the ~18G configuration is not
  fully offline and requires an HF token.
- The guide points to the diffusers FLUX.2 release blog for how quantisation affects output
  quality; that comparison was not captured, so the quality cost of the 4-bit paths is unknown
  here.

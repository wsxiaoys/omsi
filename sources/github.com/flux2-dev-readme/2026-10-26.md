### `FLUX.2 [dev]` section (verbatim)

> `FLUX.2 [dev]` is a 32B parameter flow matching transformer model capable of generating and
> editing (multiple) images. The model is released under the FLUX.2-dev Non-Commercial License and
> can be found here.

> Note that the below script for `FLUX.2 [dev]` needs considerable amount of VRAM (H100-equivalent
> GPU). We partnered with Hugging Face to make quantized versions that run on consumer hardware;
> below you can find instructions on how to run it on a RTX 4090 with a remote text encoder, for
> other quantization sizes and combinations, check the diffusers quantization guide here.

### Prompt upsampling (verbatim)

> `FLUX.2 [dev]` benefits significantly from prompt upsampling. The inference script below offers
> the option to use both local prompt upsampling with the same model we use for text encoding
> (`Mistral-Small-3.2-24B-Instruct-2506`), or alternatively, use any model on OpenRouter via an API
> call.

### Autoencoder (verbatim)

> The FLUX.2 autoencoder has considerably improved over the FLUX.1 autoencoder. The autoencoder is
> released under Apache 2.0 and can be found here.

### Local installation and runtime (verbatim)

> The inference code was tested on GB200 using CUDA 12.9 and Python 3.12.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e . --extra-index-url https://download.pytorch.org/whl/cu129 --no-cache-dir
```

Weights are downloaded automatically if `FLUX2_MODEL_PATH` / `AE_MODEL_PATH` are unset; the CLI is
`PYTHONPATH=src python scripts/cli.py`.

### Watermarking (verbatim)

> We've added an option to embed invisible watermarks directly into the generated images via the
> invisible watermark library. Additionally, we are recommending implementing a solution to mark
> the metadata of your outputs, such as C2PA.

## What this establishes

- **Self-host requirement, first-party:** the reference script needs an "H100-equivalent GPU";
  consumer GPUs are served by quantised builds, not by the reference path.
- **[dev] is guidance-distilled but not step-distilled** — unlike [klein], which is 4-step
  distilled. That is consistent with the diffusers examples using 28–50 steps.
- The licence is restated as the "FLUX Non-Commercial License" for [dev], and the FLUX.2
  autoencoder is carved out as Apache 2.0 — a mixed-licence release.
- BFL's own recommendation table puts [dev] at "maximum quality, no latency constraints" among the
  open models, and recommends it (with [klein] Base) for fine-tuning.

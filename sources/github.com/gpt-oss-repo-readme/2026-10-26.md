## Highlights (verbatim, identical in substance to the HF card)

> - **MXFP4 quantization:** The models were post-trained with MXFP4 quantization of the MoE weights,
>   making `gpt-oss-120b` run on a single 80GB GPU (like NVIDIA H100 or AMD MI300X) and the
>   `gpt-oss-20b` model run within 16GB of memory. All evals were performed with the same MXFP4
>   quantization.

> Both models were trained using our harmony response format and should only be used with this
> format; otherwise, they will not work correctly.

## Reference implementations, not a serving stack

The repository ships three reference implementations — PyTorch, a Triton MoE kernel path, and Metal
— plus a terminal chat application:

> We also include an optimized reference implementation that uses an optimized triton MoE kernel
> […] This version can be run on a single 80GB GPU for `gpt-oss-120b`.

> The terminal chat application is a basic example of how the harmony format works together with the
> PyTorch, Triton, and vLLM implementations, and it also exposes both the python tool and browser
> tool as optional tools.

The tools are contracts the caller must implement. The browser example parses a tool call out of
the completion and then performs the fetch itself:

```python
last_message = messages[-1]
if last_message.recipient.startswith("browser"):
  # perform browser call
  response_messages = await browser_tool.process(last_message)
```

The Python tool runs in Docker, with an explicit warning:

> This implementation runs in a permissive Docker container which could be problematic in cases like
> prompt injections. It's serving as an example and you should consider implementing your own
> container restrictions in production.

Also relevant to reproducing the model's behaviour: the tool was trained with a **stateful** Python
tool, but "this reference implementation, however, uses a stateless mode", so `PythonTool` overrides
the definition shipped in `openai-harmony`.

## Other captured details

- The chat CLI takes `-c/--context` with "Max context length (default: 8192)" — a default, not the
  model's limit.
- The Triton/Metal paths consume the `original/` checkpoint directory; vLLM consumes the Hub
  conversion in the repository root.
- Downloads are documented through `hf download openai/gpt-oss-120b --include "original/*"`, i.e.
  the MXFP4 originals are a subdirectory of the same Hub repository.

## Summary

The repository is the developer-facing half of the release: reference PyTorch/Triton/Metal
implementations, a harmony-based chat client, and example browser/Python tools the caller must run
and secure. It confirms the single-80GB-GPU target and the MXFP4-only evaluation regime, and it is
the source for the Docker/prompt-injection caveat on the Python tool.

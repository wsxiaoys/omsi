## Description (verbatim)

> *Leffa* is a unified framework for controllable person image generation that enables precise
> manipulation of both appearance (i.e., virtual try-on) and pose (i.e., pose transfer).

The README carries the paper abstract, a method figure, a qualitative comparison figure, install
instructions (`conda create -n leffa python==3.10`, `pip install -r requirements.txt`, `python app.py`
for a local Gradio app), and a pointer to `franciszzj/VtonEval` as the metric-evaluation code. It
documents no hosted API and no text-prompt input.

## Checkpoints and their backbones (from `app.py`, `leffa/model.py`)

`app.py` instantiates three models, each from a checkpoint plus a base diffusion model:

| Checkpoint | Base model passed as `pretrained_model_name_or_path` | Task / training data |
| --- | --- | --- |
| `virtual_tryon.pth` | `./ckpts/stable-diffusion-inpainting` | virtual try-on, VITON-HD |
| `virtual_tryon_dc.pth` | `./ckpts/stable-diffusion-inpainting` | virtual try-on, DressCode |
| `pose_transfer.pth` | `./ckpts/stable-diffusion-xl-1.0-inpainting-0.1` | pose transfer, DeepFashion |

`leffa/model.py` selects the architecture from the base-model path string: `"stable-diffusion-inpainting"`
sets `diffusion_model_type = "sd15"`, `"stable-diffusion-xl-1.0-inpainting-0.1"` sets `"sdxl"`, and
`rescale_betas_zero_snr` follows from that. So the two virtual try-on checkpoints are SD1.5-inpainting
models and the pose-transfer checkpoint is an SDXL-inpainting model. The paper documents only an SD1.5
baseline, so the SDXL pose-transfer checkpoint is a release that the paper does not describe.

## Pipeline behaviour visible in the code

- Both tasks take `src_image`, `ref_image`, `mask` and `densepose`. For virtual try-on the mask is a
  garment-agnostic mask built from SCHP human parsing plus OpenPose keypoints
  (`get_agnostic_mask_hd` for the VITON-HD checkpoint, `get_agnostic_mask_dc` for the DressCode one).
  For pose transfer the mask is all-white (`np.ones_like(src_image_array) * 255`), i.e. the whole
  canvas is repainted.
- For virtual try-on the DensePose signal is extracted from `src_image`; for pose transfer it is also
  extracted from `src_image`. The reference image supplies appearance in both cases. This matches the
  paper's task definition (pose from source, appearance from reference).
- Images are resized and centre-cropped to 768×1024 (`resize_and_center(src_image, 768, 1024)`) in the
  reference app.
- `LeffaInference.__call__` defaults: `num_inference_steps=50`, `guidance_scale=2.5`, `seed=42`,
  `ref_acceleration=False`, `repaint=False`.
- The local app exposes a virtual try-on model selector (`viton_hd` / `dress_code`), `garment_type`,
  `ref_acceleration`, `repaint`, an optional garment-image preprocessing flag (PNG only), and an
  editable DensePose image input for both tabs.

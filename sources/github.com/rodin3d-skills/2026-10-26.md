## What the repository is

`SKILL.md` front matter: "Enterprise-grade 3D model generation using Hyper3D Rodin Gen-2.5 API…",
tags include "Rodin Gen-2.5", and the documentation link is
`https://developer.hyper3d.ai/api-specification/rodin-gen2.5` — i.e. this is the vendor's own Gen-2.5
integration, not a community wrapper. The README, which is older, still says "using the Hyper3D Rodin
Gen-2 API" and lists the legacy tier set.

## Tier table (SKILL.md, verbatim)

| Tier | Description | Credit Cost | Recommended use |
| --- | --- | --- | --- |
| `Gen-2.5-Extreme-Low` | Rapid generation for simple assets | 0.5 | Prototyping |
| `Gen-2.5-Low` | Clean assets, small hardsurface props | 0.5 | Basic models, low-poly |
| `Gen-2.5-Medium` | Balanced structure and detail | 0.5 | **Default** |
| `Gen-2.5-High` | Rich structural representation, smooth surfaces | 0.5 | Production-ready assets |
| `Gen-2.5-Extreme-High` | High-frequency detail reproduction | 1.0 | Premium quality |
| `Gen-2` | "Legacy tier" | 0.5 | Backward compatibility |
| `Detail/Regular/Smooth/Sketch` | "Legacy tiers" | 0.5 | "Deprecated, use Gen-2.5" |

This is the **only captured first-party statement that any Rodin generation is deprecated**, and it
deprecates Gen-1/1.5 (not Gen-2, which is called "Legacy tier" without the word deprecated).

## Other operational details

- **Face counts:** high 1M Raw / 50k Quad; medium 500k / 18k; low 60k / 8k; extra-low 20k / 4k —
  matches the API reference.
- **`HighPack` add-on: "+1 credit"** — the API reference gives no credit price for it, and the API
  changelog says add-on pricing was revised across generations in August 2026, after this repo's last
  push.
- **`geometry_instruct_mode` default listed as `faithful`** — the vendor changed the default to
  `creative` in July 2026, after this repo's last push.
- **Materials:** `PBR`, `Shaded`, `All`, `None` (no `Hybrid`, same omission as fal's schema).
- **Gen-2.5-exclusive parameters listed:** `hd_texture`, `texture_delight`, `texture_mode`, `is_micro`,
  `geometry_instruct_mode` — but `texture_mode`'s value set and the texture-resolution matrix are not
  given, and `hd_texture` is described only as "Enable 4K texture generation".
- **Image input guidance (README):** "Use high-resolution images (at least 512 x 512 pixels)"; "Supported
  formats: JPEG, PNG, WEBP"; "File size limit: 16MB"; "Resolution range: 512x512 to 4096x4096".
- **Result URLs expire:** "Download links expire in 10 minutes… Do not store or cache the URLs
  themselves."
- **Polling defaults:** `poll_interval` 10 s, `max_retries` 60.
- **Error codes** in SKILL.md (`INSUFFICIENT_FUND`, `Invalid tier`) do not match the API reference's
  enumerated codes (`API_INSUFFICIENT_FUNDS`, `INVALID_REQUEST`), so the skill's error table is
  approximate.

## What this establishes

- Gen-2.5 has an official first-party developer integration, which corroborates the API reference's tier
  and face-count tables independently of the docs site.
- **The vendor's own tooling lags its documentation.** Three months before capture, the official skill
  still defaulted to `faithful`, priced `HighPack` at +1 credit, and described `hd_texture` as a 4K
  switch — all superseded by the July/August 2026 changes. Anyone integrating from this repo inherits
  stale defaults.
- The 512×512–4096×4096 and 16 MB image limits and the 10-minute download-URL expiry appear nowhere in
  the API reference; this is the only captured source for them.
- Gen-1/1.5 is deprecated according to first-party tooling, while the API reference still documents it
  as a live family. Both are true as of capture: deprecated in guidance, still served.

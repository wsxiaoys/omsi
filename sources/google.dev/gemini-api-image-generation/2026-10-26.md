# Google Gemini API docs: image generation guide ("Nano Banana")

- Origin: Google, "Nano Banana image generation", https://ai.google.dev/gemini-api/docs/image-generation
- Evidence kind: official documentation (first-party developer guide)
- Publication date: not stated; page is continuously edited. Content described here is the
  state of the page as served on the capture date.
- Capture date: 2026-10-26
- Relevant models: Nano Banana 2 (`gemini-3.1-flash-image`), with adjacent entries for Nano
  Banana 2.1 (`gemini-nano-banana-2.1`), Nano Banana 2 Lite
  (`gemini-3.1-flash-lite-image`), Nano Banana Pro (`gemini-3-pro-image`), and Nano Banana
  (`gemini-2.5-flash-image`).

## Captured content

### Model selection (verbatim, Nano Banana 2 entry)

> **Nano Banana 2** (Gemini 3.1 Flash Image) (`gemini-3.1-flash-image`): The
> previous-generation high-efficiency workhorse model, balancing speed with 4K generation,
> world knowledge, and multi-reference image consistency. Recommended for all new projects to
> use Nano Banana 2.1.

The same list gives, in the vendor's own words, Nano Banana 2.1 as "An update to Nano Banana
2, serving as the primary high-efficiency workhorse model", Nano Banana 2 Lite as "The
fastest and cheapest Gemini image model", Nano Banana Pro as "The premium choice for the most
complex visual tasks", and Nano Banana (`gemini-2.5-flash-image`) as "The legacy pioneer of
the Nano Banana series". Every generated image is stated to carry a SynthID watermark.

### Features (verbatim, relevant sentences)

> **High-resolution output**: Built-in generation capabilities for 1K, 2K, and 4K visuals.
> Gemini 3.1 Flash Image adds the smaller 512px (0.5K) resolution (not supported on Gemini
> Nano Banana 2.1).

> **Advanced text rendering**: Capable of generating legible, stylized text for infographics,
> menus, diagrams, and marketing assets.

> **Grounding with Google Search**: The model can use Google Search as a tool to verify facts
> and generate imagery based on real-time data (e.g., current weather maps, stock charts,
> recent events).

> Gemini Nano Banana 2.1 and Gemini 3.1 Flash Image add the integration of Google Image
> Search Grounding alongside Web Search.

> **Thinking mode**: The model utilizes a "thinking" process to reason through complex
> prompts. It generates interim "thought images" (visible in the backend but not charged) to
> refine the composition before producing the final high-quality output.

> **Up to 14 reference images**: Mix up to 14 reference images to produce the final image.

> Gemini Nano Banana 2.1 and Gemini 3.1 Flash Image are optimized for speed and high-volume
> use-cases, and Gemini 3 Pro Image is optimized for professional asset production.

### Reference-image budget (verbatim table, including its own header defect)

The page's "Use up to 14 reference images" table has three columns and **no row-label
column**, so each row reads as three per-model values:

| Gemini 3.1 Flash Lite Image | Gemini Nano Banana 2.1 & Gemini 3.1 Flash Image | Gemini 3 Pro Image |
| --- | --- | --- |
| Up to 14 images of objects with high-fidelity to include in the final image | Up to 10 images of objects with high-fidelity to include in the final image | Up to 6 images of objects with high-fidelity to include in the final image |
| N/A | Up to 4 images of characters to maintain character consistency | Up to 5 images of characters to maintain character consistency |
| N/A | N/A | Up to 3 images to be used as style references |

Read literally: `gemini-3.1-flash-image` allows 10 object images plus 4 character images
(14 total), while `gemini-3-pro-image` allows 6 + 5 + 3. The prose elsewhere only says "up to
14 reference images", which is the total, not the object count.

### Thinking levels (verbatim table)

| Model | Supported thinking levels | Default |
| --- | --- | --- |
| Gemini Nano Banana 2.1 | minimal, medium, high | medium |
| Gemini 3.1 Flash Image | minimal, high | minimal |
| Gemini 3.1 Flash Lite Image | minimal, high | minimal |

### Output sizes for Gemini 3.1 Flash Image (summary of verbatim table)

The per-model aspect-ratio table for Gemini 3.1 Flash Image lists **14 aspect ratios** —
`1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9` — each with
512px, 1K, 2K and 4K pixel dimensions. Token counts per output image are constant per
resolution tier, not per ratio: 747 tokens at 512px (512×512), 1120 at 1K (1024×1024), 1680 at
2K (2048×2048), 2520 at 4K (4096×4096). The neighbouring Nano Banana 2.1 table has the same
14 ratios but no 512px column; the Flash Lite table has only 10 ratios (no 1:4/1:8/4:1/8:1).

### Limits and caveats (verbatim)

> For best performance, use the following languages: EN, ar-EG, de-DE, es-MX, fr-FR, hi-IN,
> id-ID, it-IT, ja-JP, ko-KR, pt-BR, ru-RU, ua-UA, vi-VN, zh-CN.

> Image generation does not support audio inputs. Video inputs are only supported for Gemini
> Nano Banana 2.1, Gemini 3.1 Flash Image, and Gemini 3.1 Flash Lite Image.

> The model won't always follow the exact number of image outputs that the user explicitly
> asks for.

> `gemini-2.5-flash-image` works best with up to 3 images as input, while `gemini-3-pro-image`
> supports 5 images with high fidelity, and up to 14 images in total. `gemini-nano-banana-2.1`
> and `gemini-3.1-flash-image` support character resemblance of up to 4 characters and the
> fidelity of up to 10 objects in a single workflow.

> When generating text for an image, Gemini works best if you first generate the text and then
> ask for an image with the text.

> `gemini-nano-banana-2.1` and `gemini-3.1-flash-image` Grounding with Google Search do not
> support using real-world images of people from web search at this time.

Video-to-image generation is documented as available for Nano Banana 2.1, Gemini 3.1 Flash
Image and Gemini 3.1 Flash Lite Image: a public YouTube URL or an uploaded video can be passed
as multimodal context alongside the text prompt.

## Known gaps

- No per-model pricing on this page; prices live on the separate pricing page.
- No latency or quality benchmarks; capability statements are unquantified.
- The reference-image table has no row labels, so the object/character split is inferred from
  column order and from the Limitations paragraph, which states the same 10-object / 4-character
  figures. The two agree, but the table itself is malformed.
- The page does not date individual feature additions, so it cannot be used to establish when
  a capability (e.g. 512px output or Image Search grounding) reached Nano Banana 2.

## Additional Nano Banana 2.1 detail (verbatim, from the same capture)

The 2.1 per-aspect-ratio table has the same 14 ratios as Gemini 3.1 Flash Image but no 512px
column: `1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9`. Token counts
per output image are constant per resolution tier, not per ratio: 1120 at 1K, 1680 at 2K, 2520 at
4K.

Image Search grounding is scoped: "This feature is only available for the Gemini Nano Banana 2.1
and Gemini 3.1 Flash Image models", enabled by setting `search_types` to
`["web_search", "image_search"]` on the `google_search` tool.

### Contradictions with other first-party pages

- **4K token count: 2520 here vs 3780 on the pricing page.** Same model, same 4096x4096 size.
- "Thought images [...] not charged" here, while the pricing page bills "text and thinking" as
  output tokens. These can both be true (thought *images* uncharged, thought *text* charged) but
  the pages never reconcile them.
- The 2.1 table's `2:3` 1K entry reads 848x1264 while `3:2` reads 1264x848 — consistent, but note
  the 1K figures are ~1.07 MP rather than exactly 1 MP, so "1K" is a bucket name, not a pixel
  count.

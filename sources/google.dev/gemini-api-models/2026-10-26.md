# Google Gemini API docs: models catalogue

- Origin: Google, "Models", https://ai.google.dev/gemini-api/docs/models
- Evidence kind: official documentation (first-party model catalogue)
- Publication date: not stated; continuously edited.
- Capture date: 2026-10-26
- Relevant models: the Nano Banana family entries, in particular Nano Banana 2 →
  `gemini-3.1-flash-image`.

## Captured content

### Card descriptions (verbatim)

> Nano Banana 2.1 — High-efficiency image generation and editing model with improved visual
> quality, typography, and multi-turn consistency. (`New`, `Stable`)

> Nano Banana 2 — Powerful, high-efficiency image generation and editing, optimized for speed
> and high-volume use cases. (`Stable`)

> Nano Banana 2 Lite — Ultra-low latency and cost-effective image generation and editing,
> designed for high-volume interactive use cases. (`Stable`)

> Nano Banana Pro — State-of-the-art image generation and editing models for highly contextual
> native image creation. (`Stable`)

> Nano Banana — State-of-the-art native image generation and editing designed for fast,
> creative workflows. (`gemini-2.5-flash-image`, listed under the Gemini 2.5 models)

### Name-to-endpoint table (verbatim rows)

| Model | Endpoint |
| --- | --- |
| Nano Banana 2.1 | `gemini-nano-banana-2.1` |
| Nano Banana 2 | `gemini-3.1-flash-image` |
| Nano Banana 2 Lite | `gemini-3.1-flash-lite-image` |
| Nano Banana Pro | `gemini-3-pro-image` |
| Nano Banana | `gemini-2.5-flash-image` |

This is the first-party resolution of the "Nano Banana" marketing names to Gemini model IDs.
Two details matter for identity:

- Nano Banana 2 and Nano Banana 2 Lite map to Gemini **3.1** model IDs
  (`gemini-3.1-flash-image`, `gemini-3.1-flash-lite-image`).
- Nano Banana 2.1 does **not** follow that pattern: its ID is `gemini-nano-banana-2.1`, a
  marketing-derived identifier rather than a Gemini generation identifier. Nano Banana Pro
  likewise keeps a generation-derived ID, `gemini-3-pro-image`.

## Known gaps

- The catalogue gives no release dates, deprecation dates or prices; those are on the
  changelog, deprecations and pricing pages.
- The status chips (`New`, `Stable`) are not defined on this page; `Stable` does not state a
  support window.
- The catalogue does not say which image model is recommended for new work; that judgement
  appears only in the image generation guide, and it differs from the `Stable` chip shown here
  for Nano Banana 2.
- It lists no knowledge cutoff, token limit or modality matrix per model; those are on the
  individual model pages.

- Capture date: 2026-10-26
- Relevant models: HeyGen Avatar V (`avatar_v`), Avatar IV

## Captured content (verbatim, Avatar V entries in changelog order)

**Added - October 2026 — "Avatar V blinking"**

> `POST /v3/videos` now accepts `"more_blinking": true` in `engine` for Avatar V, for avatars that
> blink too little.

**Changed - August 2026 — "Avatar V Photo Fallback"**

> When an Avatar V photo avatar's group has no eligible digital-twin or curated reference look, video
> creation now renders directly from the photo instead of rejecting the request.
>
> * The fallback works when `reference_look_id` is omitted and no eligible look can be selected
>   automatically.
> * `motion_prompt` still requires an animation reference for Avatar V photo avatars.

**Changed - June 2026 — "Motion Prompt Enhancements"**

> * Updated `motion_prompt` in `POST /v3/videos`: Now supports natural-language control for both body
>   motion and hand gestures. Expanded support for photo avatars across both engines. **Added support
>   for video avatars specifically when using `engine.type: 'avatar_v'`.**

**Changed - May 2026 — "Video Engine Updates & Brand Kit Support"**

> * **Breaking Change:** The `engine` property in `POST /v3/videos` now requires an object structure
>   (e.g., `{"type": "avatar_v"}`) instead of a string. `ApiAvatarEngine` has been removed.
> * **Video Scaling:** Added a new optional `fit` parameter …
> * **Parameter Constraints:** Note that `expressiveness` and `motion_prompt` in `POST /v3/videos` are
>   now strictly for Avatar IV and are not supported when `engine.type` is set to `avatar_v`.

**Added - May 2026 — "Support for Stock TTS and Engine Selection"**

> * **Video Generation:** Added an optional `engine` field to `POST /v3/videos` (for
>   `CreateVideoFromAvatar` requests). You can now explicitly select between Avatar IV and Avatar V
>   engines. If omitted, the system defaults to Avatar IV.

**Changed - April 2026 — "API Documentation Overhaul"**

> * **Video Generation**: `POST /v3/videos` now officially documents support for the Avatar IV engine
>   and **upcoming Avatar V**.

Adjacent entries used for dating: "Custom Watermark Controls — Added - April 30, 2026"; "Corrected
`avatar_video.success` Webhook Payload Fields — Fixed - May 11, 2026".

## Summary

The changelog gives the API-side timeline: Avatar V was described as "upcoming" in the April 2026 docs
overhaul, selectable via an `engine` string in May 2026, converted to the current object form in the
same month, extended to `motion_prompt` on video avatars in June 2026, given a photo-avatar fallback in
August 2026, and given `more_blinking` in October 2026.

Two entries matter beyond dating. The May 2026 constraint ("`expressiveness` and `motion_prompt` …
are not supported when `engine.type` is set to `avatar_v`") was partially reversed by the June 2026
entry, which restores `motion_prompt` for video avatars on `avatar_v`. And the August 2026 fallback
means an Avatar V request can silently render from a photo with no animation reference.

## Gaps

- Month-level dates only; no exact day for any Avatar V change.
- No entry announces Avatar V's availability to end users — the API entries are about the `engine`
  field, and the product launch is dated separately by the blog post.
- No entry explains why 4K is documented as an Avatar III capability while hosts expose 4K for Avatar V.
- The changelog is ordered newest-first and paginated; only the captured page was read.

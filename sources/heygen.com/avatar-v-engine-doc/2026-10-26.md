## Captured content (verbatim)

Page summary line:

> Avatar V is HeyGen's highest-fidelity v3 rendering engine, using cross-reference-driven
> animation for the most natural motion and lip-sync. Opt-in per look.

> **Supported avatar types:** `digital_twin`, `studio_avatar`, and `photo_avatar` looks that list
> `avatar_v` in `supported_api_engines`.

> **Supported parameters**
>
> `motion_prompt` — natural-language control of body motion and hand gestures.
>
> `engine.reference_look_id` (optional) — a `digital_twin` look to use as the animation reference.
> Must belong to the same avatar group as `avatar_id`, and a non-public one must clear its group's
> consent requirements. When omitted, a digital twin or studio avatar references itself, and a
> photo avatar uses an eligible look from its group. A photo avatar with no eligible look renders
> directly from its image, and `motion_prompt` is then rejected.
>
> `engine.more_blinking` (optional): set to `true` for more natural blinking. Defaults to `false`.
>
> For **expressiveness** control, use [Avatar IV](https://developers.heygen.com/avatar-iv).

> **Checking eligibility**
>
> Avatar V is opt-in per look. Before using it, fetch the look and check `supported_api_engines`:
> `GET /v3/avatars/looks/{look_id}` … Avatar V is available when `"avatar_v"` appears in
> `supported_api_engines`.

Request example (verbatim body):

```json
{
  "type": "avatar",
  "avatar_id": "YOUR_LOOK_ID",
  "script": "Hello from Avatar V.",
  "voice_id": "YOUR_VOICE_ID",
  "resolution": "1080p",
  "engine": { "type": "avatar_v" }
}
```

> Video generation is asynchronous — the response returns a `video_id` you poll with
> `GET /v3/videos/{video_id}`.

## Summary

- Avatar V is addressed as an **engine selection** on `POST /v3/videos` (`engine.type = "avatar_v"`),
  not as a separate endpoint. There is no first-party "Avatar V model ID".
- It is **opt-in per look** and gated by an eligibility array the caller must read first. Nothing on
  this page says how a look becomes eligible or whether newly created avatars default into it.
- Supported look types: digital twin, studio avatar, photo avatar.
- Unique parameters versus Avatar IV: `reference_look_id`, `more_blinking`, and `motion_prompt` for
  *video* avatars (Avatar IV rejects `motion_prompt` for those). `expressiveness` is explicitly not
  available on Avatar V.
- Generation is asynchronous with a poll loop. No real-time/latency statement appears anywhere on
  the page.

# HeyGen: `POST /v3/videos` API reference (avatar request schema)

- Origin: HeyGen API reference, "Create Video" — <https://developers.heygen.com/reference/create-video>
  (OpenAPI-derived page; Markdown at `/reference/create-video.md`, 79 KB). Fields transcribed from the
  `CreateVideoFromAvatar` request body and its referenced schemas.
- Evidence kind: official API schema (first-party)
- Publication date: none stated on the page. The changelog dates the current `engine` object shape and
  the `fit` parameter to May 2026 and custom watermark controls to 2026-04-30. Capture date 2026-10-26.
- Capture date: 2026-10-26
- Relevant models: HeyGen Avatar V (`avatar_v`); Avatar IV and III for contrast

## Captured content (verbatim schema descriptions)

Endpoint summary:

> Creates an avatar video: a HeyGen avatar or an image speaks your script or audio with lip-sync.
> Choose Avatar III, IV or V with `engine` (Avatar IV by default). To generate a whole scene from a
> prompt instead, use POST /v3/models/videos.

`engine` (on `CreateVideoFromAvatar`):

> Engine configuration for video generation. Pass {"type": "avatar_v"} to enable
> cross-reference-driven animation for higher quality. Check supported_api_engines on the avatar look
> to confirm eligibility. Defaults to Avatar IV when omitted.

`AvatarVEngineConfig`:

> Avatar V engine configuration with cross-reference-driven animation.
>
> `type` — Must be 'avatar_v'. Check `supported_api_engines` on the avatar look to confirm
> eligibility.
>
> `reference_look_id` — Optional look to use as the animation reference. When provided, it must be a
> `digital_twin` look accessible to your workspace and in the same avatar group as `avatar_id`
> (`studio_avatar` and `photo_avatar` looks are rejected). When omitted, video avatars self-reference
> and photo avatars select from their group's eligible candidates, preferring digital twins … then
> curated public studio looks. A photo avatar whose group has no eligible reference renders directly
> from its image without one; motion_prompt is rejected in that case. A non-public `digital_twin`
> reference, whether provided or selected automatically, must also satisfy its group's consent
> requirements.
>
> `more_blinking` — Ask Avatar V for more natural blinking. … Rejected for a photo avatar whose group
> has no animation reference (no digital twin or curated reference look), and in `studio` videos.

`motion_prompt`:

> Natural-language prompt controlling avatar body motion and hand gestures. Supported for photo
> avatars on either engine, and for video avatars when engine.type is 'avatar_v'. Rejected for video
> avatars on the default Avatar IV engine, and for photo avatars on 'avatar_v' when the avatar's group
> has no animation reference.

`expressiveness`:

> Avatar expressiveness level. Photo avatars only. Defaults to 'low' when omitted. Avatar IV only;
> rejected when engine.type is 'avatar_v'.

`resolution` (`VideoResolution`):

> Output video resolution. `4k` is available for Avatar III digital twins and studio avatars.

Enum: `4k`, `1080p`, `720p`.

`aspect_ratio` (`VideoAspectRatio`): enum `16:9`, `9:16`, `4:5`, `5:4`, `1:1`, `auto`. `auto` "preserve[s]
the source's aspect ratio … short-edge anchored to the requested resolution and capped at the tier's
long edge".

`output_format`: `mp4` (default) or `webm`; "webm" returns a video with a transparent background (alpha
channel)" and "requires an avatar that supports matting"; when webm is selected "any 'background' value
is rejected and background removal is applied automatically".

`remove_background`: "Remove the avatar background. Video avatars must be trained with matting
enabled."

`watermark`: "Custom watermark image to overlay on the video (PNG or JPEG). Available as a premium
option for select Enterprise customers."

`caption`: "A sidecar subtitle file is always returned via subtitle_url; set 'style' to additionally
burn captions into the rendered video."

`script` / `audio_url` / `audio_asset_id`: script is "Mutually exclusive with audio_url/audio_asset_id";
`voice_id` is "Required when script is provided, unless avatar_id is set (the avatar's default voice is
used as fallback)".

`fit`: "How the subject is fitted to the output canvas. 'cover' scales to fill the frame (may crop
edges). 'contain' scales to fit entirely within the frame".

## Summary

The vendor schema is the authoritative statement of what an Avatar V request accepts: an engine
object with `reference_look_id` and `more_blinking`, optional `motion_prompt`, no `expressiveness`, and
a resolution enum that offers `4k` but attributes it to Avatar III.

That last point is the key contradiction with the hosts: HeyGen's own field description says 4K belongs
to Avatar III digital twins and studio avatars, while fal and Replicate both expose `4k` on their
Avatar V endpoints with no caveat. The schema does not say what happens if a caller sends
`resolution: "4k"` with `engine.type: "avatar_v"`.

## Gaps

- No per-engine output-resolution table; only the one-line note that 4K is an Avatar III capability.
- No latency, generation-time, or throughput information.
- No error taxonomy for engine/eligibility failures on this page (the Avatar Looks reference documents
  `invalid_parameter` for an unlisted engine).
- The `watermark` field is Enterprise-gated per this description, while both hosts expose a watermark
  object on their endpoints; the hosts' relationship to that gate is not stated anywhere captured.

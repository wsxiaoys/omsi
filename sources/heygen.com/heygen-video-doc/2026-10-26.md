## Identity (verbatim)

> **HeyGen Video is our general-purpose video model, built on MiniMax H3 and post-trained by
> HeyGen.** Give it a prompt and it generates the whole scene: subject, setting, light and sound
> together, in one call. Text-to-video and image-to-video clips can run 5 to 30 seconds with
> compatible settings; reference-to-video stays at 5 to 15 seconds. Each clip has its own audio track
> of dialogue, ambience and sound effects, so there is no separate speech pass, lip-sync step or
> avatar to pick.
>
> One model, `heygen-video-1`, called in three ways:

| Mode | You give it | You get |
| - | - | - |
| **Text to video** (`text_to_video`) | A prompt | A new scene with its sound |
| **Image to video** (`image_to_video`) | A prompt and one image | A clip that opens on your image as its first frame |
| **Reference to video** (`reference_to_video`) | A prompt and your images, videos or audio | A new scene that keeps the products, people or places you supplied |

> It is a different tool from the avatar rendering engines behind `POST /v3/videos`. Those animate a
> look you already own from a script you already wrote. This one invents the subject, the setting, the
> light and the sound at once, from a description.

Endpoints: create `POST /v3/models/videos`, retrieve `GET /v3/models/videos/{video_id}`; the same job
is readable through `GET /v3/videos/{video_id}`. Auth is an `x-api-key` header; scopes `videos:write`,
`videos:read`, `assets:write`. Submission returns `202` with `{"data": {"status": "pending",
"video_id": "…"}}`; terminal states are `completed`, `failed`, `cancelled`; failures carry
`failure_code` (`generation_failed` or `generation_cancelled`). `Idempotency-Key` retries within 24 h
return the original response; a concurrent duplicate returns `409`. "This route runs on paid API
keys."

## Parameters (verbatim table)

| Field | Type | Default | Notes |
| - | - | - | - |
| `model` | string | required | `heygen-video-1` |
| `mode` | enum | `reference_to_video` | `text_to_video`, `image_to_video`, `reference_to_video` |
| `prompt` | string | required | 1 to 32,000 characters |
| `duration` | integer or `auto` | `5` | Whole seconds from 5 to 30 for compatible text-to-video and image-to-video requests; otherwise 5 to 15 |
| `resolution` | enum | `768p` | `480p`, `768p`, `1080p` or `2k`. `1080p` and `2k` bill at 3× the `768p` rate |
| `prompt_enhancement` | enum | `quality` | `turbo`, `quality`, `ultraquality` or `disabled` |
| `aspect_ratio` | enum | see below | `21:9`, `16:9`, `4:3`, `1:1`, `3:4` or `9:16`, plus `adaptive` for `reference_to_video`. `image_to_video` follows the first frame |
| `seed` | integer | random | Unsigned 32-bit. Random when omitted |
| `callback_url` / `callback_id` | string | | HTTPS only / at most 256 characters |
| `image` | asset | | `image_to_video` only, required there |
| `reference_images` / `reference_videos` / `reference_audio` | array | `[]` | `reference_to_video` only |

"The schema is strict: unknown fields are rejected rather than ignored." Mode aliases `t2v`, `i2v`,
`ref2va` are accepted; a field from another mode returns `400` when it carries a value.

## Duration limits (verbatim)

| Request settings | Explicit duration | `auto` range |
| - | - | - |
| `text_to_video` or `image_to_video`, with `turbo` or `quality` | 5–30 seconds | 8–30 seconds |
| `reference_to_video`, or `ultraquality` or `disabled` enhancement | 5–15 seconds | 8–15 seconds |
| HeyGen Video through MCP, on any plan | 5–15 seconds | 8–15 seconds |

"An explicit duration above the limit for your settings is rejected rather than shortened."

**Auto duration** counts words inside double quotes at 2.5 words per second, adds one second of
lead-in, rounds up, applies an 8-second minimum and the mode maximum: "60 quoted words select 25
seconds"; "A prompt without quoted dialogue selects 8 seconds."

## Output (verbatim)

| | |
| - | - |
| Container | MP4, H.264 |
| Frame rate | 24 fps, rounded up to the next whole frame: a 7-second request encodes 175 frames |
| Audio | AAC, 32 kHz stereo, generated dialogue and effects |
| Delivery | HTTPS URL on the job record |

`resolution` names a size class and `aspect_ratio` sets the shape; explicit ratios resolve to fixed
pixel sizes:

| `aspect_ratio` | `2k` | `1080p` | `768p` | `480p` |
| - | - | - | - | - |
| `21:9` | | | 1536 × 672 | 960 × 416 |
| `16:9` | 2688 × 1536 | 1890 × 1080 | 1344 × 768 | 832 × 480 |
| `4:3` | | | 1024 × 768 | 640 × 480 |
| `1:1` | | | 768 × 768 | 480 × 480 |
| `3:4` | | | 768 × 1024 | 480 × 640 |
| `9:16` | 1536 × 2688 | 1080 × 1890 | 768 × 1344 | 480 × 832 |

"`1080p` and `2k` render in `16:9` or `9:16`." `text_to_video` defaults to 16:9; `reference_to_video`
defaults to `adaptive` (aspect of the first reference image, else first reference video);
`image_to_video` always follows the first frame "including its EXIF orientation". Adaptive output is
scaled to the short edge of the resolution with each side rounded to a multiple of 32 ("A 1280 × 852
reference at `480p` returns 736 × 480").

## References (verbatim)

"In `reference_to_video`, list order becomes the label you address in the prompt": `<Picture 1>`,
`<Video 1>`, … "The API does not rewrite these labels."

| List | Maximum |
| - | - |
| `reference_images` | 9 |
| `reference_videos` | 3 |
| `reference_audio` | 3 |
| Total across all three | 12 |

"The model reads the first 5 seconds of each reference video, so longer clips are trimmed to that
length before generation." Each reference accepts an HTTPS URL, an uploaded asset ID, or inline
base64. Size ceilings: image by URL 16 MB; video/audio by URL 32 MB; image as base64 5 MB;
video/audio as base64 16 MB. "URLs are fetched server side with SSRF checks … The fetcher does not
follow redirects."

## Prompt enhancement (verbatim)

`turbo` (fastest), `quality` (default, balanced), `ultraquality` (highest quality, slowest),
`disabled` (prompt goes to the model exactly as written). `default` is accepted as a legacy alias for
`turbo`.

## Vendor capability claims (labelled as claims)

"Every clip on this page is raw model output, with the audio it generated." Claimed strengths: scenes
that hold together ("Objects stay the same size and shape, stay where they were put, and obey
physics"); literal prompt following ("If you did not ask for dialogue, you do not get dialogue");
picture and sound generated from the same prompt; and "Holding an object you supply" in
`reference_to_video`. Claimed weak spots, stated by the vendor itself: "It is least reliable on long
on-screen text, soft organic motion such as petals, paper and hair, and close hand work like
assembling or operating equipment." Also: "Long prompts beat short ones. A few hundred to a few
thousand characters gives materially better output."

Twelve styles are "a prompt variable", not a model parameter. Seeds: "the same prompt and the same
seed, submitted in succession, return an identical file", but "Treat a seed as reproducible within a
deployment rather than as a permanent handle on one render."

## Internal contradictions

- **Prompt length:** this page says `prompt` is "1 to 32,000 characters"; the create-video API
  reference (same capture date) says `maxLength: 16000`. fal's schema says 32,000.
- **Reference total:** the table above lists 9 + 3 + 3 = 15 items but states "Total across all three
  | 12". The API reference says "up to fifteen references in total", which matches the arithmetic.
- **Mode default:** `mode` defaults to `reference_to_video`, which requires references — so a request
  that omits `mode` and supplies only a prompt fails validation. The docs state the default without
  flagging this.

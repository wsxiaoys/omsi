Two size classes exist: **~220.7 M parameters** (Swin-L class, including `dynamic` and `HR`) and
**~44.4 M parameters** (`lite`, `lite-2K`, `lite-matting`, Swin-T class). There is no BiRefNet
checkpoint of any other size on this account.

All cards except `BiRefNet-DIS5K-TR_TEs` declare `license: mit` in card metadata; every card's body
links a "License-MIT" badge. No card carries a commercial-use restriction, an acceptable-use
policy, or a gating prompt.

## Model card text

The `BiRefNet`, `BiRefNet_lite` and `BiRefNet_lite-2K` cards are the same repository README with
short per-variant notes (e.g. "## How to use (this tiny version)" for `lite`). The shared opening
(verbatim):

> This repo is the official implementation of "[**Bilateral Reference for High-Resolution
> Dichotomous Image Segmentation**](https://arxiv.org/pdf/2401.03407.pdf)" (___CAAI AIR 2024___).
>
> Visit our GitHub repo: [https://github.com/ZhengPeng7/BiRefNet](https://github.com/ZhengPeng7/BiRefNet)
> for more details -- **codes**, **docs**, and **model zoo**!

`BiRefNet_dynamic` carries an extra section (verbatim):

> An arbitrary shape adaptable BiRefNet for general segmentation.
> This model was trained on arbitrary shapes (256x256 ~ 2304x2304) and shows great robustness on
> inputs with any shape.
>
> ## Performance
> How it looks when compared with BiRefNet-general (fixed 1024x1024 resolution) -- greater than
> BiRefNet-general and BiRefNet_HR-general on the reserved validation sets (DIS-VD and
> TE-P3M-500-NP).
> The `dynamic_XXxXX` means this BiRefNet_dynamic model was being tested in various input
> resolutions for the evaluation.

The `dynamic` performance statement is illustrated with images only; no numeric table is given in
the card, so the claim ("greater than BiRefNet-general and BiRefNet_HR-general on DIS-VD and
TE-P3M-500-NP") cannot be checked against numbers in this record.

Cards also link a project page at `https://www.birefnet.top`, which returned HTTP 401 / "Forbidden"
behind a parked-domain redirect on capture (see
[project page record](../../birefnet.cv/birefnet-project-page/2026-10-26.md) for the other project
URL). The `BiRefNet` card's own "Page" badge points at `birefnet.top`, while the GitHub repo's
`homepage` field points at `birefnet.cv`.

## Gaps

- Cards do not state input resolution per checkpoint except through the shared README (ONNX
  "Input resolution is `1024x1024` by default") and the `dynamic` note (256–2304). Native
  resolutions for `lite-2K` (2560x1440) and `HR` (2048x2048) come from the GitHub README news
  items, not from the cards themselves.
- No card reports evaluation numbers for its own checkpoint; the numbers live in the GitHub model
  zoo table.
- `lastModified` dates in 2026-02/2026-08 are metadata or README edits; the cards do not say
  whether weights changed.
- HF download counts mix direct `transformers`/`pth` users, Spaces, and inference endpoints, so they
  do not separate hosted inference from local use.

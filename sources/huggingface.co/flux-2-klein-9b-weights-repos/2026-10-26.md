## What this establishes

- **Four separate obtainable checkpoints**, all published on the same day (2026-01-14):
  distilled 9B, Base 9B, distilled 4B, Base 4B. None is a rename of another; the four repos
  have distinct download counts and distinct file counts (9B repos carry 29 files, 4B repos 25).
- **Licence split follows size, not variant**: both 9B checkpoints are
  `flux-non-commercial-license` and **gated**; both 4B checkpoints are `apache-2.0` and
  **ungated**. So the "open weights" headline is fully open only for the 4B.
- The distilled 9B repo has roughly **2.2x** the downloads of the Base 9B repo, and the Base
  4B repo has more downloads than the distilled 4B — i.e. for 4B, the community reaches for the
  fine-tunable Base first, while for 9B it reaches for the distilled model first. This is a
  usage signal, not a quality measurement.
- Repo creation dates place all four weights **one day before** BFL's 2026-01-15 launch post
  (`../../bfl.ai/flux2-klein-9b-release-notes/2026-10-26.md`).

## Gaps

- `downloads` is a 30-day count on the capture date, not a lifetime figure.
- No `config.json` was readable for the gated 9B repos, so parameter counts were not verified.
- HF metadata does not say which repo, if either, the BFL API's `flux-2-klein-9b` endpoint
  serves, nor whether the Base checkpoints back the `-kv-finetuned` endpoint.

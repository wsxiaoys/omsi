## Differences from the distilled card — verbatim

> This repository holds the undistilled base checkpoint, for fine-tuning, LoRA training and
> research. You can find the distilled checkpoint here: FLUX 3 Image Klein.

> Train on this base checkpoint; it was trained without step or guidance distillation. The
> distilled checkpoint is intended for generation and editing rather than as the starting point
> for these training workflows.

The checkpoint table on this card still lists both rows, with Klein Base as "undistilled,
bfloat16, 50 steps, guidance 3.5, fine-tuning / LoRA training / research" and Klein as
"distilled, bfloat16, 16 steps, no guidance, generation and editing, self-hosting; the checkpoint
behind the BFL API".

### Hardware (verbatim) — note the higher quantized figures

> Peak GPU memory with the reference code, B200, 1024x1024, prompt upsampler off: 31 GB in BF16,
> **29 GB in FP8, 26 GB in NVFP4**. The prompt upsampler adds about 28 GB on an 80 GB GPU.

(The distilled card gives 26 GB FP8 / 25 GB NVFP4 for the same configuration.)

## What this establishes

- The base checkpoint is **5.6B parameters as well** — the two variants differ in distillation, not
  size.
- Base is the **fine-tuning target**; the distilled checkpoint is explicitly discouraged as a
  training starting point.
- Base costs more memory than distilled at the same quantization, as expected for a 50-step
  CFG model.
- Base is published as weights only: no API endpoint is offered for it in BFL's docs, and its
  model card lists Hugging Face as the sole availability.

## Gaps

- No training-dataset description, no licence difference from the distilled checkpoint, and no
  guidance on how many images a usable LoRA needs beyond BFL's docs example (20 images).
- No indication whether LoRAs trained on Base transfer to the *API* (which serves distilled);
  BFL's docs describe Base→Distilled transfer for self-hosting only.
- Same gated-repo limitation as the distilled card: `LICENSE.md` was not retrievable.

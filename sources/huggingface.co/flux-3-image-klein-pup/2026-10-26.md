## Model card — verbatim

> FLUX 3 Image Klein Prompt Upsampler is a 9B vision-language model that expands a short image
> request into the detailed prompt FLUX 3 Image Klein works best with. It takes the request, up to
> 10 reference images and an optional list of bounding boxes, and returns one prompt. It is a
> fine-tune of Qwen3.5-9B.

> FLUX 3 Image Klein is not meant to run without a prompt upsampler in front of it, for
> text-to-image, editing and layout alike; a short prompt sent to the image model as typed gives
> generic output. This one is tuned for it [...] Any other LLM can do the job with the system
> prompts in system_prompts.json.

Training:

> A full fine-tune of Qwen3.5-9B with the vision tower frozen, in two stages: supervised training
> on pairs of short requests and their expanded prompts, then preference tuning on pairs of the
> model's own prompts, rendered with FLUX 3 Image Klein at the same seed and ranked on the
> resulting image.

Decoding settings stated: greedy, `top_p 0.95`, `top_k 20`, `presence penalty 1.5` for
text-to-image and `0` for edits; `max_new_tokens=3584`; thinking disabled. `system_prompts.json`
holds four prompts: `t2i`, `i2i`, `t2i_bbox`, `i2i_bbox`.

### Limitations (verbatim list)

> * Output is English. The request can be in any language.
> * The prompts are written for FLUX 3 Image Klein; no other image model was part of training.
> * Reference images are resized before the model sees them (at most 1 MP for one reference, less
>   for several), so small details in a reference can be described wrongly.
> * **The model does not refuse requests.** The inference code wraps it with optional prompt and
>   image checks (--safety).

Licence: "This model is released under the Apache License 2.0. It is derived from Qwen3.5-9B by
the Qwen team at Alibaba Cloud, released under the Apache License 2.0."

## What this establishes

- Klein's practical prompt path is a **separate 9B VLM with its own 18.8 GB download and ~28 GB
  GPU footprint**, and it is Apache-2.0 — a different licence from the image model.
- The image model's quality depends on a component with its own failure modes: English-only
  output, lossy reference downscaling (≤1 MP), and no refusal behaviour.
- The upsampler is replaceable by any LLM given the same system prompts, so the "must use an
  upsampler" constraint is about caption *format*, not about this particular model.

## Gaps

- No measurement of how much quality is lost without the upsampler; BFL asserts "noticeably
  weaker" / "generic output" without numbers.
- No latency figure for the upsampling pass, which the reference CLI runs inline and the BFL API
  performs server-side (per BFL's launch post). End-to-end API latency therefore includes it.
- Whether the hosted API uses this exact checkpoint (and which decoding settings) is not stated.

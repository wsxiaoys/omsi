## Model card — verbatim

> FLUX 3 Image Klein is a 5.6B open weights model for text-to-image generation and image editing.
> It takes a prompt and up to 10 reference images and returns one image. Text-to-image,
> single-reference edits and multi-reference compositions run through the same model, with
> Qwen3-VL-4B-Instruct as the text encoder.

> The 5.6B parameter label refers to the image transformer; the text encoder is separate.

> This repository holds the distilled checkpoint for generation and image editing. For
> fine-tuning, LoRA training and research, use FLUX 3 Image Klein Base.

Checkpoint table, verbatim:

| Checkpoint | Format | Steps | Guidance | Built for |
| --- | --- | --- | --- | --- |
| Klein Base | undistilled, bfloat16 | 50 | 3.5 | fine-tuning, LoRA training, research |
| Klein | distilled, bfloat16 | 16 | none | generation and editing, self-hosting; **the checkpoint behind the BFL API** |

Key features:

> * Text-to-image, single-reference editing and multi-reference generation in one model.
> * Bounding boxes in the prompt. Place elements with boxes on a 0 to 1000 grid, then recolor,
>   move, replace or remove them through the prompt. **Boxes guide placement and scale; they do
>   not constrain pixels to a hard mask.**
> * Text rendering within generated images.

Prompt-upsampling warning:

> Do not use the model without a prompt upsampler. FLUX 3 Image Klein takes full scene captions,
> for text-to-image, editing and layout with boxes alike; a short prompt sent as typed gives
> generic output.

Prompting notes:

> The caption controls composition; reference images anchor content, they do not lock structure.

> For edits, the prompt upsampler writes the caption from the instruction and the references: a
> complete caption of the reference with the edit folded in.

### Limitations (verbatim list)

> * This model is not intended or able to provide factual information.
> * While the model can output text, text rendered may be inaccurate or subject to distortion.
> * As a statistical model, this checkpoint may represent or amplify biases observed in the
>   training data.
> * The model may fail to generate output that matches the prompts.
> * Prompt following is heavily influenced by the prompting style. Short prompts produce generic
>   output.
> * Boxes set placement and scale, not a hard mask: an element can extend past its box, and small
>   requested elements may not appear. Edits can change content outside the requested region.

### Hardware (verbatim)

> Peak GPU memory with the reference code, B200, 1024x1024, prompt upsampler off: 31 GB in BF16,
> 26 GB in FP8, 25 GB in NVFP4. The prompt upsampler adds about 28 GB on an 80 GB GPU.

## What this establishes

- Independent (platform-measured) confirmation of the parameter count and checkpoint size.
- The distilled checkpoint — the one served by the BFL API — is documented as **CFG-free, 16
  steps**, and the model expects **full scene captions**, not short prompts.
- Klein's bounding boxes are a **soft layout control**, not a mask; the card says so explicitly
  and warns that edits can change content outside the requested region.
- Licence scope: non-commercial plus a commercial *output* exception under $5M revenue;
  commercial fine-tuning and distribution are explicitly outside it.
- Measured memory floor with the reference code is **25–31 GB** at 1024×1024 on a B200 — the
  8 GB / RTX 3090 claims elsewhere refer to quantized builds and a different framework.

## Gaps

- The card's own hardware numbers are for the reference implementation on a B200 and exclude the
  prompt upsampler (+~28 GB), so they describe the *maximum* configuration, not the minimum.
  Nothing here states the memory needed by the INT8 ComfyUI build.
- No benchmark results, no comparison to FLUX 3 Image, no latency numbers.
- The `LICENSE.md` file itself is behind the gated-repo wall and was not retrieved, so the
  Qualifying-User definition, attribution clauses and output-ownership terms are known only
  through the card's summary and BFL's marketing pages.
- Downloads and likes are point-in-time popularity signals, not quality evidence.

The only differences between the Olmo 3 32B base config and the two 3.1 configs are cosmetic (the base
sets `use_cache: true`; the 3.1 configs set `use_cache: false`, and the Think config is formatted with
spaces). Positional capacity is unchanged at 65,536 tokens.

```json
  "max_new_tokens": 32768

```

Both checkpoints ship the same default sampling configuration, matching the Think card's recommended
settings. The Instruct card's own inference snippet instead uses `top_k=50, top_p=0.95` with no
temperature.

## Summary

3.1 is architecturally the same model as Olmo 3 32B: a 64-layer dense transformer, hidden 5120, 40 query
heads with 8 KV heads (GQA), vocabulary 100,278, a 4,096-token sliding window on three of every four
layers, and a **65,536-token** maximum context reached by YaRN extension (factor 8) of an 8,192-token
base. Nothing in the configs distinguishes 3.1 from Olmo 3 32B except the sampling defaults and the
`use_cache` flag.

## Gaps

- `config.json` does not state the parameter count. Deriving it from the fields (≈32B) matches the
  "32B" label and Artificial Analysis's 32.2B, but the vendor never prints a number in these files.
- No tokenizer file captured here, so the vocabulary size is known but the tokenizer family is not
  documented in this record.
- The 65,536 figure is the positional-embedding ceiling; neither config states a recommended practical
  context length or whether long-context degradation was measured for the 3.1 checkpoints specifically.

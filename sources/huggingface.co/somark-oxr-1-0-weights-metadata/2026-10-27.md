## `config.json`, selected keys verbatim

- `architectures`: `["OXR"]`; `model_type`: `oxr`; `dtype`: `bfloat16`; `hidden_size`: 1024.
- `conversation_formatter_class`: `Qwen3ConversationFormatter`.
- `llm_config._name_or_path`: **`Qwen/Qwen3-0.6B-Base`**; `llm_config.architectures`:
  `["Qwen3ForCausalLM"]`; `llm_config.hidden_size`: 1024; `layer_types` is a list of
  `full_attention` entries.
- `eos_token_id` 151643, the Qwen3 base end-of-text id.

The `llm_config` block is a nested copy of a Qwen3-0.6B-Base configuration, i.e. the language
backbone is initialised from that checkpoint rather than trained from random weights. That is a
statement about initialisation, not about the training data or the number of tokens seen.

## What the artefact set establishes

- The model is a **single 3.07 GB BF16 file** plus a **79 MB layout checkpoint**; the "1.3B" label
  in the card does not match the 1,534,378,216 BF16 parameters in the safetensors header
  ([card](../../huggingface.co/somark-oxr-1-0-model-card/2026-10-27.md)).
- Inference requires custom code: `modeling_oxr.py` and an out-of-tree vLLM plugin ship inside the
  weights repository, so a stock `transformers` or `vLLM` install cannot load it unaided.
- The olmOCR-bench numbers in the wiki's sense are **vendor-reported**, and the same figures are
  what the Hugging Face official-benchmark map reads as the #1 entry.

## Gaps

- No commit-level provenance for the evaluation run, no seed, no evaluator commit hash.
- `layout_analysis/metadata.json` (718 bytes) records identity and a SHA-256 for the layout
  checkpoint according to the repository's own README, but was not fetched here.
- No quantised or GGUF variants in the official repository at capture; the only quantisations
  found were third-party ([MLX](../../huggingface.co/oxr-1-0-mlx-8bit/2026-10-27.md)).

# Ideogram developer docs: Generate with Ideogram 4.5 (API reference)

- Origin: Ideogram developer documentation, "Generate with Ideogram 4.5",
  https://developer.ideogram.ai/api-reference/images/generate/ideogram-4-5 (Markdown:
  https://developer.ideogram.ai/api-reference/images/generate/ideogram-4-5.md)
- Evidence kind: official documentation (first-party API reference)
- Publication date: none stated
- Capture date: 2026-10-26
- Relevant models: Ideogram 4.5 (endpoint `POST https://api.ideogram.ai/v2/image/generate/ideogram-4-5`,
  `multipart/form-data`)

## Captured content

### Summary (verbatim)

> Generate images with Ideogram 4.5 from a natural-language or structured JSON prompt. Optionally
> upload source images as `images` using `multipart/form-data` to edit them with the prompt.

### Parameters that constrain behavior (verbatim)

- `prompt`: "The prompt to generate images from, or the edit instruction when source images are
  supplied. Natural language or a structured Ideogram 4.0 JSON prompt."
- `magic_prompt`: "`auto` (the default) and `on` rewrite and expand the prompt before generation.
  `off` keeps your wording and only converts it into a structured prompt. […] With source images,
  every mode converts the edit instruction into a structured edit prompt."
- `images`: "Optional source images to edit (max 5, max 25MB each; JPEG, PNG, or WEBP). The first
  image is the one being edited; any others are extra references. Multipart requests only."
- `mask`: "An optional mask that limits the edit to part of the first source image (max 25MB […])
  Black marks the area to edit and white the area to keep; values in between are rounded to the
  nearer of the two. The mask must have the same width and height as the first source image and
  contain both black and white areas. A masked request can include at most three other source
  images. With a mask, the output is always the first source image's own size, so `size` cannot
  be set."
- `size`: "Without source images, an exact size must be one of the supported 1K/2K presets (for
  example 1024x1024, 2048x2048 or 1440x2880); 'auto' or omitted picks a supported size based on
  the prompt. 'source' is rejected. With source images, 'auto' (the default) picks a supported 2K
  size based on the source images and the prompt, and 'source' returns the output at the first
  source image's own width and height (scaled down, keeping its proportions, if it is too large
  for the model). Every source image's aspect ratio must be between 1:6 and 6:1. An exact size
  must have both sides a multiple of 32 and at least 256px, a total of at most 2048x2048 pixels,
  and an aspect ratio of at most 6:1."
- `quality`: "Defaults to `medium` with source images and `high` without. `very_low`, the fastest
  and cheapest, requires source images."
- `background`: "`transparent` returns images with an alpha channel, `opaque` returns a solid one,
  and `auto` decides for you."
- `enable_copyright_detection`: "Run copyright detection on the generated images. Adds latency;
  flagged images are returned with `is_image_safe: false`."

### Pricing basis (verbatim)

> Pricing is tiered by the resolved output pixels: up to 1024x1024 bills as 1K, above that as 2K.
> An "auto" size bills as 2K.

This is the only captured statement that resolution affects the Generate price. It conflicts with
the product page's "does not change with […] the output resolution"
([model page](../ideogram-4-5-model-page/2026-10-26.md)) and with both hosts' single
price-per-quality schedules. The size of the 2K premium is not published anywhere captured.

### Errors relevant to capability claims (verbatim)

- `402`: `reject_reason` enum includes `insufficient_funds`, `subscription_required`,
  `daily_limit`, `priority_credit_required`, `inflight_limit`, `feature_limit`.
- `422`: "The prompt did not pass safety checks."

### Other

- `dry_run=true` validates and prices without generating: "nothing is generated, stored, or
  billed, and no safety review is performed."
- Async: `async` or `webhook_url` returns `generation_id`; webhooks are Ed25519-signed and
  verifiable against `https://api.ideogram.ai/v1/.well-known/jwks.json`.

## Known gaps

- No published price table in the reference itself; prices live on the marketing page and in the
  app's usage-cost list, which is not publicly crawlable.
- The reference does not say whether quality tiers differ by checkpoint, sampling budget, or
  post-processing.

## Verbatim, by question

**Vision / images**

> Mercury 3, Mercury 2.5, Mercury 2, and Mercury Edit 2 accept text input only, and image
> generation is not supported. Mercury Decide accepts images in a decision's state and
> instructions.

**Sampling / reproducibility**

> No. The chat completions request schema does not accept a `seed` parameter, and `temperature` on
> `mercury-3`, `mercury-2.5`, and `mercury-2` is restricted to the range 0.5–1.0. Values outside
> that range are silently reset to the model's default (0.75 for `mercury-2`, 1 for `mercury-2.5`)
> and the response includes a `warning` field noting the reset. Bit-exact reproducibility across
> runs is not supported today.

**Caching**

> Prefix caching is automatic and requires no request parameter. … The API does not expose a
> documented TTL or a way to pin, invalidate, or inspect cache entries.

**Fine-tuning / embeddings**

> Fine-tuning is not available through the public API. There is no fine-tuning endpoint …

> No. Inception's API covers chat completions (`/v1/chat/completions`), fill-in-the-middle
> completions (`/v1/fim/completions`), and code edit completions (`/v1/edit/completions`). There is
> no `/v1/embeddings` endpoint or embedding model.

**Billing units**

> Responses include a `usage` object with token counts, but not a dollar-cost field … Cached
> prompt tokens use the cached-input rate; completion tokens, including reasoning tokens, use the
> output rate.

**Data retention**

> Data handling for the Inception API is covered by the Privacy Policy and Terms of Use. Custom
> data-handling arrangements, including zero-retention configurations for regulated workloads, are
> handled case by case.

**Free credit**

> Every new account includes a one-time credit of 100 million free tokens. The credit is shared
> across all models rather than granted per model.

**MCP**

> The API does not include a dedicated MCP (Model Context Protocol) server or endpoint. Mercury 3
> supports OpenAI-compatible tool calling … Set the base URL to `https://api.inceptionlabs.ai/v1`,
> provide your API key, and set the model to `mercury-2.5`.

## Reading

- **Text-only is explicit and vendor-confirmed**, which is the sharpest capability boundary for
  Mercury 3: no images, no files, no vision.
- **No `seed` and a clamped temperature of 0.5–1.0** make Mercury 3 unsuitable for deterministic
  pipelines. Note the clamp sentence names only `mercury-2` and `mercury-2.5` defaults, so
  Mercury 3's default temperature is not stated in this answer; the models page's sample request
  uses `temperature: 0.75`.
- **The MCP answer names `mercury-2.5` while answering a Mercury 3 question** — an internal
  inconsistency in the docs. It is a doc bug, not evidence that Mercury 3 lacks tool calling (the
  Tool Use page documents Mercury 3 tool calling).
- Caching is implicit and unpinnable: cost control is a function of prompt-prefix stability, not
  of an API surface.

## Gaps

- No statement of Mercury 3's default temperature, context-truncation behaviour at 1M tokens, or
  what happens when `max_completion_tokens` exceeds the 131,072 ceiling.
- Retention is described by reference to external policies; no concrete TTL is given.

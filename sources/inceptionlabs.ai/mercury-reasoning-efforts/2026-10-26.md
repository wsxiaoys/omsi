## Verbatim

> `reasoning_effort` controls how much the model deliberates before answering. It applies to
> `mercury-3`, `mercury-2.5`, and `mercury-2` on the chat completions endpoint and accepts four
> values:

| Value | Latency | Best for |
| - | - | - |
| `instant` | Lowest | Voice, realtime turns, high-volume automations |
| `low` | Low | Latency-sensitive chat and tool-calling |
| `medium` | Balanced | General-purpose use |
| `high` | Highest | Complex, multi-step reasoning |

> If `reasoning_effort` is omitted, `mercury-3` defaults to `low`, while `mercury-2.5` and
> `mercury-2` default to `medium`.

## Reading

- Mercury 3 has the same four effort levels as its predecessors; what changed is the **default**
  (`low` rather than `medium`), consistent with the latency-first positioning.
- Reasoning cannot be turned off with a documented switch — `instant` is the lowest documented
  setting, and it is still a reasoning mode. No `reasoning: {"enabled": false}` or "none" value
  is documented here.
- This contradicts OpenRouter, which publishes `supported_efforts: ["high","medium","low","none"]`
  and `default_effort: "medium"` for the same model
  (`../../../openrouter.ai/mercury-3/2026-10-26.md`). Either OpenRouter maps `instant` to `none`
  and defaults differently, or its metadata is wrong; both are recorded.

## Gaps

- No statement of what each level costs in tokens or latency, and no per-level benchmark.
- No documentation of whether reasoning tokens are billed separately (the FAQ says completion
  tokens including reasoning are billed at the output rate).

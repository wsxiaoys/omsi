## Verbatim

> Inception API supports streaming output and diffusion effect modes:
>
> * **Streaming:** Get responses block-by-block for instant feedback—ideal for chat and live
>   applications. A "block" is a chunk of refined text the model emits as it decodes, rather than
>   one token at a time.
> * **Diffusing:** Optionally visualize how noisy outputs are refined into final text, showcasing
>   the model's iterative denoising process.

> Set `diffusing` to `true` to stream the model's intermediate denoising steps. Each chunk
> contains the full text as it is refined into the final answer.

> The diffusing effect is best shown by overwriting the displayed text on each step.

## Reading

- This is the only first-party description of the **serving semantics** that distinguishes a
  diffusion LLM from an autoregressive one: streaming arrives in **refined blocks**, and each
  `diffusing` chunk is the **whole text so far**, not an increment. Client code that appends
  deltas will duplicate text in diffusing mode; the documented pattern is overwrite.
- `diffusing` is an Inception-specific request parameter outside the OpenAI schema, so it is
  unlikely to survive a generic OpenAI-compatible client or a third-party router.
- No statement of block size, number of denoising steps, or whether block boundaries are stable
  across requests.

## Gaps

- No latency or throughput figures, and no explanation of how `reasoning_effort` interacts with
  the number of denoising steps.
- Nothing about how stop sequences or structured output behave with block-level refinement.

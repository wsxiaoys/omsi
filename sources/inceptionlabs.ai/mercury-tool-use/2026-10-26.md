- Evidence kind: first-party API documentation.
- Publication date: none stated (living docs page). Capture date 2026-10-26.
- Relevant models: `mercury-3`; the FIM/edit endpoints and Mercury Edit 2 are excluded.

## Verbatim

> Mercury 3 supports OpenAI-compatible tool calling on the chat completions endpoint, including
> parallel tool calls. You define functions the model may call; when the model decides tools are
> needed, it returns one or more `tool_calls` with JSON arguments. You then execute the functions
> and send the results back so the model can produce a final answer.

The page's examples use `"model": "mercury-3"` throughout, including a read-only coding-agent
example that defines `list_directory` and `read_file` tools.

Related, from the API reference index
(`https://docs.inceptionlabs.ai/llms.txt`, captured the same day): the chat completions endpoint
"Supports tool calling, structured output via `response_format`, and reasoning controls", while
the FIM endpoint and the edit endpoint both state "Tool calling and function calling are not
supported".

## Reading

- Tool use is a **chat-completions feature of the reasoning models**, and Mercury 3 is the model
  every example names. Parallel tool calls are documented explicitly.
- Structured outputs (`response_format`) is the other named capability, and the models table
  lists exactly those two features for Mercury 3.
- No MCP server exists; the FAQ tells MCP users to point an OpenAI-compatible client at
  `https://api.inceptionlabs.ai/v1` (`../mercury-api-faq/2026-10-26.md`).

## Gaps

- No maximum tool count, schema-size limit, or statement about tool-call reliability.
- No documentation of how tool results interact with the reasoning/denoising loop.

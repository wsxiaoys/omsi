## Captured content

### Output formats (verbatim, abridged to the format facts)

> Multiple audio formats are available via API to support different application requirements. The
> default is MP3.

| Format | Sample rate | Depth / bit rate |
| --- | --- | --- |
| MP3 | 16 kHz – 48 kHz | 32 kbps – 320 kbps |
| PCM | 8 kHz – 48 kHz | 16-bit signed LE, no header |
| WAV | 8 kHz – 48 kHz | 16-bit signed LE with header (first chunk only when streaming) |
| LINEAR16 | 8 kHz – 48 kHz | 16-bit signed LE with WAV header, kept for backward compatibility |
| Opus | 8 kHz – 48 kHz | 32 kbps – 192 kbps |
| μ-law | 8 kHz | compressed telephony |
| A-law | 8 kHz | compressed telephony |

### Model-scoped controls — this is where TTS-1.5 differs from TTS-2

- **Delivery mode** (`STABLE`, `BALANCED`, `CREATIVE`): "Only supported by `inworld-tts-2`."
- **Temperature**: "Not supported by `inworld-tts-2`." Higher values increase variation; "The
  default is 1.0." The default of 1.0 is stated for the current docs set, not for TTS-1.5 — see the
  Replicate schema record, which gives 1.1 for `realtime-tts-1.5-max`.
- **Talking speed**: 0.5–1.5, "1.0 is the normal native speed".
- **Language**: if unset, "the language will be auto-detected from the input text".
- **Synthesis context**: prior-turn text via `synthesisContext`.

### Voices and cloning

> Regardless of model, a voice delivers the best speaker similarity when synthesizing text in its
> native language — the language it was cloned in.

"For greater customization, we recommend voice cloning … with as little as 3 seconds of audio."

## Summary

The formats/sample-rate table is the vendor's current statement of what the TTS API can emit:
MP3/WAV/PCM/LINEAR16/Opus at up to 48 kHz, plus 8 kHz telephony encodings. It is written for the
TTS-2 family and does not name TTS-1.5, so applying it to TTS-1.5 is an inference — corroborated,
but not stated, by the two host schemas.

## Gaps

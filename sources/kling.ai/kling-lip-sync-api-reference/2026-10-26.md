| Operation | Method | Path |
| --- | --- | --- |
| Create task | POST | `/v1/videos/advanced-lip-sync` |

Base URL in every example: `https://api-singapore.klingai.com`.

## Verbatim: request body

`session_id` (string, **required**) —

> Session ID generated during the identify face API. It remains unchanged during the selection/editing
> process.

`face_choose` (array, **required**) —

> Specified Face for Lip-Sync. Includes Face ID, lip movement reference data, etc.
> Currently only supports one person lip-sync.

Child attributes of `face_choose`:

- `face_id` (string, required) — "Face ID. Returned by the facial recognition interface."
- `audio_id` (string, optional) —

  > Sound ID Generated via TTS API. Only supports audio generated within the last 30 days with a
  > duration of no less than 2 seconds and no more than 60 seconds. Either audio_id or sound_file must
  > be provided (mutually exclusive; cannot be empty or both populated).

- `sound_file` (string, optional) —

  > Supports Base64-encoded audio or accessible audio URL. Accepted formats: .mp3/.wav/.m4a/.aac (max
  > 5MB). … Only supports audio with a duration of no less than 2 seconds and no more than 60 seconds.
  > … The system will verify the audio content and return error codes if there are any problems.

- `sound_start_time` / `sound_end_time` (long, required) — crop points in ms from the original audio;
  "the cropped sound must not be shorter than 2 seconds"; end "shouldn't be later than the total
  duration of the original sound".
- `sound_insert_time` (long, required) —

  > The time range for inserting sound should overlap with the face's lip-sync time interval for at
  > least 2 seconds. The start time for inserting sound must not be earlier than the start time of the
  > video, and the end time for inserting sound must not be later than the end time of the video.

- `sound_volume` (float, optional, default 1, range 0–2) — inserted-audio volume.
- `original_audio_volume` (float, optional, default 1, range 0–2) —

  > Original video volume (higher values = louder) … No effect if source video is silent.

- `watermark_info` (object, optional) — `{"enabled": boolean}`; "true: generate watermarked result,
  false: do not generate. Custom watermarks are not currently supported".
- `external_task_id`, `callback_url` (optional).

### The source video is not in this request

The lip-sync call takes no `video_url` and no `video_id`. The video enters through the Face
Recognition call, whose `session_id` this endpoint consumes. The two calls are one workflow.

## Verbatim: response shape

Task result:

```
"task_info": { "parent_video": { "id", "url", "duration" } },
"task_result": { "videos": [ { "id", "url", "watermark_url", "duration" } ] },
"watermark_info": { "enabled": boolean },
"final_unit_deduction": "string",
"final_balance_deduction": { "quota", "list_price" }
```

- `videos[].url` — "URL for generating videos (Please note that for security purposes, generated
  images/videos will be deleted after 30 days. Please save them promptly.)"
- `videos[].watermark_url` — "Watermarked video download URL, anti-hotlinking format"
- `videos[].duration` — "Total video duration, unit: s"
- `task_status_msg` — "displaying the failure reason when the task fails (such as triggering the
  content risk control of the platform, etc.)"

**No output resolution, frame rate, container or channel count appears anywhere in the reference.**
The response carries a URL and a duration only.

## Summary

The vendor's lip-sync API is a two-step, audio-driven service: identify faces in a video, then apply
speech or singing to one chosen face at a chosen insertion time, with independent volumes for the new
audio and the original track and an optional watermark. Audio may be an uploaded file (mp3/wav/m4a/aac,
≤5 MB, 2–60 s) or a TTS-generated `audio_id` from the last 30 days. There is no text→lip-sync path at
the vendor: text has to pass through the TTS API first.

Billing is per task (`final_unit_deduction`), and the vendor price list bills lip sync per 5 seconds of
video.

## Gaps

- Output resolution, frame rate, container and audio channel count are undocumented. The input is
  constrained to 720p/1080p, so a pass-through is plausible but not stated.
- `face_choose` says "Currently only supports one person lip-sync", while the vendor's API changelog
  records a 2025-09-15 update that added "multi person screen lip-sync". Unreconciled (see the
  changelog record).
- The page does not say what happens to the video's own audio when `original_audio_volume` is left at
  its default of 1 alongside an inserted segment — mix, duck, or overlap.
- No moderation policy is linked; the only signal is the "content risk control" phrase in
  `task_status_msg`.

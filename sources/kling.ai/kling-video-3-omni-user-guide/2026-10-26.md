### Input limits (FAQ, verbatim)

> **Images**: You can upload up to 7 images with a width and height of at least 300 px, file size ≤
> 10MB, and formats .jpg / .jpeg / .png.

> **Videos**: You can upload one video with a duration between 3s and 10s, file size ≤ 200MB, and
> resolution ≤ 2k.

> **Elements**: […] up to 4 [images from multiple perspectives] […] you can also upload a 5-30s
> single-person speech audio […] you can upload a 3-8s video clip of a single character to create a
> more vivid and informative video character element.

> **Note**: When a video is provided, a total of up to 4 images/elements can be uploaded. If no video
> is provided, up to 7 images/elements can be uploaded.

## Summary

First-party documentation for the Omni surface of the Kling 3.0 generation, published 2026-02-06. It
establishes three things this knowledge base relies on:

1. **The O-line is the Omni line.** The vendor states that "the Kling VIDEO O1 model has been upgraded
   to VIDEO 3.0 Omni", so O1 and 3.0 Omni are consecutive versions of one lineage, distinct from
   VIDEO 2.6 → VIDEO 3.0.
2. **Video-input requests are the editing path, and native audio is not available with them.** The
   credit table lists "With Video Input" rows only for "Native Audio Off", with "Not Supported Yet"
   in both audio-on cells.
3. **Source-video limits are 3–10 s, ≤ 200 MB, ≤ 2K**, and supplying a video drops the reference
   budget from 7 images/elements to 4.

The guide names no "O3" and no API model ID; it is written for the Kling AI product, not the
developer API.

## Gaps

- No output frame rate, bit depth, audio channel count, or container beyond the mp4 examples.
- The credit figures are consumer credits, not API dollars; no exchange rate is given here.
- "Video editing … function the same as in O1" is a pointer, not a specification: this page never
  describes the editing parameter surface, and no dedicated 3.0-Omni editing doc was found.
- No date for when 4K became available for Omni, and this page lists only 1080p and 720p.
- No statement of how a video-input request prices the *output* length (whether it follows the source
  clip).

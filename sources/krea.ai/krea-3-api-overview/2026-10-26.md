## Captured content

### Positioning and availability (verbatim)

> Krea 3 is a fast image editing model. It follows plain-language instructions: you say what should
> change and what should stay the same, and Krea 3 produces the edit in seconds. You can also use it
> for text-to-image generation.

> The Krea 3 API is available to every workspace. The `fast` and `high` thinking modes do not require
> beta access. The `ultra` thinking mode requires a Max plan or above.

Endpoint: `POST /generate/image/krea/krea-3`. The docs also use `image/krea/krea-3` as the SDK/MCP
model ID. Output is at `result.urls[0]` after polling `GET /jobs/{job_id}`.

### Parameters (verbatim table, abridged to the substantive rows)

| Field | Type | Notes |
| - | - | - |
| `prompt` | string | The editing instruction. Optional if at least one bounding box contains a note. |
| `image_urls` | array of strings | Optional. Input image references, up to 8. Include at least one for an edit; omit for text-to-image. |
| `thinking_mode` | enum | Optional. `fast` (default), `high`, or `ultra`. |
| `priority` | enum | Optional. `low`, `normal`, or `high`. Default `normal`. `low` queues behind other work. `high` currently queues the same as `normal`. |
| `resolution` | enum | Optional. `1K` or `2K`. Lowercase accepted. When omitted, the output is 1K. |
| `aspect_ratio` | enum | `1:1`, `4:5`, `3:4`, `2:3`, `9:16`, `5:4`, `4:3`, `3:2`, `16:9`, `21:9`; omit for automatic framing. |
| `width` / `height` | integers | Up to 4096 each. Set both together; cannot combine with `aspect_ratio` or `resolution`. |
| `seed` | integer | Omit for random. |
| `negative_prompt` | string | Up to 1,024 characters. |
| `regions` | array of regions | Bounding boxes, up to 24. |
| `regional_edit` | boolean | Local edit that keeps the rest of the image exact. Needs at least one input image. |

The docs warn that with `width`/`height` "the output is rounded to the nearest supported aspect
ratio and a 1K or 2K canvas. Exact pixel dimensions are not guaranteed." They also state that
reusing a seed "does not guarantee identical results, because the prompt expansion step can vary
between runs."

### Thinking modes (verbatim table)

> Before it generates, Krea 3 interprets your prompt. `thinking_mode` sets how much planning it does.

| Mode | What happens | Use for |
| - | - | - |
| `fast` | Krea quickly expands the prompt, then generates. Fastest. **Default and recommended.** | Clear, simple edits and most everyday requests. |
| `high` | Krea uses a stronger reasoning engine to plan more complex edits from the prompt and the reference images, then generates. Slower. | Complex or multi-step edits, several references to combine, or a `fast` result that missed the request. |
| `ultra` | Krea generates several candidates, reviews them against your prompt and references, and returns the best one. Always 2K. Slowest: a job can take several minutes. | Final, high-stakes edits where quality matters more than speed or cost. |

This is the substantive documentation of what "thinking mode" changes: prompt expansion at `fast`,
planning by a "stronger reasoning engine" at `high`, and candidate generation plus selection at
`ultra`. The docs do not name the reasoning model, publish its size, or give any measured quality
delta between modes.

### Ultra constraints (verbatim bullets)

- Available to workspaces on a Max plan or above. Other workspaces get a `402` with
  `K3_ULTRA_ACCESS_REQUIRED`.
- Include at least one image in `image_urls`. A text-only request with `ultra` runs as `fast` and is
  billed as `fast`.
- The output is always 2K. Omit `resolution` or set it to `2K`.
- Use `aspect_ratio` to set the shape. `width` and `height` are not supported.
- `negative_prompt`, `loras`, and `style_urls` are not supported.
- Zero Data Retention is not supported.
- Each request produces one image. A run can take up to about 10 minutes, or about 16 minutes with
  `priority: "low"`.

### Regional edits and bounding boxes (verbatim)

> With `regional_edit: true`, Krea 3 regenerates only the parts of the image that need to change.
> Everything else stays exactly as it was, so you can edit the same image again and again without
> quality loss.

> Regular edits re-render the whole image, so artifacts can build up when you keep editing the
> latest output.

Bounding boxes: coordinates 0–1 as a fraction of width/height, up to 24 regions, optional `label`
referenced as `@label` in the prompt or another box's note, and `prompt` optional when at least one
box has a note.

### Image references (verbatim)

> Krea 3 uses each reference at its uploaded resolution. A reference larger than 4 MP is resized to
> 4 MP.

> Around 1 MP is enough for most edits. Do not upscale a reference before you send it.

> With five or more references in one request, each reference is resized to at most 1536 px on its
> longest side. For full-detail references, send four or fewer.

### Zero Data Retention (verbatim bullets)

- Every image in `image_urls` must be a base64 data URI.
- `thinking_mode` can be `fast` or `high`; `ultra` with images returns a `422`.
- A request can use up to 8 image references.
- Bounding boxes are supported.

### Pricing (verbatim table)

| Pricing component | 1K output | 2K output |
| - | - | - |
| Base price | $0.03 | $0.06 |
| Each 1K reference image | +$0.02 | +$0.02 |
| Each 2K reference image | +$0.07 | +$0.07 |
| `high` thinking mode | +$0.02 per generation | +$0.02 per generation |
| `ultra` thinking mode | Not available | +$0.20 per generation |

So the first-party schedule is per output tier plus a per-reference charge that depends on the
reference's 1K/2K class, not a per-input-megapixel rate. Hosts price differently; see the
[fal](../../fal.ai/krea-3/2026-10-26.md) and [Replicate](../../replicate.com/krea-3/2026-10-26.md)
records.

### Not yet available (verbatim)

Sending `loras` returns `LoRAs are coming soon to the API.`; sending `style_urls` returns
`Style references are coming soon to the API.`

## Gaps

- No architecture, model size, training description, or technical report link. Contrast Krea 2,
  whose docs page links a technical report.
- No benchmark, quality comparison, or measured latency. "Most edits in seconds" and the mode
  descriptions are unquantified.
- The page says "up to 8" references, while the launch post says 6.
- "Stronger reasoning engine" is not identified. Whether `high` is a separate model, a tool-using
  loop, or a longer prompt-expansion pass is not stated.
- The exact pixel dimensions of a "1K" or "2K canvas" are not given; only the 4096 per-side cap and
  the rounding rule.
- The docs do not state a moderation/safety policy for first-party calls.

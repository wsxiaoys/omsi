# Krea changelog: Krea 3 entries (2026-10-15 to 2026-10-26)

- Origin: Krea documentation, "Krea changelog", https://www.krea.ai/docs/changelog
  (read through https://docs.krea.ai/llms-full.txt). This record extracts the Krea 3 entries from the
  site-wide weekly changelog; the source document is the changelog, not a Krea 3-only page.
- Evidence kind: official documentation (vendor changelog)
- Publication date: entries dated 2026-10-01 through 2026-10-26; Krea 3 entries quoted below are
  dated 2026-10-15, 2026-10-20, 2026-10-23, 2026-10-24, and 2026-10-26
- Capture date: 2026-10-26
- Relevant models: Krea 3 (API, Ultra mode, bounding boxes, regional edits, Zero Data Retention)

## Captured content

### 2026-10-15 — launch day: "Krea 3 API in early access, with Zero Data Retention and renamed thinking modes"

Verbatim:

> **Edit images with plain-language instructions through the API.** Krea 3 is a fast image editing
> model. Describe what should change and what should stay the same, and Krea 3 returns the edit in
> seconds. It also handles text-to-image generation.
>
> * Combine up to 8 reference images in one request.
> * Pick the `fast` thinking mode for everyday edits, or `high` for complex, multi-step edits.
> * Turn on regional edits to change only part of an image and keep the rest pixel-exact. This lets
>   you chain edits without quality loss.
> * Output at 1K or 2K. Pricing starts at $0.03 per 1K image.
>
> The API is open to workspaces in the Krea 3 beta. To request access, contact
> [sales@krea.ai](mailto:sales@krea.ai).

Zero Data Retention section, same date:

> Enterprise workspaces can now use Krea 3 with Zero Data Retention. Both thinking modes are
> supported. References must be sent as base64 data URIs, with up to 4 per request.

Thinking-mode rename section, same date:

> **The legacy Krea 3 `thinking_mode` values sunset on October 23, 2026.** Send `fast` instead of
> `instant`, and `high` instead of `medium`. Until then, the old values still work. After the sunset
> date, requests that use them are rejected.

This establishes that the modes were originally named `instant`/`medium`/`max` and were renamed to
`fast`/`high`/`ultra` at/after launch, and that the API was a gated beta on launch day even though
the app and partner endpoints were live.

### 2026-10-20 — "Krea 3 Ultra in the API, Krea 3 out of beta"

Verbatim:

> **Set `thinking_mode` to `ultra` for your highest-quality Krea 3 edits.** Krea generates several
> candidates, reviews them against your prompt and references, and returns the best one at 2K.
>
> * Available on Max plans and above.
> * Requires at least one reference image.
> * Jobs can take several minutes, so use a webhook or poll with a long timeout.
> * Adds $0.20 per generation.

The same entry is titled with "Krea 3 out of beta", and adds "Krea 3 is now in the iOS image model
picker" and "Text-only Krea 3 image prompts submit right away, with no confirmation pop-up."

### 2026-10-23 — bounding boxes require `high`

Verbatim:

> **Pass `regions` to point Krea 3 at specific areas of your reference images.** Each box can carry
> its own `note`, so you can give different instructions for different parts of an image.
>
> * Coordinates run from 0 to 1 as a fraction of image width and height.
> * Up to 24 regions per request.
> * Refer to a box with `@label` in your prompt or in another box's note.
> * `prompt` is optional when at least one box has a note.
> * Requires `thinking_mode: "high"`.

Also: "The legacy Krea 3 `thinking_mode` values now sunset on October 30, 2026, instead of October
23." and the rename list now includes `ultra` instead of `max`.

### 2026-10-24 — bounding boxes no longer require `high`

Verbatim:

> **You can now send `regions` and `regional_edit` with `thinking_mode: "ultra"` in the API.**
> Bounding boxes no longer require `high`.

Zero Data Retention note:

> * `thinking_mode: "ultra"` with images still returns a `422` under Zero Data Retention.
> * Text-only `ultra` requests are accepted and run as `fast`.

This supersedes the 2026-10-23 "Requires `high`" bullet. The current API overview no longer states a
mode requirement for bounding boxes.

### 2026-10-26 — free images

> **Every plan now includes 9 free Krea 3 images.**

## Contradictions and evolution captured here

- **API status:** 2026-10-15 "open to workspaces in the Krea 3 beta" vs 2026-10-20 "Krea 3 out of
  beta" vs current docs "available to every workspace". The page records this as a transition, not a
  contradiction.
- **Zero Data Retention reference cap:** 4 per request on 2026-10-15 vs 8 in the current API
  overview. The cap changed or the changelog was wrong; unresolved.
- **Thinking-mode sunset:** October 23 on 2026-10-15, moved to October 30 on 2026-10-23.
- **Bounding-box mode requirement:** required `high` on 2026-10-23, removed on 2026-10-24.

## Gaps

- The changelog is a weekly product feed, not a complete release history; entries may omit changes.
- It gives no quality or benchmark data for `high`/`ultra`.
- It does not name the Berry/Jam variants or explain how they relate to thinking modes.
- It records 8 references on 2026-10-15, the same day the launch post said 6, so it does not
  resolve that conflict.
- It does not mention the default output resolution, so a change to or from the 1K default would not
  be visible here.

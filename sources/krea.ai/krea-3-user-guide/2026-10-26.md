## Captured content

### What Krea says it is (verbatim)

> Krea 3 is Krea's newest image model and the default image model in the app. It generates images
> from text and edits existing images from plain-language instructions. Most edits finish in under
> 8 seconds at native 2K resolution, while keeping products, characters, logos, and text consistent.

> Krea 3 is available to everyone in the app and uses compute units like other models. Check the
> model picker for the cost of your selected settings. **Krea 3 Ultra** is available on Max plans
> and above.

### Ownership classification (verbatim)

The docs split the app's models into two tables. Krea 3 is in the first:

> **Krea models** are developed and maintained by Krea:

with the row: "Krea 3 | Krea's newest model and the app default. Fast text-to-image and image
editing at native 2K, with consistent products and characters."

The second table, "**Third-party models** are provided by external AI labs", lists Google, ByteDance,
and Recraft models. This is the explicit first-party statement that Krea 3 is Krea's own model, not a
hosted third-party model.

### Positioning against Krea 2 (verbatim)

> Choose **Krea 3** for fast, instruction-following generation and editing, especially when a
> product or character must stay consistent. Choose **Krea 2** for aesthetic exploration with
> weighted style references, moodboards, LoRAs, and Generative Sliders, or **Krea 2 Turbo** for
> low-cost style iteration.

> Krea 3 does not yet support the Krea 2 API's style-reference or LoRA controls. Image references
> for editing are different from weighted style references.

### Model overview row (verbatim)

| Model | Images per generation | Compute units | Seconds per generation | Maximum resolution |
| - | - | - | - | - |
| Krea 3 | See model picker | See model picker | Most edits under 8 | **2K native** |

The same overview lists Krea 3 as supporting aspect ratio and image prompt, and marks character
reference with an asterisk:

> Krea 3 can keep characters consistent using image references and plain-language instructions.
> Seedream 4 and Nano Banana also understand character or style images through prompts rather than
> dedicated reference settings. Image references are different from weighted style references or
> trained LoRAs.

### Task table (verbatim rows, abridged)

| Task | How Krea 3 helps |
| - | - |
| Product photography | Put a product in a new scene while preserving its shape, label, and logo. |
| Consistent characters | Use references to keep the same person or character across poses, locations, and lighting. |
| Precise edits | Change an object, material, color, or piece of text without changing the rest of the brief. |
| Sketches and concepts | Turn a sketch or visual reference into a finished image with instructions for materials and light. |
| Text-to-image | Generate a new image directly from a text description. |

### API pointer (verbatim)

> The endpoint is `POST /generate/image/krea/krea-3`. It supports text-to-image, image references,
> `fast` and `high` thinking modes, and regional edits.

The user guide mentions only `fast` and `high`, while the API overview adds `ultra`. This is a docs
inconsistency, not necessarily a product limitation.

## Gaps

- No architecture, benchmark, or independent quality data.
- The "<8 seconds" figure is not qualified here; the API docs and launch post also give it without a
  test protocol.
- The user guide does not document `thinking_mode` in detail; the API overview is the only
  first-party explanation.
- It does not state pixel dimensions for "1K"/"2K".
- It does not mention the host-exposed "Berry"/"Jam" variants.

# LTX documentation: migrate from V1 to V2

- Origin: LTX documentation, "Migrate from V1 to V2 — Migrate an LTX API integration from synchronous V1
  video generation endpoints to the asynchronous V2 job API", <https://docs.ltx.io/migrate-v1-to-v2>
- Evidence kind: official vendor API migration notice
- Publication date: undated; states the V1 shutdown deadline of 2026-10-26 23:59 UTC. Capture date
  2026-10-26.
- Capture date: 2026-10-26
- Relevant models: all LTX API models, including `ltx-2-5-fast` / `ltx-2-5-pro`
- Capture type: transcription of the page's markdown variant

## Shutdown notice (verbatim)

> The V1 video generation endpoints listed below will no longer be available after October 26, 2026 at
> 11:59 PM UTC. Migrate your integration to V2 before then.

## Endpoint mapping (verbatim)

| V1 endpoint | V2 endpoint |
| --- | --- |
| `POST /v1/text-to-video` | `POST /v2/text-to-video` |
| `POST /v1/image-to-video` | `POST /v2/image-to-video` |
| `POST /v1/audio-to-video` | `POST /v2/audio-to-video` |
| `POST /v1/retake` | `POST /v2/retake` |
| `POST /v1/extend` | `POST /v2/extend` |

> The media upload endpoint remains `POST /v1/upload`. You do not need to change uploaded `ltx://` URIs
> or replace `/v1/upload` as part of this migration.

## Behaviour change (verbatim table)

| V1 | V2 |
| --- | --- |
| `POST` returns `200 OK` after generation finishes. | `POST` returns `202 Accepted` immediately. |
| The response body is the generated MP4 file. | The response body is JSON containing a job `id`. |
| One connection remains open during generation. | Poll `GET /v2/{endpoint}/{id}` until the job finishes. |
| A generation failure is returned by the original request. | A generation failure appears as `status: "failed"` with an `error` object. |
| Concurrency limits can return `concurrency_limit_error`. | Queue limits can return `rate_limit_error`. |

> Your API key, request body, model selection, input URIs, and pricing do not change.

## Summary

The synchronous LTX API is withdrawn on the capture date. LTX-2.5 launched (2026-08-11) with both V1 and
V2 available, so its first integrations were written against an endpoint with a 76-day remaining life.
The request body and pricing carry over unchanged; only the response flow changes.

# Luma Agents API docs: image editing guide (`type: "image_edit"`)

- Origin: Luma AI, Luma Agents API docs, "Image editing",
  <https://docs.agents.lumalabs.ai/guides/images/editing/>
- Evidence kind: official documentation (vendor API reference)
- Publication date: no page-level date
- Capture date: 2026-10-26
- Relevant models: `uni-1`, `uni-1-max`

## Captured content

> Modify existing images with natural language instructions. Describe the edit you want and the
> `uni-1` family applies it while preserving the parts of the image you did not mention.

> Image editing works with both `uni-1` and `uni-1-max` — same parameters, same wire format.

The page's own distinction between editing and reference-guided generation (verbatim table):

| Scenario | Use | Why |
| --- | --- | --- |
| Change a photo's background | `image_edit` + `source` | Keeps the subject, only changes the background |
| Convert a photo to manga style | `image_edit` + `source` + `style: "manga"` | Transforms the existing image |
| Create a new image in a similar style | `image` + `image_ref` | Generates something new using the reference for style guidance |
| Combine elements from multiple images | `image` + `image_ref` (multiple) | Compositing, not editing a single source |

`source` accepts exactly one of: a public `url`, inline base64 `data` with `media_type`, a
`generation_id` from a prior completed generation owned by the same client, or a `file_id` from the
Files API.

Aspect-ratio rule (verbatim):

> The `style: "manga"` portrait-only aspect-ratio rule documented for image generation does **not**
> apply to `type: "image_edit"`. Edit output dimensions are derived from the `source` image rather
> than the request body [...] (`aspect_ratio` on edit requests is ignored regardless).

References with edits (verbatim): "Combine `source` (the image to edit) with `image_ref`
(style/content references) to guide the edit. Up to 8 reference images are supported."

Validation rules (verbatim, condensed): `type` must be `"image_edit"`; `source` required, exactly
one of `url`/`data`/`generation_id`/`file_id`; "source.url [...] Max 50 MB, max 8000 px per side";
`source.generation_id` "No upload size limit — references stored media"; `image_ref` "Optional. Up to
8 additional reference images"; `prompt` "Required. 1–6,000 characters describing the desired edit".

Named error cases include `400 "source is required for type 'image_edit'"`, `400 "source is only
valid for type 'image_edit', ..."`, `413 "source: image exceeds 50 MB limit"`, `422 "source: failed
to fetch URL"`, `422 "source: invalid base64 data"`.

## What this establishes

- Editing is in-place instruction following on a supplied source; the source's dimensions are
  preserved and `aspect_ratio` is silently ignored.
- Edits can be chained through `source.generation_id`, which is how multi-turn refinement is
  implemented at the API level.
- Reference ceiling for edits is 8 (plus the source), one lower than generation's 9.

## Gaps

- No fidelity/identity-preservation metrics, and no statement of how many chained edits can be
  applied before drift.
- The 8000 px / 50 MB limits are stated for URL and base64 sources only; `generation_id` and
  `file_id` bypass them, so effective input limits differ by transport.
- No moderation detail on this page; see the [FAQ](../luma-agents-api-faq/2026-10-26.md).

# Luma Agents API docs: image generation guide (`type: "image"`)

- Origin: Luma AI, Luma Agents API docs, "Image generation",
  <https://docs.agents.lumalabs.ai/guides/images/generation/>
- Evidence kind: official documentation (vendor API reference)
- Publication date: no page-level date
- Capture date: 2026-10-26
- Relevant models: `uni-1`, `uni-1-max`

## Captured content

Defaults when only `prompt` is sent: `model: "uni-1"`, `type: "image"`, `style: "auto"`;
`aspect_ratio` and `output_format` are left unset so the model picks.

`prompt`: "1 to 6,000 characters".

`model`: "Defaults to `"uni-1"`. Supported values: `uni-1` — the default. `uni-1-max` — produces
higher-quality output than `uni-1`."

`aspect_ratio` values and orientations (verbatim table): `3:1` ultra-wide landscape, `2:1` wide
landscape, `16:9` standard widescreen, `3:2` classic landscape, `1:1` square, `2:3` classic
portrait, `9:16` standard portrait, `1:2` tall portrait, `1:3` ultra-tall portrait.

`style`: `auto` (default) or `manga`. Constraint (verbatim): "`manga` is portrait-only. Pair it with
a portrait `aspect_ratio` (`2:3`, `9:16`, `1:2`, `1:3`), or omit `aspect_ratio` [...] Pairing
`style: "manga"` with a landscape or square ratio (`3:1`, `2:1`, `16:9`, `3:2`, `1:1`) is rejected at
submit time with `HTTP 422`". The error body:

> {"detail": "aspect_ratio='1:1' is not allowed when style='manga'. Valid aspect_ratio: 1:2, 1:3, 2:3, 9:16"}

`output_format`: `png` (lossless) or `jpeg` (smaller).

`web_search`: "When set to `true`, the model searches the web for visual references before
generating. This improves accuracy for prompts that reference real-world subjects, landmarks, or
products."

`image_ref` (verbatim):

> Provide up to 9 reference images to guide the generation. Each reference takes the same `ImageRef`
> shape used elsewhere — a `url` (publicly accessible), inline `data` (base64-encoded with
> `media_type`), or a `file_id` from the Files API.

> **`image_ref` is not image editing.** With `type: "image"` + `image_ref`, the references are
> style/content guidance for a brand-new image — none of the input pixels are preserved.

> Each `image_ref` entry must provide either `url` or `data` — not both. [...] Maximum 50 MB per
> image, up to 9 references total.

Validation rules (verbatim table, condensed): `prompt` required 1–6,000 chars; `model` must be
`uni-1` or `uni-1-max`; `type` must be `image` or `image_edit`; `aspect_ratio` one of the 9 values or
`null`; `style` `auto`/`manga`; `output_format` `png`/`jpeg`/`null`; `image_ref` max 9 entries,
"Max 50 MB, max 8000 px per side" for both `url` and `data`; `web_search` boolean, default false;
`source` must be null or omitted for `type: "image"`.

Response: HTTP 201 with `{id, type, state: "queued", model, created_at, output: [], failure_reason,
failure_code}`; states `queued` → `processing` → `completed` | `failed`; poll
`GET /v1/generations/{id}`; output URLs are presigned and "expire after 1 hour".

## What this establishes

- The generation surface is small and fixed: prompt, model tier, aspect ratio, one style preset,
  format, web search, references. There are no steps, guidance, sampler, negative prompt, or seed
  parameters.
- Reference inputs are capped at 9, 50 MB each, 8000 px per side.
- `web_search` is a first-class request parameter for grounding prompts in real subjects.
- Generation is asynchronous and poll-based; outputs are ephemeral (1-hour URLs).

## Gaps

- No statement of output pixel dimensions per aspect ratio; only "the model picks the resolution
  based on the chosen aspect ratio" (see the [FAQ](../luma-agents-api-faq/2026-10-26.md)). The
  pricing page says 2048px for all image requests
  ([pricing](../luma-agents-api-pricing/2026-10-26.md)); the two statements are not reconciled.
- No latency figures on this page (the announcement post claims ~31 s/image).
- Multi-output is not exposed here: one request yields one image, although the vendor FAQ lists
  "multi-output" as future work on the product page.

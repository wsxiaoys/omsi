# Luma Agents API docs: image layering (`type: "layering"`)

- Origin: Luma AI, Luma Agents API docs, "Image layering",
  <https://docs.agents.lumalabs.ai/guides/images/layering/>
- Evidence kind: official documentation (vendor API reference)
- Publication date: no page-level date
- Capture date: 2026-10-26
- Relevant models: `uni-1` (layering is documented for `uni-1` only)

## Captured content

> Decompose an existing image into up to 10 ordered RGBA layers — each a standalone PNG with real
> transparency, stacked front-to-back so the original composition can be reassembled or re-edited
> layer by layer. The `uni-1 model` analyzes the image, plans the split automatically, and extracts
> each layer as a complete element.

How it works (verbatim):

> You submit a source image (and optionally a short `prompt` guiding how to split it).
> The server plans the layers automatically — a vision model analyzes the image before generating,
> deciding how many layers to extract and what goes in each.
> Each planned layer is generated as a full RGBA image. Occluded regions are completed, so every
> layer is a whole element rather than a cutout with holes behind it.
> The completed generation returns N outputs (up to 10), ordered front-to-back — the `last` output
> is always the opaque background. Each layer PNG is cropped to its visible content, and its
> `layer.bounds` carries the geometry to place it back on the composite canvas.

Request shape: `type: "layering"`, `model: "uni-1"`, a `source` image; `prompt` is required by the
schema but "for layering it may be an empty string".

Luma's product post for the corresponding app feature ("Introducing Layers", 2026-07-29) says:
"Powered by Uni-1, Layers gives Luma customers precision editing and control over every element of
any image. It's AI generates images as independent, editable layers, and it decomposes any uploaded
image into layers too." (<https://lumalabs.ai/news/introducing-layers>, byline on the Luma news
index).

## What this establishes

- Uni-1 is used as a *planning* model here, not just a renderer: a vision pass decides the layer
  count and contents before any layer is generated. This is the clearest documented instance of the
  "reasoning before rendering" claim in a shipped feature.
- Layering produces up to 10 RGBA PNGs per request, with geometry metadata.
- The feature is documented only for `uni-1`; the docs do not say whether `uni-1-max` supports
  `type: "layering"`.

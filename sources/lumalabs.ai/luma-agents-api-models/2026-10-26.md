# Luma Agents API docs: Models (`uni-1`, `uni-1-max` capability matrix)

- Origin: Luma AI, Luma Agents API docs, "Models",
  <https://docs.agents.lumalabs.ai/guides/model/>
- Evidence kind: official documentation (vendor API reference)
- Publication date: no page-level date; documents `uni-1`, `uni-1-max` and `ray-3.2`
- Capture date: 2026-10-26
- Relevant models: `uni-1`, `uni-1-max`

## Captured content

Base URL: `https://agents.lumalabs.ai/v1`; one endpoint, `POST /v1/generations`, handles image
generation, image editing, video generation/extension, video editing, and video reframing.

At a glance (verbatim table):

| Model | Supports | Use for |
| --- | --- | --- |
| `uni-1` | `image`, `image_edit` | Default image generation and editing |
| `uni-1-max` | `image`, `image_edit` | Higher-quality image output than `uni-1` |
| `ray-3.2` | `video`, `video_edit`, `video_reframe` | Text-to-video, image-to-video, video editing, reframing |

Image model capability matrix (verbatim):

| Capability | Supported |
| --- | --- |
| Text-to-image (`type: "image"`) | ✓ |
| Image editing (`type: "image_edit"`) | ✓ |
| `image_ref` for style or content guidance (up to 9) | ✓ |
| `source` image for editing | ✓ |
| `web_search` grounding | ✓ |
| Output formats `png` / `jpeg` | ✓ |

> `uni-1-max` produces higher-quality output than `uni-1`; the two share the same wire format and
> parameter set.

"Image model strengths" (verbatim descriptions): **Text rendering** — "Renders readable text on
signs, labels, book covers, and other surfaces. Put exact text in quotes in your prompt.";
**Spatial reasoning** — "Produces accurate shadows, correct perspective, and physically plausible
object layouts."; **Cultural styles** — "understands visual traditions — manga panels with screentone
shading, ukiyo-e woodblock prints, film noir lighting, art house cinema framing"; **Reference-guided
generation** — "up to 9 reference images via `image_ref` for text-to-image, or up to 8 for image
editing (where the `source` image occupies its own slot)"; **Image editing**; **Web search
grounding**; **Multi-panel output** — "Generates multi-panel sequences (e.g., storyboards) with
consistent style when described in the prompt."

Output specifications: nine image aspect ratios for `uni-1`/`uni-1-max` (the shared `AspectRatio`
enum has twelve members, but no single model/type pair accepts all twelve); PNG or JPEG; presigned
URLs expire after 1 hour.

> `uni-1-max` produces higher-quality output than `uni-1`. Same wire format and parameter set — same
> prompts, same `aspect_ratio`, same `image_ref` semantics. Pass `"model": "uni-1-max"` on
> `POST /v1/generations`.

## What this establishes

- Canonical API model IDs are **`uni-1`** and **`uni-1-max`** — lowercase, hyphenated. There is no
  `uni-1.1` model ID anywhere in the API reference, despite Luma's marketing calling the API
  "Uni-1.1".
- `uni-1` is a single model that does generation and editing; the "max" tier is a quality/price
  tier of the same wire format, not a different task model.
- Reference ceilings: 9 for generation, 8 for editing (source occupies one slot).
- `web_search` grounding is a documented, model-level capability — not a separate tool.

## Gaps

- No parameter count, context length, or training-data description.
- "Higher-quality output" is not quantified; no benchmark compares `uni-1` with `uni-1-max`.
- No statement of which checkpoint the IDs resolve to over time (rolling vs pinned).
- Layering (`type: "layering"`) is documented separately and is not in this capability matrix; see
  the [layering record](../luma-agents-api-image-layering/2026-10-26.md).

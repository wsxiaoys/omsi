# Luma Agents API docs: Pricing (credits per image for `uni-1` / `uni-1-max`)

- Origin: Luma AI, Luma Agents API docs, "Pricing",
  <https://docs.agents.lumalabs.ai/guides/pricing/>
- Evidence kind: official documentation (vendor pricing reference)
- Publication date: no page-level date; covers `uni-1`, `uni-1-max`, `ray-3.2`
- Capture date: 2026-10-26
- Relevant models: `uni-1`, `uni-1-max` (Ray 3.2 video rates out of scope)

## Captured content

Two billing shapes: **Pay-as-you-go** (credits per generation) and **Provisioned Throughput**
(monthly per unit of guaranteed capacity).

> All prices are in credits per generation — your dashboard shows each request's charge in credits.
> The dollar value of a credit depends on your account's plan or contract.

> All requests output at 2048-pixel (2K) resolution.

### `uni-1` — per-image pricing (verbatim)

| Task | Credits per image |
| --- | --- |
| Text to image | 14 |
| Image edit (image to image) | 15 |
| Image reference (1 image) | 15 |
| Image reference (2 images) | 16 |
| Image reference (3 images) | 17 |
| Image reference (4 images) | 18 |
| Image reference (5 images) | 19 |
| Image reference (6 images) | 20 |
| Image reference (7 images) | 21 |
| Image reference (8 images) | 22 |
| Image reference (9 images) | 23 |

> Each extra reference image adds 1 credit on top of the 1-image price. Note: `image_edit` requests
> support up to 8 reference images (the source occupies one slot); `image` requests support up to 9.

### `uni-1-max` — per-image pricing (verbatim)

| Task | Credits per image |
| --- | --- |
| Text to image | 34 |
| Image edit (image to image) | 35 |
| Image reference (1 image) | 35 |
| Image reference (2 images) | 36 |
| ... | ... |
| Image reference (9 images) | 43 |

> `uni-1-max` is available to all accounts — pass `"model": "uni-1-max"` on `POST /v1/generations`.

### Provisioned Throughput (verbatim excerpts)

> 1 unit = 1 RPM on `uni-1`; 1 unit = 0.4 RPM on `uni-1-max`. [...] Minimum commitment is 8 units.

| Commitment | $ / unit / month | Effective per-image cost (`uni-1` / `uni-1-max`) |
| --- | --- | --- |
| 1 month | $3,800 | $0.088 / $0.220 |
| 3 months | $2,800 | $0.065 / $0.163 |
| 1 year | $2,100 | $0.049 / $0.123 |

> Provisioned Throughput plans include a **no-train guarantee** — data processed through Provisioned
> Throughput is never used to train Luma models.

> Video rates are subject to change ahead of general availability.

## What this establishes

- The billing unit is a **credit**, not a dollar: 14 credits for a `uni-1` T2I, 34 for `uni-1-max`,
  +1 credit per extra reference image, +1 for an edit.
- Provisioned Throughput carries the explicit no-train guarantee; pay-as-you-go does not state one.
- The docs' own dollar conversion ($0.088/image for `uni-1` at a 1-month commitment) is consistent
  with the $0.0404 list price on [lumalabs.ai/api](../luma-api-overview/2026-10-26.md) only if the
  effective cost column is a discounted/committed rate, not a list rate. The two pages are not
  reconciled.
- `type: "layering"` has no row in either table.

## Gaps

- No dollar value per credit is published on this page, so list prices can only be cross-read from
  the marketing API page.
- The "effective per-image cost" column does not state whether it assumes the minimum 8 units or a
  particular request mix.
- No statement of what a failed generation costs (the FAQ says synchronous errors are never charged;
  asynchronous failures are not covered here).

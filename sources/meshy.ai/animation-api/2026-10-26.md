# Meshy: Animation API reference

- Origin: Meshy Docs, "Animation API", https://docs.meshy.ai/en/api/animation
- Evidence kind: official documentation (vendor API reference)
- Publication date: none stated; live documentation as of capture.
- Capture date: 2026-10-26
- Relevant models: Meshy 7.1 output after rigging; preset action library; Text to Motion clips

## Captured content (summary with verbatim quotes)

Endpoint: `POST https://api.meshy.ai/openapi/v1/animations`. "Creates an Animation task, which applies
an animation to a character you rigged earlier."

Three animation sources:
1. "A preset action from the animation library (`action_id`)"
2. "Several preset actions merged into one file (`action_ids`)"
3. "A motion clip you generated with the Text to Motion API (`motion_task_id`)"

Multi-action behaviour (changelog 2026-09-02): "you can apply up to 10 preset actions to a rigged
character in one request and receive a single file containing one animation clip per action ... Costs
3 credits per action".

Post-processing is available, e.g. `post_process: {operation_type: "change_fps", fps: 24}`.

The library itself is enumerable: `GET /openapi/v1/animations/library` returns "every preset action the
Animation API accepts (`action_id`, `name`, category, and an animated GIF preview) ... Free; consumes no
credits" (changelog 2026-09-04).

## Summary

Animation is billed per action (3 credits each) and applies only to already-rigged characters. The
combination the docs describe — 7.1 mesh, then rigging, then up to 10 actions — is the documented path
from an image or prompt to a game-ready animated character, and each stage is a separately billed task.

## Gaps

- The number of available actions is not stated on this page; the web pricing page says "600+ motions"
  while the fal host schema bounds `animation_action_id` at 0–696. The two numbers were not reconciled
  from any captured page.
- No clip duration, frame-rate, or retargeting documentation captured.

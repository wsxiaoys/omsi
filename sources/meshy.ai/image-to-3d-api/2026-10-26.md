# Meshy: Image to 3D API (v1) reference

- Origin: Meshy Docs, "Image to 3D API", https://docs.meshy.ai/en/api/image-to-3d
- Evidence kind: official documentation (vendor API reference)
- Publication date: none stated; live documentation as of capture.
- Capture date: 2026-10-26
- Relevant models: Meshy 7.1 (`ai_model: "meshy-7.1"`, `latest`), Meshy 7 (deprecated), Meshy 6,
  Meshy 6 Lite, Meshy T2 / T2.5

## Endpoint

`POST https://api.meshy.ai/openapi/v1/image-to-3d` — single request, not the two-step preview/refine
pair used by Text to 3D. Texturing is controlled in the same request by `should_texture`.

## Inputs

- `image_url` (required unless `input_task_id`): "a public URL or a base64-encoded data URI ... The
  image must be a JPG, JPEG, PNG, or WebP file of at most 20 MB."
- `input_task_id` (required unless `image_url`): "The ID of a Text to Image or Image to Image task
  whose image you want to use as the input ... must ... have produced exactly one image." If both are
  sent, "Meshy uses `input_task_id`".
- `image_enhancement` default true: "Whether to optimize the input image before generating. false
  keeps the exact look of the input image, with no style processing. It works only with meshy-6,
  meshy-7.1, or latest. With meshy-6-lite or model_type: smart-topology, it returns 400."
- `texture_prompt` / `texture_image_url`: "up to 800 characters" / ≤20 MB image; "Meshy guides the
  texture with only one of `texture_prompt` and `texture_image_url`."
- `pose_mode`, `moderation`, `auto_size`, `origin_at`, `alpha_thumbnail`, `target_formats` as on
  Text to 3D.

## Geometry and texturing controls

- `ai_model`: `latest` (Meshy 7.1), `meshy-7.1`, `meshy-6`, `meshy-6-lite`; `meshy-7` deprecated.
- `geometry_resolution`: `standard`, `2k`, `4k`. "`2k` needs meshy-7.1, latest, or the deprecated
  meshy-7. `4k` needs meshy-7.1 or latest."
- `should_texture` default true; `should_texture: false` "skips texturing and returns an untextured
  mesh". `enable_pbr` "needs `should_texture: true`, and returns 400 with `should_texture: false`".
  "With `meshy-6`, Meshy also generates an emission map ... These models don't produce an emission map:
  meshy-6-lite, meshy-7, meshy-7.1, meshy-t2, meshy-t2.5, latest."
- `texture_resolution` 2k/4k/8k: "4k and 8k aren't available with meshy-6-lite, and return 400 with it."
- `should_remesh` default "true (meshy-6-lite), false (other models)"; `save_pre_remeshed_model`
  returns a pre-remesh GLB in `model_urls.pre_remeshed_glb`; `topology` quad/triangle;
  `target_polycount` 100–300,000 (default 30,000) when remeshing.
- `remove_lighting` default true: "It takes effect only with meshy-6. meshy-7.1 and latest accept it
  and ignore it. With meshy-6-lite or model_type: smart-topology, it returns 400."
- `surface_mode` deprecated: "Use ai_model instead. It doesn't affect the output, because the model
  generation it selected is retired."

## Summary

The image-to-3D reference confirms that Meshy 7.1's parameter surface is the same as Meshy 7's and
Meshy 6's, with the geometry-resolution ceiling being the one capability the older models lack:
`4k` requires `meshy-7.1` or `latest`. Output formats, polycount ranges, texture resolutions, and PBR
behaviour are shared across the standard models, apart from the emission-map and `remove_lighting`
differences that favour Meshy 6.

## Gaps

- No documented limit on the number of concurrent requests beyond the account-wide rate limits.
- No statement of what `image_enhancement` actually does to the input image.
- The page does not say whether a 4K geometry request costs more time, only that it costs 5 extra
  credits (see the pricing record).

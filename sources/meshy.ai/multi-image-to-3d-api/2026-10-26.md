# Meshy: Multi Image to 3D API reference

- Origin: Meshy Docs, "Multi Image to 3D API", https://docs.meshy.ai/en/api/multi-image-to-3d
- Evidence kind: official documentation (vendor API reference)
- Publication date: none stated; live documentation as of capture.
- Capture date: 2026-10-26
- Relevant models: Meshy 7.1 (`ai_model: "meshy-7.1"`, `latest`), Meshy 7 (deprecated), Meshy 6,
  Meshy 6 Lite

## Endpoint and inputs

`POST https://api.meshy.ai/openapi/v1/multi-image-to-3d`.

- `image_urls` (required unless `input_task_id`): "One to four images, each as a public URL or a data
  URI ... Each image must be a .jpg, .jpeg, .png, or .webp file of at most 20 MB. More than four
  images returns 400." "For the best results, the images should show the same object from different
  angles. With `meshy-7.1` or `latest`, Meshy uses the first image as the front view, and the order of
  the others doesn't matter."
- `input_task_id`: a Text to Image / Image to Image task "including a multi-view one".
- `texture_image_urls`: "One to four images of the object from different views that guide the texture
  ... `texture_image_urls` needs `meshy-7.1`, `latest`, or the deprecated `meshy-7`. You can't send it
  with `texture_image_url` or `texture_prompt`."

## Geometry ceiling — the 7.1 limitation that matters

- `geometry_resolution`: `standard` or `2k` only. "2k: runs the Ultra pass at 2048³. Needs `meshy-7.1`,
  `latest`, or the deprecated `meshy-7`."
- "4k is not available on Multi-Image to 3D": the documented 400 case reads "Unsupported resolution for
  multi-image input: `geometry_resolution` is "4k", which this endpoint doesn't support. Use 2k or
  standard." The response schema likewise says "The Ultra tier the task ran, which is 2k."

## Other controls

`ai_model`, `should_texture`, `enable_pbr`, `texture_resolution` (2k/4k/8k), `should_remesh`,
`topology`, `target_polycount`, `pose_mode`, `moderation`, `target_formats`, `multi_view_thumbnails`
(added 2026-05-26, four cardinal-view thumbnails, "Adds approximately 3 seconds to task latency").

## Summary

Multi Image to 3D exposes Meshy 7.1 but caps geometry at the Ultra 2K pass, so 7.1's headline 4096³
capability is unavailable on the multi-view route. This is consistent with the launch post's statement
that "Ultra 4K is available for single-view generation only", and it is the clearest documented case
where a 7.1 capability is endpoint-dependent rather than model-wide.

## Gaps

- No documented guidance on how much each additional view improves output.
- No statement of whether the 4K restriction is a compute limit or a product decision.

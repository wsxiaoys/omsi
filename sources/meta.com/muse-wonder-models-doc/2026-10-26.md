Muse Wonder section:

> Muse Wonder is Meta's most capable model, built for complex software engineering and long-horizon
> agentic work. It makes and verifies changes across many files in real repositories, and it plans,
> delegates to sub-agents, calls tools in parallel, and recovers from errors across many steps,
> following detailed instructions closely. Take on hard coding tasks, build personal and
> professional agents, and drive a desktop with computer use. Muse Wonder also handles chat
> completion, image understanding, video and audio understanding, tool calling, structured output,
> and search grounding.
>
> Muse Wonder takes text, image, video, audio, and PDF input, returns text, has a 1,048,576-token
> context window, and supports reasoning effort levels from `"minimal"` to `"max"`.

Preview note:

> **NOTE: Preview**
>
> Muse Wonder is in preview. For more about the model, see the Muse Wonder model page and the Muse
> Wonder model card.

Availability section:

> Muse Wonder comes in two variants. Muse Wonder is on Model API and in Muse Code. Muse Wonder Full,
> the higher-capability variant, is available only in Muse Code with a subscription, so setting
> reasoning effort to `"max"` on Muse Wonder doesn't select it.

| Variant | Model API (pay-as-you-go) | Muse Code |
| --- | --- | --- |
| Muse Wonder (`muse-wonder-1.0`) | Available (Standard mode only) | Pay-as-you-go and every plan |
| Muse Wonder Full | Not available | Power Usage and Maximum Usage |

> With a subscription, Muse Wonder is available on every plan and Muse Wonder Full on the Power
> Usage and Maximum Usage plans, each in Standard mode and Contributor mode.
>
> Muse Wonder and Muse Wonder Full aren't currently available in South Korea, on Model API or in
> Muse Code.

Data-use note:

> In Standard mode, your content — the prompts, code, files, and context you send, plus the model
> responses you get back — is not used to train Meta models. Muse Code subscribers can also use
> Contributor mode, which is on by default: it gives you more usage in exchange for letting Meta use
> your content to train future Meta models, and you can turn it off at any time in your settings.
> For Muse Wonder, Contributor mode isn't available on pay-as-you-go.

Muse Wonder vs Muse Spark:

> Muse Wonder and Muse Spark take the same requests on the same endpoints, so moving a workload
> between them is a model ID change. Choose by workload:
>
> - **Muse Wonder**: long-running, complex tasks where capability matters more than cost per token,
>   such as multi-file coding changes, multi-hour agent runs, and sub-agent orchestration.
> - **Muse Spark**: high-volume, latency-sensitive, or cost-sensitive work, such as sub-agent tasks,
>   classification, and tight tool loops. On Model API, Muse Spark also offers a discounted
>   Contributor mode.

## Notes

- Meta documents **PDF input** here, while the model card's modality line lists only text, image,
  video and audio. OpenRouter's `file` input modality matches this docs page.
- Muse Wonder Full has its own model ID and a capability claim, but **no Model API access and no
  published price**; it is a subscription tier inside Muse Code.
- Muse Wonder is explicitly **preview** in the docs, while the product page labels it "New" and
  gives it list prices.
- The docs describe Muse Image as a separate line: "Muse Image is Meta's image generation model
  line." Muse Wonder's output is text only.

## Gaps

- No per-modality input limits (video duration, audio length, PDF size, image resolution).
- No knowledge cutoff, no deprecation date, and no statement of what "preview" changes about
  availability or support.
- No published context limit for Muse Wonder Full beyond "1M".

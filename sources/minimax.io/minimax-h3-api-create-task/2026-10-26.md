## Captured content

Page summary (verbatim):

> Video generation V2 endpoint. Provide multimodal input via the content array (text / image / video /
> audio); switch between MiniMax H3, MiniMax H3 Highspeed, MiniMax H3 Lite, and MiniMax H3 Max with
> the model field to support text-to-video, image-to-video (first & last frame), and reference-to-video,
> with output up to 2K.
>
> Note: To use MiniMax H3, MiniMax H3 Highspeed, MiniMax H3 Lite, or MiniMax H3 Max, please select the
> Pay-as-you-go API.

### `model` enum (verbatim descriptions)

| Value | Description |
| --- | --- |
| `MiniMax-H3` | "the variant for high-quality video creation. Supports text-to-video, image-to-video (first / last frame), and reference-to-video; 768P / 2K resolution, 4–15s duration." |
| `MiniMax-H3-Highspeed` | "balances generation quality and speed. Supports text-to-video, image-to-video (first / last frame), and reference-to-video (reference image / video / audio); 768P resolution, 2K is not supported; 4–15s duration." |
| `MiniMax-H3-Lite` | "the lightweight variant. Supports text-to-video, image-to-video (first / last frame), and reference-to-video (reference image / video / audio); 480P / 768P resolution, 2K is not supported; 4–15s duration." |
| `MiniMax-H3-Max` | "the fast generation variant. Supports text-to-video, image-to-video (first / last frame), and reference-to-video (reference image / video / audio); 480P / 768P resolution, 2K is not supported; 5–15s duration." |

### Input combinations (verbatim)

> Text-to-video: a single text element only.
> Image-to-video, first frame: text + 1 image_url (role=first_frame, or omitted).
> Image-to-video, last frame: text + 1 image_url (role=last_frame).
> Image-to-video, first & last frame: text + 2 image_url items with role set to first_frame and
> last_frame respectively.
> Reference-to-video: text + any combination of reference images (role=reference_image), reference
> videos (role=reference_video), and reference audio (role=reference_audio).
>
> Image-to-video and reference-to-video are mutually exclusive: if any reference_image / reference_video
> / reference_audio role appears in content, then first_frame / last_frame must not appear (and vice
> versa); the two cannot be mixed.

A text item is mandatory in every request: "Every request must include one non-empty text item (the
prompt is required)".

### Media limits (verbatim table values)

Total request body ≤ 64 MB ("use public URLs for large files, avoid Base64").

| Modality | Limits |
| --- | --- |
| Image (`image_url`) | JPG/JPEG/PNG/WEBP/HEIC/HEIF; ≤ 30 MB each; width/height [256, 5760] px; aspect ratio (w/h) [0.4, 2.5]; first frame ≤ 1, last frame ≤ 1, reference images ≤ 9 |
| Video (`video_url`, reference only) | MP4/MOV; H.264/AVC or H.265/HEVC video, AAC or MP3 audio; ≤ 50 MB each; ≤ 3 clips; each clip [2, 15] s, total ≤ 15 s; width/height [256, 5760] px; aspect [0.4, 2.5]; frame rate [23.976, 60] |
| Audio (`audio_url`, reference only) | WAV/MP3; ≤ 15 MB each; ≤ 3 clips; each clip [2, 15] s, total ≤ 15 s |

### `resolution` and `duration`

`resolution` is required; options `480P`, `768P`, `2K`, with availability differing per model
(H3: 768P/2K; Highspeed: 768P; Lite and Max: 480P/768P, defaulting to 768P).

`duration` is required, integer, and the allowed range differs per model: `MiniMax-H3` 4–15,
Highspeed 4–15, Lite 4–15, `MiniMax-H3-Max` 5–15 ("4 seconds is not supported"). Available options
are listed as 4 through 15.

### `ratio`

Defaults to `adaptive`. Options: `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`. Verbatim:

> Text-to-video (t2va, content contains only text): ratio is required and cannot be adaptive; available
> values 21:9, 16:9, 4:3, 1:1, 3:4, 9:16.
> Image-to-video (i2va, content contains a first_frame / last_frame image): the aspect ratio is
> determined by the input image and ratio is always adaptive; passing another valid value does not
> error but is ignored and treated as adaptive.
> Reference-to-video (r2va, …): ratio is optional and defaults to adaptive; you may also explicitly
> specify any of the concrete ratios above.
> MiniMax-H3-Lite does not support adaptive yet; specify a concrete ratio.

### Other fields

- `extra` — "Additional generation options for MiniMax-H3-Max. Currently only prompt_expansion_mode is
  supported. If extra or this property is omitted, balanced is used."
- `callback_url` — task-status webhook with a `challenge` verification handshake; statuses `queued`,
  `running`, `succeeded`, `failed`, `cancelled`.

### Documented error codes

`2013` invalid params / prompt required (400); `1004` auth (401); `1008` insufficient balance (402);
`1026` "video description contains sensitive content" (422); `1002` rate limit (429); `1000` internal
error (500).

The nav lists sibling endpoints for the same family: Query Task, List Tasks, Cancel or Delete Task,
**Create H3-Context-IR Task**, **Create Video Regeneration Task**, and a legacy "Video Generation"
section. The section heading is "MiniMax-H3" and is marked "NEW".

## Summary

The first-party API exposes **four H3 model IDs**: `MiniMax-H3` (flagship, 768P/2K, all task types),
`MiniMax-H3-Highspeed`, `MiniMax-H3-Lite`, and `MiniMax-H3-Max`. Only the flagship is called "H3"
plainly; the others are variants under the same endpoint. H3 Max's first-party description here is
"the fast generation variant" — it is the only model in the family whose 5 s floor excludes 4 s, and
the only one that takes an `extra.prompt_expansion_mode` option.

The request shape is a single multimodal `content` array with `role` labels, with first/last-frame and
reference modes mutually exclusive — a hard constraint a caller must design around.

## Gaps

- No frame rate, audio sample rate, codec or container for **output**; the output envelope is only in
  the model card.
- No pricing (separate price page) and no licence terms.
- No launch dates per variant, and the models-intro page omits Highspeed and Lite entirely.
- The docs do not say whether the 2K option on `MiniMax-H3` is native generation or regeneration, or
  whether it is billed as a separate task; the price page implies regeneration is a separate endpoint.
- Moderation is documented only as error `1026` ("contains sensitive content"); no policy or
  threshold is published on this page.

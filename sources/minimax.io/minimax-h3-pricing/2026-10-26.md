Billing notes (verbatim):

> Image input: The first 5 images per task are free; additional images are billed per image. The unit
> price does not vary with image or output video resolution.
> Video input: Billed by input duration at the output resolution of the selected model.
> Task types: For the same model and resolution, all task types share the same unit price. Audio input
> is free.

Task-type matrix for the flagship trio: text-to-video, image-to-video, first & last frame, and
reference ("Image, video, audio") are all listed Supported for H3, H3-Highspeed and H3-Lite.

## Summary

Per-second billing, with the flagship H3 at **$0.08/s at 768P and $0.13/s at 2K**. Input video is
billed at the same per-second rate as output; audio input is free; images are free for the first five
per task and $0.04 each after that.

Two billing structures are worth flagging because they complicate any simple per-second comparison:

1. **2K on the flagship is not obviously one charge.** The page prices 768P→2K "Video Regeneration"
   as a separate endpoint at $0.05/s on top of the original task. Whether the flagship's own `2K`
   option already includes that regeneration, or whether a caller who wants 2K is expected to run
   `MiniMax-H3` at 768P and then pay $0.05/s for regeneration, is not stated on the page. Both routes
   exist in the API reference.
2. **H3-Max bills input video higher than output video** ($0.143/s input at 768P versus $0.08/s
   output), unlike the flagship tier where the two rates are equal.

## Summary

- **Output ceiling:** 524,288 tokens maximum, 131,072 recommended, stated by the vendor for both
  M3.1 Flash and M3. OpenRouter's `max_completion_tokens: 524288` matches exactly.
- **Image input:** ≤10 MB, four formats, public URL or base64, with a `detail` knob whose own
  documentation admits token usage from "a few hundred" to "~15k+".
- **Video input:** four container formats, ≤50 MB by URL/base64 or ≤512 MB through the Files
  API, with frame sampling 0.2–5 fps. Long video therefore requires an upload round-trip.
- `max_tokens` is deprecated in favour of `max_completion_tokens`; both are accepted but the
  docs point at the latter.

## Gaps

- No limit on the **number** of images or videos per request, no total-request size cap, and no
  aggregate token accounting for media.
- No per-request token budget for video beyond the fps knob; no maximum video duration.
- No statement of how media tokens interact with the 1M context window.
- The page's example requests all set `max_completion_tokens: 500` and `reasoning_effort: max`,
  which are illustrative rather than recommended production settings.

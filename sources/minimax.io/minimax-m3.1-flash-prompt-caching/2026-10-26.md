# MiniMax API docs: Prompt Caching

- Origin: MiniMax API Platform documentation, "Prompt Caching",
  <https://platform.minimax.io/docs/api-reference/text-prompt-caching> (markdown source
  `.../text-prompt-caching.md`).
- Evidence kind: official documentation (vendor billing mechanics).
- Publication date: n/a — living page.
- Capture date: 2026-10-26
- Relevant models: MiniMax-M3.1-Flash (example code and supported-model list), plus M3 and M2.x.
- Capture type: full text of the feature, limits and billing sections; code examples abridged.

## Captured content

Features, verbatim: "**Automatic Caching**: Automatically identifies repeated context content
without changing API call methods"; "**Cost Reduction**: Input tokens that hit the cache are
billed at a lower price"; "**Speed Improvement**: Reduces processing time for repeated
content".

Limits and supported models, verbatim:

> * Caching applies to API calls with 512 or more input tokens
> * Supported models: MiniMax-M3.1-Flash, MiniMax-M3, MiniMax-M2.7 series, MiniMax-M2.5 series,
>   MiniMax-M2.1 series

Guidance, verbatim: "Place static or repeated content (including tool list, system prompts, user
messages) at the beginning of the conversation, and put dynamic user information at the end of
the conversation to maximize cache utilization".

Billing, verbatim:

> Cost per request = New input tokens × Input price
>                  + Cache hit tokens × Cache hit price
>                  + Output tokens × Output price
>
> * New input tokens = Total input tokens − Cache hit tokens

Usage fields, verbatim: "Anthropic-compatible API: `usage.cache_read_input_tokens`;
`usage.input_tokens` is the number of new input tokens"; "OpenAI-compatible API:
`usage.prompt_tokens_details.cached_tokens`; `usage.prompt_tokens` is the total number of input
tokens".

## Summary

- Caching is **automatic** (no cache-control blocks, no explicit create call) and applies only to
  requests of **≥512 input tokens**.
- M3.1 Flash is named first in the supported-model list and is used throughout the code
  examples.
- Billing is a simple three-term sum: new input at the input rate, cache hits at the cache rate,
  output at the output rate. No cache write or storage charge is described.

## Gaps

- No TTL, no eviction policy, no maximum cache size, no per-account cache quota.
- No statement of how the 512-token threshold interacts with the 1M context window, or whether
  caching works across requests in different sessions.
- Cache **write** pricing is not mentioned; the pricing page also lists only a cache-read rate
  ([pricing](../minimax-m3.1-flash-pricing/2026-10-26.md)).

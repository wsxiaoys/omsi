## Captured content

Opening, verbatim:

> MiniMax-M3.1-Flash natively supports Interleaved Thinking, enabling it to reason between each
> round of tool interactions. Before every Tool Use, the model reflects on the current
> environment and the tool outputs to decide its next action.
>
> This ability allows the model to excel at long-horizon and complex tasks, achieving
> state-of-the-art (SOTA) results on benchmarks such as SWE, BrowseCamp, and xBench, which test
> both coding and agentic reasoning performance.

> The key principle is to return the model's full response each time—especially the thinking
> fields (`thinking` / `reasoning_content`).

Request parameter: `tools` — "Defines the list of callable functions, including function names,
descriptions and parameter schemas."

Response fields, verbatim: `thinking` / `reasoning_content`; `text` / `content`; `tool_use` /
`tool_calls`; `name` / `function.name`; `input` / `function.arguments`; `id`.

Thinking is not guaranteed on every turn, verbatim:

> MiniMax-M3.1-Flash thinks on demand: for simple tool calls, the model may call the tool
> directly without producing thinking content, in which case that turn has no `thinking` block
> or `reasoning_content` field. Check whether the field exists before reading it, and always
> append the full returned message to the history whether or not it contains thinking.

Multi-turn requirement, verbatim:

> In multi-turn function call conversations, the complete model response (i.e., the assistant
> message) must be appended to the conversation history to maintain the continuity of the
> reasoning chain.

Example response (first request) shows the model answering, then calling `get_weather`, with
`"model": "MiniMax-M3.1-Flash"` and `usage` fields `input_tokens` / `output_tokens`; the second
turn's thinking block reads, verbatim: "The user asked about the weather in San Francisco. The
tool returned 24°C, sunny. Let me just report this. Simple answer."

## Summary

- Tool use is first-class and documented specifically for M3.1 Flash: function tools, with
  reasoning interleaved between tool rounds.
- The documented contract is that the **entire assistant message, including thinking, must be
  replayed** on each turn; dropping `reasoning_content`/`thinking` breaks the chain.
- Thinking is described here as "on demand" for tool turns, which sits alongside the
  `text-generation` guide's "thinking cannot be turned off". Both can be true: the *policy* is
  always-on, but a given turn may emit no thinking block.
- Names SWE, "BrowseCamp" (sic — presumably BrowseComp) and xBench as the benchmarks it targets,
  with no numbers on this page.

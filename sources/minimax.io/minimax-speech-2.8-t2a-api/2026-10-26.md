## Model enum (verbatim)

```yaml
model:
  description: The speech synthesis model version to use.
  enum:
    - speech-2.8-hd
    - speech-2.8-turbo
    - speech-2.6-hd
    - speech-2.6-turbo
    - speech-02-hd
    - speech-02-turbo
    - speech-01-hd
    - speech-01-turbo
```

Both 2.8 IDs are accepted by one endpoint; there is no separate HD endpoint.

## Text input and limits (verbatim)

> The text to be converted into speech. Must be less than 10,000 characters.
>
> - For texts over 3,000 characters, streaming output is recommended.
>
> - Paragraph breaks should be marked with newline characters.
>
> - **Pause control**: You can customize speech pauses by adding markers in the form `<#x#>`, where
>   `x` is the pause duration in seconds. Valid range: `[0.01, 99.99]`, up to two decimal places.
>   Pause markers must be placed between speakable text segments and cannot be used consecutively.
>
> - **Inline pronunciation**: Wrap Mandarin Pinyin (with tone number `1–5`) or IPA symbols or
>   Cantonese Jyutping (with tone number `1–6`) in half-width parentheses to override pronunciation
>   of the target word or polyphonic character.
>
> - **Interjection tags**: Only supported when using `speech-2.8-hd` or `speech-2.8-turbo` models.
>   Supported interjections: `(laughs)`, `(chuckle)`, `(coughs)`, `(clear-throat)`, `(groans)`,
>   `(breath)`, `(pant)`, `(inhale)`, `(exhale)`, `(gasps)`, `(sniffs)`, `(sighs)`, `(snorts)`,
>   `(burps)`, `(lip-smacking)`, `(humming)`, `(hissing)`, `(emm)`, `(sneezes)`.

That is **19** interjection tags on the T2A route. The 2.8-only restriction is stated explicitly,
which makes interjections the clearest documented behavioural difference from 2.6.

## Emotion (verbatim)

> Emotion control for synthesized speech. Supported values:
> `["happy", "sad", "angry", "fearful", "disgusted", "surprised", "calm", "fluent", "whisper"]`.
> - By default, the model automatically selects the most natural emotion based on text. Manual
>   specification is only recommended when explicitly needed.
> - Available for models: `speech-2.8-hd`, `speech-2.8-turbo`, `speech-2.6-hd`, `speech-2.6-turbo`,
>   `speech-02-hd`, `speech-02-turbo`, `speech-01-hd`, `speech-01-turbo`.
> - Option `fluent`, `whisper` is only available for models: `speech-2.6-turbo`, `speech-2.6-hd`.
>   `speech-2.8-hd` and `speech-2.8-turbo` do not support `whisper`.

So the enum has 9 values but 2.8 accepts at most 8 of them (`whisper` is 2.6-only). The "7 emotions
supported" line in the models catalogue is a third count — see
`../minimax-speech-2.8-models-list/2026-10-26.md`.

## Voice settings (verbatim field ranges)

| Field | Range / default | Notes |
| --- | --- | --- |
| `voice_id` | required unless `timbre_weights` is used | "Supports system voices, cloned voices, and AI-generated voices" |
| `speed` | `[0.5, 2]`, default 1 | |
| `vol` | `(0, 10]`, default 1 | |
| `pitch` | `[-12, 12]`, default 0 | |
| `emotion` | enum above | 2.8: no `whisper` |
| `text_normalization` | boolean, **deprecated** | superseded by `text_normalization_mode` |
| `latex_read` | boolean, default false | Chinese only; forces `language_boost=Chinese`; formulas in `$$` |

`timbre_weights` mixes "Up to 4 voices" with weights `[1, 100]`; `voice_id` must be left empty when
mixing.

## Voice modification (verbatim)

> Voice effects configuration.
>
> Supported audio formats:
> - Non-streaming: `mp3`, `wav`, `flac`
> - Streaming: `mp3`

| Field | Range | Mapped to |
| --- | --- | --- |
| `pitch` | `[-100, 100]` | "Deepen/Brighten" slider |
| `intensity` | `[-100, 100]` | "Stronger/Softer" slider |
| `timbre` | `[-100, 100]` | "Nasal/Crisp" slider |
| `sound_effects` | `spacious_echo`, `auditorium_echo`, `lofi_telephone`, `robotic` | "Only one can be applied at a time" |

Note the sign convention differs from the marketing sliders: for `intensity`, "Values closer to -100
create a stronger, more forceful sound, while values closer to 100 yield a softer tone."

## Audio output (verbatim)

```yaml
sample_rate:
  description: Supported values: [`8000`, `16000`, `22050`, `24000`, `32000`, `44100`].
bitrate:
  description: Supported values: [`32000`, `64000`, `128000`, `256000`].
  Note: This parameter only applies to audio in `mp3` format.
format:
  description: Supported values: [`mp3`, `pcm`, `flac`, `wav`, `pcmu_raw`, `pcmu_wav`, `opus`].
  Note: `pcmu_raw` and `pcmu_wav` are G.711 μ-law encoded (8 kHz sample rate; `pcmu_raw` is
  headerless raw, `pcmu_wav` is wrapped in a WAV container). `opus` is Ogg/Opus encoded.
  default: mp3
channel: 1 or 2, default 1
force_cbr: only takes effect when output is streamed in MP3 format
```

Seven container/codec options, six sample rates up to 44.1 kHz, four MP3 bitrates, mono or stereo.
No sample rate is stated as the model's native rate — the field only lists what can be requested.

## Response and billing fields (verbatim, selection)

> `usage_characters`: Number of billable characters used in this synthesis.

> `usage_voice_count`: Number of voices billed in this request (a voice is charged on its first
> use). Returned only when a voice fee is incurred.

> `word_count`: Number of characters in the synthesized text (punctuation and spaces included). For
> reference only and not used for billing; see `usage_characters` for billable characters.

> `invisible_character_ratio`: … If ≤ 10%, audio is generated normally and the ratio is returned. If
> \> 10%, an error is returned.

> `output_format`: Options: `[url, hex]`. Default is `hex`. Only effective in non-streaming
> scenarios. In streaming, only `hex` is supported. Returned url is valid for 24 hours.

Error codes include `1042` ("invalid characters exceed `10%`") and `2013` (invalid input).

## Subtitles and normalization (verbatim)

> `subtitle_enable`: … Available for models: `speech-2.8-hd`, `speech-2.8-turbo`, `speech-2.6-hd`,
> `speech-2.6-turbo`, `speech-02-hd`, `speech-02-turbo`, `speech-01-hd`, `speech-01-turbo`.

> `subtitle_type`: `sentence` | `word` | `word_streaming`; default `sentence`. Non-streaming
> returns `subtitle_file` (JSON, millisecond timestamps, sentences ≤ 50 characters).

> `text_normalization_mode`: `basic` uses fast, rule-based normalization. `quality` uses a hybrid
> LLM + rule-based approach… `quality` currently takes effect only for non-streaming requests
> (`stream=false`) with `speech-2.8-hd`, `speech-2.8-turbo`, `speech-2.6-hd`, and
> `speech-2.6-turbo`. For streaming requests or other models, `quality` is processed as `basic` and
> no error is returned.

## Language control (verbatim)

> Controls whether recognition for specific minority languages and dialects is enhanced. Default is
> `null`. If the language type is unknown, set to `"auto"` and the model will automatically detect
> it.
>
> Note: The speech-01 and speech-02 series models do not currently support Persian, Filipino, or
> Tamil.

The `language_boost` enum contains exactly **40** named values plus `auto`: Chinese, Chinese,Yue,
English, Arabic, Russian, Spanish, French, Portuguese, German, Turkish, Dutch, Ukrainian, Vietnamese,
Indonesian, Japanese, Italian, Korean, Thai, Polish, Romanian, Greek, Czech, Finnish, Hindi,
Bulgarian, Danish, Hebrew, Malay, Persian, Slovak, Swedish, Croatian, Filipino, Hungarian, Norwegian,
Slovenian, Catalan, Nynorsk, Tamil, Afrikaans.

## What this establishes

- One endpoint, two 2.8 tiers (`-hd`, `-turbo`), and a documented feature delta: interjections are
  2.8-only; `whisper` emotion is 2.6-only.
- **10,000 characters** is the vendor's hard sync limit ("Must be less than 10,000"), with 3,000
  characters named as the point past which streaming is recommended.
- Billing is **per character** (`usage_characters`), with a separate **per-voice** charge on a
  voice's first use.
- Seven output formats and six sample rates on the vendor route — the widest surface of any route
  captured for this model.
- Nothing in this reference mentions a watermark, an output-identification field, or a consent
  requirement for cloned voices.

## Gaps

- No statement of native sample rate, model size, checkpoint, or training data.
- No rate limit (see the rate-limits guide: T2A is 60 RPM for all current speech models).
- No statement about whether interjections are billed as characters (they are counted inside
  `text`, but the page does not say).
- No watermark or provenance field anywhere in the schema.

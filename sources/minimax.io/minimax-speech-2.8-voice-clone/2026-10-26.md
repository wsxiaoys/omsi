## Upload requirements (verbatim)

> Requirements for uploaded files:
> * Supported formats: mp3, m4a, wav
> * Duration: minimum 10 seconds, maximum 5 minutes
> * File size: up to 20 MB

Optional second clip:

> Requirements for example files:
> * Supported formats: mp3, m4a, wav
> * Duration: less than 8 seconds
> * File size: up to 20 MB

The optional clip is passed as `clone_prompt.prompt_audio` with a `prompt_text` transcript: "Providing
this field helps improve the similarity and stability of synthesized voice."

## Cloning call (verbatim schema notes)

> The `voice_id` of the cloned voice. Example: `"MiniMax001"`. When defining a custom `voice_id`,
> note the following rules:
> - Length range: [8, 256]
> - Must start with an English letter
> - Can contain letters, digits, `-`, and `_`
> - Cannot end with `-` or `_`
> - Must not duplicate an existing `voice_id`, otherwise an error will occur

> If a cloned voice is not used within 7 days, the system will delete it.

> `text`: Optional preview text, up to 1000 characters. The cloned voice will be used to read the
> text, and an audio preview link will be returned.
> Note: Preview requests are charged based on character count, consistent with T2A pricing.

> `text_validation`: Optional. The expected transcript of the cloning sample audio … When provided,
> the audio is sent to ASR and the recognized text is compared against `text_validation`. If the
> similarity is below `accuracy`, the request is rejected with status code `1043` (`The asr
> similarity check failed`). Maximum length: 200 characters.

> `accuracy`: … Valid range: `[0, 1]`. When omitted or set to `0`, defaults to `0.7`.

> `aigc_watermark`: Indicates whether to append an AIGC watermark tone to the end of the synthesized
> preview audio. Default: `false`.

## Interjection list on this page (verbatim)

> **Interjection tags**: Only supported when using `speech-2.8-hd` or `speech-2.8-turbo` models.
> Supported interjections: `(laughs)`, `(chuckle)`, `(coughs)`, `(clear-throat)`, `(groans)`,
> `(breath)`, `(pant)`, `(inhale)`, `(exhale)`, `(gasps)`, `(sniffs)`, `(sighs)`, `(snorts)`,
> `(burps)`, `(lip-smacking)`, `(humming)`, `(hissing)`, `(emm)`, `(whistles)`, `(sneezes)`,
> `(crying)`, `(applause)`.

That is **22** tags, three more than the T2A reference's list — `(whistles)`, `(crying)` and
`(applause)` appear only here. Both pages describe the same 2.8-only feature.

## What this establishes

- **The clone sample floor is 10 seconds, not 5 or 10 "as little as".** The launch post advertises a
  "10-second sample" and Replicate advertises "5 seconds of reference audio"; the API rejects
  anything under 10 s. 10 s is the hard floor and 5 minutes the ceiling.
- **Cloned voices expire if unused:** "If a cloned voice is not used within 7 days, the system will
  delete it." That is a retention rule with real pipeline consequences, and it is stated only in the
  API reference's one-line summary.
- **There is a consent-adjacent check but it is an ASR transcript match, not identity consent.**
  `text_validation`/`accuracy` verify that the sample audio says what the caller claims it says. No
  page captured here requires proof of the speaker's permission.
- **`aigc_watermark` exists only on this endpoint**, defaults to `false`, and is described as an
  audible "watermark tone" appended to the **preview** audio — not an inaudible watermark on T2A
  output. No equivalent field exists in the T2A schema.
- The interjection count is **19 on T2A and 22 here**; the vendor's own two lists disagree.

## Gaps

- No statement of what audio characteristics make a good clone sample, or of any similarity metric.
- No consent/authorisation workflow documented: nothing on who may clone whom, or how a complaint
  about an impersonating voice is handled.
- No statement whether a clone made through one account is usable through a host (fal, Replicate).
- The 7-day deletion rule's clock start (creation vs last use) is stated as "not used within 7 days"
  but not otherwise defined.

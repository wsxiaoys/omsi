# MiniMax API Docs: Music Generation guide (retirement notice, cover workflow)

- Origin: MiniMax, "Music Generation", <https://platform.minimax.io/docs/guides/music-generation>
- Evidence kind: official documentation (vendor capability guide and service-availability notice)
- Publication date: not stated; live guide. The retirement notice it carries is dated
  "August 20, 2026". Capture date 2026-10-26
- Capture date: 2026-10-26
- Relevant models: `music-3.0`, `music-2.6`, `music-cover` (and their `-free` variants)

## Service-availability notice (verbatim, top of page)

> Starting August 20, 2026, the paid APIs (Music Generation and Lyrics Generation) will no longer be
> available to new users; existing paying users can continue to use the current API services. The
> free music generation APIs (Music-3.0-free, Music-2.6-free, music-cover-free) will be discontinued.
>
> To experience or use music generation capabilities, please visit
> [MiniMax Audio](https://www.minimax.io/audio), or use the open-source
> [MiniMax Music 3 model on Hugging Face](https://huggingface.co/MiniMaxAI/MiniMax-Music3).

## What the guide documents

- Endpoint: `POST https://api.minimax.io/v1/music_generation`, `model` selects the version.
- The worked example uses `"model": "music-3.0"`; the guide's framing is Music 3.0 ("Music 3.0:
  Experience the New Music Generation Capabilities").
- Two-step workflow: optional `POST /v1/lyrics_generation` (`mode: "write_full_song"`) to write
  lyrics from a theme, then `/v1/music_generation` to compose.
- `lyrics_optimizer: true` generates lyrics from the prompt, so a song can be produced from a style
  description alone.
- "Music 3.0 supports instrumental-only generation; see the `is_instrumental` parameter."
- Cover generation has two modes, documented under the same endpoint with `model: "music-cover"`:
  - **One-Step Cover**: pass `audio_url`; "Lyrics are automatically extracted from the audio."
  - **Two-Step Cover**: `POST /v1/music_cover_preprocess` (free, "no charge") returns
    `cover_feature_id`, `formatted_lyrics`, `structure_result` and `audio_duration`; the ID is
    "valid for 24 hours". When it is used, `lyrics` is required (10–1000 characters) and
    `audio_url` / `audio_base64` must not be sent.
- Example `audio_setting`: `{"sample_rate": 44100, "bitrate": 256000, "format": "mp3"}`.

## What this establishes

- The first-party music API is **closed to new users as of 2026-08-20**, and the free tiers are
  discontinued outright. Existing paying users are told they "can continue to use the current API
  services" — so `music-2.6` remained reachable for grandfathered accounts after that date, even
  though the vendor's model list calls it retired (see `../music-26-model-list/2026-10-26.md`).
- The vendor's forward path is the consumer app and the **open-weights Music 3** model, not Music 2.6.
- Cover is documented as its own `model` value (`music-cover`), not as a flag on `music-2.6` — even
  though the 2.6 launch post introduced cover as a 2.6 feature
  (`../music-26-launch/2026-10-26.md`).

## Gaps

- No statement of which model the guide's parameters apply to where they differ; it presents
  Music 3.0 and Music 2.6 as interchangeable through one schema.
- No maximum song duration anywhere in the guide.
- No language list for sung lyrics.
- No statement on watermarking or output provenance.

# Mistral docs: audio formats

- Origin: Mistral AI, "Audio formats", Studio audio specs and limits, <https://docs.mistral.ai/studio/audio/specs-and-limits/audio-formats>
- Evidence kind: official vendor documentation (first-party)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: all Voxtral 3 audio models; TTS output section is `voxtral-mini-tts-3-0`
- Capture type: rendered page text

## Verbatim

Speech output table:

| Format | Use it for |
| --- | --- |
| `mp3` (default) | "Playback in browsers and apps, when file size matters" |
| `opus` | "Streaming and playback over limited bandwidth" |
| `wav` | "Editing, or when you need uncompressed audio in a standard file" |
| `flac` | "Lossless archiving at a smaller size than WAV" |
| `pcm` | "Raw pipelines and telephony bridges that take raw samples, with no file header" |

> "Generated speech is mono at 24 kHz. To set the format in a request, see Response formats."

Reference audio table:

| Use | Format | Number and length |
| --- | --- | --- |
| "Speaker references for diarization" | "The base64 encoding of an audio file, keyed by a speaker name" | "Up to 8 clips, 3 to 15 seconds each" |
| "Voice cloning" | "An MP3 or WAV file, base64-encoded. A URL isn't accepted." | "A few seconds to a few minutes" |

Voice Agents SDK: "16-bit signed PCM, mono, 48 kHz" for the custom audio interface.

## Summary

Fixes the output contract: mono, **24 kHz**, five containers, MP3 by default. No bitrate is
published for any container, so a delivered file cannot be compared to the 24 kHz mono PCM baseline
on documented grounds.

The cloning reference clip is bounded only qualitatively — "a few seconds to a few minutes" — the
only length statement for the zero-shot path anywhere in the docs.

## Gaps

- No bitrate, no channel-count alternative to mono, no maximum output duration.
- "A few seconds to a few minutes" is not an operational limit; no error is documented for a clip
  outside it.

## Transcription-specific capture (same vendor page)

## Transcription input, verbatim

| Mode | How you send audio | Formats | Details |
| --- | --- | --- | --- |
| File transcription | One file per request: `file` (upload), `file_url` (a URL of up to 2,083 characters), or `file_id` (a file uploaded to `/v1/files` with `purpose=audio`) | *(cell empty in the page HTML)* | File transcription |
| Realtime transcription | Raw audio in base64 chunks, described by `audio_format` in `session.update` | `pcm_s16le` (16-bit signed little-endian PCM, mono). Default sample rate: 16,000 Hz. | Realtime transcription |

## Reading

- **The file-transcription format list is missing from the page.** The cell is present and empty in
  the HTML, so the page that every other audio page links to for "the accepted audio formats" does not
  state them for the offline models. Realtime is fully specified (16 kHz mono `pcm_s16le`).
- Voxtral Transcribe 2's announcement documented `.mp3, .wav, .m4a, .flac, .ogg up to 1GB each` for
  the Studio playground (`../../mistral.ai/voxtral-transcribe-2-launch/2026-10-26.md`); nothing in the
  Voxtral 3 docs confirms or replaces that list.

## Gaps

- Accepted container/codec list and maximum file size for file transcription are both undocumented at
  capture (the same empty-cell problem appears on the limits page).
- Sample rate and channel requirements for file transcription are not stated.

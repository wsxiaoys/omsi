# Mistral docs: speak in realtime (Voxtral TTS Realtime 3)

- Origin: Mistral AI, "Speak in realtime", Studio audio documentation, <https://docs.mistral.ai/studio/audio/text-to-speech/speak-in-realtime>
- Evidence kind: official vendor documentation (first-party)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: Voxtral TTS Realtime 3 (`voxtral-mini-tts-realtime-3-0`)
- Capture type: rendered page text

## Verbatim

Endpoint:

> `wss://api.mistral.ai/v1/audio/speech/realtime?model=voxtral-mini-tts-3-0`

Note that the query string carries the **offline** identifier. The server's `session.created` event
echoes a different string:

> `"session": { "model": "voxtral-mini-tts-3-0-13", "voice": "voice_447", "streaming_mode":
> "responsive", "response_format": "wav" }`

Session fields:

| Field | Type | Default | Use it to |
| --- | --- | --- | --- |
| `voice` | "String, a preset voice ID" | `voice_447` | "Pick a ready-made voice." |
| `ref_audio` | "String, base64-encoded audio" | not set | "Reproduce a voice from a short recording. Provide this or voice, not both." |
| `streaming_mode` | String | `responsive` | "responsive (lower latency) or long_form (higher quality for longer text)." |
| `response_format` | String | `wav` | "pcm, wav, mp3, flac, opus." |

Lifecycle: `session.created` → `session.update` / `session.updated` → `input_text.append` →
`input_text.flush` (next generation on the same socket) or `input_text.end` (close, code 1000).

> "One session supports multiple sequential generations: finish one, start the next, without
> reconnecting."

> "The server does not automatically flush on pauses, spaces, or punctuation — you decide when a
> generation is complete."

> "Updating during an active generation is a recoverable error: the update is rejected, and the
> connection stays open."

## Summary

The realtime path takes the same identifiers, the same voice catalogue and the same cloning input as
the offline path, and adds a `streaming_mode` choice. Cloning is available in realtime via
`ref_audio`, which the OpenRouter host does not expose.

The echoed `voxtral-mini-tts-3-0-13` string is the only first-party evidence of a hidden snapshot
suffix behind the alias.

## Gaps

- No session duration cap, text cap, or concurrency limit documented.
- No latency number on this page beyond the qualitative `responsive` / `long_form` distinction.
- The `-13` snapshot suffix is unexplained.

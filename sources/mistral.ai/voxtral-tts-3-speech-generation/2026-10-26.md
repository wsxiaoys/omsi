# Mistral docs: speech generation request reference

- Origin: Mistral AI, "Speech generation", Studio audio documentation, <https://docs.mistral.ai/studio/audio/text-to-speech/generate-speech>
- Evidence kind: official vendor documentation (first-party)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: Voxtral TTS 3 (`voxtral-mini-tts-3-0`)
- Capture type: rendered page text

## Verbatim

Request fields table:

| Field | What it does |
| --- | --- |
| `model` | "The speech model, for example voxtral-mini-tts-3-0." |
| `input` | "The text to speak. It can carry inline emotion and pace tags." |
| `voice_id` | "The voice to use: a preset slug such as gb_jane_neutral, or the ID of a voice saved in your workspace." |
| `ref_audio` | "A short recording, base64-encoded, to clone a voice for this request only, instead of voice_id." |
| `response_format` | "The audio format of the result." |
| `expressiveness` | — |
| `instruction` | "Style instructions are not available at launch." |
| `phoneme_hints` | "The pronunciation of specific words, as lists of phonemes." |
| `stream` | "Set to true to receive the audio in chunks as it's generated." |
| `conversation_history` | "Prior conversation audio that conditions the delivery of the new response." |

Expressiveness:

> "expressiveness sets how strongly the generated speech follows what you ask for: the voice, the
> text, and any emotion tags or style instruction. It accepts values from 1.0 to 5.0."
>
> "Higher values trade voice similarity and stability for stronger delivery. Start with the default,
> raise it if the emotion doesn't come through, and lower it if the speech sounds forced."

Contextual TTS:

> "conversation_history is an array of turns, oldest first. Each turn is either a user turn with
> audio, or an assistant turn with text and audio. The new input is the assistant's reply to the last
> user turn in the history."
>
> "conversation_history requires a Voxtral 3 preset voice (voice_id), and cannot be combined with
> ref_audio, instruction, or realtime_context."
>
> "The history must be nonempty, alternate between user and assistant, and end with a user turn."

Response: "The response carries the audio, base64-encoded, in audio_data".

Errors quoted: `400 error: Either ref_audio or voice must be provided.`; `404 error of type
invalid_voice: Voice 'x' not found.`

## Summary

The parameter surface for the offline model. It sets expressiveness to a 1.0–5.0 range (the overview
page says ">= 1.0"), makes contextual TTS a real feature with hard structural constraints, and
confirms cloning-per-request and voice-by-ID are mutually exclusive.

No field carries a length limit, and the page states none.

## Gaps

- `realtime_context` is referenced as a mutually exclusive field but is not documented on this page.
- The public OpenAPI schema for `POST /v1/audio/speech` does not list `expressiveness`,
  `instruction`, or `conversation_history`; see the API reference record.
- No maximum `input` length, and no cost example.

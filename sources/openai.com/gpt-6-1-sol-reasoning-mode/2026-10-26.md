# OpenAI reasoning guide: `pro` mode and GPT-6.1 Sol reasoning settings

- **Origin:** OpenAI, "Reasoning models", <https://developers.openai.com/api/docs/guides/reasoning>
  (Markdown variant `…/guides/reasoning.md`). Retrieved 2026-10-26.
- **Evidence kind:** official documentation (first-party API behaviour).
- **Publication date:** none stated; live guide.
- **Capture date:** 2026-10-26
- **Relevant models:** `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`.
- **Capture type:** full text of the Markdown variant. Excerpts below are verbatim.

## Reasoning mode, verbatim

> GPT-5.6 and GPT-6 models support `standard` and `pro` reasoning modes in the Responses
> API. `standard` is the default. Set `reasoning.mode` to `pro` for difficult tasks that
> need more model work and can tolerate higher latency and token usage.
>
> Reasoning mode and reasoning effort are independent. Mode selects standard or pro
> execution, while `reasoning.effort` controls how much reasoning the model applies within
> that mode. If you omit `reasoning.effort`, GPT-5.6 defaults to `medium` in both modes.
> GPT-6.1 Sol, GPT-6 Sol, and GPT-6 Luna also default to `medium` reasoning effort.
>
> Pro mode aggregates the model work performed to produce the final answer and bills those
> tokens at the selected model's standard token rates. Pro mode performs more model work
> than standard mode, increasing token usage and cost. Existing Pro model IDs keep their
> current behavior and pricing.

The guide's pro-mode example sets `"model": "gpt-6.1-sol"` with `reasoning.mode: "pro"`.

## Constraints stated for GPT-6.1 Sol, verbatim

> [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) does not support
> `none` reasoning effort. Setting `reasoning.effort` (Responses) or `reasoning_effort`
> (Chat Completions) to `none` returns HTTP 400. [GPT-6.1 Sol](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra#gpt-61-sol)
> does not support `none` or `minimal` and defaults to `medium`.
>
> Use the [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses)
> for function calling. Chat Completions does not support function calling with GPT-6
> Astra or GPT-6.1 Sol.

> The [GPT-5.6 model family](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6)
> supports `all_turns` and uses it by default. Earlier models default to `current_turn`.
> [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) also supports
> `all_turns`. Omit `reasoning.context` or set it to `auto` to use the selected model's
> default.

> `all_turns` … Renders available, compatible reasoning items from earlier turns into the
> next sample. GPT-5.6 models and GPT-6.1 Sol support this value.

## Summary

Three things this establishes:

1. **`pro` is a mode of the same model, not a separate model.** OpenAI has no
   `gpt-6.1-sol-pro` ID on its model page; the pro behaviour is `reasoning.mode: "pro"` on
   `gpt-6.1-sol`, billed at the same token rates. This is what OpenRouter's
   `openai/gpt-6.1-sol-pro` slug serves
   ([host record](../../openrouter.ai/gpt-6-1-sol/2026-10-26/index.md)).
2. **Sol is a reasoning-only model**: it rejects `none` *and* `minimal` effort (the model
   page lists exactly `low`, `medium`, `high`, `xhigh`, `max`) and defaults to `medium`.
3. **Persisted reasoning across turns (`all_turns`)** is supported by GPT-6.1 Sol, but the
   guide states the GPT-5.6 family *defaults* to it while Sol's default is only described
   as "the selected model's default". Whether Sol defaults to `all_turns` is not stated.

## Gaps

- The guide gives no cost multiplier or token-count expectation for pro mode beyond
  "more model work".
- It does not state whether `pro` is available at every effort level or only some; the
  captured model page lists no mode dimension at all.

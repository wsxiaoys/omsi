# OpenAI "Using GPT-6" guide: the GPT-6.1 Terra section and migration rules

- **Origin:** OpenAI, "Using GPT-6", <https://developers.openai.com/api/docs/guides/latest-model>
  (Markdown variant `…/guides/latest-model.md`). Retrieved 2026-10-26.
- **Evidence kind:** official documentation (first-party usage and migration guidance).
- **Publication date:** none stated; live guide.
- **Capture date:** 2026-10-26
- **Relevant models:** `gpt-6.1-terra`, with `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna`,
  `gpt-6-sol`, `gpt-5.6-terra`.
- **Capture type:** full text of the Markdown variant (20 KB); excerpts verbatim. The sibling
  record [GPT-6 family guide](../gpt-6-family-guide/2026-10-26.md) captures the tier list
  and the Sol-specific migration bullets; this record captures the Terra-specific section and

## Tier list, verbatim

> - **GPT-6 Astra** **Highest intelligence** — For the most demanding reasoning, coding,
>   and professional work.
> - **GPT-6.1 Sol** **Balanced speed, cost, and intelligence** — Near-Astra performance
>   for complex work at a lower cost.
> - **GPT-6.1 Terra** **Fast and efficient** — For visual reasoning, precise computer use,
>   and clear, natural writing.
> - **GPT-6 Luna** **Fastest and most cost-effective** — Strong performance for focused,
>   high-volume tasks.

**There is no `gpt-6-terra`.** The Terra tier skipped the 6.0 generation: the family is
Astra (6.0), 6.1 Sol, 6.1 Terra, Luna (6.0), and OpenAI's price sheet carries `gpt-5.6-terra`
and `gpt-6.1-terra` with nothing between
([pricing](../gpt-6-1-terra-pricing/2026-10-26.md)).

## GPT-6.1 Terra section, verbatim

> GPT-6.1 Terra is a fast, efficient model for visual reasoning, precise computer
> use, and clear, natural writing. Use it to match product photos to catalog
> entries, compare technical drawings, act on application screens, or draft and
> revise text.
>
> It supports `none`, `low`, `medium` (default), `high`, `xhigh`, and `max`
> reasoning effort. Start with `medium` and increase it if the improvement in
> quality is worth the added time and tokens.
>
> When migrating from GPT-5.6 Terra, compare both models on representative images
> and workflows using the same reasoning effort. If your application calls tools
> through Chat Completions, migrate those requests to the Responses API.

The migration sentence is the closest first-party statement of succession: Terra replaces
GPT-5.6 Terra in the same tier, framed as a comparison to run, not as a deprecation.

## Migration-checklist bullets that name Terra, verbatim

> - **Reasoning effort:** … GPT-6 Astra and GPT-6.1 Sol do not support `none`; use `low`
>   instead. GPT-6.1 Terra, GPT-6 Sol, and GPT-6 Luna support `none`. If your existing
>   request uses `minimal`, start with `low` and compare results on representative tasks.

> - **Tool calling:** Use the Responses API. GPT-6 Astra, GPT-6.1 Sol, and GPT-6.1 Terra
>   support Chat Completions, but tool calling requires Responses. GPT-6 Sol and GPT-6
>   Luna support function calling in Chat Completions only with `reasoning_effort: "none"`.

> - **Data residency:** Fast mode supports EU data residency for GPT-6.1 Sol, GPT-6.1
>   Terra, and GPT-6 Luna, but not GPT-6 Astra or GPT-6 Sol. … Fast mode for GPT-6 Astra
>   does not include a latency SLA.

## Family capabilities introduced with GPT-6, verbatim abridgements

- **Async tool calling** — "Set `async: true` on a function or custom tool and return its
  result when ready using the original `call_id`."
- **Mid-turn steering** — send additional instructions while the model works, over a
  WebSocket connection.
- **Change reasoning mid-conversation** — `configuration_update` input items change effort
  "without rewriting the original prompt prefix".
- **Misalignment monitoring** — described as part of OpenAI's strengthened safeguards "for
  GPT-6 Astra".

The guide also lists computer use, Structured Outputs, streaming, Programmatic Tool Calling,
multi-agent orchestration, prompt caching, persisted reasoning, compaction, and pro mode as
inherited GPT-5.6 capabilities. Prompting best practices on the page are written for Astra
("They address behavior observed with GPT-6 Astra; evaluate them with your chosen model and
workload"), so none of that guidance is Terra-specific.

## Summary

The guide is the first-party source for three Terra facts the model page leaves implicit:
`none` reasoning effort is supported (as on GPT-6 Sol and GPT-6 Luna, unlike Astra and 6.1
Sol), Chat Completions works but tool calling requires Responses, and Terra is the migration
target for GPT-5.6 Terra. It also confirms Fast-mode EU residency for Terra.

## Gaps

- No benchmark table and no Terra-specific prompting guidance.
- Does not say whether GPT-5.6 Terra is being retired; no deprecation date appears here.
- Does not state whether Terra supports `reasoning.mode: "pro"` or
  `reasoning.context: "all_turns"`.

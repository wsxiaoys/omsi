# OpenAI reasoning guide: what applies to `gpt-6.1-terra`

- **Origin:** OpenAI, "Reasoning", <https://developers.openai.com/api/docs/guides/reasoning>
  (Markdown variant `…/guides/reasoning.md`). Retrieved 2026-10-26.
- **Evidence kind:** official documentation (first-party parameter reference).
- **Publication date:** none stated; live guide.
- **Capture date:** 2026-10-26
- **Relevant models:** `gpt-6.1-terra`, with `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-sol`,
  `gpt-6-luna`, `gpt-5.6-*` for the support lists.
- **Capture type:** verbatim excerpts from the reasoning-effort, reasoning-mode, and
  persisted-reasoning sections. The full page is large and its code samples were not stored.

## Effort set

The model page states Terra's own set — `none`, `low`, `medium` (default), `high`, `xhigh`,
`max` ([model page](../gpt-6-1-terra-model-page/2026-10-26.md)). The guide's effort section
names only the models that *reject* values, verbatim:

> GPT-6 Astra does not support `none` reasoning effort. Setting `reasoning.effort`
> (Responses) or `reasoning_effort` (Chat Completions) to `none` returns HTTP 400. GPT-6.1
> Sol does not support `none` or `minimal` and defaults to `medium`.

Terra is absent from that exclusion list, consistent with `none` being available.

## Reasoning mode, verbatim

> GPT-5.6 and GPT-6 models support `standard` and `pro` reasoning modes in the Responses API.
> `standard` is the default. Set `reasoning.mode` to `pro` for difficult tasks that need more
> model work and can tolerate higher latency and token usage.

> Pro mode aggregates the model work performed to produce the final answer and bills those
> tokens at the selected model's standard token rates. Pro mode performs more model work than
> standard mode, increasing token usage and cost.

The statement is family-wide ("GPT-6 models"), so it covers Terra by scope. Every worked
example on the page uses `gpt-6.1-sol`, and Terra is not named in this section. OpenRouter
nonetheless sells a `-pro` slug for Terra described as "the same underlying model … served
with `reasoning.mode` set to `pro`"
([host record](../../openrouter.ai/gpt-6-1-terra/2026-10-26/index.md)), which is
consistent with the family-wide statement.

## Effort default

> If you omit `reasoning.effort`, GPT-5.6 defaults to `medium` in both modes. GPT-6.1 Sol,
> GPT-6 Sol, and GPT-6 Luna also default to `medium` reasoning effort.

Terra is **not** in that list, but its own model page states `medium` as the default, so the
two agree in effect and the guide's list is simply incomplete.

## Persisted reasoning across calls, verbatim

> The GPT-5.6 model family supports `all_turns` and uses it by default. Earlier models
> default to `current_turn`. GPT-6.1 Sol also supports `all_turns`.

> | `all_turns` | Renders available, compatible reasoning items from earlier turns into the next
> sample. GPT-5.6 models and GPT-6.1 Sol support this value. |

> Persisted reasoning can be reused only within the same model family. For example,
> `gpt-5.6-sol`, `gpt-5.6-terra`, and `gpt-5.6-luna` can reuse each other's reasoning, but
> reasoning does not carry between the GPT-5.6 and GPT-5.5 families.

**Terra is named nowhere in this section.** Both statements of `all_turns` support name the
GPT-5.6 family and GPT-6.1 Sol only. Whether `gpt-6.1-terra` supports `all_turns` is therefore
undocumented on this capture — it is not evidence that Terra rejects the value, but it is not
evidence that it accepts it either.

## Mid-conversation effort changes

> Configuration updates are supported by the GPT-6 model family in standard, single-agent
> mode. They change only reasoning effort.

Family-scoped, so Terra is covered by scope; no Terra-specific example exists.

## Summary

Terra sits inside the documented GPT-6 reasoning contract for **modes** (standard/pro) and
**mid-conversation effort changes**, is excluded from the models that reject `none` effort,
and is **absent** from the `all_turns` persisted-reasoning support list. Only the last point
is a Terra-specific gap rather than a positive capability statement.

## Gaps

- No Terra-specific `pro`-mode example, price note, or latency figure.
- No statement anywhere of Terra's `reasoning.context` default.
- The page never says whether `minimal` is accepted by Terra; only Astra and Sol are described
  as rejecting `none`/`minimal`.

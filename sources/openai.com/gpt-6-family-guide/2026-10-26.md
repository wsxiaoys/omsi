- **Evidence kind:** official documentation (first-party usage and migration guidance).
- **Publication date:** none stated; live guide.
- **Capture date:** 2026-10-26
- **Relevant models:** `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-luna`,
  `gpt-6-sol`.
- **Capture type:** full text of the Markdown variant. Excerpts verbatim.

## Tier list, verbatim

> - [GPT-6 Astra](…) **Highest intelligence** — For the most demanding reasoning, coding,
>   and professional work.
> - [GPT-6.1 Sol](…) **Balanced speed, cost, and intelligence** — Near-Astra performance
>   for complex work at a lower cost.
> - [GPT-6.1 Terra](…) **Fast and efficient** — For visual reasoning, precise computer use,
>   and clear, natural writing.
> - [GPT-6 Luna](…) **Fastest and most cost-effective** — Strong performance for focused,
>   high-volume tasks.

(Links elided; the page's anchors are the model IDs.)

## Predecessor statement, verbatim

> If you already use [`gpt-6-sol`](https://developers.openai.com/api/docs/models/gpt-6-sol),
> review the [migration guidance](#migration-quickstart) before switching to GPT-6.1 Sol.

This is the closest first-party statement that GPT-6.1 Sol is the successor of GPT-6 Sol in
the same tier. It is framed as a migration path, not as a deprecation.

## GPT-6.1 Sol section, verbatim

> GPT-6.1 Sol delivers near-Astra performance at a lower cost for complex coding, computer
> use, and professional work. It supports `low`, `medium` (default), `high`, `xhigh`, and
> `max` reasoning effort.

## Migration checklist entries that bind GPT-6.1 Sol, verbatim

> - **Reasoning effort:** … GPT-6 Astra and GPT-6.1 Sol do not support `none`; use `low`
>   instead. …
> - **Tool calling:** Use the Responses API. GPT-6 Astra, GPT-6.1 Sol, and GPT-6.1 Terra
>   support Chat Completions, but tool calling requires Responses. …
> - **Unsupported parameters:** When reasoning effort is not `none`, remove `temperature`,
>   `top_p`, and `top_logprobs`. For Chat Completions, also remove `logprobs`. …
> - **Data residency:** Fast mode supports EU data residency for GPT-6.1 Sol, GPT-6.1
>   Terra, and GPT-6 Luna, but not GPT-6 Astra or GPT-6 Sol. Ultrafast mode for GPT-6.1 Sol
>   supports US and EU data residency and global processing. …

## Family capabilities introduced with GPT-6 ("What's new"), verbatim abridgements

- **Async tool calling** — "Set `async: true` on a function or custom tool and return its
  result when ready using the original `call_id`."
- **Mid-turn steering** — send additional instructions while the model works, over a
  WebSocket connection.
- **Change reasoning mid-conversation** — `configuration_update` input items change effort
  without rewriting the prompt prefix.
- **Misalignment monitoring** — described as part of OpenAI's safeguards "for GPT-6 Astra".

The guide also lists computer use, Structured Outputs, streaming, Programmatic Tool Calling,
multi-agent orchestration, prompt caching, persisted reasoning, compaction, and pro mode as
existing GPT-6 capabilities.

## Summary

First-party tier positioning (Sol is the balanced middle tier, Astra above, Terra and Luna
below), the migration path from `gpt-6-sol`, and the concrete parameter constraints: no
`none`/`minimal` effort, no `temperature`/`top_p`/`top_logprobs` while reasoning is on,
tool calling only through Responses.

## Gaps

- Prompting best practices on this page are explicitly written for Astra ("They address
  behavior observed with GPT-6 Astra; evaluate them with your chosen model and workload"),
  so none of the behavioural guidance is Sol-specific.
- No benchmark table for Sol; the only launch-post link is `openai.com/index/gpt-6-astra/`,
  which returned HTTP 403 to this capture.

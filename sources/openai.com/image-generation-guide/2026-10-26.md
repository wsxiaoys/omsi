# OpenAI: image generation guide (GPT Image 2 sections)

- Origin: OpenAI, "Image generation", https://developers.openai.com/api/docs/guides/image-generation
  (retrieved as https://developers.openai.com/api/docs/guides/image-generation.md)
- Evidence kind: official documentation (usage guide)
- Publication date: not stated; rolling. Captured 2026-10-26.
- Capture date: 2026-10-26
- Relevant models: GPT Image 2 (`gpt-image-2`), GPT Image 2.5 Sunburst/Flare, earlier GPT Image
  models

## Shape of the page at capture

The guide is now written around the 2.5 models. Its overview opens (verbatim):

> The API lets you generate and edit images from text prompts using `gpt-image-2.5-sunburst` and
> `gpt-image-2.5-flare`.

GPT Image 2 documentation survives in a collapsed section introduced as (verbatim):

> The details below apply to earlier models, not Sunburst or Flare. For new integrations, use one
> of the GPT Image 2.5 models described above.

That section is titled "GPT Image 2 settings and input fidelity", so the following parameters
are stated for `gpt-image-2` rather than inferred.

## Sizes and quality (verbatim, from the GPT Image 2 section)

Popular sizes: `1024x1024` (square), `1536x1024` (landscape), `1024x1536` (portrait),
`2048x2048` (2K square), `2048x1152` (2K landscape), `3840x2160` (4K landscape),
`2160x3840` (4K portrait), `auto` (default).

> `gpt-image-2` accepts any resolution in the `size` parameter when it satisfies the constraints
> below. Square images are typically fastest to generate.

Size constraints (verbatim list):

> - Maximum edge length must be less than or equal to `3840px`
> - Both edges must be multiples of `16px`
> - Long edge to short edge ratio must not exceed `3:1`
> - Total pixels must be at least `655,360` and no more than `8,294,400`

Quality options for `gpt-image-2` (verbatim): `low`, `medium`, `high`, `auto` (default).
Elsewhere on the page, `xhigh` and `max` are described as additions on the 2.5 models only, and
"Earlier GPT Image models support quality settings up to `high`."

## Input fidelity (verbatim)

> The `input_fidelity` parameter controls how strongly a model preserves details from input
> images during edits and reference-image workflows. For `gpt-image-2`, omit this parameter; the
> API doesn't allow changing it because the model processes every image input at high fidelity
> automatically.

> Because `gpt-image-2` always processes image inputs at high fidelity, image input tokens can be
> higher for edit requests that include reference images.

## Per-image cost examples (verbatim table rows, "Calculating costs")

Prices for GPT Image 2 at three sizes; the table header says these are the same sizes used for
previous GPT Image models "for comparison", and adds "Additional sizes available".

| Quality | 1024 × 1024 | 1024 × 1536 | 1536 × 1024 |
| --- | --- | --- | --- |
| Low | $0.006 | $0.005 | $0.005 |
| Medium | $0.053 | $0.041 | $0.041 |
| High | $0.211 | $0.165 | $0.165 |

Also stated: "`gpt-image-2` supports thousands of valid resolutions", and "A larger non-square
resolution can sometimes produce fewer output tokens than a smaller or square resolution at the
same quality setting."

Partial images, when streaming (verbatim): "each partial image will incur an additional 100
image output tokens."

Cached input pricing (verbatim): "For GPT Image 2 and GPT Image 2.5, cached input pricing
applies only to the image generation tool in the Responses API. It doesn't apply to direct
Images API requests, including `/v1/images/edits`." Cached token counts are billed but are not
reported in `usage`.

## Limitations section (verbatim, scoped to "GPT Image models" generally)

> - **Latency:** Complex prompts may take up to 2 minutes to process.
> - **Text Rendering:** Although significantly improved, the model can still struggle with
>   precise text placement and clarity.
> - **Consistency:** While capable of producing consistent imagery, the model may occasionally
>   struggle to maintain visual consistency for recurring characters or brand elements across
>   multiple generations.
> - **Composition Control:** Despite improved instruction following, the model may have
>   difficulty placing elements precisely in structured or layout-sensitive compositions.

Moderation (verbatim): all prompts and images are filtered per the usage policy; the `moderation`
parameter takes `auto` (default) or `low`.

## Known gaps

- The limitations list is written for "GPT Image models" as a class. It is not stated to be
  measured on `gpt-image-2` specifically, and it is not quantified.
- The cost table is explicitly a comparison subset, not a schedule; per-image cost for 2K/4K
  sizes must be measured or read from the interactive calculator, which is a client component
  and was not captured as data.
- The guide gives no guidance on how many reference images `gpt-image-2` accepts on the Images
  API, and no token-per-image table for `gpt-image-2` (only the older models' token table).
- No benchmark, no latency figures beyond "up to 2 minutes", no comparison against 2.5.

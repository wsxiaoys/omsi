# OpenAI: Image generation guide

- **Origin:** "Image generation", OpenAI API documentation,
  <https://developers.openai.com/api/docs/guides/image-generation>. Retrieved via the Markdown
  export (`…/image-generation.md`, ~114 KB).
- **Evidence kind:** official documentation (first-party conceptual + how-to guide).
- **Publication date:** not stated. Capture date 2026-10-26.
- **Relevant model/version:** `gpt-image-2.5-flare` (and `gpt-image-2.5-sunburst`, used
  throughout the guide's examples). Provider OpenAI. Endpoints `v1/images/generations`,
  `v1/images/edits`, and the Responses API `image_generation` tool.
- **Capture type:** summary of the sections that bear on Flare, with verbatim quotes marked.
  The guide is largely code samples; they are not reproduced.

## Positioning (verbatim)

> The API lets you generate and edit images from text prompts using `gpt-image-2.5-sunburst` and
> `gpt-image-2.5-flare`. Choose Sunburst for workflows where editing precision matters most, and
> Flare for fast, high-quality everyday image generation.

Two surfaces are described: the **Image API** (`v1/images/generations`, `v1/images/edits`) and
the **Responses API** image generation tool. With the Image API you set `model` to
`gpt-image-2.5-sunburst` or `gpt-image-2.5-flare` directly; with the Responses API you *"select a
supported mainline model at the top level and specify `gpt-image-2.5-sunburst` or
`gpt-image-2.5-flare` in the image generation tool's `model` field"* (verbatim).

## Size and quality (verbatim, condensed)

> `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare` add `xhigh` and `max` quality settings. Both
> default to `auto`. Earlier GPT Image models support quality settings up to `high`.

| Setting | Options |
| --- | --- |
| Recommended sizes | `1024x1024`, `1536x1024`, `1024x1536` |
| Quality | `low`, `medium`, `high`, `xhigh`, `max`, `auto` |

Verbatim constraints on custom sizes: *"Width and height must be multiples of 16, the aspect
ratio must be between 1:3 and 3:1, and neither edge may exceed 3840 pixels. The total pixel count
must be between 655,360 and 8,294,400 (4K). Resolutions above `2560x1440` are experimental."*

Verbatim on transparency: *"For transparent backgrounds with either model, set `background:
"transparent"` and use `output_format: "png"` or `"webp"`."*

Verbatim guidance: *"Use `quality: "low"` for quick drafts. For final assets, compare higher
quality settings to find the right balance of detail, latency, and cost."*

## Output format (verbatim, condensed)

> The Image API returns base64-encoded image data. The default format is `png`, but you can also
> request `jpeg` or `webp`.

`output_compression` applies to `jpeg`/`webp` only. *"Using `jpeg` is faster than `png`."*

## Editing and masks

- Multi-turn editing and File-ID inputs are described as Responses-API-only advantages over the
  Image API (summary).
- Mask requirements (verbatim, condensed): the image and mask *"must be of the same format and
  size (less than 50MB in size)"*, and the mask *"must also contain an alpha channel"*; the guide
  supplies code to derive an alpha channel from a black-and-white mask.
- The guide does **not** state a maximum number of reference images for edits.

## Limitations (verbatim, page-level for "GPT Image models")

> - **Latency:** Complex prompts may take up to 2 minutes to process.
> - **Text Rendering:** Although significantly improved, the model can still struggle with
>   precise text placement and clarity.
> - **Consistency:** While capable of producing consistent imagery, the model may occasionally
>   struggle to maintain visual consistency for recurring characters or brand elements across
>   multiple generations.
> - **Composition Control:** Despite improved instruction following, the model may have
>   difficulty placing elements precisely in structured or layout-sensitive compositions.

## Moderation

`moderation` accepts `auto` (default, "Standard filtering") or `low` ("Less restrictive
filtering"). Blocked generations can return `error.type = "image_generation_user_error"` with
`error.code = "moderation_blocked"`. All prompts and images are filtered per OpenAI's usage
policies (summary of the guide's wording).

## Cost notes that matter for comparison (verbatim, condensed)

- *"Both GPT Image 2.5 models use the same token rates: $8 per million image input tokens, $2 per
  million cached image input tokens, $30 per million image output tokens, $5 per million text
  input tokens, and $1.25 per million cached text input tokens."*
- *"Equal token rates don't mean equal cost per image: token consumption can differ by model and
  quality setting."*
- *"For GPT Image 2 and GPT Image 2.5, cached input pricing applies only to the image generation
  tool in the Responses API. It doesn't apply to direct Images API requests, including
  `/v1/images/edits`."*
- Partial (streamed) images each cost an additional 100 image output tokens.
- The guide ships a token calculator for 2.5, but the model page notes the *GPT Image 2*
  calculator does not estimate 2.5 token consumption.

## Known gaps

- Every capability statement here is vendor documentation. No quality, latency, or failure-rate
  measurement for Flare specifically appears in the guide; the "Limitations" list is written for
  "GPT Image models" as a class.
- `input_fidelity` is discussed only for `gpt-image-2` (where it cannot be changed). The guide
  does not say whether Flare accepts the parameter or always processes image inputs at high
  fidelity.
- No maximum reference-image count, no per-image price table, and no statement of which surface
  is cheaper in practice.

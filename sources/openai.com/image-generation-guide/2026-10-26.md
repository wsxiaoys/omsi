## Model selection (verbatim)

> The API lets you generate and edit images from text prompts using `gpt-image-2.5-sunburst`
> and `gpt-image-2.5-flare`. Choose Sunburst for workflows where editing precision matters
> most, and Flare for fast, high-quality everyday image generation.

> With the Image API, set `model` to `gpt-image-2.5-sunburst` or `gpt-image-2.5-flare`
> directly. With the Responses API, select a supported mainline model at the top level and
> specify `gpt-image-2.5-sunburst` or `gpt-image-2.5-flare` in the image generation tool's
> `model` field.

Two access paths, as the guide frames them:

- **Image API** — `v1/images/generations` (from scratch) and `v1/images/edits` (modify an
  existing image, wholly or partly).
- **Responses API** — the `image_generation` built-in tool. The guide says it adds
  "Multi-turn editing: Iteratively make high fidelity edits to images with prompting" and
  "Flexible inputs: Accept image File IDs as input images, not just bytes".

## Access gate (verbatim)

> To ensure these models are used responsibly, you may need to complete the API Organization
> Verification [...] before using GPT Image models.

> If your application serves individual end users, include a stable, privacy-preserving
> `safety_identifier` in each image generation or image edit request. [...] Safety identifiers
> are recommended but not required.

The Images API `user` parameter is documented as deprecated in favour of `safety_identifier`.

## Output controls (verbatim)

> `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare` add `xhigh` and `max` quality settings.
> Both default to `auto`. Earlier GPT Image models support quality settings up to `high`.

| Setting | Options |
| --- | --- |
| Recommended sizes | `1024x1024` (square), `1536x1024` (landscape), `1024x1536` (portrait) |
| Quality | `low`, `medium`, `high`, `xhigh`, `max`, `auto` |

> Both models also support custom dimensions as `WIDTHxHEIGHT` strings, such as `1536x864`.
> Width and height must be multiples of 16, the aspect ratio must be between 1:3 and 3:1, and
> neither edge may exceed 3840 pixels. The total pixel count must be between 655,360 and
> 8,294,400 (4K). Resolutions above `2560x1440` are experimental.

> For transparent backgrounds with either model, set `background: "transparent"` and use
> `output_format: "png"` or `"webp"`.

Output formats `png` (default), `jpeg`, `webp`, with `output_compression` 0–100 for the latter
two. The Image API returns base64-encoded image data; `jpeg` is documented as faster than `png`
when latency matters.

## Editing and masks (verbatim)

> Masking with GPT Image is entirely prompt-based. The model uses the mask as guidance, but may
> not follow its exact shape with complete precision.

> If you provide multiple input images, the mask will be applied to the first image.

## Limitations (verbatim)

> - **Latency:** Complex prompts may take up to 2 minutes to process.
> - **Text Rendering:** Although significantly improved, the model can still struggle with
>   precise text placement and clarity.
> - **Consistency:** While capable of producing consistent imagery, the model may occasionally
>   struggle to maintain visual consistency for recurring characters or brand elements across
>   multiple generations.
> - **Composition Control:** Despite improved instruction following, the model may have
>   difficulty placing elements precisely in structured or layout-sensitive compositions.

These are stated for "GPT Image models" generally, not measured per variant.

## Moderation (verbatim, condensed)

> All prompts and generated images are filtered in accordance with our content policy.

The `moderation` parameter takes `auto` (default, "Standard filtering that seeks to limit
creating certain categories of potentially age-inappropriate content") or `low` ("Less
restrictive filtering"). Blocked requests can return `error.type =
"image_generation_user_error"` with `error.code = "moderation_blocked"` and an optional
`error.moderation_details` object whose `moderation_stage` is `input`, `output`, or `unknown`
and whose `categories` are coarse public labels ("harassment", "self-harm", "sexual",
"violence").

## Cost notes (verbatim)

> Both GPT Image 2.5 models use the same token rates: $8 per million image input tokens, $2 per
> million cached image input tokens, $30 per million image output tokens, $5 per million text
> input tokens, and $1.25 per million cached text input tokens.

> Use the response's `usage` to measure token consumption for your prompts, sizes, and quality
> settings. Equal token rates don't mean equal cost per image: token consumption can differ by
> model and quality setting.

> For GPT Image 2 and GPT Image 2.5, cached input pricing applies only to the image generation
> tool in the Responses API. It doesn't apply to direct Images API requests, including
> `/v1/images/edits`.

> If you want to stream image generation using the `partial_images` parameter, each partial
> image will incur an additional 100 image output tokens.

## Notes and gaps

- The guide is written for the pair, so most capability statements are model-family statements.
  Only the quality-setting sentence and the cost paragraph name Sunburst explicitly.
- It does **not** state a maximum number of input/reference images for GPT Image 2.5 edits. A
  host (fal) exposes 16; see [fal's edit record](../../fal.ai/gpt-image-2.5-sunburst-edit/2026-10-26.md).
- The latency, text-rendering, consistency and composition bullets carry no numbers or test
  method.
- The token calculator widget and the streaming/partial-image behaviour were not exercised.

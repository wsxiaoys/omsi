## Shape of the page at capture

The guide is now written around the 2.5 models. Its overview opens (verbatim):

> The API lets you generate and edit images from text prompts using `gpt-image-2.5-sunburst` and
> `gpt-image-2.5-flare`. Choose Sunburst for workflows where editing precision matters most, and
> Flare for fast, high-quality everyday image generation.

GPT Image 2 documentation survives in a collapsed section introduced as (verbatim):

> The details below apply to earlier models, not Sunburst or Flare. For new integrations, use one
> of the GPT Image 2.5 models described above.

That section is titled "GPT Image 2 settings and input fidelity", so the following parameters
are stated for `gpt-image-2` rather than inferred.

## GPT Image 2.5: surfaces, sizes, quality

Two surfaces are described: the **Image API** (`v1/images/generations`, `v1/images/edits`) and
the **Responses API** image generation tool. With the Image API you set `model` to
`gpt-image-2.5-sunburst` or `gpt-image-2.5-flare` directly; with the Responses API you *"select a
supported mainline model at the top level and specify `gpt-image-2.5-sunburst` or
`gpt-image-2.5-flare` in the image generation tool's `model` field"* (verbatim).

Quality and recommended sizes (verbatim, condensed):

> `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare` add `xhigh` and `max` quality settings. Both
> default to `auto`. Earlier GPT Image models support quality settings up to `high`.

| Setting | Options |
| --- | --- |
| Recommended sizes | `1024x1024`, `1536x1024`, `1024x1536` |
| Quality | `low`, `medium`, `high`, `xhigh`, `max`, `auto` |

Custom sizes (verbatim): *"Width and height must be multiples of 16, the aspect ratio must be
between 1:3 and 3:1, and neither edge may exceed 3840 pixels. The total pixel count must be
between 655,360 and 8,294,400 (4K). Resolutions above `2560x1440` are experimental."*

Transparency (verbatim): *"For transparent backgrounds with either model, set `background:
"transparent"` and use `output_format: "png"` or `"webp"`."*

## GPT Image 2.5: output format, editing, masks

> The Image API returns base64-encoded image data. The default format is `png`, but you can also
> request `jpeg` or `webp`.

`output_compression` applies to `jpeg`/`webp` only. *"Using `jpeg` is faster than `png`."*

- Multi-turn editing and File-ID inputs are described as Responses-API-only advantages over the
  Image API (summary).
- Mask requirements (verbatim, condensed): the image and mask *"must be of the same format and
  size (less than 50MB in size)"*, and the mask *"must also contain an alpha channel"*; the guide
  supplies code to derive an alpha channel from a black-and-white mask.
- The guide does **not** state a maximum number of reference images for edits.

## GPT Image 2.5: cost notes

- *"Both GPT Image 2.5 models use the same token rates: $8 per million image input tokens, $2 per
  million cached image input tokens, $30 per million image output tokens, $5 per million text
  input tokens, and $1.25 per million cached text input tokens."*
- *"Use the response's `usage` to measure token consumption for your prompts, sizes, and quality
  settings. Equal token rates don't mean equal cost per image: token consumption can differ by
  model and quality setting."*
- *"For GPT Image 2 and GPT Image 2.5, cached input pricing applies only to the image generation
  tool in the Responses API. It doesn't apply to direct Images API requests, including
  `/v1/images/edits`."*
- Partial (streamed) images each cost an additional 100 image output tokens.

## GPT Image 2: sizes and quality (verbatim, from the GPT Image 2 section)

Popular sizes: `1024x1024` (square), `1536x1024` (landscape), `1024x1536` (portrait),
`2048x2048` (2K square), `2048x1152` (2K landscape), `3840x2160` (4K landscape),
`2160x3840` (4K portrait), `auto` (default).

> `gpt-image-2` accepts any resolution in the `size` parameter when it satisfies the constraints
> below. Square images are typically fastest to generate.

Size constraints (verbatim list):

> - Maximum edge length must be less than or equal to `3840px`
> - Both edges must be multiples of `16px`
> - Long edge to short edge ratio must not exceed `3:1`
> - Total pixels must be at least `655,360` and no more than `8,294,400`

Quality options for `gpt-image-2` (verbatim): `low`, `medium`, `high`, `auto` (default).
Elsewhere on the page, `xhigh` and `max` are described as additions on the 2.5 models only, and
"Earlier GPT Image models support quality settings up to `high`."

## GPT Image 2: input fidelity (verbatim)

> The `input_fidelity` parameter controls how strongly a model preserves details from input
> images during edits and reference-image workflows. For `gpt-image-2`, omit this parameter; the
> API doesn't allow changing it because the model processes every image input at high fidelity
> automatically.

> Because `gpt-image-2` always processes image inputs at high fidelity, image input tokens can be
> higher for edit requests that include reference images.

## GPT Image 2: per-image cost examples (verbatim table rows, "Calculating costs")

Prices for GPT Image 2 at three sizes; the table header says these are the same sizes used for
previous GPT Image models "for comparison", and adds "Additional sizes available".

| Quality | 1024 × 1024 | 1024 × 1536 | 1536 × 1024 |
| --- | --- | --- | --- |
| Low | $0.006 | $0.005 | $0.005 |
| Medium | $0.053 | $0.041 | $0.041 |
| High | $0.211 | $0.165 | $0.165 |

Also stated: "`gpt-image-2` supports thousands of valid resolutions", and "A larger non-square
resolution can sometimes produce fewer output tokens than a smaller or square resolution at the
same quality setting."

Cached input pricing (verbatim): "For GPT Image 2 and GPT Image 2.5, cached input pricing
applies only to the image generation tool in the Responses API. It doesn't apply to direct
Images API requests, including `/v1/images/edits`." Cached token counts are billed but are not
reported in `usage`.

## Access gate (verbatim)

> To ensure these models are used responsibly, you may need to complete the API Organization
> Verification [...] before using GPT Image models.

> If your application serves individual end users, include a stable, privacy-preserving
> `safety_identifier` in each image generation or image edit request. [...] Safety identifiers
> are recommended but not required.

The Images API `user` parameter is documented as deprecated in favour of `safety_identifier`.

## Limitations (verbatim, page-level for "GPT Image models")

> - **Latency:** Complex prompts may take up to 2 minutes to process.
> - **Text Rendering:** Although significantly improved, the model can still struggle with
>   precise text placement and clarity.
> - **Consistency:** While capable of producing consistent imagery, the model may occasionally
>   struggle to maintain visual consistency for recurring characters or brand elements across
>   multiple generations.
> - **Composition Control:** Despite improved instruction following, the model may have
>   difficulty placing elements precisely in structured or layout-sensitive compositions.

## Moderation (verbatim, condensed)

> All prompts and generated images are filtered in accordance with our content policy.

The `moderation` parameter takes `auto` (default, "Standard filtering that seeks to limit
creating certain categories of potentially age-inappropriate content") or `low` ("Less
restrictive filtering"). Blocked requests can return `error.type =
"image_generation_user_error"` with `error.code = "moderation_blocked"` and an optional
`error.moderation_details` object whose `moderation_stage` is `input`, `output`, or `unknown`
and whose `categories` are coarse public labels ("harassment", "self-harm", "sexual",
"violence").

## Known gaps

- Every capability statement here is vendor documentation. No quality, latency, or failure-rate
  measurement for either 2.5 tier or for GPT Image 2 appears in the guide; the "Limitations" list
  is written for "GPT Image models" as a class and is not quantified.
- The per-image cost table is explicitly a comparison subset, not a schedule; per-image cost for
  2K/4K sizes must be measured or read from the interactive calculator, which is a client
  component and was not captured as data.
- `input_fidelity` is discussed only for `gpt-image-2` (where it cannot be changed). The guide
  does not say whether Flare or Sunburst accept the parameter or always process image inputs at
  high fidelity.
- No maximum reference-image count, and no statement of which surface is cheaper in practice.
- The token calculator widget and the streaming/partial-image behaviour were not exercised.

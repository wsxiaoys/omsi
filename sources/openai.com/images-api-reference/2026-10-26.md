## `POST /images/generations` (verbatim excerpts)

Supported models, verbatim:

> Supported models include `gpt-image-1-mini`, `gpt-image-1.5`, `gpt-image-2`,
> `gpt-image-2-2026-04-21`, `gpt-image-2.5-sunburst`, `gpt-image-2.5-sunburst-2026-09-08`,
> `gpt-image-2.5-flare`, `gpt-image-2.5-flare-2026-09-08`, and `chatgpt-image-latest`.

The `ImageModel` enum additionally contains `gpt-image-1`, `dall-e-2`, `dall-e-3`; the page notes
"`gpt-image-1` was shut down on October 23, 2026."

Parameters relevant to `gpt-image-2`, verbatim:

- `prompt`: "A text description of the desired image(s). The maximum length is 32000
  characters."
- `n`: "The number of images to generate. Must be between 1 and 10."
- `background`: `transparent` | `opaque` | `auto`. "`gpt-image-2.5-sunburst` and
  `gpt-image-2.5-flare`, including their `2026-09-08` snapshots, support `opaque` and
  `transparent` backgrounds. … For `gpt-image-2` and `gpt-image-2-2026-04-21`, this support is
  in preview. When using `transparent`, set the output format to `png` or `webp`."
- `moderation`: `low` | `auto`.
- `output_compression`: 0–100, only for `webp`/`jpeg`, defaults to 100.
- `output_format`: `png` | `jpeg` | `webp`.
- `partial_images`: 0–3, for streaming responses.
- `quality`: "`high`, `medium` and `low` are supported for the GPT image models.
  `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare` … also support `xhigh` and `max`." Default
  `auto`.
- `size`: "For `gpt-image-2`, `gpt-image-2-2026-04-21`, … arbitrary resolutions are supported as
  `WIDTHxHEIGHT` strings, for example `1536x864`. Width and height must both be divisible by 16
  and the requested aspect ratio must be between 1:3 and 3:1. Resolutions above `2560x1440` are
  experimental, and the maximum supported resolution is `3840x2160`."
- `stream`, `safety_identifier` (≤128 chars, recommended, replaces the deprecated `user`
  parameter), `response_format`, `user` (deprecated), `style` (`vivid` | `natural`).

## `POST /images/edits` (verbatim excerpts)

- `input_fidelity`: "Supports `high` and `low` on `gpt-image-1.5`; `gpt-image-1-mini` supports
  only `low`. For `gpt-image-2`, omit this parameter. Defaults to `low` on supported models."
- `model`: "The GPT image model to use for image editing, including `gpt-image-2`, its dated
  snapshot `gpt-image-2-2026-04-21`, … Defaults to `gpt-image-2.5-sunburst`."

## Notes

- The two endpoints have **different defaults**: the image generation endpoint requires the model
  to be specified ("Specify a model explicitly"), while the edit endpoint defaults to
  `gpt-image-2.5-sunburst`. Neither defaults to `gpt-image-2`.
- `input_fidelity` exists in the schema but is explicitly not settable on `gpt-image-2`; a client
  sending it to `gpt-image-2` is outside the documented contract.
- The reference lists no maximum number of input images for `/images/edits`.

## Known gaps

- No per-model token tables and no statement of how many reference images `gpt-image-2` accepts.
- The mask parameter's size/format limits are in the guide, not restated per model here.
- The `quality` enum also lists `standard` and `hd`, which are DALL·E-era values; the page does
  not say whether they are rejected for `gpt-image-2`.

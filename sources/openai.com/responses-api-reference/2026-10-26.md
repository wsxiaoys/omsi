## Captured content (verbatim, `ImageGeneration` tool object)

> - `model: optional string or "gpt-image-1" or "gpt-image-1-mini" or "gpt-image-1.5" or 6 more`
>
>   The image generation model to use. One of `gpt-image-1-mini`, `gpt-image-1.5`,
>   `gpt-image-2`, `gpt-image-2-2026-04-21`, `gpt-image-2.5-sunburst`,
>   `gpt-image-2.5-sunburst-2026-09-08`, `gpt-image-2.5-flare`,
>   `gpt-image-2.5-flare-2026-09-08`, or `chatgpt-image-latest`. **Default: `gpt-image-2`.**

> - `action: optional "generate" or "edit" or "auto"` — "Whether to generate a new image or edit
>   an existing image. Default: `auto`."

> - `background: optional "transparent" or "opaque" or "auto"` — "… For `gpt-image-2` and
>   `gpt-image-2-2026-04-21`, this support is in preview. When using `transparent`, set the
>   output format to `png` or `webp`. Default: `auto`."

> - `input_fidelity: optional "high" or "low" or null` — "Supports `high` and `low` on
>   `gpt-image-1` and `gpt-image-1.5`; `gpt-image-1-mini` supports only `low`. For `gpt-image-2`,
>   omit this parameter."

> - `input_image_mask: optional object { file_id, image_url }` — "Optional mask for inpainting."

## Why this record matters

This is the strongest single first-party statement that GPT Image 2 is still the default, not a
legacy leftover: on 2026-10-26, a Responses API request that uses the image generation tool
without naming a model gets `gpt-image-2`, even though two 2.5 models exist and are marketed as
the current generation.

## Known gaps

- The reference does not say why the tool default lags the models, nor whether the default is
  scheduled to change.
- The page is very large (the capture is the whole Responses create reference); only the image
  generation tool object was extracted. Other tools' schemas are out of scope for this record.
- No cost, latency, or quality statements appear in the schema.

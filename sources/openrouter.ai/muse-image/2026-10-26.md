## Notes

- **Upstream model string: `muse-image-1.0-eval-20260824`.** OpenRouter's endpoint name exposes a
  Meta snapshot identifier dated 2026-08-24 — two days before the listing. This is the only captured
  evidence of a dated revision under the `muse-image-1.0` ID, and it is labelled "eval".
- **Price arithmetic checks out to the list price.** The billed unit is `image_token` at
  $2.3952…e-6; $0.01 / $2.3952…e-6 = 4,175 image tokens per image, i.e. exactly $0.01 per image.
  Prompt and completion tokens are priced at zero, consistent with per-image billing.
- **Context 65,536 tokens** with `max_completion_tokens` 58,982. Meta's own docs describe Muse Image
  as billed per image and do not publish a context window, so 66K is OpenRouter's figure.
- **`supports_image_reference: false`** contradicts the model's documented reference-image support.
  The flag appears to be a text-model capability field that does not describe this image model's
  `input_image` parts; treat it as unreliable here rather than as evidence against reference inputs.
- **Contradiction with Meta's own page.** Meta's model page says OpenRouter "routes across multiple
  inference providers for cost, speed, and availability"; OpenRouter says one provider, `Meta`, and
  the endpoint tag is `meta`. Preserve both.
- **The generated `llms.txt` guide is boilerplate for text models.** It documents
  `POST /v1/chat/completions`, `max_tokens`, streaming text and a "502 — the upstream text
  generation failed" error, for a model whose only output modality is `image`. The same guide does
  state that failed generations are not billed.
- `meta/muse-image` is **not** in `GET /api/v1/models`; that index lists only `meta/muse-spark*`,
  `meta/muse-wonder` and `meta/muse-glimmer-30b` from Meta. The image model is reachable only via
  its own page and endpoints route.

## Gaps

- **No resolution, aspect-ratio, or reference-count documentation** on the OpenRouter listing.
- **No image-specific request/response schema** published; the page documents Chat Completions
  fields only.
- **No latency or throughput data**: `latency_last_30m` and `throughput_last_30m` are `null` for
  this endpoint, so OpenRouter reports uptime only (100 % over 30 min, 5 min and 1 day).
- **Unclear whether the `-eval-20260824` snapshot is the same revision fal proxies**, and whether it
  will be replaced by a non-eval build under the same slug.

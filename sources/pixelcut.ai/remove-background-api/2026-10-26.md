The spec names no model, checkpoint, architecture, or model version. The only identity the vendor
publishes for this capability is the HTTP operation and the API spec version. Authentication is
`ApiKeyAuth` (`X-API-KEY: sk...`) or OAuth 2.0 with scope `pixa:write`.

## Description (verbatim)

> Removes the background from an image and optionally adds AI-generated shadows, crops to the
> subject, and applies margins. When AI shadows are requested, an additional 3 credits will be
> consumed.
>
> **Input Image Limits:**
> - Formats: JPEG, PNG, WebP, HEIC, AVIF
> - Max size: 25MB
> - Min resolution: 64x64px
> - Max resolution: 10000x10000px

## Request (verbatim parameter descriptions)

| Field | Type | Notes (verbatim) |
| --- | --- | --- |
| `image_url` | url | "URL of the image to be processed." Required in JSON; mutually exclusive with `image` in multipart |
| `image` | binary | "Binary file of the image to be processed, this is mutually exclusive with image_url, if both are provided the image will be used." |
| `format` | string enum | enum is `[png]`; "The format of the resultant image. Currently, only png is supported." |
| `shadow` | object | `enabled` (bool, default false), `opacity` (0–1, default 0.5), `light_source` (`size` 0–1 default 0.3; `position` x/y normalized to image centre −1..1, z 0–2). "When enabled, +3 credits are consumed. Pass `true` for automatic shadow estimation or provide a light source for custom control." |
| `crop` | bool | "When true, crops the image to the region of interest (the detected subject)." Default false |
| `margin`, `margin_left/right/top/bottom` | string | "(Beta) ... Only applies if crop is true. When specified as a string with '%' (0-49%), it represents a percentage of the image dimensions. When specified as a string with 'px', it represents pixels (>=0px)." |

Content types accepted: `application/json` and `multipart/form-data`. `Accept` header:
"`application/json` or `image/*`. Default is `application/json`."

## Response (verbatim)

- `200 application/json` → `PngImageJSONResponse`:
  `result_url` — "A URL to access the resultant image. The file is deleted after at most 24 hours.
  File format will be png."
- `200 image/*` → `PngBinaryResponse`: "Resultant image in binary format. The file format will be
  png."

There is **no mask, alpha-matte, or confidence output** in the schema — only a PNG (with alpha,
per the surrounding documentation). Nothing in the spec controls edge refinement or alpha
thresholding.

## Error codes (verbatim `error_code` enum for 400)

`invalid_request_body`, `missing_parameter`, `invalid_parameter`, `unsupported_content_type`,
`malformed_image`, `unsupported_image_format`, `file_size_too_large`, `resolution_too_high`,
`unknown_foreground`.

- `unknown_foreground`: "The foreground subject of the image could not be detected." This is the
  documented failure mode when the model finds no subject to cut out.
- `403` `insufficient_api_credits`: "Returned when you have insufficient credits to perform the
  requested action."
- `429` `rate_limit_exceeded`; `500` internal service error.

## Contradictions with other Pixelcut pages (recorded here, not resolved)

1. **Max resolution.** This page says 10000×10000. The docs' Image Requirements page says
   "Remove background: min `64×64`, max `6000×6000`"
   ([image requirements](../image-requirements/2026-10-26.md)).
2. **Accepted formats.** This page lists JPEG, PNG, WebP, HEIC, AVIF. The Image Requirements page
   and the API FAQ both say JPEG and PNG only
   ([image requirements](../image-requirements/2026-10-26.md), [FAQ](../api-faq/2026-10-26.md)).

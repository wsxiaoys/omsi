# PixVerse Platform Docs: Concurrency Rules

- Origin: PixVerse Platform Docs, "Concurrency Rules",
  <https://docs.platform.pixverse.ai/concurrency-rules-2394990m0>
- Evidence kind: official API documentation (first-party)
- Publication date: undated; current at capture
- Capture date: 2026-10-26
- Relevant models: all PixVerse API models

## Captured content (verbatim)

> Concurrency limits control how many generation tasks one account can process at the same time. The
> applicable quota depends on the account plan and configuration. Check the PixVerse API console for
> the current account limit.

> | `500044` | Concurrency limit reached | Wait for active tasks to reach a terminal state, then
> retry with exponential backoff and jitter. |

> - Do not submit duplicate creation requests merely because a task remains in `status=5`.

## Summary

There is a per-account concurrency cap, it is plan-dependent, and the numeric value is **not
published** — it lives in the API console. The documented failure mode is `ErrCode 500044`, to be
handled with backoff rather than retries that create duplicate tasks.

This matters for the model page because it means throughput cannot be planned from documentation:
the same V6 endpoint has a different effective parallelism per account.

## Gaps

- No quota table by plan, no per-model limits, no queue-depth or priority documentation.
- No stated behaviour when a plan is upgraded mid-flight.

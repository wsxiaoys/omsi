# PixVerse Platform Docs: First and Last Frame Video (`POST /openapi/v2/video/transition/generate`)

- Origin: PixVerse Platform Docs, "First and Last Frame Video",
  <https://docs.platform.pixverse.ai/first-and-last-frame-video-43051213e0>
- Evidence kind: official API specification (first-party)
- Publication date: undated; current at capture
- Capture date: 2026-10-26
- Relevant models: PixVerse V6, C1, V5.6, V5

## Captured content (verbatim)

> Create a transition between two uploaded images. Use img_id values in first_frame_img and
> last_frame_img. Model-specific duration/quality limits apply.

`model` enum on this endpoint: `c1`, `v6`, `v5.6`, `v5` — **`v6-max` is not accepted**, matching the
capability map's "First and Last Frame: Not supported" for V6 Max.

Other fields include `prompt` (`maxLength: 5000`), `duration`, `quality` (360p/540p/720p/1080p),
`seed`, `webhook_id`, and the two frame image IDs.

## Summary

First/last-frame transition is a first-class V6 mode: two uploaded stills plus a prompt, with the
same 1–15-second duration range and four quality tiers as the other V6 endpoints. The vendor's own
enumeration of accepted models (`c1`, `v6`, `v5.6`, `v5`) is one of the clearer pieces of evidence
that V6 is a distinct model entry rather than an alias of V6 Max, which cannot run this task at all.

## Gaps

- "Model-specific duration/quality limits apply" is not expanded into a table; V6's limits are
  inferred from the 1–15-second range stated for V6 elsewhere.
- No statement on how the model reconciles frames of differing aspect ratios or subjects.

## Launch claims (verbatim)

> In this release we are opening the weights of **Qwen3.8-Flash-Next**, a multimodal MoE
> model that also serves as an early preview of the architecture used in **Qwen4**. It
> plays the same role that Qwen3-Next played for Qwen3.5 […] We are again releasing the
> architectural changes early, so that the community can examine them before the full
> Qwen4 model family is built on top of them.

> Qwen3.8-Flash-Next features a **125B**-parameter main model, supplemented by an
> additional **51B** N-gram embeddings, with **6B** parameters activated per token.
> Compared with Qwen3.7-Plus, Qwen3.8-Flash-Next substantially reduces both training and
> inference cost — training takes only about 1/9 as much, yet it delivers superior
> capabilities in coding and office tasks.

> It natively supports **262,144** tokens of context and is extensible to **1,000,000**
> tokens with YaRN.

> The production version, with 1M context by default and official built-in tools, is
> served as **Qwen3.8-Flash** on [QwenCloud](https://www.qwencloud.com/models/qwen3.8-flash),
> **priced at 0.15 USD per million input tokens and 0.47 USD per million output tokens**.

The last sentence is the only first-party statement that ties the open artifact to a
named API SKU, and the only price the post gives. It gives no price for self-hosting and
no rate for the weights themselves.

## Architecture claims (verbatim, abridged)

Four named changes, all vendor-described and none independently reproduced:

- **Attention — "GDN + QSA hybrid":** "three out of every four layers use Gated DeltaNet
  (GDN) … while the remaining layer uses global Attention", with Qwen Sparse Attention
  (QSA) replacing token-level sparse indexing with "micro-block" selection. Claimed
  effect: "At **1M tokens**, QSA's Attention Kernel achieves up to **7.6×** and **4.9×**
  speedups in Prefill and Decode", and at a "**90% Prefix Cache hit rate**, Qwen3.8-Flash-Next
  achieves **8.6×** the Prefill throughput of Qwen3.7-Plus at a **1M-token context
  length**".
- **Residual — Gated Residual:** the residual stream is widened "into four parallel
  branches" with data-dependent read/write gates; residual state "supports **FP8**
  storage".
- **Embedding — N-gram Embedding:** "an additional **51B N-gram Embedding parameters**"
  looked up by local context, offloadable to host memory. The post argues they "can be
  stored in Host Memory and asynchronously prefetched … without permanently occupying GPU
  memory" and that they "are deterministically addressed and do not enter the per-token
  matrix-multiplication budget".
- **Optimization — Muon:** Muon for attention/GDN/MoE-expert weights, AdamW for
  embeddings, the MoE router and the low-rank Gated Residual parameters; batch-size
  warmup dropped because it "requires **18.8% more optimizer steps**".

## What this establishes

- Canonical name `Qwen3.8-Flash-Next`, open weights, 125B main + 51B n-gram + 4B MTP,
  6B active, native 262,144 context, YaRN to 1,000,000.
- That the model is positioned as an architecture preview for Qwen4, not as a product
  flagship.
- The first-party mapping between the open artifact and the API SKU `qwen3.8-flash`
  ("the production version, with 1M context by default and official built-in tools").
- Vendor-reported benchmark levels; no independent reproduction.

## Gaps

- No release date printed on the page body; only the contested proxy metadata.
- No statement of what the production SKU changes beyond context length and built-in
  tools (post-training differences are not described).
- No weights-licence terms in the post; those are only in the repository licence.
- No serving price for the open weights, and no statement about which third parties may
  host them.

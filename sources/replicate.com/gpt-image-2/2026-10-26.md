## Captured content (summary with key quotes)

Description (verbatim): "OpenAI's state-of-the-art image generation model. Create and edit images
from text with strong instruction following, sharp text rendering, and detailed editing."

README, "What it does" (verbatim):

> GPT Image 2 handles two workflows: generating images from text descriptions, and editing
> existing images with specific instructions. It's designed to follow your directions closely
> while keeping the parts you want unchanged.

> When you pass reference images, GPT Image 2 processes them at high fidelity automatically.
> There's no knob to adjust — the model always does its best to preserve the details of the
> input. Pass one image to edit it, or pass multiple images to combine styles, subjects, or
> references into a single output.

Key capabilities claimed by the host: photorealism and detail; text rendering for "Dense text,
small lettering, and complex layouts like infographics, UI mockups, and marketing materials";
"Precise editing — Targeted changes without reinterpreting the entire image"; style control;
"World knowledge — Ask for a scene set in 'Bethel, New York in August 1969' and the model
understands you want Woodstock — it has reasoning built in."

Transparent backgrounds (verbatim): "set `background` to `transparent` and `output_format` to
`png` (or `webp`). This gives you a real alpha channel … JPEG can't store transparency, so if you
pick `jpeg` the background falls back to opaque."

Prompting advice given by the host: be specific; use photo language ("Shot with a 50mm lens, soft
daylight, shallow depth of field"); "Lock what shouldn't change"; "Put text in quotes"; iterate
with small changes; label references by number.

### Pricing (verbatim from the page's billing configuration)

Per output image, by quality tier: `auto` **$0.128** ("or around 78 images for $10"), `low`
**$0.012** ("or around 83 images for $1"), `medium` **$0.047** ("or around 21 images for $1"),
`high` **$0.128** ("or around 78 images for $10").

These are flat per-image rates that do not vary with output size in the captured configuration,
which is a different billing shape from OpenAI's token-based pricing. See the model page for the
comparison against OpenAI's per-image examples.

## Contradiction inside this page

- The README's input list says `aspect_ratio` is "`1:1` (square), `3:2` (landscape), or `2:3`
  (portrait)" only, while the model schema on the same page accepts seven ratios plus ten explicit
  pixel sizes and `auto`, and the schema description warns "Sizes above 2560x1440 are
  experimental". The README text appears stale relative to the schema. Unresolved; a caller should
  trust the schema, which is what the endpoint validates.
- `output_format` defaults to `webp` here, while OpenAI's Images API defaults to `png`. Anyone
  comparing byte-for-byte output across hosts is comparing different encodings.

  `/hyper3d/hyper3d-rodin` each returned **HTTP 404**.
- `GET https://replicate.com/api/search?query=rodin` returned exactly one Hyper3D-owned model,
  `hyper3d/rodin` ("Generate complex 3D models from images with Rodin Gen-2"); the remaining hits were
  unrelated fuzzy matches (`roop`, `controlnet`, `ri`, …).

## What this establishes

- **Replicate is not an independent host for Rodin Gen-2.5 as of capture.** It hosts the previous
  generation only, under the unversioned slug `hyper3d/rodin`, and its `tier` parameter defaults to
  `Gen-2`.
- Replicate and fal charge the **same flat $0.40 per generation** for their respective Rodin versions
  (fal for Gen-2.5, Replicate for Gen-2), which makes the two hosts' prices non-comparable as a
  version-to-version price signal.
- The `tier` field exists on Replicate but is described only as "Generation tier" with default
  `Gen-2`; nothing in the captured schema says whether `Gen-2.5-*` values are accepted. A caller should
  assume not, given the absence of any Gen-2.5 slug.

## Gaps

- Replicate's model API returns HTTP 401 to unauthenticated metadata reads, so `created_at` for the
  *model* (as opposed to the latest version) and any older version list were not read.
- Whether Replicate plans to host Gen-2.5 is not stated anywhere captured.
- The page has no readme, so Replicate documents no Rodin-specific limitations, formats, or licensing.

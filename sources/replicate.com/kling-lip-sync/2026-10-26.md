## Input schema (verbatim descriptions)

| Field | Type | Description |
| --- | --- | --- |
| `video_id` | string | "ID of a video generated by Kling. Cannot be used with video_url." |
| `video_url` | string | "URL of a video for lip syncing. It can be an .mp4 or .mov file, should be less than 100MB, with a duration of 2-10 seconds, and a resolution of 720p-1080p (720-1920px dimensions). Cannot be used with video_id." |
| `audio_file` | file | "Audio file for lip sync. Must be .mp3, .wav, .m4a, or .aac and less than 5MB." |
| `voice_id` | string enum, default `en_AOT` | "Voice ID for speech synthesis (if using text and not audio)" |
| `text` | string | "Text content for lip sync (if not using audio)" |
| `voice_speed` | number 0.8–2, default 1 | "Speech rate (only used if using text and not audio)" |

One endpoint covers both modes: supply `audio_file` **or** `text` + `voice_id`. The `video_id` field
exposes the vendor's Kling-generated-video path directly; `video_url` is the arbitrary-upload path.

**Replicate caps the source video at 2–10 s**, the same as fal's audio-to-video leaf and half of the
vendor's documented 60 s ceiling. The `voice_id` list is prefixed (`en_AOT`, `zh_laopopo_speech02`,
`zh_mengwa-v1`, …) where fal's is not — the same voices, differently namespaced.

## Output

A single file URL. The example prediction's output is an `.mp4` on `replicate.delivery`. No resolution,
frame-rate or channel field.

## Price

> This model is priced by second of output video. It costs **$0.014 per second of output video**, or
> around 71 seconds for $1.

Same unit rate as fal, **different basis**: Replicate bills per second of *output* video; fal bills per
second of *input* video rounded up to 5 s. For an audio shorter than the clip they diverge.

```json
"logs": "Generating lip sync video...\nGenerated video in 634.3sec\nDownloading 6287351 bytes\nDownloaded 6.00MB in 1.45sec\nOutput video duration: 9.97",
"metrics": { "predict_time": 635.85, "total_time": 635.87 },

"status": "succeeded", "version": "hidden"
```

This is the only run-level timing in the whole corpus for this model: **~636 s (10.6 min) to produce a
9.97 s output**, which corroborates fal's "~12 minutes" claim and contradicts the vendor changelog's
"as little as 2 minutes". It is Replicate's own showcased example, not a controlled measurement, and it
carries no date beyond the page's 2025-05-20 `created_at`.

## Summary

Replicate's record agrees with the vendor on inputs (2–60 s audio ≤5 MB, mp3/wav/m4a/aac, TTS voice +
speed) and agrees with fal on price per second, but it is the only route that surfaces the vendor's
`video_id` (Kling-generated video) option. It caps the source clip at 10 s and states plainly that data
is forwarded to Kuaishou.

## Gaps

- The model page shows no per-version list, so the "over 1 year ago" created date cannot be resolved to a
  day, and `version` is `"hidden"` in the example.
- No README section on limitations, languages, or face requirements.
- The 2–10 s cap is not explained; it matches neither the vendor's current 60 s nor fal's own
  text-to-video leaf.

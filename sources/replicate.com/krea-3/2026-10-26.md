## Captured content

### Description (verbatim)

> Krea 3 is a fast image editing model from Krea. Tell it what should change and what should stay
> the same, and it returns the edit in seconds. It also generates images from text.

> This is the Berry version of Krea 3, which is tuned for image quality. A faster version called Jam
> is coming from Krea.

The page had 10.3K runs at capture. The Berry/Jam sentence is the only host statement found that
names a Krea 3 variant and describes the difference; Krea's own docs do not use either name.

### What it can do (verbatim bullets)

- "Edit an image with a plain-language instruction."
- "Combine up to 8 input images into one result."
- "Generate an image from a text prompt when you don't pass any input images."
- "Change only part of an image and keep the rest unchanged, with regional edits."
- "Output at 1K or 2K resolution."

### How to use it (verbatim, abridged)

> `prompt`: describe the edit or the image you want. Lead with the change, then add one sentence
> about what should stay the same. With several input images, refer to each one by what it shows,
> like "Put the sneaker from the second image on the person in the first image."

> `images`: up to 8 input images. Leave empty for text-to-image.

> `thinking_mode`: `fast` is quicker and works for most requests. `high` plans complex or multi-step
> edits more carefully, but it takes longer and costs more.

> `resolution`: `1k` or `2k`.

> `aspect_ratio`: pick a ratio, or leave it on `auto` to let the model choose the framing from your
> images and prompt.

> `regional_edit`: experimental. Use it for local changes like recoloring an object or fixing a
> detail. It needs at least one input image. Expect lower quality and slower generation than a
> regular edit. Don't use it for global changes like restyling or relighting.

> `negative_prompt`: what to avoid.

> `seed`: reusing a seed doesn't guarantee identical results, because the prompt is expanded before
> generation.

> Around 1 megapixel is enough for most input images. Send the highest-resolution version you have
> when small details like text or faces matter. Input images larger than 4 megapixels are resized.

### Input schema defaults (verbatim)

- `resolution`: enum `["1k","2k"]`, default **`2k`**.
- `thinking_mode`: enum `["fast","high"]`, default `fast`; description "How much planning happens
  before generation. 'fast' is quicker and works for most requests. 'high' plans complex or
  multi-step edits more carefully, but is slower and costs more."
- `aspect_ratio`: enum `["auto","1:1","4:5","3:4","2:3","9:16","5:4","4:3","3:2","16:9","21:9"]`,
  default `auto`.
- `regional_edit`: boolean, default false, "Experimental. [...] Quality may be lower and generation
  slower than a regular edit."
- `negative_prompt`: string, nullable, "What to avoid in the output."

Replicate defaults to **2K**, while Krea's API defaults to 1K. The default request therefore costs
more on Replicate ($0.06 fast) than the cheapest first-party default ($0.03 at 1K).

Replicate exposes only `fast` and `high`; there is no `ultra` option. It does expose
`negative_prompt`, which Krea's `ultra` mode does not accept.

### Pricing (verbatim table)

| Output | Fast thinking | High thinking |
| --- | --- | --- |
| 1K | $0.03 | $0.05 |
| 2K | $0.06 | $0.08 |

> Input images cost $0.02 per megapixel.

This is a third schedule: per output tier plus a per-input-megapixel charge. It does not match
Krea's first-party reference pricing (which is $0.02 per 1K reference and $0.07 per 2K reference) or
fal's flat per-megapixel rate.

## Gaps

- No `ultra` mode, so the highest-quality Krea 3 configuration cannot be reached through Replicate
  as documented at capture.
- No page-update date; only the model creation timestamp.
- No statement of which Krea 3 build/snapshot Replicate serves, or whether Berry is a separate
  checkpoint from the first-party default.
- The page does not state safety-filter behavior.
- No benchmark or latency data; "returns the edit in seconds" is the host's restatement of Krea's
  claim.
- The page says "a faster version called Jam is coming from Krea", while fal already exposes a `jam`
  option. Whether Jam is generally available, and on which hosts, is unresolved.

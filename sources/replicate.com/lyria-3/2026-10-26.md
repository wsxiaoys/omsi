## `google/lyria-3` README (verbatim)

> Lyria 3 is Google's music generation model, available through the Gemini API. It generates
> high-quality, **48kHz stereo** audio from text prompts or images.
>
> This is the Clip variant — it always generates a 30-second MP3 clip. For full-length songs (up to
> ~3 minutes), use Lyria 3 Pro.

> Provide **up to 10 images** as inspiration — the model composes music based on visual content
> Generate instrumental tracks or tracks with vocals and lyrics
> Prompt in different languages to get lyrics in that language

> Include structure tags like `[Verse]`, `[Chorus]`, `[Bridge]` to guide composition

> **Output** — 30-second MP3 audio clip; 48kHz stereo; All output includes SynthID watermarking

> **Limitations** — Always generates 30-second clips (use Lyria 3 Pro for longer tracks); Single-turn
> generation only — no iterative editing; Some prompts may be blocked by safety filters; Results vary
> between calls, even with the same prompt

## `google/lyria-3-pro` README (verbatim)

> This is the Pro variant — it generates songs up to approximately 3 minutes long.

> Generate full-length songs with professional structure (verses, choruses, bridges)
> Control timing with timestamps like `[0:00 - 0:30] Intro: soft piano`
> Provide custom lyrics with section tags like `[Verse]`, `[Chorus]`, `[Bridge]`
> Provide up to 10 images as inspiration

> Influence duration by specifying it in your prompt (e.g. "create a 2-minute song")

> **Output** — MP3 audio, up to ~3 minutes; 48kHz stereo; All output includes SynthID watermarking

Same four limitations, with "Exact duration varies and can be influenced through prompting" replacing
the fixed-30-second limit.

## Input/output schema (verbatim)

Both models, `required: ["prompt"]`:

| field | type | description |
| --- | --- | --- |
| `prompt` | string | clip: "Text prompt describing the music to generate…"; pro: "…Include details like genre, instruments, mood, tempo, lyrics, and song structure (e.g. [Verse], [Chorus], [Bridge]) for best results. You can also use timestamps like [0:00 - 0:30] to control timing." |
| `images` | array of URIs, default `[]` | "Input images to inspire the music composition (up to 10 images)" |
| `seed` | integer, nullable | "Random seed for generation. Set to a specific value for more reproducible results, though exact determinism is not guaranteed." |

Output is a **single URI string** — one audio file, no lyrics field and no description field, unlike
fal, which returns `audio` + `lyrics`. No `duration`, `bpm`, `intensity`, `negative_prompt`, or
`num_outputs` field exists on either model.

## The 48 kHz contradiction

Replicate states **48kHz stereo** for both Lyria 3 variants. Google's model card says **44.1 kHz /
192 kbps**, and fal restates 44.1 kHz / 192 kbps. Replicate's README also says Lyria 3 is "available
through the Gemini API", which is where a 48 kHz figure could originate if a different surface
resamples. No source reconciles the two; record both and treat 44.1 kHz as the vendor-documented
figure because two independent surfaces (model card, fal) state it and only Replicate says 48 kHz.

## Notes

- Replicate's "up to 10 images" matches the Google prompt guide's "up to 10 reference images or
  PDFs" but drops PDFs; the Replicate schema accepts `images` only.
- "Single-turn generation only — no iterative editing" is a host-side statement of a limitation that
  Google's docs do not state in those words. It is plausible but host-sourced.
- The 583.7K run count on the clip model against 53.5K on Pro (11:1) is the only usage signal found
  for the family.

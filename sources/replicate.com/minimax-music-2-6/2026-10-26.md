## README (verbatim, selected)

> Music 2.6 is MiniMax's latest music generation model. Give it lyrics and a style description, and it
> generates a full-length song with vocals and instrumentation — or go instrumental-only with just a
> prompt.

> **What's new in 2.6**
>
> Music 2.6 builds on Music 2.5 with major improvements:
>
> **BPM and key control** — specify a key and BPM in your prompt (e.g. "E minor, 90 BPM") and the
> output matches 99%+ of the time
>
> **Faster streaming** — end-to-end chunk latency dropped from over 60 seconds to under 25 seconds
>
> **Longer songs** — up to 6 minutes per generation (most songs land between 2 and 4 minutes)
>
> **Instrumental mode** — generate music without vocals. Set `is_instrumental` to true and provide a
> prompt describing the style. No lyrics needed.
>
> **Automatic lyrics** — set `lyrics_optimizer` to true and the model generates lyrics from your
> prompt, so you can create a complete song from just a style description.

> **Language support:** English and Mandarin Chinese have the strongest support. Other languages work
> but with less consistent pronunciation.

> **Each generation is unique.** The same prompt and lyrics produce different arrangements each time.
>
> **Reproducibility:** Use a seed parameter (0–1,000,000) for deterministic output.

> **Max song length:** Up to 6 minutes per generation. Most songs land between 2 and 4 minutes.

> **BPM/key accuracy:** Specify exact BPM and key in the prompt and the output matches 99%+ of the
> time.

The README also lists 14 structure tags, swapping the vendor's `[Post Chorus]` for `[Drop]` (the
page's own schema description uses the vendor's set, without `[Drop]`), and gives a prompt recipe of
`[Key], [BPM], [Genre], [Mood/Emotion], [Vocal description], [Key instruments], [Production style]`.

| `sample_rate` | enum 16000 / 24000 / 32000 / 44100 | 44100 |
| `bitrate` | enum 32000 / 64000 / 128000 / 256000 | 256000 |

**There is no `seed` field in the schema**, despite the README promising one. There is also no
duration field.

## Pricing

Billing config (verbatim payload):

```json
{"billingConfig": {"current_tiers": [{"prices": [{"description": "or around 66 files for $10",
  "metric": "audio_output_count", "metric_display": "output audio file", "price": "$0.15",
  "title": "per output audio file", "type": "per-unit"}]}]},
 "price": "$0.0001 per second", "p50price": "$0.012"}
```

The effective customer price is **$0.15 per output audio file** (≈66 files per $10); the
`$0.0001 per second` / `p50price $0.012` fields describe the CPU compute line, not the charge, and are
not reconciled with the per-file price anywhere on the page.

## What this establishes

- Replicate is a second independent host, at the same $0.15-per-track price as fal and the vendor,
  with an **official** MiniMax-published model rather than a community port.
- Its README is the only source in the corpus with a **language statement** (English and Mandarin
  strongest), a **song-length figure** (up to 6 minutes), a **BPM/key accuracy claim** (99%+) and a
  **streaming-latency comparison** against 2.5 (>60 s → <25 s). All four are unsourced host copy, and
  the 6-minute figure contradicts the vendor's own "up-to-5 minutes" billing unit.
- The README is **stale on identity**: it calls 2.6 "MiniMax's latest music generation model" four
  months after Music 3 shipped, and Replicate does not list Music 3 at all.
- The README's `seed` promise is **not implementable** on this route; the schema has no seed field.
  The same is true on fal. Reproducibility is therefore not available from either host as documented.

## Gaps

- No explanation of where the 6-minute cap comes from or whether it is enforced by Replicate or by
  MiniMax.
- No statement of which MiniMax API account/workspace proxies the calls, or of region.
- No independent quality evidence: no comparisons, no listening-test data, no failure rates.
- The 99%+ BPM/key claim has no method, sample size or example set.

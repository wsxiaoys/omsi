### README (verbatim, abridged)

> Nano Banana 2.1 is Google's latest image generation model — the fast, high-efficiency counterpart
> to Nano Banana Pro. It builds on Nano Banana 2 with sharper output, better text rendering, and
> real-time grounding, while keeping the speed and low cost of the Flash family.

Host-written capability bullets:

> **Generate images from text.** [...] photorealistic scenes, illustrations, product mockups,
> infographics, whatever you need.
>
> **Render text accurately.** Text in images is crisp and readable, with support for multiple
> languages — signage, posters, labels, and infographics come out clean.
>
> **Edit existing images.** Pass in one or more images along with a text prompt [...] You can use
> up to 14 reference images at once.
>
> **Ground in real-world information.** Turn on `google_search` to generate images based on
> real-time information like weather, sports scores, or recent events. Turn on `image_search` to
> pull web images as visual context for generation.

> Output at 1K, 2K, or 4K. Higher resolutions take longer to generate.

Aspect ratios listed: 1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9, plus the ultra-wide
and ultra-tall 4:1, 1:4, 8:1, 1:8. `match_input_image` matches the aspect ratio of the input
image. Output format: "Choose between jpg (default) and png."

### Input schema (verbatim from the dereferenced OpenAPI schema)

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `prompt` | string | required | "A text description of the image you want to generate" |
| `image_input` | array of URI | `[]` | "Input images to transform or use as reference (supports up to 14 images)" |
| `aspect_ratio` | enum | `match_input_image` | enum: match_input_image, 1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9 |
| `resolution` | enum | `1K` | 1K, 2K, 4K; "Higher resolutions take longer to generate" |
| `google_search` | boolean | `false` | "Use Google Web Search grounding to generate images based on real-time information" |
| `image_search` | boolean | `false` | "Use Google Image Search grounding to find web images as visual context [...] When enabled, web search is also used automatically." |
| `output_format` | enum | `jpg` | jpg, png |

Output: a single URI string. No `num_images`, `seed`, `thinking_level`, `system_prompt`, or
moderation parameter is exposed.

## What this establishes

- A second independent host serving the same model, with a **different parameter surface** from
  fal: one endpoint for both generation and editing (via `image_input`), `jpg` default instead of
  `png`, `match_input_image` default instead of `auto`, and no thinking-level or seed control.
- Replicate's per-image prices match Google's list equivalents to four significant figures
  ($0.0336 / $0.0504 / $0.1134 vs Google's $0.0336 / $0.0504 / $0.113), i.e. a pass-through with
  no visible markup, unlike fal's ~17.6% token markup.
- Both hosts independently describe the model as the efficient counterpart to Nano Banana Pro and
  an update to Nano Banana 2, which matches Google's own wording.

## Known gaps

- Replicate's README does not say which Google snapshot it serves or when it is refreshed; the
  version timestamp (2026-10-06) matches the GA date.
- No `thinking_level` control, so a Replicate caller cannot tell whether thinking is on or at
  which level. Replicate's prices matching the no-thinking-equivalent Google list prices is
  suggestive but not proof.
- No latency, throughput, or failure-rate data; "437.2K runs" is a popularity count, not a
  quality measure.

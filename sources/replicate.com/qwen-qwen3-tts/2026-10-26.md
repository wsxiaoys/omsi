## Input schema (verbatim OpenAPI, one endpoint for all three modes)

Required: `text`.

| Property | Type / enum | Default | Description |
| --- | --- | --- | --- |
| `mode` | `custom_voice`, `voice_clone`, `voice_design` | `custom_voice` | "TTS mode: 'custom_voice' uses preset speakers, 'voice_clone' clones from reference audio, 'voice_design' creates voice from description" |
| `text` | string | — | "Text to synthesize into speech" |
| `speaker` | `Aiden, Dylan, Eric, Ono_anna, Ryan, Serena, Sohee, Uncle_fu, Vivian` | `Serena` | "Preset speaker voice (only for 'custom_voice' mode)" |
| `language` | `auto, Chinese, English, Japanese, Korean, French, German, Italian, Spanish, Portuguese, Russian` | `auto` | "Language of the text (use 'auto' for automatic detection)" |
| `voice_description` | string | null | "Natural language description of desired voice (only for 'voice_design' mode). Example: 'A warm, friendly female voice with a slight British accent'" |
| `reference_audio` | URI | null | "Reference audio file for voice cloning (only for 'voice_clone' mode)" |
| `reference_text` | string | null | "Transcript of the reference audio (recommended for 'voice_clone' mode)" |
| `style_instruction` | string | null | "Optional style/emotion instruction (e.g., 'speak slowly and calmly', 'excited tone')" |

Output: a single `uri` string (an audio file URL). There is no sampling-parameter surface and no
model-size selector — the host picks the checkpoint.

Note the speaker enum casing differs from Qwen's own names: `Ono_anna` and `Uncle_fu` here versus
`Ono_Anna` and `Uncle_Fu` in the vendor README and in fal's schema.

## Host README (verbatim claims)

> Qwen3-TTS is a text-to-speech model from the Qwen team at Alibaba Cloud. This model turns text
> into natural-sounding speech across 10 languages, including Chinese, English, Japanese, Korean,
> German, French, Russian, Portuguese, Spanish, and Italian.
>
> The model can clone a voice from just 3 seconds of audio, create entirely new voices from text

> audio packet.

and, on length:

> The model handles noisy input text well and maintains stability even when generating long-form
> speech—it can produce over 10 minutes of continuous audio without degrading quality or introducing
> artifacts.

Benchmark sentence, verbatim (no numbers, no harness):

> The model achieves better performance than comparable systems on multilingual benchmarks. In word
> error rate tests across 10 languages, it outperforms models like GPT-4o Audio Preview and

Limitations, verbatim:

> The 1.7 billion parameter model handles background noise better than the 600 million parameter
> version. For best results with voice cloning, use clean audio recordings without background sounds.
> The model works best when you provide clear, well-formed text. While it's robust to some input
> errors, giving it clean text produces better results.

## Gaps

- The page does not state which checkpoint the latest version runs (1.7B or 0.6B), and the input
  schema has no size selector.
- No character limit, no reference-audio length limit, and no output duration cap are documented;
  the "over 10 minutes" figure is prose, not a schema constraint.
- No sample rate, container or bitrate is documented for the returned URI.
- No safety-checker toggle is exposed (unlike fal), and no refusal or watermark behaviour is
  described.
- The `voice_clone` mode takes a reference clip per call; there is no stored-voice mechanism and no
  consent verification documented.

# Replicate: no official SAM 3 — community models only

- Origin: Replicate,
  - org listing `https://replicate.com/meta`
  - search JSON `https://replicate.com/api/search?query=sam%203` and `?query=sam-3`
  - model pages `https://replicate.com/vufinder/sam3` and `https://replicate.com/8digit/gener8-sam3`
- Evidence kind: provider documentation (host catalogue and host-written model pages)
- Publication date: `vufinder/sam3` page says "Model created 4 months, 2 weeks ago" (≈2026-06-10);
  `8digit/gener8-sam3` page says "Model created 2 weeks, 3 days ago" / "Model updated 3 days, 17
  hours ago" (≈2026-10-06 / 2026-10-22). Both are relative dates rendered at capture.
- Capture date: 2026-10-26
- Relevant models: SAM 3 (community hosting on Replicate); SAM 2 for contrast

## There is no `meta/sam-3` on Replicate

`https://replicate.com/meta/sam-3` returns **404**. The Meta organisation page lists Meta's own
models, including the SAM predecessors:

> meta / sam-2-video — SAM 2: Segment Anything v2 (for videos) — 108.7K runs
> meta / sam-2 — SAM 2: Segment Anything v2 (for Images) — 328.6K runs

but no SAM 3 entry, and no `sam3`/`sam-3` link appears anywhere in the org page's HTML (the only
`sam` links are `/meta/sam-2` and `/meta/sam-2-video`). The search JSON for "sam 3" and "sam-3"
returns `meta/sam-2` and two **community** SAM 3 models, with no Meta-owned SAM 3:

> 8digit/gener8-sam3 — "SAM 3 video segmentation that keeps every object's ID across the clip: one
> 16-bit label map per frame, plus an optional colored preview." — 1.1K runs

> vufinder/sam3 — "Segment Anything Model 3 - unified foundation model for promptable segmentation
> in images." — 149K runs

Both are marked `is_official: false` in the page JSON. So Replicate is a SAM 3 host only through
third-party uploads, and any Replicate behaviour is the wrapper author's, not Meta's.

## `8digit/gener8-sam3` (community, video wrapper)

This is the most detailed host-side description of SAM 3 video found anywhere outside Meta, and it
documents constraints Meta does not:

> SAM 3 video segmentation that keeps every object's ID across the clip: one 16-bit label map per
> frame, plus an optional colored preview.

> Segment every instance of a text prompt (default `person`) across a whole video with Meta's SAM 3,
> and get each object separately, with an ID that stays the same for the whole clip.

> Most SAM 3 video wrappers return one merged mask of everything that matched. This one keeps the
> identities, so you can choose which people to replace, blur, relight or cut out.

Inputs: `video` — "The video. **Up to 2000 frames.** Frames are read as stored (rotation metadata is
not applied), so upload upright video."; `prompt` — default `person`, "Every matching instance gets
its own ID."; `preview` — default `false`, "Also return an MP4 with every object tinted in its own
color and labeled with its number."

Output: a zip bundle of `labels/labels_00000.png`, … "one 16-bit PNG per frame. A pixel is 0 for
background and L for the object whose label is L. **SAM 3's masks are non-overlapping**, so one image
per frame holds every object without losing pixels", plus `objects.json` with per-object `label`,
`sam_id`, `frames`, `first_frame`, `last_frame`, `mean_score`, `best_frame`, `best_box`,
`best_area`, `best_area_fraction`, `best_score`.

Run time and cost (verbatim):

> Runs on an Nvidia L40S. Time grows with the number of frames and the number of tracked objects.
> Measured on a crowded 24 s clip (576 frames):
> 720×1280, 29 people, with preview: 212 s tracking + 66 s preview — 291 s of GPU, about $0.28
> 540×960, 26 people, no preview: 200 s of GPU, about $0.20

Implementation note (verbatim):

> Hugging Face `transformers` `Sam3VideoModel` (SAM 3's detector + tracker) in bfloat16, with the
> `kernels-community/cv-utils` kernel for non-maximum suppression, hole filling and sprinkle removal.
> Without that kernel, `transformers` silently skips those steps, so this model refuses to start
> without it.

Licence note on the page: "SAM 3 code and weights are Meta's, under the SAM License."

## Observations

- The 2000-frame cap is the wrapper author's limit, not a documented Meta or Replicate limit.
- The `objects.json` schema implies the wrapper computes per-object scores and best frames itself;
  those are wrapper-side derived values.
- 200 s of L40S time for 576 frames at 26–29 objects is a third-party measurement of a community
  wrapper, not of fal's or Meta's pipeline. It is the only run-time figure captured that is not the
  vendor's own, and it is not comparable to Meta's H100/H200 FPS numbers.

## Gaps

- The official Replicate API (`/v1/models/...`) requires authentication, so `created_at`,
  `input_schema` and per-second pricing for these community models could not be captured as
  structured data; only the rendered pages were available.
- No Replicate-hosted SAM 3.1 was found by either query.
- No information on what happens above 2000 frames, or on audio handling.

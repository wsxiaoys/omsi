- **Example-based editing** — "Instead of describing a complex edit in words, show the model what

## Documentation inconsistency observed at capture

Every code sample in the page README calls `replicate.run("bytedance/seedream-5", ...)`, not
`bytedance/seedream-5-lite`. On capture, `https://replicate.com/bytedance/seedream-5` returned
HTTP 404, and so did the version payload's own model URL
`https://replicate.com/replicate/bytedance-seedream-5`. The version payload identifies the
underlying model as `replicate/bytedance-seedream-5` (owner `replicate`, not `bytedance`), so the
public page appears to be a copy of a Replicate-internal model whose slug is not the one the
README examples use.

## What this establishes

- Replicate hosts Lite as a first-class model with its own slug and a $0.035 per-output-image
  price, matching BytePlus's first-party price.
- Replicate exposes **2K and 3K only** — no 4K option — and documents 14 reference images and
  sequential generation, matching the BytePlus parameter set.
- The `return_byteplus_urls` input is direct evidence that Replicate's predictions run through
  BytePlus-hosted output URLs, i.e. Lite on Replicate is a proxy of the BytePlus model rather than
  an independent deployment. (Inference from the parameter's description, not a Replicate
  statement of hosting type.)

## Captured content

### Model description (verbatim)

> LingBot World 2.0 is the 14B realtime camera-controlled world model in the LingBot family. It
> generates continuously from a live causal session, accepts control updates between chunks, and
> reuses DiT and VAE state for incremental frame delivery.

> Choose 2.0 when the larger model and interactive KV-window path justify an 8-GPU deployment. Like
> the earlier LingBot release, it prioritizes responsive control and bounded causal state over the
> full-clip global context of offline video diffusion.

### Deployment (verbatim command, abridged to the load-bearing flags)

```
export SGLANG_LINGBOT_LAZY_VAE_ENCODE_BLACK_FRAMES=60
export SGLANG_LINGBOT_ENABLE_INTERACTIVE_KV_WINDOW=true
sglang serve \
  --model-path robbyant/lingbot-world-v2-14b-causal-fast-diffusers \
  --pipeline-class-name LingBotWorldCausalDMDPipeline \
  --num-gpus 8 --ulysses-degree 8 \
  --vae-config.use-parallel-decode true --vae-config.parallel-decode-mode spatial
```

> Intel Xeon CPU deployment is supported with `SGLANG_DIFFUSION_PLATFORM_OVERRIDE=cpu`.

Optional: "Long-running sessions can enable lossy int4 PRQ compression for completed causal KV-cache
chunks" via `--kv-cache-quant int4`; "The current and most recent completed chunks remain in BF16."

### Realtime API (verbatim excerpts)

> LingBot World 2.0 uses the realtime video WebSocket endpoint. The server keeps one live session,
> generates one chunk at a time, and accepts runtime control events while generation is running.

Endpoint: `ws://…/v1/realtime_video/generate`. First message must be a MessagePack `init` map:

| Field | Required | Meaning |
| --- | --- | --- |
| `type` | yes | `"init"` |
| `model` | no | model id; empty = served model |
| `prompt` | yes | "Text prompt for the initial scene and motion style." |
| `first_frame` | yes | "Initial reference image. Send bytes from the WebUI/client, or a server-readable image path/string." |
| `size` | yes | "Generation size as `WIDTHxHEIGHT`, for example `832x480`." |
| `fps` | yes | "Target playback FPS for the generated stream." |
| `num_frames` | yes | "Frames per generated chunk." |
| `seed` | no | random seed for deterministic sampling |
| `num_inference_steps` | no | "Denoising steps per chunk. LingBot defaults to `4` when omitted." |
| `guidance_scale` | no | "Classifier-free guidance scale. Realtime LingBot commonly uses `1`." |
| `negative_prompt` | no | passed to the diffusion pipeline |
| `quality` | no | `exact` / `lossless` / `high`; "`lossless` keeps FP32 VAE decode" |
| `max_chunks` | no | "Stop after this many chunks. Omit for a continuous session." |
| `realtime_causal_sink_size`, `realtime_causal_kv_cache_num_frames` | no | causal attention / KV window sizes |
| `realtime_output_format` | no | `webp` / `jpeg` / `raw`; "`raw` (the default when omitted) sends lossless raw RGB" |
| `enable_upscaling`, `upscaling_scale` | no | server-side super resolution; "Current default is 4 when upscaling is enabled" |
| `enable_frame_interpolation`, `frame_interpolation_exp` | no | RIFE interpolation; "Keep this disabled when measuring true generated FPS." |
| `condition_inputs.camera_actions` | no | "Initial scripted camera actions, one action list per frame." |

Runtime `event` messages carry `kind: "prompt" | "camera_actions" | "composite_input"`.
"Supported LingBot action tokens include `w`, `a`, `s`, `d` for camera movement and `i`, `j`, `k`,
`l` for look controls." Server messages: `frame_batch`, `chunk_stats`, `error`.

Consistency section (verbatim): "LingBot World 2.0 uses raw-frame websocket GT plus per-chunk latency
guards for consistency checks." Notes add: "Prefer WebP preview transport for interactive testing; use
raw-frame transport for consistency checks" and "Long-running sessions should be validated with
raw-frame consistency before changing causal cache, condition sampling, or VAE decode behavior."

## Summary

An independent framework's deployment guide, which is the only captured document that gives concrete
operating parameters for the open weights: a diffusers-format 14B causal-fast checkpoint, 8 GPUs,
832×480 example generation size, 4 denoising steps per chunk by default, guidance 1, optional
super-resolution (4×) and RIFE frame interpolation, and a continuous session unless `max_chunks` is
set.

It also confirms the model is camera-controlled with the same WASD/IJKL token set the hosted APIs use,
and that the model family's design trade is "responsive control and bounded causal state over the
full-clip global context of offline video diffusion" — an independent framing of the same limitation
the vendor admits.

## Gaps

- No performance measurements: no latency, throughput, or VRAM figures, and no statement of the
  maximum resolution or fps the pipeline supports. 832×480 is only an example value.
- Whether upscaling and interpolation are enabled in the hosted deployments (fal, Reactor) is not
  stated here or there.
- "8-GPU deployment" is stated for the 14B realtime path; the 1.3B path is not covered by this page.
- The guide is documentation of a third-party serving stack, not a measurement of model quality, and
  SGLang is not a model host.

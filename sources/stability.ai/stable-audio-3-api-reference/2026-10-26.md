## Endpoints and the model id

`POST https://api.stability.ai/v2beta/audio/stable-audio/text-to-audio` (and `/audio-to-audio`,
`/inpaint`). Asynchronous: "it returns a generation `id` immediately (HTTP 202). Poll
`GET /v2beta/audio/results/{id}` to retrieve the result."

The `model` parameter (verbatim):

> enum: `stable-audio-3`, default `stable-audio-3`
> "The model to use for generation. — `stable-audio-3` requires 8 credits per generation"

**No size is named anywhere on these pages.** The tag description says only:

> **Stable Audio 3.0**: Fast, Best-Quality, Long-Form Music & Audio Generation. Our most advanced audio
> generation model, capable of generating up to 6-minute, 44.1 kHz stereo compositions. Stable Audio
> 3.0 supports text-to-audio, audio-to-audio, and audio-inpaint workflows …

## Charges (verbatim)

> **Stable Audio 3.0** — Flat rate of 8 credits per successful generation.
>
> As always, you will not be charged for failed generations.

1 credit = $0.01 (per the pricing page), so **$0.08 per successful generation, flat, at any duration
up to 380 s**. No per-second, per-minute, or per-character tier exists.

## Text-to-audio request schema (verbatim bounds)

| Field | Type | Default | Bounds | Notes |
| --- | --- | --- | --- | --- |
| `prompt` | string | — | maxLength **10000** | "What you wish the output audio to be. A strong, descriptive prompt that clearly defines instruments, moods, styles, and genre will lead to better results." |
| `model` | enum | `stable-audio-3` | — | only value |
| `duration` | number | **190** | 1–380 | "Controls the duration in seconds of the generated audio." |
| `seed` | number | 0 | 0–4294967294 | "Omit this parameter or pass `0` to use a random seed." |
| `steps` | integer | **8** | **4–8** | "Controls the number of sampling steps." |
| `cfg_scale` | number | **1** | 1–25 | "How strictly the diffusion process adheres to the prompt text (higher values make your audio closer to your prompt). Defaults to 1 if not specified." |
| `output_format` | enum | `mp3` | — | `mp3`, `wav` — "Dictates the `content-type` of the generated audio." |

**There is no `negative_prompt` on the vendor API**, and no `enable_prompt_expansion`, `bitrate`,
`sync_mode`, or `audio` input on the text-to-audio route. The response body is raw audio bytes
(`accept: audio/*`) or base64 JSON (`accept: application/json`).

## Audio-to-audio and inpaint (verbatim additions)

- Both require `audio` (binary, "Supported Formats: mp3, wav") with the validation rule "Audio must be
  between **6 and 380 seconds** long".
- Audio-to-audio adds `strength` (0–1, default **1**): "Sometimes referred to as _denoising_, this
  parameter controls how much influence the `audio` parameter has on the generated audio. A value of 0
  would yield audio that is identical to the input. A value of 1 would be as if you passed in no audio
  at all."
- Inpaint adds `mask_start` (0–380, default **30**) and `mask_end` (0–380, default **380**) and
  **retains `duration` (1–380)**. One mask window per request.
- **There is no continuation/outpaint endpoint** on the vendor API. Extending audio past its end is
  available on the API only as inpaint with `mask_end` at the tail, and explicitly on fal as a
  separate `audio-outpainting` endpoint.

## Safety, language and rejection behaviour (verbatim error catalogue)

- `403 content_moderation`: "Our content moderation system has flagged some part of your request and
  subsequently denied it. You were not charged for this request."
- `422 invalid_language`, example: "English is the only supported language for this service."
- `422 copyrighted_content`, example: "Our system has detected the presence of copyrighted content in
  your audio. To comply with our guidelines, we cannot process this request. Please upload a different
  audio file."
- Rate limit: "150 requests every 10 seconds … you will receive a `429` response and be timed out for
  60 seconds."

The `copyrighted_content` example appears on the **text-to-audio** page, where no audio input exists —
the error catalogue is shared across the three endpoints, so it is evidence about the audio-input
routes, not about text prompts.

## Training-data statement (verbatim, tag description)

> Stable Audio models were exclusively trained on licensed data from the AudioSparx music library,
> honoring opt-out requests and ensuring fair compensation for creators. Additionally, Stable Audio 3.0
> was pre-trained on licensed data from Freesound.

## Summary

The vendor API exposes a single `stable-audio-3` model id, 1–380 s at 44.1 kHz stereo, 8 sampling steps
by default (4–8 allowed), mp3/wav only, English prompts up to 10,000 characters, flat 8 credits per
successful generation, and an async 202/poll protocol. Relative to the fal host it is narrower
(two output formats, no negative prompt, no outpaint endpoint, no prompt-expansion switch) and
cheaper per call at long durations.

## Gaps

- The API reference never states which size (`small`, `medium`, `large`) the `stable-audio-3` id
  serves. The launch post says Large is the API model; this page cannot confirm it.
- No statement of channel count beyond "stereo", no bitrate, no file-size ceiling.
- No latency figures beyond the FAQ's "Most requests finish in seconds, and time scales with the length
  of audio you ask for".
- No watermarking statement anywhere.
- `steps` 4–8 is a narrower range than fal's 1–100 and than the paper's 50-step base models; nothing
  here says whether a base checkpoint is reachable through the API at all.

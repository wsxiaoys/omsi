## What the page says changed

> Previous models processed video in small, independent snippets. sync-3 takes a fundamentally
> different approach — it builds a global understanding of a person across an entire shot, generating
> all frames at once rather than stitching together isolated segments.

The change table lists close-ups/partial faces, extreme angles, obstruction detection, and style and
emotion preservation. The page says obstruction detection is automatic and that `temperature`,
`reasoning_enabled` and `occlusion_detection_enabled` are not applicable to sync-3 because those
capabilities are built in.

## Inputs

- Video + audio
- Video + text (TTS)
- Image + audio
- Image + text (TTS)

Image formats: JPEG, PNG, WebP. The page calls image input "a capability exclusive to this model"
relative to lipsync-2 and lipsync-2-pro. For multi-face images it requires manual speaker selection
with `coordinates` and `frame_number: 0`; `auto_detect: true` is not supported for images.
`sync_mode` is ignored for image inputs.

## Operational statements

- "Change the `model` parameter from your current model (e.g. `lipsync-2`) to `sync-3`. The rest of
  the request schema is unchanged — no other code changes required."
- sync-3 "works with the Batch API the same way as other models".
- "Free accounts can run one sync-3 generation per month with a 15-second maximum duration. Paid plan
  duration limits follow the plan tier listed in Billing."

## Summary

First-party reference for the canonical model ID (`sync-3`), its status as the default model, its
video-or-image input surface, 95+ language claim, 4K native claim, and its position above
lipsync-2-pro and lipsync-2. The page is also the clearest first-party statement that sync-3 is a new
architecture rather than a re-badged lipsync-2.

## Gaps

  billing pages.
- No release date appears on the model page.

# sync. labs generation times: sync-3 latency and async workflow

- Origin: sync. labs, "Generation Times & Performance", <https://docs.sync.so/product/generation-times>
- Evidence kind: official documentation (expected latency, job-status workflow)
- Publication date: page footer says "Last updated May 15, 2026"
- Capture date: 2026-10-26
- Relevant models: `sync-3`; `lipsync-2`, `lipsync-2-pro`, `react-1`, `lipsync-1.9.0-beta` for comparison

## Expected generation times (verbatim table)

| Model | Typical time (30s video) | Typical time (2min video) | Notes |
| --- | --- | --- | --- |
| lipsync-2 | ~1-3 min | ~4-8 min | Best general-purpose quality |
| lipsync-2-pro | ~2-5 min | ~6-12 min | Enhanced facial detail, diffusion-based super resolution |
| sync-3 | ~10-15 min | ~45-55 min | Most powerful model, 4K native output |
| react-1 | ~1-2 min | N/A (max 15s input) | Adds emotion and facial expressions |
| lipsync-1.9.0-beta | ~30-60s | ~2-4 min | Legacy model |

> Most generations complete within a few minutes.

The page says times depend on model, duration, resolution and system load, and that "During peak usage
periods, jobs may queue longer before processing begins. The PENDING status reflects time spent in the
queue."

## Async workflow (verbatim)

> Call the `GET /v2/generate/{id}` endpoint at regular intervals. We recommend polling every 10
> seconds.

> Configure a webhook URL in your generation request to receive an HTTP POST notification when the job
> completes or fails. This is more efficient than polling for production workflows.

Terminal statuses are `COMPLETED`, `FAILED` and `REJECTED`. A generation that exceeds its internal
processing time limit transitions to `FAILED` with a timeout error. "Long videos are divided into
30-40 second chunks for processing."

The page recommends the Batch API for high-volume jobs: "submit up to 500 generations in a single
request with a 24-hour turnaround time."

## Summary

sync-3 is an asynchronous, queue-based model, not a real-time or streaming service. The vendor's own
table puts a 30-second sync-3 generation at roughly 10–15 minutes and a 2-minute generation at roughly
45–55 minutes, an order of magnitude slower than lipsync-2. Jobs are polled or delivered by webhook;
there is no documented real-time generation endpoint.

## Gaps

- The table is "estimates based on standard input conditions"; no percentiles or measured distribution.
- No latency figure for 4K input or for image-to-video.
- The page's generic line "Most generations complete within a few minutes" conflicts with the sync-3
  row; read the row, not the summary.
- No statement of whether queue time is included in the published estimates.

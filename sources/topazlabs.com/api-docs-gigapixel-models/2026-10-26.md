### Face enhancement inside the upscale models

Standard 2 and High Fidelity 3 document the same shared parameters (verbatim):

> * `faceEnhancement` — boolean — Leverages our face recovery model to enhance faces.
> * `faceEnhancementStrength` — decimal between 0 and 1 *(required if `faceEnhancement=true`)*
> * `faceEnhancementCreativity` — decimal between 0 and 1 *(required if `faceEnhancement=true`)* —
>   Choose realistic or creative face recovery.
> * `subjectDetection` — `"foreground"`, `"background"`, or `"all"`
> * `sharpen` / `denoise` / `fixCompression` — decimal between 0 and 1
> * `strength` — decimal between 0.01 and 1 — "Controls model strength. Too high of a result can
>   make results look unrealistic."

> These parameters should be appended as key-value fields in the form-data request bodies (i.e.
> alongside the `model`, `outputHeight`, and `faceEnhancement` etc. fields). Any parameters not
> explicitly provided are **automatically** configured by our auto-parameter model. Extra parameters
> provided that are not supported are ignored.

So face recovery is both a switch on the general upscale models and a set of standalone models.

### Standalone face models (verbatim guidance)

- Detail Faces: "This model works best on large images, where the *face* in the input image is at
  least is 512 x 512 pixels. For smaller images, we recommend using `Recover Faces`."
- Recover Faces: "This model works best on smaller images, where the *face* in the input image is
  less than 512 x 512 pixels. For larger images, we recommend using `Detail Faces`."
- Face Recovery 3: "an updated facial reconstruction model designed to restore recognizable facial
  detail from low-resolution, damaged, or heavily compressed images. When facial information is
  missing or unreadable, Face Recovery 3 reconstructs plausible features rather than strictly
  preserving original pixels." It "includes both Realistic and Creative variants" and "results may
  include subtle changes to expressions or fine facial characteristics."

### Transparent Image Upscale

> A specialized upscaling model designed specifically for images with transparency, including
> logos, icons, titles, and graphic overlays. This model enhances resolution while preserving alpha
> channel integrity.

The page documents `inputHeight`/`inputWidth`/`outputHeight`/`outputWidth` and grain parameters but
**does not state a fixed scale factor**. fal's schema for the same model says the model "always
returns a fixed 4x-scaled image regardless of the requested `upscale_factor`"
(`../../fal.ai/topaz-upscale/2026-10-26.md`); the first-party page is silent, and its before/after
example files are named "Transparent Upscale 4x".

## Gaps

- **The family page and the per-model pages disagree on the credit unit** (24 MP/credit family-wide
  vs 2 MP/credit on the High Fidelity 3 page). See
  `../../topazlabs.com/api-docs-pricing/2026-10-26.md` for the individual-model table, which gives
  High Fidelity 2 = 4 and High Fidelity 3 = 2 MP/credit.
- **`model` strings are not uniform**: `"Standard V2"`, `"CGI"`, `"Text Refine"`, `"Faces"`,
  `"Detail"`, `"Transparency Upscale"`, but `"Upscale High Fidelity V3"` with an `Upscale` prefix.
  fal exposes the same model as `High Fidelity V3`. A caller cannot infer the string from the
  display name.
- The `/enhance/async` OpenAPI enum does not contain `"Upscale High Fidelity V3"` or `"Faces"`, and
  `/restore-gen/async`'s enum does not contain `"Face Recovery V3"` — the reference schema lags the
  model pages (`../../topazlabs.com/api-docs-image-reference/2026-10-26.md`).
- No page states a maximum upscale factor for the API; the only dimensional limits published are the
  output-width/height ceiling (32,000 px, from the OpenAPI) and the per-model output megapixel caps
  above.
- No dates: none of these pages records when a model shipped. Release dates come from the updates
  index (`../../topazlabs.com/topaz-upscale-release-notes/2026-10-26.md`).

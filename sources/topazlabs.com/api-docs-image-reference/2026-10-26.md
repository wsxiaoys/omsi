### `POST /enhance/async` — `EnhanceGANRequest`

Tag description (verbatim):

> Enhance images by removing noise, sharpening, and upscaling while preserving the details of your
> image, including the faces of important subjects.
>
> Just pass in an image and our **Autopilot** will automatically determine the best settings for the
> highest quality.
>
> Additional configuration can be optionally provided, specifically: `model`, `output_height`,
> `output_width`, `output_format`, `crop_to_fill`

Request body is `multipart/form-data`. Fields:

| Field | Schema (verbatim) |
| --- | --- |
| `image` | octet-stream; "Supported formats: jpeg (or jpg), png, tiff (or tif)" |
| `source_id` | string, unique identifier of the source image |
| `source_url` | string, URL of the source image |
| `model` | enum `["Standard V2","Low Resolution V2","CGI","High Fidelity V2","Text Refine"]`, default `"Standard V2"` |
| `output_height` | integer, min 1, **max 32000**; "Your image will automatically be upscaled to this specified value. If only one of `output_height` and `output_width` is set, then the other dimension is scaled proportionally." |
| `output_width` | integer, min 1, **max 32000** (same wording) |
| `crop_to_fill` | boolean, default false; "Default behavior is to letterbox the image if a differing aspect ratio is chosen." |
| `output_format` | enum `["jpeg","jpg","png","tiff","tif"]`, default `"jpeg"` |
| `webhook_url` | string; POSTs a JSON payload on status change, with `notification_id` (ULID), `process_id`, `status`, `creation_time`, `modification_time`, `progress`, `download_url`, `head_url`, `input_download_url`, `input_head_url`; retries 5xx with exponential backoff from 5 s up to 15 min |
| additional | `additionalProperties: string` — "Additional key-value pairs to be used as model settings. Only pairs relevant for your chosen model are used." |

### `POST /enhance-gen/async` — `EnhanceGenRequest`

Same field set, with this model enum (verbatim):

> `"model"`: enum `["Standard MAX","Recovery V2","Wonder","Redefine"]`, default `"Redefine"`

### `POST /restore-gen/async` — `RestoreGenRequest`

Same field set minus the sizing fields, with this model enum (verbatim):

> `"model"`: enum `["Dust-Scratch","Dust-Scratch V2"]`, default `"Dust-Scratch"`

### Response

```json
"AsyncResponse":{"type":"object","required":["process_id","source_id","eta"],
  "properties":{"process_id":..., "source_id":..., "eta":...}}
```

plus response headers `X-Process-ID`, `X-SOURCE-ID`, `X-ETA`, and documented error responses for 400,
401, 402, 403, 412, 413, 415, 422, 425, 429, 500.

## Gaps

- **The reference schema is behind the model catalogue.** `/enhance/async` lists five models; the
  per-model docs add `"Upscale High Fidelity V3"`, `"Faces"` and `"Transparency Upscale"`
  (`../../topazlabs.com/api-docs-gigapixel-models/2026-10-26.md`). `/enhance-gen/async` lists four;
  the docs add `"Wonder 3.5"`, `"Bloom 2"`, `"Face Recovery V3"` (on `/restore-gen/async`),
  `"Detail"` and others. The `additionalProperties: string` escape hatch may be how the newer model
  strings are accepted, but nothing states that.
- **No upscale-factor field.** Scaling is expressed as absolute output dimensions (max 32,000 px per
  side) or left to autopilot; a "2x/4x" convenience parameter exists only on the hosts.
- The reference does not state maximum input file size, input megapixel cap (per-model pages do:
  512 MP for Gigapixel, 24 MP for Standard Max/Recover 3), concurrency, or rate limits.
  `resources/api-limits.md` exists but its body is empty at capture
  (`../../topazlabs.com/api-docs-operations/2026-10-26.md`).
- No latency figure. `/status` returns progress, but no SLA or typical duration is published.

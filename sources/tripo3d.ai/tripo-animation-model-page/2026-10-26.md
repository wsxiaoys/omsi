## Captured content (verbatim)

> retarget-v1.0
> Preset motion library for rigged models.
> Quick Start
> Motions — 100+ Presets
> Speed — ~ 5s
> Input — Rigged Model
> Output — Animated GLB/FBX

> Apply preset animations to rigged models. Supports walk, run, idle, combat actions, and
> creature-specific motions for bipeds, quadrupeds, and more. Process up to 5 animations in a single batch
> request. The upgraded retargeting delivers faster, higher-quality humanoid motion, and an in-place mode
> is available to remove root displacement for game engine locomotion systems.

> 100+ preset animations (incl. 90+ biped-exclusive)
> Batch process up to 5 animations at once

Pricing:

> Single animation — 10
> Batch animation — 10 × count
> Input must be a rigged model (typically from Auto Rig)

Parameters: `animation` (e.g. `preset:walk`, `preset:quadruped:walk`, `preset:biped:walk`), `animations`
("Batch array: up to 5 presets"), `out_format` (`glb` default or `fbx`), `export_with_geometry`
(default `true`), `animate_in_place` (default `false`).

Snapshot notes on the page:

> v3.0-20260909 (rig) — Same 16 presets as v2.5
> v2.5-20260210 (rig) — 16 universal presets
> v1.0-20240301 (rig) — 90+ biped presets

## Summary

Animation is a preset library applied to an already-rigged model: no text-to-motion, no custom motion
authoring, and the preset count depends on which rig version produced the skeleton (16 universal presets on
v2.5/v3.0 rigs, 90+ biped presets on the older v1.0 rig). H3.1 therefore cannot produce an animated asset
in one call: generation, rigging and animation are three separately billed tasks on three different
endpoints.

## Gaps

- No listing of the 16 universal presets or the full 90+ set.
- No statement on animation length, frame rate, or whether root motion is baked.
- No support for importing external motion data is documented.

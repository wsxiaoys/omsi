# Tripo: API changelog

- Origin: Tripo (Holymolly Ltd), "Changelog", <https://developers.tripo3d.ai/en/docs/changelog>
- Evidence kind: official documentation (release notes)
- Publication date: entries are dated in the page itself; the most recent captured entry is 2026-10. The
  page has no overall "last updated" line.
- Capture date: 2026-10-26
- Relevant models: Tripo H3.1, its texture sub-model `v3.5-20260815`, the rigging/animation line, and the
  v3 API surface

**There is no entry for `v3.1-20260211` / "H3.1" anywhere on the page**, and no entry dated 2026-02 or

### The 2026-04 entry is about the API, not the model

> ## v3.0 (2026-04)
> ### New API Architecture
> - **Dedicated endpoints replace the universal POST endpoint**: Capability-specific endpoints, such as
>   `POST /v3/generation/text-to-model`, replace the previous universal `POST /v2/openapi/task` endpoint
>   with a `type` field
> - **Unified `{input}-to-{output}` naming convention** …
> - **Removed the redundant `/openapi` path**: The Base URL is simplified from `/v2/openapi/` to `/v3/`

The entry is a full v2→v3 endpoint and field migration table (`create_time` → `created_at`,
`consumed_credit` → `credits_consumed`, universal `input`, `POST /v3/tasks/list`,
`GET /v3/account/usage`).

### Texture model `v3.5-20260815` (2026-09), relevant to H3.1

> - **`POST /v3/models/texture`**: `model` now accepts `v3.5-20260815`. The default is still
>   `v3.0-20250812`, so requests that omit the field are unchanged.
> - **Generation endpoints** (`text-to-model`, `image-to-model`, `multiview-to-model`, including P1 / P2):
>   new `texture_version` pins the texture model independently of the geometry `model`. …
> - **`texture_quality=fast`**: … **Output texture size and credit cost are both identical to
>   `standard`** …
> - **`delight`** (boolean, default `true`) … Older texture versions ignore it.

### Other entries that touch the H-series surface

- 2026-10 Rigging v3.0: "`POST /v3/animations/rig` accepts `model=v3.0-20260909` … The default model is
  unchanged; v3.0 must be requested explicitly. Credits are unchanged." Rig-check input formats widened to
  "GLB, FBX, OBJ, and STL (previously GLB only)".
- 2026-10 Retopology v3.0 and Smart UV: retopology `face_limit` 500–20,000 triangle / 500–10,000 quad,
  35/40 credits; new `POST /v3/mesh/uv` at 20 credits, input capped at "80,000 equivalent triangles".
- 2026-08 P2: "`model=P2-20260801` (an upgrade of P1)", credits 100/110/120/130 by texture tier.

## Summary

The changelog is the strongest available evidence about H3.1's status by omission: the model ID
`v3.1-20260211` is absent from every release note, including the 2026-04 API re-architecture entry that
introduced the endpoint shape H3.1 is served on. H3.1 therefore either shipped before the v3 API surface
(so it was first reachable through the v2 universal endpoint) or was rolled out without a changelog entry.
Either way, **the snapshot string is the only date evidence for the model**, and the changelog documents
that the surrounding platform (textures, rigging, retopology) has kept moving after it.

The page also creates a naming collision worth flagging: "v3.0" here means the **API** version, while
`v3.0-20250812` in the model registry means the **H3.0 geometry snapshot**.

## Gaps

- No entry, announcement, or deprecation note for H3.1 or H3.0.
- The changelog is not exhaustive for the v2 era, so absence of a 2026-02 entry is suggestive rather than
  conclusive.
- No support-window or retirement dates for any 3D geometry snapshot.

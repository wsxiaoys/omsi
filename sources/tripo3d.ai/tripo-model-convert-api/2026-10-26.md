# Tripo: Model Format Conversion (API reference)

- Origin: Tripo (Holymolly Ltd), "Model Format Conversion",
  <https://developers.tripo3d.ai/en/docs/models-convert>
- Evidence kind: official documentation (API reference)
- Publication date: none stated.
- Capture date: 2026-10-26
- Relevant models: Tripo H3.1 output (as input), and the vendor's export-format surface generally

## Captured content

> **Endpoint:** `POST /models/convert`
> Convert a 3D model to another format with optional mesh processing, texture baking, and export settings.

### Accepted input (verbatim)

> - task_id — The task ID returned by a previous 3D generation task (`text_to_model`, `image_to_model`, or
>   `multiview_to_model`).
> - file_token — Upload a 3D model file via the File Upload API first, then pass the returned token.
> - URL — A publicly accessible direct link to a 3D model file.
>
> - Supported formats: `GLB`, `GLTF`, `FBX`, `OBJ`, `STL`
> - Max file size: **150 MB**

### Target formats (verbatim)

> - `GLTF` — web viewers, WebGL engines (Three.js, Babylon.js).
> - `FBX` — Unreal, Unity, DCC tools (Maya, Blender).
> - `USDZ` — Apple AR Quick Look, RealityKit.
> - `OBJ` — legacy exchange, no animation.
> - `STL` / `3MF` — 3D printing, geometry only.
>
> Enabling `quad` will force the output format to `FBX`.

### Export controls (selected, verbatim)

- `texture_size` default `4096`: "Diffuse texture size in pixels."
- `texture_format` default `JPEG`; also `PNG` ("lossless, supports transparency"), `WEBP`, `BMP`,
  `DPX`, `HDR`, `OPEN_EXR`, `TARGA`, `TIFF`.
- `bake` default `true`: "Bake advanced materials into base textures."
- `pack_uv` default `false`: "Pack all UVs into a unified layout."
- `flatten_bottom`, `flatten_bottom_threshold`, `pivot_to_center_bottom`, `scale_factor`,
  `export_vertex_colors` ("Only valid for `OBJ` and `GLTF`"), `force_symmetry` ("Only valid when quad is
  true"), `part_names`, `export_orientation`, `with_animation` (default `true`), `animate_in_place`.
- `fbx_preset` default `blender`; also `3dsmax`, `mixamo`, `bake_scale`.

## Summary

Generation itself emits GLB (or FBX when `quad` is set); every other container is reached through this
separate, separately billed conversion task. That matters for a reader who needs USDZ (Apple AR) or OBJ or
STL/3MF (printing): those are not generation outputs. The converter also carries the only documented
texture-size control in the product (`texture_size`, default 4096), plus UV packing and material baking.

## Gaps

- No statement of whether conversion is lossy for PBR maps when `bake` is true.
- `with_animation` implies the converter passes skeleton and animation through, but nothing here says
  which rigs or animation formats survive each target container.
- No statement of the coordinate-system convention for each export beyond the `export_orientation` axis
  choice.

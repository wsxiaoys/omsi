# Tripo: Multiview to 3D Model — H Series (API reference)

- Origin: Tripo (Holymolly Ltd), "Multiview to 3D Model — H Series",
  <https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard>
- Evidence kind: official documentation (API reference)
- Publication date: none stated.
- Capture date: 2026-10-26
- Relevant models: Tripo H3.1 (`v3.1-20260211`, documented default); H3.0 / H2.5 for contrast

## Captured content

> **Base URL:** `https://openapi.tripo3d.ai/v3`
> **Endpoint:** `POST /generation/multiview-to-model`
> Generate a 3D model from multiview images. Multiple angles improve geometry accuracy and texture
> coverage.

### View input (verbatim)

> **Three formats — use exactly one, do not mix.**
>
> - **view-key (recommended)** — Array of objects; each object has exactly one key among `front`, `left`,
>   `back`, `right`. … Order does not matter; the server canonicalizes to **[front, left, back, right]**.
> - **legacy positional** — Exactly 4 strings in order **[front, left, back, right]**. Use an empty string
>   `""` to skip a view.
> - **task_id** — Pass the ID of a previous Image to Multiview or Edit Multiview task to reuse its 4-view
>   output.
>
> - The front view **cannot be omitted**. You may omit other views, but at least 2 images are required.
> - All images should depict the same object under consistent lighting.
> - Formats: `PNG`, `JPEG`, `WebP`
> - Recommended resolution: at least **256 × 256 px**.

There are four named views — front, left, back, right. There is no top, bottom, or oblique slot.

The remaining parameter block is identical, wording included, to the
[text-to-3D reference](../tripo-text-to-model-api/2026-10-26.md): `model` (default `v3.1-20260211`),
`face_limit` (same version table), `texture`, `pbr`, `texture_seed`, `texture_quality`,
`texture_version`, `delight`, `geometry_quality`, `auto_size`, `quad`, `smart_low_poly`,
`generate_parts`, `compress`, `export_orientation`, `model_seed`, `export_uv`, plus `texture_alignment`
and `orientation` as on image-to-3D.

## Summary

Multiview-to-3D is the third H-series entry point and is priced identically to image-to-3D (20 credits
base; see the [model page](../tripo-h3-1-model-page/2026-10-26.md)). It accepts two to four views on a
fixed four-slot front/left/back/right rig, requires the front view, and can also consume the four-view
output of Tripo's own image-to-multiview task directly by `task_id`. It is a camera-constrained rig, not
an arbitrary multi-photo reconstruction: no top/bottom coverage exists, so the top of an object is
inferred in every case.

## Gaps

- No statement on how the model resolves inconsistent lighting, scale, or inter-view disagreement beyond
  the "consistent lighting" recommendation.
- No camera/FOV metadata input, so views are assumed to be orthographic-ish and evenly spaced.
- No face-limit or capability difference documented between multiview and single-image conditioning.

# Tripo: Rate Limits & Concurrency (API reference)

- Origin: Tripo (Holymolly Ltd), "Rate Limits & Concurrency",
  <https://developers.tripo3d.ai/en/docs/rate-limits>
- Evidence kind: official documentation (service limits)
- Publication date: none stated.
- Capture date: 2026-10-26
- Relevant models: all Tripo API models; the H-series row covers Tripo H3.1

## Captured content (verbatim)

> Rate limits are calculated at the **API Key** level … When a limit is exceeded, the API returns HTTP
> `429 Too Many Requests` with error code `1007`

> Concurrency is calculated at the **account** level (not per API Key) … Limits are applied **per task
> category** … When a category's concurrency is full, new task creation for that category returns HTTP
> `429` with error code `2000`

> | Category | Included Task Types | Default Concurrency |
> | 3D Generation — H Series | text-to-model (H), image-to-model (H), multiview-to-model (H) | 10 |
> | 3D Generation — P Series | text-to-model (P), image-to-model (P), multiview-to-model (P) | 5 |
> | Image Generation | text-to-image, image-to-image, image-to-multiview, edit-multiview | 1 |
> | Animation | auto-rig, rig-check, animation-retarget | 10 |
> | Model Processing | texture, format-convert, refine | 5 |
> | Mesh Operations | segmentation, completion, retopology | 10 |

> Tasks within the same category share the concurrency pool. For example, if you have 10 H-series
> text-to-model tasks running, you cannot start an H-series image-to-model task until one completes.

> To request higher concurrency limits, please contact our team via the support channel.

Response headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; a `Retry-After`
header accompanies concurrency rejections.

## Summary

H3.1 generation is one shared pool of ten concurrent tasks per account across all three H-series
endpoints; queueing beyond that is the normal state for batch work, and concurrency is raised only by
asking sales. No per-minute request rate is published — only the existence of per-endpoint rate limits and
the 429/`1007` behaviour.

## Gaps

- The actual numeric request-rate limits per endpoint are not published; only concurrency numbers are.
- No published latency, throughput, or SLA figures.
- No statement of whether concurrency tiers scale with spend.

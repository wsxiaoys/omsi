# Tripo: Text to 3D Model — H Series (API reference)

- Origin: Tripo (Holymolly Ltd), "Text to 3D Model — H Series",
  <https://developers.tripo3d.ai/en/docs/generation-text-to-model/standard>
- Evidence kind: official documentation (API reference)
- Publication date: none stated.
- Capture date: 2026-10-26
- Relevant models: Tripo H3.1 (`v3.1-20260211`, the documented default), with H3.0 / H2.5 behaviour
  recorded for contrast

## Captured content

> **Base URL:** `https://openapi.tripo3d.ai/v3`
> **Endpoint:** `POST /generation/text-to-model`
> Generate a 3D model from a text prompt. Produces geometry, optional textures, and optional PBR
> material maps.

### Inputs (verbatim limits)

- `prompt` — "Text prompt, up to 1024 characters. Describe shape, material, style, and scale."
  Vendor example good prompt: "A low-poly medieval wooden treasure chest with iron hinges and a rusty
  lock."; bad: "A box."
- `model` — "Default: `v3.1-20260211`". Values: `v3.1-20260211` ("default; latest, best quality"),
  `v3.0-20250812` ("stable, advanced features"), `v2.5-20250123` ("balanced").
- `negative_prompt` — "Negative prompt, up to 255 characters."
- `model_seed` — "Using the same seed with the same input will produce an identical 3D mesh."
- `image_seed` — "Random seed for the internal text-to-image stage. Controls the reference image
  generated from your text prompt before 3D conversion."
- `texture_seed` — "keep model_seed unchanged and vary texture_seed" for a new texture on the same mesh.

### Polygon budget (verbatim)

> Maximum polycount for the output mesh. If omitted, the model uses adaptive topology.
>
> | Mode | Standard | Ultra |
> | Triangle — v3.1 | 1,500,000 | 2,000,000 |
> | Triangle — v3.0 | 1,000,000 | 2,000,000 |
> | Triangle — v2.5 | 500,000 | / |
> | Quad (`quad: true`) | 150,000 |
>
> Game-ready assets: 50,000 – 100,000. Web/mobile: 10,000 – 50,000.
> When `smart_low_poly: true`, face limits are fixed regardless of model version: Triangle 500 – 20,000,
> Quad 500 – 10,000.

### Textures and PBR (verbatim)

- `texture` default `true`; "Set to false to get a bare geometry without any textures."
- `pbr` default `true`; "Enable PBR material maps (`base_color`, `metallic`, `roughness`, `normal`). When
  `pbr` is set to `true`, `texture` will be automatically forced to `true`."
- `texture_quality`: `fast` | `standard` (default) | `detailed` | `extreme`. "`extreme` — 8K textures,
  highest fidelity." "`fast` … Requires texture `v3.5-20260815`; costs the same as `standard`."
- `texture_version`: `v3.5-20260815` | `v3.0-20250812` | `v2.5-20250123`. "v3.0-20250812 — default for
  v3.x and P-series geometry." "If omitted, it is derived from the geometry `model`."
- `delight` default `true`: "Removes baked-in lighting from the reference image before texturing. …
  Only the `v3.5-20260815` texture model reads this; older texture versions ignore it."

### Topology and export (verbatim)

- `quad` default `false`: "Whether to output a quad mesh (four-sided polygons) instead of triangles. If
  `face_limit` is not set, the default face count will be 10,000. Enabling `quad` will force the output
  format to `FBX`."
- `smart_low_poly` default `false`: "low-poly model with hand-crafted, clean topology style. Best suited
  for simple, non-complex inputs. Complex models may occasionally fail."
- `generate_parts` default `false`: "Generate editable segmented parts." Rejected with error `1004` if
  `texture`/`pbr` are true (including by default); ignored if `quad`; superseded by `smart_low_poly`.
- `compress`: "`geometry` — meshopt compression for reduced file size."
- `export_uv` default `true`; `export_orientation` default `+x`, with a warning that setting it breaks
  later post-processing silently ("the task still reports `status: success` — no error is raised").
- A page note scopes the newer parameters: "The following parameters are only valid when `model ≥
  v3.0-20250812`: `texture_quality`, `geometry_quality`, `auto_size`, `quad`, `smart_low_poly`,
  `generate_parts`, `compress`."

### Result shape (verbatim example)

```json
"output": {
  "model_url": "https://cdn.tripo3d.ai/output/model_pbr.glb",
  "rendered_image_url": "https://cdn.tripo3d.ai/output/preview.png"
},
"credits_consumed": 100.00
```

"Asynchronous task pattern": create a task, then poll `GET /v3/tasks/{task_id}` or use a webhook.

## Summary

The reference confirms that H3.1 is the server-side default for text-to-3D, that text input is capped at
1024 characters with a 255-character negative prompt, and that the generation response is a single mesh
file (GLB, or FBX when `quad` is set) plus a preview render. The one documented capability difference
between H3.1 and H3.0 visible here is the standard-mode triangle ceiling: 1,500,000 for v3.1 against
1,000,000 for v3.0. Both reach 2,000,000 in `geometry_quality=detailed` ("Ultra") mode.

The page also shows the two-model split inside one request: geometry comes from `model`, texturing from
`texture_version`, and for `v3.x` geometry the default texture model is the older `v3.0-20250812`.

## Gaps

- No lower bound for `face_limit` in triangle mode (only the `smart_low_poly` band 500–20,000 is stated).
- No texture resolution in pixels for `standard` or `detailed`; only the word "8K" for `extreme`.
- No statement of up-axis, unit scale (beyond `auto_size` in meters), or UV atlas layout.
- No latency or SLA figures.
- `negative_prompt` is documented at 255 characters here, while fal's schema for the same model accepts
  1024 — see the [fal record](../../fal.ai/tripo3d-h3-1/2026-10-26.md).

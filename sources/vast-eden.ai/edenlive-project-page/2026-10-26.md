## Verbatim: abstract

> We present EdenLive, a real-time generative video renderer for interactive applications in the
> Project Eden series (project-eden). EdenLive continuously renders enhanced and stylized video from
> reference videos of different geometric granularities that range from proxy videos, namely
> simplified renderings produced by a coding agent or a game engine, to directly recorded videos, with
> a target first frame and a text prompt as input to guide the appearance. This design conveys the
> world state to the model through the reference video and thereby decouples its interaction-induced
> evolution from visual rendering: the upstream code or engine maintains the game logic and world state
> explicitly and precisely, whereas EdenLive renders reference video into detailed visual output. …
> To handle references for diverse rendering scenarios, we employ a vision encoder that maps them into
> a shared feature space despite their differences in geometric granularity and appearance, and
> condition the video generation model on these features, which mitigates leakage of the reference
> appearance into the generated video. To enable streaming generation, we distill the generator into a
> few-step chunk-wise autoregressive model and deploy it in a serving system that pipelines program
> simulation, reference encoding, and generation with a one-chunk lookahead, so that the system
> presents the generated video in real time and responds to user interaction. Experiments on short- and
> long-horizon generation show that EdenLive achieves good reference control and visual quality, while
> generating 720P videos in real time at over 24 FPS on a single GPU.

## Verbatim: inputs, outputs, pipeline

> EdenLive operates on three inputs: a proxy or reference video (stream) that specifies layout, camera,
> and motion; a target first frame that determines the overall visual appearance; and a text prompt
> that supplies stylistic and fine-grained details. The proxy can originate from arbitrary sources — a
> 2D or 3D scene assembled by a coding agent, animation or simulation frames from an existing engine or
> workbench, or even a screen recording. The output is a refined video or a continuous video stream.

> The paradigm of EdenLive can be summarized as proxy-to-fine: it leverages the structural and motion
> information provided by the proxy, without requiring the reference to attain a specific level of
> geometric detail or to be produced through a particular rendering pipeline (e.g., G-buffers). Its two
> defining properties are real-time generation (24 fps or more on a single GPU*) and long-horizon
> synthesis (minutes of continuous generation).

Interaction-loop caption, verbatim:

## Verbatim: open-source release contents

> Releases 5B and 14B weights for both bidirectional and few-step (chunk-AR) inference, real-time

> frontend for the full prompt-to-game pipeline.

Two further highlights, verbatim:

> Generates at 24 fps or above and sustains minute-scale continuous synthesis, enabling rendering to
> consume a continuously evolving live reference stream. The 5B model runs in real time on a consumer

> Camera, layout, and motion remain constrained by the reference, while target appearance and style are
> specified by the first frame and the prompt. A single reference can thus be rendered in multiple
> distinct styles.

## Verbatim: positioning table ("Comparison with Related Approaches")

The page states the table "clarifies differences in positioning rather than ranking methods."

| Approach | Mechanism | Difference from EdenLive |
| --- | --- | --- |
| Interactive world models (Lingbot World, Pixverse R, …) | Generates interactive frames conditioned on actions or text | Decouples state from rendering: the proxy maintains state and interaction control, while EdenLive is responsible only for rendering, so that health, cooldowns, NPC state, and success or failure feedback can be preserved |
| Vidu S2 | Also performs real-time reference-driven generation | Vidu S2 is largely restricted to portrait scenes, whereas EdenLive handles diverse forms of reference |
| Blockout (Seedance 2.5, MiniMax H3) | Offline controllable video generation | EdenLive supports real-time generation and can be placed inside a live interaction loop |
| DLSS 5 | Upscaling and frame generation on top of an existing render pipeline | EdenLive is a generative renderer: appearance can be altered wholesale, unconstrained by the original assets |

## Application areas claimed

Four carousels, each with a one-line body: "Interactive Game Preview" (coding agent builds the proxy
and engine code, EdenLive renders), "Scene and Animation Preview" (one layout, many appearances),
"Video Re-Rendering and Restyling" (existing video as reference), and "Embodied Data Augmentation"
(human manipulation footage re-rendered as a robot viewpoint, or objects replaced).

## Summary

VAST's own page frames EdenLive as a **real-time generative renderer** for interactive worlds, not as
an avatar or text-to-video product. The interface is a reference/proxy video stream plus a target first
frame plus a prompt; the model is sold on throughput (">24 FPS", "minutes" continuous), output sizes
(480P/720P), and open weights at two sizes. VAST publishes no pricing on this page: the commercial
routes it links are the hosted endpoints at Reactor and, by host listing, fal.

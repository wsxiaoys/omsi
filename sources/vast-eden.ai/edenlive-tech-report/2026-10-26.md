## Cover and scope

> TECHNICAL REPORT / EdenLive: Real-Time Generative Rendering from Any Visual Reference / 1VAST …
> DATE October 2026

> Figure 1 Real-time generative rendering from diverse visual references. … Examples include game and
> 2D proxies, normal maps, scene previews, video restyling, and embodied scenes. All outputs use the
> EdenLive 5B model.

Two backbones, verbatim:

> We initialize the video generator from two pretrained latent video diffusion transformers,
> Wan2.2-TI2V-5B and Wan2.1-I2V-14B [85], and progressively adapt them for reference conditioning,
> chunk-causal autoregressive generation, and few-step sampling.

The conditioning signal is a frozen, fine-tuned DINOv3-L/16 encoder whose features are concatenated
into the DiT input; the report describes fine-tuning on reference–target image pairs and
"self-paired" training on appearance-perturbed copies of unpaired video.

## Real-time system, verbatim

> The optimized 5B renderer exceeds 24 FPS at 1280 × 704 on a single NVIDIA H100, measured from
> model-side condition processing to decoded frames in CPU memory.

> At inference, EdenLive generates the latent stream in chunks of 𝐿 latent frames … Each chunk is
> sampled in four denoising steps without classifier-free guidance.

> We use 𝐿 = 3 latent frames to trade off the response delay against these costs.

> Under this schedule, an input that arrives during the generation of chunk 𝑘−1 enters the simulation
> of chunk 𝑘 and becomes visible only once chunk 𝑘 has been generated, decoded, and played back; in
> steady state, the input-to-display delay is therefore about two chunk durations plus transmission
> and scales with the chunk length 𝐿.

> the decoded frames are streamed to the client over WebRTC, which also carries keyboard and mouse
> events back.

## Verbatim: limitations (section 7)

> EdenLive leaves the mapping between reference objects and their intended identities implicit;
> explicit object associations could improve control over which entity each proxy represents. Its
> bounded temporal cache also lacks a dedicated memory for fine appearance details, motivating
> retrieval of object- or scene-specific visual evidence after extended occlusion or scene revisiting.
> Finally, the encoder provides a single learned representation without explicit control over which
> levels of reference detail to preserve.

Also relevant, from the introduction: the model is a renderer only, and the design assumption is that
"Upstream code or an engine maintains and advances the world state by executing the game logic and
interaction mechanisms."

## Summary

The report supplies the only measured throughput, latency and memory numbers for EdenLive. It
establishes that the 5B configuration is the real-time one (29.80 FPS at 1280 × 704 on a single H100;
73.52 FPS at 832 × 480) and that the 14B configuration needs eight H100s to reach 26.76 FPS at
832 × 480 — the concrete basis for the project page's footnote that single-GPU deployment "applies to
the 5B model (720P)". First-chunk latency is 0.83–1.71 s depending on configuration, and steady-state
response is about two chunk durations, which is consistent with the project page's "hundreds of
milliseconds" end-to-end claim only after warm-up.

## Gaps

- Vendor-run evaluation throughout; no third-party replication of Table 1, Table 2 or Table 3 was
  found. The VLM judge is a Gemini model, and the pairwise subset is 45 cases.
- No quality comparison against an independently measured baseline; the offline baselines in Fig. 6
  have no numbers.
- The report does not state the maximum session length, the maximum input resolution of the reference
  stream, or behaviour under content that violates a policy. "Minutes" is a claim, not a tested bound.
- No stated consent, likeness or watermarking behaviour for the restyling and re-rendering
  applications.

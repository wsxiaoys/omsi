# VEED Help Center: "VEED API: Frequently Asked Questions"

- Origin: VEED Help Center (Intercom-hosted), "VEED API: Frequently Asked Questions",
  <https://support.veed.io/en/articles/17229001-veed-api-frequently-asked-questions>. Collections > APIs
  > Direct API access.
- Evidence kind: official documentation and policy statement (first-party vendor support article)
- Publication date: none stated; header reads "Updated over a week ago" at capture, i.e. approximately
  2026-10-19.
- Capture date: 2026-10-26
- Relevant models: all VEED API models, including Fabric 1.0

## Captured content

Model list, verbatim:

> Fabric 1.0 — turn an image and an audio track into a talking video
> Lipsync 2.0 — re-sync an existing video to new audio
> Video Background Removal — remove the background from any video (Standard, Fast, Green screen)
> Clean Audio — remove background noise from speech
> Subtitles API — coming soon

Audience, verbatim:

> Who can use the API?
>
> The API is for business and professional use, including individual developers. You must be 18 or over.

Billing, verbatim:

> Each model has its own rate, charged in USD per second, per minute or per frame. […]
>
> The API runs on a credit system. Credits are prepaid, non-refundable, and expire two years after
> purchase. Prices exclude taxes.

> Can I use my VEED subscription or AI Credits for the API?
>
> No. API usage is billed separately, from your API credits. Your VEED subscription doesn't cover it.

Jobs, verbatim:

> Jobs are asynchronous. A request returns a job_id immediately. Poll the job's GET endpoint until the
> status is COMPLETED or FAILED. Webhooks are not supported.

> Output URLs expire 24 hours after the job completes […]. You can change this per request with the
> X-Veed-Media-Expiration-Seconds header, up to 30 days (2,592,000 seconds).

Data and rights, verbatim:

> We store the request and response of each API call for 7 days so you can see them in your request log.
> After that, they're deleted. To skip storing them for a specific call, send the header X-Veed-Store-IO:
> 0.

> We don't use your API inputs or outputs to train our models unless you agree to it.

> Can I use outputs commercially? Who owns them?
>
> Yes, you can use outputs commercially. See our Terms of Sale for further detail.

> What content is not allowed?
>
> See our Code of Conduct. Only use images, videos and voices you own or have permission to use. Jobs
> that break the rules fail with the content_moderation error.

Error taxonomy, verbatim (relevant rows):

> input_validation — A required input is missing or wrong
> invalid_file — We couldn't read the file
> transload_failed — We couldn't download your file
> audio_too_long — The audio is over the model's limit
> content_moderation — The input breaks our content rules
> generation_failed / timeout — Something went wrong on our side

## Summary

The API-wide FAQ fixes the commercial frame around Fabric 1.0: prepaid, non-refundable credits that
expire after two years, prices excluding tax, asynchronous jobs with no webhooks, 7-day request-log
retention with an opt-out header, commercial use of outputs permitted, and a named
`content_moderation` failure mode tied to a Code of Conduct that requires owning or having permission
for every image, video and voice.

## Gaps

- No statement of who owns outputs in the FAQ beyond pointing at a "Terms of Sale" document that was
  not captured; the API Terms of Use do address ownership
  ([API terms](../api-terms-of-use/2026-10-26.md)).
- "The audio is over the model's limit" never states the limit.
- No rate-limit numbers, only the request classes (reads, writes, AI generation) and a 429 response.
- No refund or failure-billing rule is stated for failed jobs.

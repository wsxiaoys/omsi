# Vidu API docs: Vidu Q4 Preview — Image to Video

- Origin: Vidu Open Platform documentation, "Image to Video" under *Vidu Q Video Models → Vidu Q4
  Preview*, https://platform.vidu.com/docs/api-reference/video-models/vidu-q4-preview/image-to-video
  (read as Markdown via `…/image-to-video.md`)
- Evidence kind: official documentation (first-party API reference)
- Publication date: not stated on the page
- Capture date: 2026-10-26
- Relevant models: `viduq4-preview` only

## Endpoints

> POST https://api.vidu.com/ent/v2/img2video
>
> GET https://api.vidu.com/ent/v2/tasks/{id}/creations

The China-facing documentation mirrors this page in Chinese with the same `viduq4-preview` model and a
`https://api.vidu.cn/ent/v2/img2video` host (`platform.vidu.cn/docs/api-reference/video-models/vidu-q4-preview/image-to-video`,
captured in the same session).

## Request parameters (verbatim table entries)

> | `model` | `string` | Required | Model name，Accepted values: `viduq4-preview` `viduq4-preview`: Supports audio-video
> synchronization, supports automatic camera switching；Allowed values: `viduq4-preview` |
>
> | `images` | `string` | Required | An image to be used as the start frame … Note 2: Only 1 image is accepted.
> Note 3: Supported image formats: png, jpeg, jpg, webp. Note 4: The image size must not exceed 50MB.
> Note 5: Note that the HTTP body must not exceed 20MB … |
>
> | `prompt` | `string` | Optional | A textual description for video generation. Note: Maximum length of
> **20000 characters**. |
>
> | `is_rec` | `boolean` | Optional | Whether to use the recommended prompt …；Default: `true` |
>
> | `duration` | `integer` | Optional | Video duration.；Default: `5`；Allowed values: `3 - 16` |
>
> | `resolution` | `string` | Optional | Video Resolution.；Default: `720p`；Allowed values: `540p` / `720p` /
> `1080p` / `2K` / `4K` |
>
> | `audio` | `boolean` | Optional | Whether to use direct audio-video generation capability. `false`: No
> direct audio-video generation, outputs silent video `true`: Direct audio-video generation required,
> outputs video with sound (including dialogue and sound effects)；Default: `true` |
>
> | `seed` | `integer` | Optional | Random seed … Default: `0` |
>
> | `payload` / `callback_url` | `string` | Optional | pass-through and async callback |

**Absent from this endpoint:** `aspect_ratio`, a last-frame image, `subjects`, `off_peak`, and the
watermark parameters (`wm_position`, `wm_url`, `meta_data`) that the changelog says were added to
Image-to-Video for other models. The only inputs are one image, a prompt, duration, resolution, audio
on/off, seed and `is_rec`.

## Output (verbatim table entries)

> | ↳ `url` | `string` | Optional | Creation URL, valid for 24 hours |
> | ↳ `cover_url` | `string` | Optional | Creation cover, valid for 24 hours |
> | ↳ `watermarked_url` | `string` | Optional | Watermarked creation URL, valid for 24 hours |

Results are asynchronous tasks: create → poll `tasks/{id}/creations`, or supply `callback_url` with a
signed callback. Output URLs expire after 24 hours.

## Summary

The authoritative parameter surface for Q4 image-to-video. It establishes: single start frame only, no
last frame, no aspect-ratio control (the frame is inherited from the source image), audio on by default
and switchable, 3–16 s, 540p–4K, 20,000-character prompt, and a recommended-prompt expander that
defaults **on** (`is_rec: true`) — meaning an unspecified call may not use the caller's prompt verbatim.

## Gaps

- No frame rate, bitrate, codec or container is documented for the output.
- No statement of what `is_rec` does to Q4 billing. The 2025-11-03 changelog entry that introduced the
  parameter says "Each call will consume an additional 10 credits"; the Q4 price table has no such
  line, and this page does not say whether the expander is free here.
- "Automatic camera switching" is asserted in the `model` description with no parameter, no shot limit,
  and no example.
- No rate limit, region list, or data-retention statement on this page.

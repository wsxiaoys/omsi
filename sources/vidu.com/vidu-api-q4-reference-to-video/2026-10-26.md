# Vidu API docs: Vidu Q4 Preview — Reference to Video

- Origin: Vidu Open Platform documentation, "Reference to Video" under *Vidu Q Video Models → Vidu Q4
  Preview*, https://platform.vidu.com/docs/api-reference/video-models/vidu-q4-preview/reference-to-video
  (read as Markdown via `…/reference-to-video.md`)
- Evidence kind: official documentation (first-party API reference)
- Publication date: not stated on the page
- Capture date: 2026-10-26
- Relevant models: `viduq4-preview` only

## Endpoints

> POST https://api.vidu.com/ent/v2/reference2video
>
> GET https://api.vidu.com/ent/v2/tasks/{id}/creations

## Request parameters (verbatim table entries)

> | `model` | `string` | Required | Model name，Accepted values: `viduq4-preview` `viduq4-preview`: Supports
> generating videos with reference sound; supports intelligent camera switching, achieves superior
> consistency across multiple camera positions; supports simultaneous audio and video output. |
>
> | `prompt` | `string` | Required | A textual description for video generation. Note 1: The length cannot
> exceed 20000 characters. Note 2: Use `[@subjects_name]` to represent subject content. For example: "@1
> and @2 are eating hot pot together, and the narrator says that everyone loves hot pot." |
>
> | `images` | `array` | Required | Multiple images are supported … Note 1: `viduq4-preview` model supports
> uploading 1 to 15 images; Note 2: Image Base64 encoding or image URL … Note 4: Please note that the
> POST body of an HTTP request shall not exceed 20MB |
>
> | `sounds` | `array` | Optional | Up to 0 to 3 audio files are supported … Note 1: The duration of each
> reference audio range 3-12s. Note 2: The audio supports mp3 format. Note 3: The size of each audio file
> shall not exceed 50M. |
>
> | `audio` | `boolean` | Optional | Whether to use the audio-video output capability …；Default: `true` |
>
> | `duration` | `integer` | Optional | Video duration parameter；Default: `5`；Allowed values: `3 - 16` |
>
> | `aspect_ratio` | `string` | Optional | Aspect ratio parameter.；Default: `16:9`；Allowed values: `1:1` /
> `9:16` / `16:9` / `3:4` / `4:3` |
>
> | `resolution` | `string` | Optional | Resolution parameter；Default: `720p`；Allowed values: `540p` / `720p`
> / `1080p` / `2K` / `4K` |

**Reference syntax.** The parameter table documents `[@subjects_name]`; the request example in the same
page uses positional tags instead — `[@reference_image_1]`, `[@reference_image_2]`,
`[reference_audio_1]`. Both spellings appear on one page with no statement of which is current.

**Subjects are excluded.** A note under the endpoint says:

> viduq4-preview does not support the subject invocation method for the time being.

That rules out the reusable "Subjects" objects that the platform's own `subjects` task-management API
and earlier reference-to-video models support; Q4 references must be passed per request.

## Output

Same as image-to-video: asynchronous task, `url` / `cover_url` / `watermarked_url`, each valid 24 hours.

## Summary

Q4 reference-to-video takes 1–15 images plus 0–3 mp3 voice references (3–12 s each, ≤50 MB each,
≤20 MB total body), 3–16 s output, five aspect ratios, 540p–4K, audio on by default. The 15-image cap
and the 3-voice-reference feature are the two capabilities Q3 reference-to-video lacked.

## Gaps

- The 20 MB total-body limit is a hard ceiling that the 15-image and 3-audio caps can exceed in
  practice (15 × 50 MB of images cannot be sent); no page explains how to prioritise.
- No documented behaviour for `audio: false` combined with `sounds` supplied — whether the reference
  audio still steers voice identity on a silent output.
- No statement on consent requirements for the voice references beyond the general moderation page.
- Frame rate and output codec are not documented.

# Vidu API docs: "Usage and Limits"

- Origin: Vidu Open Platform documentation, "Usage and Limits",
  https://platform.vidu.com/docs/terms-and-policies/usage-and-limits (read as Markdown via `…/usage-and-limits.md`)
- Evidence kind: official documentation (first-party account limits)
- Publication date: not stated on the page
- Capture date: 2026-10-26
- Relevant models: all Vidu API models, including `viduq4-preview`

## Verbatim

> To protect our API against abuse and ensure fair access, we have set limits on the number of
> generations you can create. Each organization has a set of limits, which apply per organization, not
> per API key.

> Each organization can use up to 5 concurrent tasks. This means you can generate up to 5 tasks
> simultaneously.

> If you submit more tasks than allowed, your excess tasks will be in queueing status, indicating they
> are stored but not yet processed. Throttled tasks are enqueued roughly in submission order.

> In rare cases, you may experience lower than maximum concurrency depending on system load.

> For custom tier information, higher limits, or guaranteed concurrency, file an exception request from
> the usage page when logged in to the developer portal.

The pricing page's top-up table repeats "≤ 5" concurrency for every package up to 20,000 RMB, so
buying more credits does not raise the concurrency cap.

## Summary

The default throughput ceiling is **5 concurrent tasks per organisation**, with no documented
per-minute request cap, and higher concurrency only through an enterprise exception. For 16-second 4K
generations this is the practical limit on batch work, and it applies equally to Q4 Preview.

## Gaps

- No published generation-time figures for Q4 at any resolution, so the throughput of 5 concurrent
  slots cannot be converted into videos per hour.
- No statement of whether preview models have lower limits than GA models.
- No region-specific limits documented.

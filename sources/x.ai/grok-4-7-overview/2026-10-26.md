## Where it runs (verbatim)

> * **xAI API**: get a key from the console
> * **US regional endpoint**: also served at `https://us.api.x.ai/v1`, which keeps inference in
>   the United States, with token usage priced at a 10% premium; see Regional Endpoints
> * **Grok Build**: the default model of the coding agent
> * **Cursor**: available on all plans
> * **Model gateways**: OpenRouter, Vercel, and Cloudflare

## Fast variant (verbatim)

> Grok 4.7 Fast is the same model served on faster infrastructure. It costs 2x the standard token
> rates, or 1.5x for long-context requests. It's available only in Cursor and Grok Build, and is
> billed through your plan there. It is not included in Grok Build's free tier. It is not
> available on the public xAI API.

## Important details (verbatim, two of three bullets)

> * **We highly recommend setting a `prompt_cache_key`** (Responses API; `x-grok-conv-id` header
>   on Chat Completions). It routes a conversation's requests to the same server, making cache
>   hits reliable; without it you often pay full input price on a cache-cold server.
> * **Long agent loops** additionally benefit from context compaction; for tool-heavy workloads
>   see function calling.
> * **Encrypted reasoning is always returned on the Responses API.** `POST /v1/responses`
>   responses from `grok-4.7` include `reasoning.encrypted_content` even when `include` does not
>   list it, so multi-turn conversations keep the model's reasoning without extra configuration.

## What this establishes

- **Knowledge cutoff: May 2026.** This is the only first-party statement of a cutoff for this
  model, and the Models page repeats it ("The knowledge cut-off date of Grok 4.7 is May 2026").
- **"No text output limit"** is a first-party claim, and it conflicts with the 450,000-token
  `max_completion_tokens` that OpenRouter attaches to the same xAI endpoint
  ([OpenRouter](../../openrouter.ai/grok-4-7/2026-10-26/index.md)). The practical cap is
  therefore unclear.
- **The API surface is the Responses API**, and this page lists only that one API. It is not the
  only way in — the pricing page documents Priority Processing for "Chat Completions and
  Responses" and the reasoning guide notes that "Chat Completions is unaffected" by the encrypted
  reasoning default — so the at-a-glance "APIs" row is narrower than the model's real surface.
- **Tools**: function calling plus four named server-side tools. Tool invocations are billed
  separately from tokens (web search $5 / 1k calls, X search $5 / 1k posts and $10 / 1k profiles,
  code execution $5 / 1k calls), which is a real cost channel beyond the token price.
- **Prompt caching is fragile without `prompt_cache_key`.** The vendor's own advice is that
  without it "you often pay full input price on a cache-cold server", which makes the $0.50
  cached-input rate conditional on caller behaviour.
- **Distribution**: first-party API and US endpoint, plus Grok Build (default model), Cursor (all
  plans), and the OpenRouter / Vercel / Cloudflare gateways. "Grok 4.7 Fast" is a
  faster-infrastructure tier of the same model, not a separate model ID, and it is **not** on the
  public API.

## Gaps

- The page gives the fast-tier multipliers (2x, 1.5x long-context) but not the fast tier's dollar
  rates; it points at the Pricing page for those.
- No benchmark figures, no context-compaction limits, no statement of what "context compaction"
  does to billed tokens.
- "Model gateways: OpenRouter, Vercel, and Cloudflare" is a vendor statement that a gateway serves
  the model; only the OpenRouter route was independently confirmed in this capture.

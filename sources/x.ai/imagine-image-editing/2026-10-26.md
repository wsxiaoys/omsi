## Editing endpoint (verbatim)

> Edit an existing image by providing a source image along with your prompt. The model understands
> the image content and applies your requested changes.

> The OpenAI SDK's `images.edit()` method is not supported for image editing because it uses
> `multipart/form-data`, while the xAI API requires `application/json`. Use the xAI SDK, Vercel AI
> SDK, or direct HTTP requests instead.

Endpoint in every example: `POST https://api.x.ai/v1/images/edits`, `"model":
"grok-imagine-image-2.0"`.

### Accepted input image forms (verbatim)

> You can provide the source image as:
>
> * A **public URL** pointing to an image
> * A **base64-encoded data URI** (e.g., `data:image/jpeg;base64,...`)
> * A **`file_id`** from the Files API

### Multi-turn editing and style transfer (verbatim)

> Chain multiple edits together by using each output as the input for the next. This enables
> iterative refinement; start with a base image and progressively add details, adjust styles, or
> make corrections.

> The `grok-imagine-image-2.0` model supports a wide range of visual styles, from ultra-realistic
> photography to anime, oil paintings, and pencil sketches.

Note the style-transfer sentence is scoped to `-2.0`, not to the base model.

## Multi-image editing (verbatim, full body)

> Use up to five source images for a single image edit. You can specify images in the order they
> are sent in the request. By default, the output aspect ratio follows the first input image. You
> can override this by setting the `aspect_ratio` parameter to a specific ratio, such as `"1:1"` or
> `"16:9"`.
>
> Each source image can be a public URL, a base64-encoded data URI, or a `file_id` from the Files
> API — and you can mix kinds within a single request.

## Prompting guide scope (verbatim)

> This guide covers prompts for `grok-imagine-image-2.0` stills: a new image from text, or an edit
> of an existing one.

> Generated URLs are temporary, so request `b64_json` when you plan to keep the file, or store it
> with Imagine outputs.

## What this establishes

- `grok-imagine-image` is a **text-and-image-in, image-out** model: editing is the same model, not a
  separate edit SKU.
- Image-to-image editing accepts URL, base64 data URI, and Files `file_id` inputs, and supports
  chained multi-turn edits.
- Multi-image editing allows up to **five** source images with output aspect ratio inherited from
  the first input unless overridden.

## Gaps

- Every example uses `grok-imagine-image-2.0`. The pages do not say whether the five-reference
  limit, the 21:9/5:2 ratios, or any of the described editing behaviours apply equally to
  `grok-imagine-image` (1.0). The release note in `sources/x.ai/release-notes/2026-10-26.md` says
  the five-reference change was an API-wide edit capability ("Image editing now accepts up to 5
  source images per request (was 3)"), which reads as endpoint-wide, but the guides never confirm
  per-model support.
- No documented identity-preservation limits, no statement on what the model refuses to edit, and
  no before/after quality examples for the base tier.

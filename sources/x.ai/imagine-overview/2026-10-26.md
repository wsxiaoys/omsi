# xAI docs: Imagine API overview

- Origin: xAI developer documentation, "Imagine Overview",
  <https://docs.x.ai/developers/model-capabilities/imagine> (`.md` capture)
- Evidence kind: official documentation (capability overview)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: `grok-imagine-image`, `grok-imagine-image-2.0`, `grok-imagine-video`,
  `grok-imagine-video-1.5`

## Scope (verbatim)

> The Imagine API lets you generate and edit images and videos with Grok Imagine models. Use it for
> image generation, image editing with up to 5 reference images, video generation from text or
> still images, video editing, and more.

## Pricing basis (verbatim)

> Image generation uses flat per-image pricing regardless of prompt length. Each generated image
> incurs a fixed fee. Image edits are billed for both the input image and the generated output
> image. Video generation uses per-second pricing where both duration and resolution affect the
> total cost.

## Image generation summary (verbatim)

> Generate new images from text prompts with Grok Imagine models. Configure output count (up to 10
> images per request), aspect ratio, resolution, and response format.

Every code sample on this page also uses `xai.image("grok-imagine-image-2.0")`.

## Data handling and compliance (verbatim)

> The Imagine APIs are built for production workloads with strict security and compliance
> requirements. Generated media is subject to content policy review and is not used for training.

> **SOC 2 Type II** […] **HIPAA Eligible** […] **GDPR Compliant** […] **Data Residency** […]
> **High Availability** […] **SSO & RBAC**

## What this establishes

- "Grok Imagine" is the **family/product name** spanning both image and video models; the image
  model is one member, not the whole product.
- Images and video are separate capabilities with separate pricing bases (per image vs per second)
  behind one API.
- Generated media is subject to content policy review — a first-party statement of a policy gate,
  not a description of what is filtered or how often.

## Gaps

- "Content policy review" is not specified: no list of prohibited categories, no statement on
  whether review is pre- or post-generation, no appeal path.
- No statement of which model tiers support which parameters; the overview examples are 2.0-only.

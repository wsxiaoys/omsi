# xAI docs: Video Generation (endpoint guide)

- Origin: xAI developer documentation, "Video Generation",
  <https://docs.x.ai/developers/model-capabilities/video/generation> (`.md` capture)
- Evidence kind: official documentation (API guide: parameters, modes, errors)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: `grok-imagine-video-1.5` (primary example model throughout),
  `grok-imagine-video-1.5-lite`, `grok-imagine-video`

Every code sample on the page uses `"model": "grok-imagine-video-1.5"`, so the guide doubles as
first-party documentation of 1.5's request surface.

## Scope and recommendation (verbatim)

> Generate videos from text prompts with Grok video models. The API supports configurable duration,
> aspect ratio, and resolution, and the SDK handles asynchronous polling automatically. On
> `grok-imagine-video-1.5`, text-to-video supports native 1080p. For simple videos, we recommend
> `grok-imagine-video-1.5-lite`, the lowest price per second.

> [!NOTE]
>
> On  and , text-to-video uses text-to-image then image-to-video under the hood: the model generates
> a first frame from your prompt, then animates it. You still make a single text-to-video request;
> the intermediate image is not returned.

The admonition's date slots are **empty** on the captured page ("On  and ,"), so it names no model
and no date while describing the pipeline. The same fact is stated concretely elsewhere: "On
`grok-imagine-video-1.5` and `grok-imagine-video-1.5-lite`, the model renders a first frame from the
prompt, then animates it" (`../imagine-video-overview/2026-10-26.md`).

## Duration, aspect ratio, resolution (verbatim)

> Set `duration` from 1 to 15 seconds; the default is 8. Reference-to-video on
> `grok-imagine-video` allows up to 10 seconds.

> Video editing does not support custom `duration`. The edited video retains the duration of the
> original, which is capped at 8.7 seconds.

Aspect ratios offered: `1:1`, `16:9` / `9:16` (default `16:9`), `4:3` / `3:4`, `3:2` / `2:3`,
`21:9`, `5:2`.

> Image-to-video output always matches the input image's aspect ratio; `aspect_ratio` is ignored.

> **Note:** `grok-imagine-video-1.5` renders `1080p` natively for text-to-video and image-to-video;
> reference-to-video goes up to `720p`. `grok-imagine-video-1.5-lite` reaches 1080p for
> text-to-video and image-to-video by upscaling 720p. `grok-imagine-video` supports up to 720p.

`480p` is the documented **default** resolution. Editing is capped at 720p output; extension,
editing and custom duration/aspect-ratio/resolution are 1.0-only.

## Audio (verbatim)

> Generated videos include an audio track by default, with lip-synced speech on
> `grok-imagine-video-1.5` and `grok-imagine-video-1.5-lite`. On `grok-imagine-video-1.5`,
> reference-to-video can give up to 3 speakers a preset voice with `reference_audios`; see
> [Reference audio](https://docs.x.ai/developers/model-capabilities/video/generation).

> Pass `generate_audio=False` to request a silent video.

## Request modes (verbatim, abridged table)

> | Mode | REST API fields | Description |
> | --- | --- | --- |
> | Text-to-video | `prompt` only | Generates video from a text prompt alone. |
> | Image-to-video | `prompt` + `image` | Generates video with the provided image as the starting frame. |
> | Reference-to-video | `prompt` + `reference_images` or `reference_audios` | Generates video guided by reference images and/or a preset voice on `grok-imagine-video-1.5`. |
> | First & Last frame | `last_frame`, optionally with `image` and/or `prompt` | On `grok-imagine-video-1.5`, pins the exact last frame. |
> | Keyframes | `keyframes` (up to 4 `{image, timestamp_s}` entries) | On `grok-imagine-video-1.5`, pins images at exact moments strictly inside the clip, on a 1/3-second grid. |
> | Edit-video | `/v1/videos/edits` + `video` | Modifies an existing video based on the prompt. |
> | Extend-video | `/v1/videos/extensions` + `video` | Extends an existing video from its last frame. |

> On `grok-imagine-video-1.5`, `image` combined with `reference_images`, `reference_audios`,
> `last_frame`, or `keyframes` is reference-to-video with a pinned first frame. The clip starts on
> that image rather than treating it as a style reference. `last_frame` or `keyframes` on its own
> (no `image`, no references) is valid: the model generates the rest of the clip around the pinned
> frames. `prompt` is optional for any request that includes `image`, `reference_images`,
> `last_frame`, or `keyframes`; it is required only for text-to-video. Classic
> `grok-imagine-video` still rejects `last_frame` and `keyframes` and rejects combining `image` with
> reference inputs.

## Asynchrony and outputs (verbatim)

> Video generation is an **asynchronous process** that typically takes up to several minutes to
> complete.

> Videos are returned as temporary URLs. Access the SpaceXSI-hosted URL directly when you need it,
> or download/process it promptly if you need to keep a copy.

Completed response body:

```json
{
  "status": "done",
  "video": {
    "url": "https://vidgen.x.ai/.../video.mp4",
    "duration": 8,
    "respect_moderation": true
  },
  "model": "grok-imagine-video-1.5"
}
```

The page's own SDK example treats the flag as a pass/fail gate (`if response.respect_moderation: print(response.url)` / `else: print("Video filtered by moderation")`) without describing what was filtered or how.

Error codes documented for failed generations: `invalid_argument` (includes "content blocked by
moderation"), `permission_denied`, `failed_precondition`, `service_unavailable`, `internal_error`.

## What this establishes

- **The parameter surface of 1.5 at capture:** 1–15 s (default 8), nine aspect ratios, 480p/720p/
  1080p (1080p native for T2V and I2V, 720p ceiling for R2V), audio on by default with an opt-out,
  up to 3 preset voices, and pinned first/last frames plus up to 4 mid-clip keyframes on a
  1/3-second grid. Reference-image count (up to 14 on 1.5) is stated on the reference-to-video page,
  not here (`../imagine-video-reference-to-video/2026-10-26.md`).
- **1.5 cannot edit or extend video.** Editing and extension are routed to `grok-imagine-video`
  (1.0), matching 1.0's `video → video` modality line.
- **No frame rate, no codec, no container** is stated anywhere on the page; output is `.mp4` by
  URL convention only.
- **Moderation is real but underspecified**: a boolean `respect_moderation` flag and a
  `invalid_argument` code that lumps "content blocked by moderation" in with parameter errors.
- The page self-brands the vendor as "SpaceXSI" in body text while the API host remains `api.x.ai`.
  Captured as observed, not interpreted.

## Gaps

- Output frame rate is not documented by xAI at all.
- No maximum prompt length, no image size/format limits beyond "JPEG, PNG, or WebP" in the REST
  reference (`../videos-api-reference/2026-10-26.md`).
- No latency SLA beyond "up to several minutes", no queue depth, no concurrency cap.
- The empty date slots in the T2V-pipeline note suggest the page is generated from a template with
  unfilled variables; nothing indicates which dates were intended.

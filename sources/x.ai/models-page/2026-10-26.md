## Additional Information Regarding Models (verbatim, complete section)

> * **No access to realtime events without search tools enabled**
>   * Grok has no knowledge of current events or data beyond what was present in its training data.
>   * To incorporate realtime data with your request, enable server-side search tools (Web Search /
>     X Search).
> * **Chat models**
>   * No role order limitation: You can mix `system`, `user`, or `assistant` roles in any sequence
>     for your conversation context.
>   * `logprobs` and `top_logprobs` are not supported by models `grok-4.20` and newer. These fields
>     will be silently ignored if set.
> * **Image input models**
>   * Maximum image size: `20MiB`
>   * Maximum number of images: No limit
>   * Supported image file types: `jpg/jpeg` or `png`.
>   * Any image/text input order is accepted (e.g. text prompt can precede image prompt)
> * **Batch API**
>   * Not every model accepts Batch API requests. See Details on each model page.
> * **Encrypted reasoning**
>   * On the Responses API, `grok-4.7` always returns `reasoning.encrypted_content`, even when
>     `include` does not list it.

> The knowledge cut-off date of Grok 4.7 is May 2026.

## Model Aliases (verbatim, complete section)

> Some models have aliases to help users automatically migrate to the next version of the same
> model. In general:
>
> * `<modelname>` is aliased to the latest stable version.
> * `<modelname>-latest` is aliased to the latest version. This is suitable for users who want to
>   access the latest features.
> * `<modelname>-<date>` refers directly to a specific model release. This will not be updated and
>   is for workflows that demand consistency.

## What this establishes

- **`grok-4.7` is the vendor's recommended default for both code and chat.** It is named twice in
  "Which model should I choose?" and is described as "the most capable model we've built".
- **4.7 and 4.6 are priced identically, line for line**, including the cached-input rate. 4.5 is
  the outlier with a cheaper cache ($0.30 / $0.60).
- **The family's context windows split into two classes**: 500k for 4.5/4.6/4.7, and 1M for 4.3
  and the 4.20 line. So 4.7 trades context for recency and capability — it is *not* the
  longest-context Grok.
- **`grok-4.7` is "newer" than `grok-4.20`** in release order, which matters for the logprobs rule
  below.
- **Image inputs on xAI text models are capped at 20 MiB, `jpg/jpeg`/`png` only, with no limit on
  the number of images.** Order of text and image parts is free.
- **The alias convention is documented but 4.7 has no aliases**: the `<modelname>-<date>` form is
  the documented way to pin a snapshot, and no such slug exists for `grok-4.7` on its own page.
  `grok-latest` is a family-wide alias (referenced by the regional-endpoints page) but is not
  listed in this table.
- **`logprobs`/`top_logprobs` are stated as unsupported "by models `grok-4.20` and newer"** and are
  "silently ignored". `grok-4.7` was released after `grok-4.20`, so on a plain reading the rule
  covers it — yet OpenRouter advertises `logprobs` and `top_logprobs` as supported parameters for
  its `x-ai/grok-4.7` endpoint ([OpenRouter](../../openrouter.ai/grok-4-7/2026-10-26/index.md)).
  Either "newer" is meant numerically (4.3/4.5/4.6/4.7 do not count as newer than 4.20) or
  OpenRouter's parameter list is wrong. Unresolved.
- **Batch API eligibility is per-model**, not family-wide, which is why 4.7's own page has to
  state it separately.

## Gaps

- No deprecation or retirement schedule for any Grok 4.x model appears on this page.
- The page does not say whether `grok-4.7` (undated) floats to new snapshots or is itself the
  pinned slug; the alias rules imply the former for `<modelname>`, but no dated 4.7 slug exists to
  contrast it with.
- No latency, throughput, or output-token limits per model.

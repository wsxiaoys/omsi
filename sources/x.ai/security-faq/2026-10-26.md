# xAI docs: Security FAQ (data handling for Imagine requests)

- Origin: xAI developer documentation, "Frequently Asked Questions - Security",
  <https://docs.x.ai/developers/faq/security> (`.md` capture)
- Evidence kind: official documentation (provider policy)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: the `grok-imagine` image models (`grok-imagine-image`,
  `grok-imagine-image-2.0`, `grok-imagine-image-quality`)

## Retention and training (verbatim)

> SpaceXSI never trains on your API inputs or outputs without your explicit permission.

> By default, all API requests and responses are stored on our servers (encrypted at rest) for 30
> days for auditing purposes in the event of suspected abuse or misuse. SpaceXSI does not train on
> this data, and it is automatically deleted after 30 days.

## Zero Data Retention and image generation (verbatim)

> **Stored image and video outputs** — Image and video generation can have SpaceXSI host the
> generated media and return it as a `file_id` or URL. Under ZDR there is no SpaceXSI-side output
> storage: no `file_id` inputs and no stored outputs. For images, return base64 or supply your own
> pre-signed upload URLs in `output.upload_urls` (one per image, required for deferred image
> requests). […] **Image generation is also limited to `grok-imagine` models and excludes agentic
> image generation.**

## Regional endpoints (verbatim)

> The default endpoint, `https://api.x.ai`, does not guarantee a processing region. To keep API
> request handling, model inference, moderation, and retained request data in the United States,
> use the US regional endpoint, `https://us.api.x.ai/v1`. It currently serves only `grok-4.7` and
> `grok-4.6`, **with no image generation, video generation, or voice APIs**, and its token prices
> are 10% higher than global rates.

## What this establishes

- xAI states that API inputs and outputs are **not used for training** and are retained 30 days by
  default for abuse auditing.
- The `grok-imagine` image models are explicitly the only image models usable under ZDR, and under
  ZDR the caller must supply output storage (base64 or pre-signed `output.upload_urls`).
- Image generation is **not** available on the US regional endpoint, so "US-only processing" and
  "image generation" are mutually exclusive on the current xAI API — a practical constraint for
  regulated workloads that the Imagine pages do not mention.

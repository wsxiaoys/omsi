# xAI docs: Reasoning (`reasoning_effort`, encrypted reasoning)

- Origin: xAI developer documentation, "Reasoning",
  <https://docs.x.ai/developers/model-capabilities/text/reasoning> (`.md` capture)
- Evidence kind: official documentation (API behaviour)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: `grok-4.7` (roster row 88) — the page's examples all use `grok-4.7`; also
  `grok-4.6`, `grok-4.5`

## Reasoning cannot be turned off (verbatim)

> `grok-4.7`, `grok-4.6`, and `grok-4.5` support the `reasoning_effort` parameter, which controls
> how much effort the model spends thinking before responding.
>
> If not specified, `reasoning_effort` defaults to `"high"`. Reasoning cannot be disabled.
>
> `presencePenalty`, `frequencyPenalty`, and `stop` cannot be used with reasoning models. Requests
> that include them return an error.

## Effort levels (verbatim)

> | Setting | Description | Best For |
> |---|---|---|
> | `"low"` | Uses some reasoning tokens, but still fast | Latency-sensitive agentic use and simple tool calling. |
> | `"medium"` | More thinking for less-latency sensitive applications | Complex data analysis and long-context reasoning. |
> | `"high"` (default) | Uses more reasoning tokens for deeper thinking | Very challenging problems, complex math, multi-step logic, competition-level tasks |
> | `"xhigh"` | Maximum reasoning depth, with correspondingly higher latency | The hardest problems, where answer quality matters more than response time |

> `"xhigh"` is available on `grok-4.6` and later. On models that do not support it, such as
> `grok-4.5`, requests with `"xhigh"` are treated as `"high"`.

## Per-model reasoning controls (verbatim row for `grok-4.7`)

> | `grok-4.7` | `reasoning.effort`: `"low"` / `"medium"` / `"high"` (default) / `"xhigh"` | Controls reasoning depth (cannot be disabled) |

## Encrypted reasoning (verbatim)

> On the Responses API, `grok-4.7` returns `reasoning.encrypted_content` on every response,
> whether or not `include` lists it, together with the encrypted outputs of any server-side tools.
> Reasoning items in the output carry an `encrypted_content` field; pass them back unchanged in
> the next request's `input` so the model keeps its reasoning across turns even when you manage
> conversation history yourself. Unlike an explicit `include`, this default does not stop SpaceXSI
> from storing the thinking trace server-side for rehydration, so clients that ignore the field
> keep working as before; whether the response itself is stored for `previous_response_id` is
> governed by `store`, not by this setting. Chat Completions is unaffected; it has no field for
> the ciphertext.

> For `grok-4.7`, we expose summarizations of the model's internal reasoning.

## What this establishes

- **`grok-4.7` is a mandatory-reasoning model.** There is no non-reasoning mode and no way to
  disable thinking, so a caller cannot trade reasoning tokens for latency below `"low"`. Every
  response carries reasoning tokens that are billed as output.
- **`xhigh` is a real, 4.7-eligible effort level** (available on `grok-4.6` and later), which
  makes 4.7 the second model in the family to support it.
- **Three sampling parameters are rejected**: `presencePenalty`, `frequencyPenalty`, and `stop`
  return an error rather than being ignored. This narrows OpenAI-SDK portability — an application
  that sets `stop` will fail on 4.7 where it worked on a non-reasoning model.
- **Encrypted reasoning is always on for `grok-4.7` on the Responses API.** Unlike an explicit
  `include`, the default does **not** prevent xAI from storing the thinking trace server-side for
  rehydration — a data-handling detail that differs from what an explicit `include` would imply,
  and one that a privacy-sensitive deployment needs to account for.
- **Chat Completions has no field for the ciphertext**, so multi-turn reasoning continuity is
  effectively a Responses-API feature.

## Contradiction with the Grok 4.5 model page

This page says `grok-4.5` does not support `xhigh` and downgrades it to `high`, while the
`grok-4.5` model page lists `xhigh` among its supported efforts
([4.5 page](../grok-4-5-model-page/2026-10-26.md)). Recorded, not resolved. It does not affect
`grok-4.7`, where both pages agree.

## Gaps

- No `reasoning_tokens` cap, no statement of whether reasoning tokens bill at the output rate
  (the Pricing page says "Reasoning tokens: Agent's internal thinking and planning" are billed as
  a standard token type, which implies yes, but this page does not restate it).
- No guidance on the latency cost of `xhigh` in seconds.
- The page does not say whether reasoning summaries are available on Chat Completions.

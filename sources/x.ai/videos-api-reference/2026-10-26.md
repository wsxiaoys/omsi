# xAI docs: Inference API — Videos (REST reference)

- Origin: xAI developer documentation, "Videos" (REST API reference),
  <https://docs.x.ai/developers/rest-api-reference/inference/videos> (`.md` capture)
- Evidence kind: official documentation (API reference / request schema)
- Publication date: none stated; live page
- Capture date: 2026-10-26
- Relevant models: `grok-imagine-video-1.5` (example model in every code block);
  `grok-imagine-video` (edits/extensions endpoints)

## Endpoints

`POST /v1/videos/generations` (T2V, I2V, R2V, first/last frame, keyframes), `POST /v1/videos/edits`,
`POST /v1/videos/extensions`, plus status polling by `request_id`.

## Request fields (verbatim, abridged)

> * `aspect_ratio` ("1:1" | "16:9" | "9:16" | "4:3" | "3:4" | "3:2" | "2:3" | "21:9" | "5:2")
> * `duration` (integer | null) — Video duration in seconds. Range: \[1, 15]. Default: 8.
>   Also accepts `seconds` for OpenAI API compatibility.
> * `image` (object) — `file_id` (File ID from the xAI Files API; "The file must be an image
>   (JPEG, PNG, or WebP) and fully uploaded") or `url` ("Public URL or base64-encoded data URL")
> * `keyframes` (array\<object>) — Optional mid-video keyframe anchors … at most 4 entries.
>   `timestamp_s` must be strictly inside the clip (0 < t < duration).
> * `reference_audios` (array\<object>) — Optional reference audio clips (voice identity) for
>   reference-to-video generation. Each entry supplies a clip via `url` or selects a voice via
>   `voice_id`; caller-supplied clips must be at most 15 seconds long. Only supported by select
>   video models; at most 3 entries. May be provided without `reference_images` (audio-only
>   reference-to-video).
> * `reference_images` (array\<object>) — Optional reference images for reference-to-video (R2V)
>   generation.
> * `resolution` ("480p" | "720p" | "1080p")
> * `output` (object) — `upload_url` (required): "Signed URL to upload the generated video via HTTP
>   PUT, e.g. an S3 / GCS presigned URL or an Azure Blob SAS URL."
> * `prompt` (string) — "Required for text-to-video (T2V) and reference-to-video (R2V). Optional for
>   image-to-video (I2V) — when omitted, the model generates a video from the image alone."
> * `storage_options` (object) — `expires_after` (seconds, max 2592000 = 30 days), `filename`,
>   `public_url`
> * `user` (string | null)

## What this establishes

- **The reference schema is the most permissive first-party statement of the request surface**: it
  lists `1080p` and all nine aspect ratios without model qualifiers, and documents `reference_audios`
  entries that accept either a preset `voice_id` **or a caller-supplied audio URL of up to 15 s**.
- **That last point contradicts the reference-to-video guide**, which says user-supplied voice
  references "are available to trusted partners on request"
  (`../imagine-video-reference-to-video/2026-10-26.md`). The schema does not gate `url`; the guide
  says access is gated. Recorded as unresolved.
- Output storage is caller-supplied via a signed `upload_url`, and `storage_options` supports up to
  30 days — relevant because generated video URLs are otherwise temporary.
- The schema does **not** include a frame-rate, codec, or seed field.

## Gaps

- No per-model applicability table: `resolution: 1080p` and `keyframes` are listed without saying
  which model accepts them, so a client generated from this spec will send invalid combinations to
  1.0 and lite (which reject 1080p / pinned frames respectively).
- No maximum prompt length, no image dimension limits, no rate-limit statement on this page.
- `POST /v1/videos/edits` and `/extensions` are documented here but no page states that they are
  1.0-only; that restriction appears only on the model pages and the overview table.

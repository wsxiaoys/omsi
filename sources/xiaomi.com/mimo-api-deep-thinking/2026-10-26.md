# MiMo API deep thinking (reasoning) guide

- **Origin:** "Deep Thinking", Xiaomi MiMo API Open Platform,
  <https://mimo.mi.com/static/docs/quick-start/usage-guide/text-generation/deep-thinking.md>.
  Retrieved 2026-10-26.
- **Evidence kind:** official documentation (first-party API usage guide).
- **Publication date:** none stated on the page.
- **Capture date:** 2026-10-26
- **Relevant models:** `mimo-v2.6-flash`, `mimo-v2.6-pro`, `mimo-v2.6-pro-ultraspeed` — these
  three are the only models the page supports.
- **Capture type:** full raw Markdown of the page.

## Reasoning control, verbatim

> "Set the `thinking.type` parameter in the request to control deep thinking: `enabled` to enable
> deep thinking or `disabled` to disable deep thinking."

> "**Default Status:** Enabled by default: `mimo-v2.6-flash`, `mimo-v2.6-pro`,
> `mimo-v2.6-pro-ultraspeed`"

> "The `thinking` field is not a standard OpenAI parameter. When passing thinking-related
> parameters via the OpenAI Python SDK, they must be included in `extra_body`."

Reasoning text streams in a separate `reasoning_content` field, and `usage` reports
`completion_tokens_details.reasoning_tokens`. The page's worked examples show a
`thinking`/`reasoning_content` round trip in non-streaming and streaming form.

## Constraints, verbatim

> "In deep thinking, `mimo-v2.6-flash`, `mimo-v2.6-pro`, `mimo-v2.6-pro-ultraspeed` models do not
> support custom `temperature` and `top_p` parameters."

> "When deep thinking is enabled in Agent product multi-turn conversations, and historical
> conversations contain tool calls, the assistant responses passed back in all subsequent user
> interaction rounds that contain tool calls **must completely pass back the `reasoning_content`
> field, otherwise the API will return a 400 error**."

> "If historical `reasoning_content` is missing, the model's context will be incomplete, which may
> result in decreased instruction following and increased hallucinations."

> "`max_completion_tokens` limits the total length of thinking content and the final answer."

The page lists affected agent products per protocol — OpenAI-compatible: TRAE, Cursor, Roo Code,
Codex, GitHub Copilot CLI, Zed, AutoGen, Goose; Anthropic-compatible: TRAE, GitHub Copilot CLI,
AutoGen, Goose, OpenClaw, OpenCode, Kilo Code.

## What this establishes

- Reasoning is a **toggle**, not an effort scale: there is no `reasoning_effort` enumeration and
  no thinking-budget parameter anywhere in the captured docs. One binary switch, on by default.
- Because thinking mode forces temperature 1.0 / top_p 0.95, any harness that relies on
  deterministic sampling has to disable thinking to get its own values honoured.
- The mandatory `reasoning_content` echo is an integration hazard for agent scaffolds: a host or
  proxy that strips reasoning from the message history will break multi-turn tool use with a 400.

## Gaps

- No statement of a maximum thinking length, a reasoning-token price differential (reasoning
  tokens bill as output tokens per the pricing page, but the docs do not say so explicitly here),
  or whether `thinking.type: disabled` degrades quality on agentic tasks.
- No guidance on which tasks benefit; the page's only quality claim is the generic
  "significantly improving accuracy on complex tasks".

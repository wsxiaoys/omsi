## Identity and positioning, verbatim

> "**GLM-5.3** is Z.ai's latest flagship model, delivering comprehensive advancements in
> complex software engineering and agent capabilities. It uses the same base model as
> GLM-5.2, with all improvements driven by post-training."

> "GLM-5.3 delivers a significant improvement in coding capabilities, achieving a 50%
> performance gain over GLM-5.2 on Z.ai Code Bench. It also reaches state-of-the-art (SOTA)
> performance among open-source models on public benchmarks, including Terminal Bench 3.0
> and Agents' Last Exam (CLI)."

> "GLM-5.3 achieves the best performance to date on the CyberGym vulnerability discovery
> benchmark. Moreover, the deeper it progresses along the vulnerability exploitation chain,
> the more pronounced its gains over GLM-5.2 become, with scores on vulnerability
> exploitation benchmarks exceeding twice those of GLM-5.2."

The page carries a banner: "GLM-5.3 is now available to all GLM Coding Plan users, with 50%
better coding performance!"

## Modalities, context and limits, verbatim

> "GLM-5.3 currently supports text-only inputs, with a 1M-token context window and a
> maximum output length of 128K tokens."

So: **text in, text out**; no image, audio, video or file input documented for this model.
(That contrasts with `GLM-5.3-Flash`, documented as natively multimodal — a different model.)

## Reasoning controls, verbatim table

| Parameter | Values | Default | Description |
| --- | --- | --- | --- |
| `thinking.type` | `enabled` | `enabled` | Supports reasoning only; disabling reasoning is not supported. |
| `reasoning_effort` | `low`, `high`, `max` | `max` | `low` – Lightweight Reasoning; `high` – Enhanced Reasoning; `max` – Deep Reasoning |

> "Migration Notice: If your application currently uses **`thinking.type: "disabled"`**,
> please change it to **`enabled`** and set **`reasoning_effort`** to **`low`** before
> updating the model ID to **`glm-5.3`**. Otherwise, the request will fail."

This is a hard API break for anything written against GLM-5.2's ability to disable thinking.

## Endpoints, verbatim

| Protocol | Base URL |
| --- | --- |
| OpenAI Chat Completion Protocol | `https://api.z.ai/api/coding/paas/v4` |
| OpenAI Response Protocol | `https://api.z.ai/api/v1` |
| Anthropic Message Protocol | `https://api.z.ai/api/anthropic` |

> "If you have previously subscribed to a GLM Coding Plan, including an expired
> subscription, you can currently access the model API only through the OpenAI Chat
> Completion-compatible protocol."

The chat-completion sample uses `POST https://api.z.ai/api/paas/v4/chat/completions` with
`"model": "glm-5.3"` — a fourth base URL, differing from the table above by the missing
`/coding` segment. Both appear on the same page; the discrepancy is not explained.

## Capability support, verbatim list

  with a wide range of external tools"
- "Context Caching：Uses an intelligent caching mechanism to optimize performance in
  long-context conversations"

No agent/tool-orchestration surface beyond function calling is documented on this page.

## GLM Coding Plan

> "The new GLM Coding Plan adopts a points-based quota system, providing transparent and
> predictable usage. Model calls made during off-peak hours, including all day on weekends,
> consume only 50% of the standard points."

## Summary

First-party confirmation of: canonical API ID `glm-5.3`; text-only modality; 1M context /
128K output; mandatory reasoning with three effort levels defaulting to `max`; a breaking
change versus GLM-5.2 for `thinking.type: "disabled"`; three-plus first-party base URLs;
and function calling, caching and structured output.
